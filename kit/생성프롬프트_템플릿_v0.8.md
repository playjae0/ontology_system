## [지시]

신규 문서 양식 하나를 등록한다. 표본 문서를 관찰해 **① 어댑터 코드**와 **② 매칭 스키마 JSON**을 산출하라. 두 산출물은 그대로 파이프라인에 투입되어 실행된다 — 설명이 아니라 **동작하는 코드**를 내라.

**첫 판단 — payload_kind.** 표본을 관찰해 이 양식이 `table`(행=record인 표)인지 `prose`(줄글·목차형·슬라이드형)인지 먼저 정하라. **이 판단이 산출물 2의 형태를 가른다:**

| payload_kind | 산출물 1 (어댑터) | 산출물 2 (매칭 스키마) |
|---|---|---|
| `table` | 헤더·열 파싱 코드 | **`fields`에 열마다 role 배정** + edges 선언 |
| `prose` | 청크 분할 규칙 코드 | **`fields`는 빈 목록 `{}`** — `layer`·`use_blocks` 선언이 계약의 전부. **role 배정표를 만들지 않는다** |

**prose에 role 표가 없는 이유** (지시가 아니라 이해를 위한 배경): prose 조각의 키는 문서의 열이 아니라 계약이 고정한 4종(`text`·`section`·`meta`·`image_ref`)뿐이고, 이 4종은 아래 「role 배정 대상이 아닌 필드」에 속한다. 개체·관계는 등록 시점의 표가 아니라 **인입 시점의 추출 단계**가 낸다. 비정형 문서는 문서마다 목차·구조가 다른 것이 기본값이므로, 헤딩 경로(`section`)의 의미를 하나의 role로 고정하려는 시도 자체가 잘못 세워진 물음이다.

**관찰 범위 규칙 (고정)**
정형(표): 헤더와 데이터 **약 10줄**이면 형식이 드러난다. 비정형(줄글·목차형): 10~30줄, 목차형처럼 패턴이 반복되면 **계층 패턴이 2~3회 반복해 나타날 때까지** 확장한다.

**관찰 체크리스트**: 들여쓰기 · 열 위치 · 번호 패턴 · 서식(굵게) · **병합 셀** · 빈 셀 · **상동 기호(`〃`)** · **한 셀 안 복수값**.

## [role 어휘 — table의 필드마다 이 6가지 중 하나 · prose는 대상 아님]

role은 **그 필드의 값으로 그래프에 수행하는 쓰기 동작**이다. 필드의 이름이나 중요도가 아니라 "이 값으로 그래프에 무엇을 하는가"로 판단한다.

| role | 뜻 | 판별 |
|---|---|---|
| `anchor` | 이미 존재하는 **골격 노드를 찾아라**(해소). 새로 만들지 않는다 | 값이 아래 골격 닫힌 목록 안에 있는가 |
| `entity` | **노드가 될 자격이 있는 것**을 데려와라 | "이것에 대해 더 말할 게 생기는가?" → 예 |
| `attribute` | 어떤 것 **자체가 아니라 어떤 것에 붙어 있는** 성질·값. 노드를 만들지 않고 노드 필드에 저장 | 위 물음에 아니오. 구조체·배열도 통째로 하나의 값 |
| `content` | 청크로 보존해 노드에 연결할 **서술** | 아래 판별 기준 참조 |
| `meta` | 내용물이 아니라 **내용물의 신상정보**. 그래프에 넣지 않고 출처 장부에만 적는다 | 개정번호·작성일·작성자·문서번호 |
| `UNMAPPABLE` | **위 5종 어디에도 맞지 않는다.** 추측하지 말고 이것을 고르고 이유를 적는다 | 사람이 판정한다 |

**`content`의 판별 기준** — "자유 서술"만으로는 부족하다. 아래 중 하나면 `content`다.
- 필드 단위 규칙 처리가 불가능하다(값이 아니라 **문장**으로 읽힌다).
- 짧더라도 **조치·대응·설명·계획** 계열이다. 예: "금형 점검 후 재검사", "가압 조건 재설정".
- 그 값 자체를 검색해 원문으로 돌려줄 필요가 있다.
반대로 규격·측정 방법·판정 기준처럼 **값으로 비교·필터되는 것**은 `attribute`다.

**중요**: role 5종은 그래프가 허용하는 쓰기 동작을 전수 열거한 것이다. 억지로 끼워 맞추지 말고, 맞지 않으면 `UNMAPPABLE`을 골라라. 판단이 서지 않는 필드도 `UNMAPPABLE` + "판정 불가" 사유로 올린다 — 검수 화면에서 사람에게 질문으로 표시된다.

** UNMAPPABLE을 피하려 하지 마라.** 관찰된 경향이 있어 적어 둔다 — 생성 세션은 `UNMAPPABLE`을 **실패로 느껴** 어떻게든 5종 중 하나에 밀어 넣으려 한다. 그것이 이 지시가 막으려는 바로 그 행동이다.

- `UNMAPPABLE`은 **오답이 아니라 정직한 답**이다. 검수 화면은 그것을 질문으로 띄우고 사람이 판정한다 — 그 경로가 설계에 있다.
- **억지 배정의 비용이 훨씬 크다.** 잘못 배정된 열은 조용히 그래프에 들어가 틀린 사실이 되고, 나중에 그것을 찾아내는 사람은 없다. 반면 `UNMAPPABLE`은 화면에 뜬다.
- 특히 이런 열을 조심하라: **집계·이력·비고 계열**(예: "최근 불량 이력", "비고", "누적 건수") — 개체도 값도 아니고 그 문서 밖 상태를 요약한 것이라 5종 어디에도 맞지 않는다. **의심스러우면 `UNMAPPABLE` + 사유다.**
- 반대로 **구조 필드는 `UNMAPPABLE`이 아니다**(아래 절). 그것은 미해결이 아니라 정상·완결이며 6지선다에 올리지도 않는다. 둘을 섞지 마라.

**그래프 입장 시험 — `attribute`는 전량 수록이 아니라 선별이다.** 위가 「억지로 5종에 밀어 넣지 마라」라면 이것은 「올릴 가치가 없는 것을 올리지 마라」다. 열을 `attribute`로 올리는 것은 **두 시험이 모두 예**일 때다:

- ⓐ **질문 시험** — 이 값을 **단독으로 묻는 질문이 성립하는가.** 「노칭의 규격은?」은 성립한다. 「측정 포인트 개수는?」 같은 서식 통계는 대개 성립하지 않는다.
- ⓑ **충돌 시험** — 두 문서가 이 값을 다르게 말할 때 **사람이 그 충돌을 판정할 가치가 있는가.** attribute는 `spec_conflict`의 대상이다 — 충돌이 잡음인 값을 올리면 개정 재인입마다 큐가 잡음으로 차 사람의 판정 시간을 먹는다.

하나라도 아니오면 **`meta`로 내린다** — 레코드 이력에는 남되 그래프·질의에 오르지 않는다. 지식이 아니면(서식 번호·서명란·개정 표기) `UNMAPPABLE`이다.

**의심스러우면 내린다.** 방향이 비대칭이기 때문이다 — 잘못 내린 열은 원본 참조로 답할 수 있고 나중에 스키마 한 줄 + 재인입으로 올릴 수 있지만, **잘못 올린 열은 올라가 있는 동안 충돌 큐·답변 근거의 잡음으로 사람 시간을 이미 쓴다.** 그래프는 문서의 보관소가 아니라 **질의가 찾는 층**이다 — 전량 보존은 원본 파일과 청크의 몫이다.

> 이 절은 **문서 2 §2.4의 발췌**다. 갈리면 **문서 2가 이긴다.**

**UNMAPPABLE로 판정한 열의 처리**: 그 열은 **스키마 `fields`에 넣지 말고, 어댑터 출력(조각)에서도 제외하라.** 산출물 3(판정 불가)에만 적는다. 이유: role 값이 닫힌 5종 밖이면 인입 루프의 핸들러 조회가 죽는다 — 2차 실측에서 실제로 크래시했다.

### role별 선택 속성
- `entity`: `category`(필수), `attach_to_field`, `target_layer`(다른 층에 기록할 때만)
- `attribute`: `attach_to_field`, `attr_name`, `contextual`(맥락별로 값이 갈리면 true)
- `anchor`: `target_category`(공정 골격이 아닌 다른 골격을 볼 때만)
- `content`: `attach_to_field`
- 전체: `optional`(빈 값 허용)

| 필드 | 지위 |
|---|---|
| **좌표 블록이 제공하는 필드** (아래 `{{공용_블록_목록}}`에 좌표 블록이 있을 때만 해당) | 대공정·세부공정 좌표 **둘만 `anchor`로 선언한다.** 공통 블록이 제공하므로 직접 쓰지 않아도 된다 |
| **사내 번호 계열**(공정번호 등) | **`meta`다.** 사내 번호 체계는 비표준·가변이라 조회 키로 쓸 수 없다. 노드에 참고 값으로만 저장된다 |
| **극성 계열**(`electrode_type` — 극성 축을 쓰는 층에만) | **role 대상이 아니다.** entity 해소 코드가 직접 읽어 canonical에 극성을 결합한다 |
| `context`(모델·사이트·라인 등 소속 맥락) | **role 대상이 아니다.** 맥락 상속 처리의 입력이며 attribute 저장 시 소비된다. **값은 반드시 딕셔너리다** — 아래 규약 9를 보라 |
| `source_locator` | `meta`. 공통 블록 `common_core`가 제공한다 |
| **`text` · `section` · `meta` · `image_ref` (prose payload 고정 키)** | **payload 구조 필드 — role 대상이 아니다.** 청크의 몸체·주소·부속이며 시스템 코드가 직접 소비한다(청크 저장·id 산식·이미지 요약). `section`은 헤딩 경로 표기일 뿐이다 — **문서마다 목차가 다른 것은 정상이며, 이 필드에 role을 붙이려 하지 마라** |

즉 문서에 "극성" 열이나 "적용모델" 열이 있으면 그것은 위 구조 필드로 **매핑**하는 것이지 role을 붙이는 것이 아니다. 어댑터 출력에서는 각각 `electrode_type` · `context`로 내보내라.

**이 절의 앞 세 행은 층에 따라 해당 여부가 갈린다** — 좌표 블록·극성 축은 **`{{공용_블록_목록}}`이 실제로 제공하는 층에만** 있다. 그 블록이 목록에 없으면 그 행은 이 층에 해당하지 않는다. **`source_locator`와 prose payload 고정 키 4종은 전 층 공통이다.**

## [출력 규격 — 실행되는 산출물]

### 산출물 1 — 어댑터 코드 (Python, 그대로 실행됨)

```python
ADAPTER = {
    "doc_type": "<이름>",
    "adapter_version": "1.0",
    "payload_kind": "table",          # "table" | "prose" — 닫힌 2값
    "expects": {                      # 관찰 상수 = 이 양식의 지문
        # --- table 필수 ---
        "header_row": 3,
        "header_labels": ["대공정", "공정No", "공정명", ...],   # 필수 — 원본 헤더 문자열의 순서 배열.
                                                              # preflight가 양식 표류를 이것으로 감지한다
        "columns": {"<좌표 필드>": "A", "<열이름>": "C", ...},  # {출력 필드명: 열문자} — 용도:
                                                              # columns의 키는 원본 헤더가 아니라 "출력 필드명"이다
        # --- prose면: header_labels 없음. 분할 신호 상수(헤딩 번호 패턴·구분자 등 — 관찰 기록)만 ---
        "multi_value_sep": ", ",
    },
}

def extract(raw) -> list[dict]:
    """reader 원시 추출물 → 정규 조각 리스트. 조각마다 source_locator 포함."""
```

**어댑터 규약 (위반 시 실행 하네스가 잡는다)**
1. **순수 함수다.** 파일 밖 상태·네트워크·LLM 호출 금지. 같은 입력 → 같은 출력.
2. **`locate` 함수를 두지 마라.** 위치는 추출 순회 중에만 자명하다. 전처리 훅도 두지 마라.
3. **`source_locator`는 문서 안에서 유일해야 한다.** 형식은 자유(예: `"검사성적서!R12"`, `"슬라이드 5"`).
4. **정본 id(`chunk_id`·`record_id`·`doc_hash`)를 만들지 마라.** 그것은 에이전트가 내용에서 계산한다.
5. **자기완결성을 보장하라** — 병합 셀은 각 행에 복제, 상동 기호(`〃`)는 실제 값으로 치환, 한 셀 복수값은 **행으로 전개**, 중첩 구조는 쌍으로 평탄화. (구현 방법은 규약 10 — 직접 구현하지 마라.)
6. **이미지는 placeholder 조각으로만 낸다**: `{source_locator, image_ref, section?}`. 요약 LLM 호출은 코어 몫이다.
7. **[table 한정]** 조각 출력의 키 이름은 **매칭 스키마의 `fields` 키와 정확히 일치**해야 한다. 구조 필드는 위 표가 정한 이름을 쓴다(좌표·번호·극성 계열은 그 블록을 쓰는 층에만 해당 · `context`는 전 층 공통). **[prose]** 조각의 키는 계약 고정 4종(`text`·`section`·`meta` / 이미지는 `image_ref`)과 구조 필드뿐이다 — 새 키를 발명하지 마라.
8. table이면 조각 = 행(record), prose면 조각 = 청크(`text`·`section`·`meta`). prose의 `section`은 그 청크의 소속 표기(예: 헤딩 경로)이며 role 배정 대상이 아니다.
9. **`context`는 임의 딕셔너리다 — 스칼라로 내지 마라.** 문서의 "적용모델" 열 값이 `M1`이면 조각에 `"context": "M1"`이 아니라 **`"context": {"model": "M1"}`**으로 낸다. 축 이름(`model`·`site`·`line`…)은 그 문서에서 관찰된 것을 쓰고, 관찰되지 않은 축을 지어내지 않는다. 값이 여럿이면 리스트다(`{"line": [1, 2, 3]}` = 공통 소속).
10. **병합 전개·상동 치환·복수값 전개·열문자 변환은 `parser.normalizer`를 불러서 하라 — 직접 구현하지 마라.** `from parser import normalizer`는 규약 1(순수 함수) 위반이 아니다 — 파서 내부의 순수 함수다. 쓰는 것: `normalizer.expand_merged(sheet)` → 전개된 `cells` / `normalizer.resolve_ditto(records, marks=…)` → `(레코드, 치환 건수)` / `normalizer.split_multi(records, fields, seps)` → `(레코드, 전개 건수)`. 어댑터가 재구현하면 병합 처리 버그 하나에 어댑터 전부를 고쳐야 한다. **어댑터 몫으로 남는 것은 「이 문서의 어느 열이 무엇인가」뿐이다** — 그것이 LLM인 네가 판단할 전부다.
   - **왜 강제인가**: `context`는 봉투→레코드 상속과 맥락별 값 분리(같은 관리항목의 모델별 규격)를 동시에 담당한다. 스칼라면 축 이름이 없어 상속도 분리도 성립하지 않는다.
   - **어기면 무슨 일이 나나**: 인입 코드가 계약 위반을 감지해 그 필드를 버리고 `missing_field` 큐로 올린다 — 문서는 들어가지만 **맥락 정보가 통째로 사라진다.** 3차 산출이 실제로 `"M1"`을 냈고, 그때는 인입이 예외로 죽었다.
   - 열이 비어 있으면 `context` 키 자체를 빼라. 빈 딕셔너리로 덮으면 봉투 값 상속이 끊긴다.

### 참조 어댑터 — 규약 10을 지킨 **실물 1종**

아래는 이미 운영 중인 어댑터다. **양식이 아니라 실례다** — 네가 낼 산출물 1이

이름·관찰 상수는 네 표본의 것이어야 한다.

### 산출물 2 — 매칭 스키마 (JSON, 그대로 로드됨)

**table:**
```json
{
  "doc_type": "<이름>", "schema_version": 1, "layer": "{{층_이름}}",
  "use_blocks": [ … {{공용_블록_목록}} 중에서 …  ],
  "fields": { "<열이름>": {"role": "...", "...": "..."} },
  "edges": [ {"from": "...", "relation": "...", "to": "...", "optional": true} ]
}
```

**prose:**
```json
{
  "doc_type": "<이름>", "schema_version": 1, "layer": "{{층_이름}}",
  "use_blocks": [ … {{공용_블록_목록}} 중에서 …  ],
  "fields": {},
  "edges": []
}
```
비정형 문서는 role 매핑 표가 없다 — **어느 층에 속하는지의 선언이 계약의 전부**이고, 개체·관계는 인입 시점의 추출 단계가 낸다. `fields`를 채우거나 `text`·`section`·`meta`에 role을 붙이면 그 스키마는 무효다.

`from`/`to`는 필드명 또는 `@<좌표필드>` 형태의 좌표 참조다(좌표 블록을 쓰는 층에 한한다). `use_blocks`가 제공하는 필드(`source_locator` + 좌표 블록이 있으면 그 좌표 필드들)는 `fields`에 다시 쓰지 않아도 된다. **어떤 블록을 쓸 수 있는지는 `{{공용_블록_목록}}`이 정한다.**

# MANIFEST — 레포 배치와 문서 반입 · 2026-08-13 개정판 (18회차 정합 수리)

> **개정 사유.** 08-07판은 요구 판본표를 숫자로 박아 두었는데, 그 표가 6일 만에 구판이 되었다(틀 v2.4·카드 v11·증분0 v1.3·raw_mock v2.1 → 실물 v2.7·v14·v1.4·v2.2). 그 상태에서 §「넣은 뒤 확인」을 문면대로 수행하면 **최신본을 구판으로 되돌리라는 지시**가 된다. 검사 5(반입 대조)를 세운 문서가 스스로 검사를 무력화했다.
> **이번 개정의 핵심은 판본 숫자를 이 파일에서 뺀 것이다.** 그리고 실제로 갈라진 4건은 이 표가 하나도 잡지 못했다는 사실을 §「판본 확인」의 경고로 남겼다.
>
> 이 파일이 정하는 것: ①레포 파일 배치와 파일명 ②무엇을 반입하고 무엇을 넣지 않는가 ③반입 후 확인 절차. **판본은 정하지 않는다.**

## 판본 확인 — 기준점은 대장 하나다 [18회차 신설]

숫자를 두 곳에 두면 반드시 어긋난다. **판본의 단일 기준점은 `docs/00_챕터_대장.md`다.**

| 무엇을 | 어디서 |
|---|---|
| 각 챕터·파생 문서의 현행 판본 | 대장 **§1** — 챕터 헤더의 `파일 vN` + 파생 문서 표 |
| 대장 자신이 최신인지 | 대장 **§4 검사 로그의 마지막 회차 번호**. 사람이 프로젝트본과 이 번호만 대조한다 |
| 어떤 결정이 살아 있는지 | 대장 **§4**(판정 이력) · **§7 ③**(추가 작성할 것) · 레포 `DECISIONS.md`(장부) |

반입 후 각 파일 머리의 `version:` 줄을 **대장 §1과** 대조한다. 어긋나면 그 파일이 낡았거나 대장이 낡은 것이고, 둘 중 어느 쪽인지는 §4 회차 번호로 가른다.

> ### ⚠ 판번호가 같아도 본문이 다를 수 있다
>
> **실측(18회차)**: `증분0_구현.md`가 프로젝트·레포 양쪽 `v1.4`인데 레포 사본은 §0 기준이 틀 v2.4/카드 v11인 구 본문이었다 — **131줄 차이**. 판본 대조를 통과했다고 동기화된 것이 아니다.
>
> 같은 회차에 갈라진 것이 4건이었고 **구 판본표는 그중 하나도 잡지 못했다**: 증분0(판번호 동일) · 00_챕터_대장(표에 없음) · CH3B(표에 없음) · CH7(표에 "넣지 않는 것"으로 잘못 등재). 반대로 표가 "불일치"로 잡은 4건은 전부 오탐이었다.
>
> **그래서 대량 개정 세션 뒤에는 판번호가 아니라 다음을 본다**: ①대장 §4 마지막 회차 ②각 문서 §0·머리말의 **기준 판본 줄**(예: 증분0 §0 상속표의 "틀 vX / 카드 vY") ③파일 크기.

## 레포 구조 — 파일명·경로는 이 트리가 정본이다

```
<레포 루트>/
├── CLAUDE.md              ← 루트 고정 (매 세션 자동 로드 — docs/로 내리면 로드되지 않는다)
├── README.md
├── DECISIONS.md           ← 가결정·확정 장부. 번호 발번처는 이 파일 하나다
├── BLOCKERS.md            ← 멈춤 사유 + 판정 필요 (판단 재료 3요소 첨부)
├── PROGRESS.md            ← 구간 정산 보고. ⚠ 결정 번호를 적지 않는다 (08-10 규칙)
├── run.py · router.py · .gitignore
├── core/                  ← 에이전트 코어. 외부 패키지 0 · 층 어휘 0(B1)
├── layers/                ← 층별 config.json + process/skeleton.json(seed 실물)
├── schemas/               ← 매칭 스키마
├── parser/                ← 파서 공용 코어 (openpyxl·python-pptx 허용 — D-9)
├── kit/                   ← 어댑터 생성 킷 6종 (템플릿 + 봉인 정답표 + run_adapter.py — D-27)
├── tools/                 ← gen_parsed_mock.py 등 보조 스크립트
├── tests/                 ← test_g1_g2.py · test_g3.py · verify_roundtrip.py · xlsx_common.py
├── mock/
│   ├── raw/               ← 실물 10종 (xlsx·pptx)
│   ├── parsed/            ← raw prefix에서 파생 (tools/gen_parsed_mock.py — D-34)
│   └── fixtures/          ← 외부 세션의 LLM이 실제로 산출한 adapter·schema 스냅샷 (D-26)
└── docs/                  ← 문서 전부, 하위 폴더 없이 평면. 확장자는 소문자 .md
```

**파일명 규칙 — Ubuntu는 대소문자를 구분한다.** 챕터는 대문자 `CH{n}_`, 기준 문서는 `00_`. 이 규칙을 어긴 반입이 두 번 사고를 냈다(D-38 `Ch2` 중복 — 정본 경로에 구판이 남아 G3이 그것을 읽을 뻔했다 / `Ch7` 동종). **반입 시 기존 파일을 교체하는지 새로 만드는지 반드시 확인한다.**

## 넣지 않는 것

| 대상 | 사유 |
|---|---|
| `claude/*` (구현 트랙 미러) | 미러는 이 레포 `PROGRESS.md`의 **사본**이다. 방향은 레포 → 프로젝트 |
| `안건/*` · `참조/*` · `archive/*` | 판정 대기 안건서·외부 조사물·폐기 이력. 필요하면 그때 지목해 반입 |
| `CH1_기반.md` | P1~P7은 카드가 압축본을 갖는다 |
| `문서체계_대전제.md` · `구조설명서_메인.md` · `파서_인수인계.md` | 대체됨 |
| `M2_판정문안_초안.md` | **18회차에 삭제.** 소진된 판정 기록 — 판정 결과는 전 정본에 반영됐고 DECISIONS 전달(D-42~D-48)도 끝났다. 남는 가치는 §11 통용성 검토뿐이며 identity_axis 일반화(이연) 착수 시 반입한다. 레포에 두면 형식 서술이 개정될 때마다 동기화 비용이 붙는다(D-53 실례) |

> **"넣지 않는 것"은 금지가 아니라 기본값이다.** 결정이 막히는데 그 문서가 필요하면 `BLOCKERS.md`에 기록하고 요청한다 — 추측으로 메우지 않는다.

## 반입 절차 — 사람이 한다

**구현 세션은 claude.ai 프로젝트를 직접 읽지 못한다**(16회차 확정). 구 MANIFEST의 "프로젝트에서 직접 내려받는다"는 사람 기준의 서술이었다. 문서는 사람이 레포에 넣고, 실행·검증은 구현 세션이 한다.

1. **넣는다** — 프로젝트 `chapters/`·`안건/`에서 위 목록의 파일을 받아 `docs/`에 평면으로 놓는다. 파일명은 위 트리 그대로(대소문자 포함).
2. **교체인지 신규인지 확인한다** — 기존 파일이 있으면 덮어쓴다. 이름이 한 글자라도 다르면 중복이 되고, 정본 경로에 구판이 남는다(D-38).
3. **대장 §1과 대조한다** — 각 파일의 `version:` 줄. 어긋나면 §「판본 확인」의 절차로 어느 쪽이 낡았는지 가른다.
4. **§0·머리말 기준 판본 줄을 본다** — 판번호가 같아도 본문이 다를 수 있다(위 경고).
5. **docs/ 안 문서끼리 대조한다 (검사 5 — 반입 대조).** 계수·판본·경로가 문서마다 다르면 그 자체가 결함 신호다. 프로젝트 안에서는 파일이 갈라져 있어 안 드러나던 것이 한 레포에 모이면 드러난다.
6. **코드 상태를 단정하는 문안은 실물을 연다 (검사 6 — 실물 대조).** 절단된 출력·요약·타 문서의 보고로 대체하지 않는다.

## 이 파일의 갱신 규칙

- **판본 숫자를 다시 적지 않는다.** 적는 순간 이 파일이 또 낡는다.
- 반입 목록에 파일을 더하거나 빼면 **같은 커밋에서** 이 파일과 대장 §1을 함께 고친다.
- 레포 구조(디렉터리·파일명 규칙)가 바뀌면 이 파일이 정본이므로 여기부터 고친다.

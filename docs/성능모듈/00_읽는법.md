# 성능 모듈 카드 — 읽는 법

> **왜 이 묶음이 있나.** 시스템의 답 품질을 실제로 좌우하는 자리는 열 남짓이다 — 문서를 어떻게 읽고 자르는가, 청크에서 무엇을 뽑는가, 같은 것인지 어떻게 판정하는가, 질문에 무엇을 모으는가. 이 자리들은 **명세·구조도·코드에 흩어져 있어** 한 자리씩 「지금 어떻게 동작하고, 무엇을 돌리면 달라지고, 실문서에서 무엇을 봐야 하는지」를 한 장으로 볼 수 없었다.
> **용도.** 사내 실측에서 한 모듈씩 보고 → 고치고 → 확정한다. **카드는 확정 도장의 자리다** — 실측을 거쳐 「이대로 간다」가 되면 머리에 그렇게 적는다.
> **정본이 아니다.** 판단이 갈리면 `docs/spec/`이 이긴다. 카드는 정본과 코드를 **읽어서 그린 설명서**이고, 코드가 바뀌면 카드도 낡는다 — 그래서 각 카드 머리에 「실물 기준 커밋」이 있다.

## 카드 한 장의 모양

| Section | What it answers |
|---|---|
| 한 줄 | 이 모듈이 답 품질에 어떻게 닿나 |
| 무엇을 받아 무엇을 내나 | 입력 → 출력, 실물 파일 이름 |
| 어떻게 동작하나 | 갈래·순서·조건 — **판정이 어디서 갈리는지** |
| 조절 손잡이 | 사람이 돌릴 수 있는 것 전부 — 값·자리·언제 효과 |
| 실측에서 볼 것 | 실문서 넣고 무엇을 확인하면 이 모듈이 맞는지 아는가 |
| 고치는 경로 | 손잡이로 안 되면 어디를 어떻게 — 명세 절·코드 자리 |
| 확정 | 실측 뒤 도장 — 날짜·누가·무엇을 근거로 |

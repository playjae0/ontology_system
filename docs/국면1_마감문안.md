# 국면 1 마감 문안

> **판정 대상**: 국면 1을 닫는다. 무엇이 확정되고, 무엇이 측정된 채 이월되는가.
> **원칙**: **완료는 무결이 아니라 미결의 목록화다.** 국면 1이 "완료"라고 선언됐던 지점의 실제 문제는 결함이 있었다는 것이 아니라 **결함 목록이 없었다는 것**이다(`core/llm.py` 부재가 어디에도 등재되지 않았다). 이 문안은 그것을 고친다.

## 1. 국면 1이 낸 것 — 산출물 둘

| 산출물 | 상태 | 정본 위치 |
|---|---|---|
| **명세** — 정제본 10종 + 개정 대장 | **확정. 이 문안으로 닫힌다** | 프로젝트 `정제본/` |
| **코드** — mock 위 메커니즘 구현 | **명세의 현재 판에 대해 갭 58건** — 측정 완료, 2A로 이월 | 레포 `aac08a5` (태그 `phase1-complete`) |

국면 1의 완료판정(시나리오 15종 + config-only + 클린 2회)은 **그 기준으로는 참이고 뒤집지 않는다.** 다만 그 판정은 "시나리오가 통과하는가"를 셌고 "명세가 요구한 것을 코드가 지키는가"를 세지 않았다. 그래서 아래를 함께 선언한다.

**국면 1 = 완료(mock 위 메커니즘 검증) + 잔여 58건 이월(측정 완료·목록 첨부).**

## 2. 명세 — 무엇이 확정되는가

정제본 10종(347KB). 개정 대장이 모든 변경을 근거와 함께 보유한다.

| 태그 | 누적 | 뜻 |
|---|---|---|
| **[복원]** | **195** | 원천에 있었는데 놓쳤던 것 — 원천과의 거리가 **줄어든 변경** |
| **[개정]** | **0** | 새 판정으로 바뀐 것 — 아직 없다 |
| **[정정]** | 5 | 정제가 만든 오류의 수정 |

**[개정]이 0이라는 것이 이 국면의 성질을 말한다** — 정제본은 지금까지 원천에서 멀어진 적이 없고, 전부 원천 쪽으로 되돌아간 변경이다. 첫 [개정]은 2A에서 실 연결 판정이 나올 때 생긴다.

### 항구 장치 — 이번에 세운 것

누수가 발생한 지점 셋에 각각 방어를 걸었다.

| 세는 지점 | 실측된 사고 | 장치 |
|---|---|---|
| 문서 → 문서 전환 | 배경 구명세 → 챕터군 승계 누락으로 `core/llm.py`·`embeddings.py`·`viz.py`가 정본에서 사라졌고, 그 상태로 완료판정을 통과했다 | **정본 전환 시 승계 대조표 의무**(README 개정 규칙) |
| 명세 → 코드 | 완료판정이 시나리오만 세고 능력을 재지 않았다 | 완료판정 범위 진술(§7.6) + **§7.6-B 실 연결 규격** + 이번 정합 감사를 상설화 |
| 코드 → 보고 | "훅 5곳"이 전부 주석이었고 자동 점검이 문자열을 세어 있는 것처럼 보고했다 | **국면마다 독립 실행 감사 1회**(클론 후 실제 실행) |

여기에 **회귀 스위트**(`회귀스위트/`)를 더했다 — 조항 기준선 1,699건 · 판정 재현 시험지 78문항 · 문면 기계 점검 8규칙. **개정은 이 셋을 통과해야 확정된다.** 시험지는 고정한다(매번 새 질문을 만들면 매번 다른 것을 놓친다).

## 3. 코드 — 무엇이 이월되는가

정제본에 복원된 140건을 레포 실물과 대조했다. **evidence(파일:줄) 없는 판정은 무효**로 처리했고, 주석·docstring·호출부 0인 함수는 구현으로 세지 않았다.

| 판정 | 건수 | 뜻 |
|---|---|---|
| 코드가지킴 | **69** (49%) | 배경 구명세가 레포에 있었으므로 코드는 지키고 있었다 — **명세만 늦게 따라잡은 것** |
| **코드가어김** | **58** (41%) | **2A 작업 목록** |
| 코드대상아님 | 13 (9%) | 문서 서술 규범 |

**갭 58건의 규모**: 설계 3 · 모듈 22 · 함수1개 30 · 1줄 3. **등급**: 높음 26 · 보통 29 · 낮음 3.

절반이 이미 지켜지고 있었다는 것이 중요하다 — `core/llm.py`처럼 아예 없는 것과, 명세가 뒤늦게 문면화한 것을 갈라냈다. 상세는 `안건/2A_작업목록.md`.

## 5. 국면 경계 — 무엇이 어디로 가는가

로드맵 번호는 바꾸지 않는다(정제본 0 §0.5가 정본이고 국면 3이 이미 있다). 국면 2를 하위 분할한다.

| | **2A — 실 연결(국면 1 잔여 소진 포함)** | **2B — 사내 이식** |
|---|---|---|
| 전제 | 없음 — 즉시 착수 | 2A 완료 + 사내 승인·게이트웨이 실물 |
| 내용 | 갭 58건 · 실 연결 · 시각화 · 관측 · mock 격리 · 실 연결 회귀 재수립 | 실 골격 · 실물 문서 파일럿 · 골든셋 · 명세 공백 56건 판정 |
| 성격 | **정제본만 주고 만드는 첫 실증** — 구현자가 막히는 지점이 곧 명세의 공백이다 | 관문 4단계(G1 무해 반입 → G2 골격 → G3 단일 문서 → G4 소규모 운영) |
| 검증 | 실 연결 회귀(계약 준수·불변식 위반 0·큐 착지 정합) | 계기판 첫 측정 |

**2A는 땜빵이 아니다 — 정제본의 실증 시험대다.** 정제본은 지금까지 읽기로만 검증됐고, "이것만 읽고 다시 만들 수 있는가"라는 목적 시험은 아직 한 번도 치르지 않았다. 2A 요청문에 **"명세에 없으면 추측으로 메우지 말고 멈추고 신고하라"**를 못박아, 검출을 사람의 직관이 아니라 구현 과정 자체에 심는다.

## 정직한 기록

이 국면에서 **네 번의 감사가 각각 앞선 감사가 못 본 것을 찾았다.** P6 검증 4종이 30건, 기저 승계 감사가 144건, 잔여 원천 대조가 25건, 문면 기계 점검이 2건. 마지막 것 중 하나는 문서 1 말미에 원천 카드의 운영 문단이 통째로 남아 있던 것으로, 앞선 세 감사를 전부 통과한 잔재였다 — 8규칙 정규식이 첫 실행에서 잡았다.

여기서 읽을 것은 두 가지다. **하나** — 검증 방법이 다르면 잡는 것이 다르다. 하나로는 안 된다. **둘** — 다음 감사도 무언가를 찾을 것이다. 그것은 실패가 아니라 이 규모 작업의 정상 상태이고, **중요한 것은 나올 때 출처를 특정할 수 있느냐**다. 원천 동결·개정 대장·회귀 스위트가 그 능력이다.

국면 1을 닫는 것은 "더 나올 것이 없다"는 선언이 아니라, **"여기까지가 확정이고, 알려진 미결은 전부 목록에 있다"**는 선언이다.

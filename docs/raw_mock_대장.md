### 2.3 TOC01 / TOC02.xlsx — 목차형 3단 계층

계층은 셀 들여쓰기(indent) 속성으로 표현한다 [D-19]. **레벨1 = 0(굵게) · 레벨2 = 1(굵게) · 레벨3 = 2 · 본문 = 3 · 이상치 = 5.**

TOC01(31행)은 레벨1이 3회 반복(`1.` `2.` `3.`)되어 관찰 확장 규칙(M5)의 재료가 강화되었고, 3단 계층·이미지 2건·**들여쓰기 이상치 1건**(A12만 5, 형제 줄은 3)을 담는다. 이상치는 등록 시 "판정 불가" 질문을, 운영 인입 시 평면 폴백 + `hierarchy_unresolved`를 유도한다.

TOC02(25행)는 **구조가 다른 정상 대조군**이다 — 레벨3이 없고(2단까지), 이상치가 없고, 행 수가 다르다. 그리고 결정적으로 **같은 번호 위치의 의미가 다르다**: TOC01의 2장은 품질 이슈명이고 TOC02의 2장은 설비명이다. 이 차이가 `section`의 role 미결을 드러냈다(`실행검증_1차` §4.3 → D-31).

### 2.4~2.7 변형본 3종과 PPT

`CP02_drift`는 cp 양식과 **1개 열만 다르다**(`관리항목` → `관리 항목명`). 데이터 16행은 정상이므로 extract가 실행되지 않았음을 확인할 수 있다. `CP03_bad`는 13행 중 **1행이 열 개수 부족**으로 설비·관리항목이 결측된다 → 문서 통째 미인입 + `parse_failure`. 나머지 12행이 정상이라 "위반 1건이면 통째"라는 문서 단위 실패 계약(C14)이 실증된다. `CP04_unlabeled`는 헤더가 cp와 완전 일치(지문 스캔이 후보를 제안할 수 있어야 하므로)하고 시트명·제목에 doc_type 힌트를 남기지 않으며, **복수값 셀 2건**을 담아 10행 → 12 record가 된다. `PPT_basic`은 9슬라이드로 슬라이드당 평균 78자를 담아 추출 재료로 충분하다.

### 2.8 IPQC01 / IPQC02.xlsx — 신규 정형 doc_type 등록

**지위가 1·2와 다르다.** CP·PFMEA는 *이미 등록된* doc_type의 운영 인입 재료이고, IPQC는 **등록 절차(구축 모드)를 처음부터 거치는** 정형 문서다. 여기서만 role 배정표의 6지선다가 실제로 돌아간다.

16열 = 유효 11 + meta 후보 3 + UNMAPPABLE 후보 2.

| 열 | 지위 |
|---|---|
| 대공정 · 공정명 | anchor(구조 필드 — `process_coord` 블록) |
| 공정No | meta(구조 필드) — 사내 번호는 조회 키가 아님 |
| 극성 · 적용모델 | **role 배정 대상 아님** — `electrode_type`·`context` 구조 필드 |
| 검사설비 · 검사항목 | entity(Unit · Property) — 기존 노드와 매칭 다수 |
| 규격 · 판정기준 | attribute (contextual 포함) |
| **측정방법** | **판정 불가 유도(정형판)** — 계측기 기종명과 행위 서술이 혼재 [D-23] |
| 부적합 조치 | content — 짧은 정형 문구, content/attribute 경계의 시험 |
| 검사자 · 검사일시 · 성적서번호 | **meta** |
| **최근 불량 이력** | **UNMAPPABLE** — 미래 층 소관·시점 종속 → L4 신호 |
| **관련 표준문서** | **UNMAPPABLE** — 다른 문서 참조 → L3 `reference` role 신호 |

표본 2부의 변형 관찰 포인트 셋: **① 대공정 채움 전략** — 01은 세로 병합(A4:A35), 02는 행별 반복. 어댑터가 두 방식을 다 다뤄야 함을 2부만 드러낸다. **② 최근 불량 이력** — 01은 부분 채움, 02는 전량 공란. 열의 성격을 1부만으로는 판단하기 어렵다는 것을 보인다. **③ 비연속 재등장** — 01은 같은 공정 블록이 날짜를 달리해 뒤쪽에 다시 나온다(재검사 회차).

확대로 새로 확보한 재료: **맥락형(M2) 3건**(같은 검사항목이 모델별로 규격이 갈림 — 주액량 2.4/2.5g, 실링 온도 180/182℃) · 골격 7개 전량 소진 · 복수값 1건.

## §3 역산 정합 — 정의와 계약 [D-18, 확대판에서 정밀화]

**계약**: `CP01.xlsx`·`PFMEA01.xlsx`를 정상 어댑터로 파싱한 records의 **앞 N건(prefix)**이 `mock/parsed/*.json`의 records와 일치한다. **N = CP01 12 · PFMEA01 13** (2026-08-07 정정 — 구 CP01 N=10 → 11 →12 (C12, D-55)).

- 확대분은 그 **뒤에 붙으며**, 기존 노드·판정에 영향을 주지 않는 신규 항목으로만 구성한다.
- 비교 제외: `parsed_at`·`source_path`·`parser_version`·`adapter_version` 등 실행 시점 값과 `process_no`.
- 이 어서션이 없으면 두 트랙은 영원히 만나지 않는다. parsed JSON은 사람이 손으로 쓴 것이고, 파서가 그것을 만들어낼 수 있는지는 **검증된 적이 없었다.**
- **IPQC·TOC·CP04는 이 계약의 대상이 아니다** — 대응하는 parsed JSON이 없는 자유 창작이며, 그 자유도가 복수값·잉여 열 같은 재료를 실을 수 있게 한다.

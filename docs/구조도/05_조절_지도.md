# 05 · 조절 지도 — 흐름 위에서, 어느 단계의 어떤 판단을 어느 자산이 만드나

> ← `04_질의` · 참조 `09_부품_해설`
> **독자**: 운영자. LLM의 판단이 아쉬울 때 "흐름의 어디서 잘못됐고, 그 자리를 만드는 자산이 무엇인지"를 찾는 지도다. **B48(⑦ 지시문)·B49(unmappable)·B50(AUTO_FIX·문답)·B55(문답 누적·지시 템플릿)·B58(재등록·관문 범위) 배지를 더했다.**
> **손잡이는 `00_칸_대장.md`의 칸 ID로 부른다**(B63) — 그림의 P/Q/R은 그리기용 노드 이름일 뿐이고 라벨 머리의 숫자가 칸이다.
> **재고 목록은 `06_손잡이_대장.md`** — 여기는 증상에서 자리를 찾는 지도이고, 손잡이 전체(config 키·상수·설정 포함)는 06이 한 장으로 갖는다.
> **여기 없는 것**: 계기판·골든셋은 *판단을 만드는 자산*이 아니라 *측정 장치*라 이 지도의 대상이 아니다 — 04 「확인 루틴」과 가이드 §5.4를 본다.
> **읽는 법**: ⚙배지가 **사람이 조절하는 자산**이다. 배지가 꽂힌 단계의 판단만 그 자산이 바꾼다 — 다른 단계는 안 변한다.

## 등록 흐름 (doc_type 1회) — 판단이 제일 많은 곳

```mermaid
flowchart TD
  A["sample document"] --> B["🤖 interview (--interview)<br/>column understanding"]
  B --> C["🤖 generate<br/>adapter + schema (unmappable included)"]
  C --> D["⚙ machine gate — harness ×4<br/>auto-fix ×1 or ask"]
  D -- "fail text carries fix" --> C
  D -- "fail text does not" --> B2["🤖 interview on failure<br/>👤 answers"] --> C
  D -- "pass" --> E["👤 review — content<br/>role table · excluded list · split"]
  E -- "--instruct" --> C
  E --> F["confirm --by"]

  P1["⚙ 1.3 · prompts/1.3_interview.md<br/>question rules · one-line persona"]:::knob -.-> B
  P1 -.-> B2
  P2["⚙ layers/{layer}/config.json<br/>categories · definitions<br/>★ what is a process / unit / property ★"]:::knob -.-> B
  P2 -.-> C
  P3["⚙ 1.4 · prompts/1.4_generate.md<br/>role rules · unmappable · output spec<br/><b>{{재생성_지시}} slot (B55) · boundary 3+3 (B58)</b>"]:::knob -.-> C
  P4["⚙ 1.1 · --hint / interview answers<br/>this doc_type's own knowledge"]:::knob -.-> C
  P5["⚙ 1.5 · cli/register.py AUTO_FIX<br/>which failures auto-fix (8) — rest ask"]:::knob -.-> D
  P6["⚙ kit/run_adapter.py<br/>what the gate checks<br/><b>= pipeline.parse full range (B58 ②)</b>"]:::knob -.-> D
  classDef knob fill:#fff3cd,stroke:#b8860b
```

**★ 「뭐가 공정 정보인지 모른다」는 config 정의문 자리다.** 정의문이 판정 프롬프트로 조립되어 문답·생성·**추출** 셋에 들어간다 — 정의문이 교과서 문장이면 판정도 교과서 수준이다. `층정의_프롬프트.md`로 사내 LLM에서 초안을 뜬다.

**뺀 열이 또 뜬다** → 템플릿(1.4)이 아니라 **스키마 `unmappable`**이 비어 있는 것이다(구판 등록분). `generate --resume`으로 스키마만 다시 뽑으면 `excluded`/`undecided`가 갈린다.

## 등록 단계 LLM 호출 셋 — 무엇을 보내고, 판단은 어디 사나 (B62 ② 이후)

등록에서 LLM을 부르는 자리는 셋(칸 1.3 · 1.4)이고, 셋 다 `review/<doc_type>/input_package.json`을 읽는다. **판단의 정본은 `input_package.json`**(`decisions[]`), **대화의 이력은 `interview_log.json`**(라운드 전문) — 둘은 묶음 `at`으로 짝을 맞춘다. `state.json`은 실행 장부(어댑터 경로·revision·지시 이력·마지막 관문 출력)이지 판단이 아니다.

| Call | Cell | System prompt | User message | Full rounds sent? |
|---|---|---|---|---|
| 초안·재생성 (`draft`) | 1.4 | 생성 템플릿 — `[확정 사항]`만 렌더(B60 ②) | `input_package.json` 원문 — 이제 decisions만 담는다 | No (B62 ②: 라운드 30개 더해도 36,418B 그대로) |
| 문답 라운드 | 1.3 | `prompts/1.3_interview.md` + role·층 어휘 발췌 | `{입력_패키지, 지난_문답: 현재 묶음의 라운드(로그)}` | 현재 묶음만 · 이전 표본 전문은 안 보낸다(판단은 decisions로) |
| 문답 확정 요약 | 1.3 | `prompts/1.3_interview.md` | `{입력_패키지, 문답_전문: history}` | Yes — 요약이 목적이라 이 호출만 |

- 조립된 지시문 실물: `ONTO_DUMP_PROMPT=1`이면 `review/<doc_type>/prompt_rendered.md`. 프롬프트가 무엇을 받는지는 코드가 아니라 **이 파일을 열어** 본다. `_sent_size`가 호출마다 전송량을 찍는다.
- 템플릿은 `prompts/1.4_generate.md` 하나(B63 ① — 옛 판은 `git show 9f58ec9:kit/…`).

## 원칙 셋

1. **지식은 페르소나 문장이 아니라 검증 가능한 데이터로** — 정의문·골격·사전·문답 네 그릇.
2. **문답에서 한 답 중 반복될 유형은 정의문으로 승격하라** — 다음 등록부터는 안 묻는다.
3. **어댑터·스키마는 손으로 고치지 않는다** — 재생성으로 고친다. 재생성분도 기계 관문을 지난다([정정] 40). **두 경로가 다르다**: 확정 전 세션 안에서는 `review --instruct`, **이미 확정된 doc_type은 `generate --revise`**(B58 ① — `revision`이 오르고 승인 이력이 누적된다).

# 11 벡터 — 질의 벡터의 재료 · 저장 · 색인 · 흐름 (인계 진입점 · B161)

> 손으로 쓴다(생성물이 아니다 — 번호 10은 생성물 `10_코드_지도.md`). 규칙의 정본은 명세다 — 문서 7 §7.8(저장 · 만드는 법) · §7.2 ·
> 문서 5 §5.4(임베딩 2종). 이 장과 갈리면 명세가 이긴다. 무엇을 치나는 가이드(`docs/가이드/2B_작업가이드.md` 명령 사전 · 증상표).

## 1. 원칙

- **벡터는 찾기 색인이고 진실은 별칭 사전이다** — 벡터는 후보를 낼 뿐이고 판단은 LLM(선별) · 사람이 한다.
- **파생물이다** — `work/vectors/vectors.sqlite`(④작업) 한 파일 · 지워도 다시 만든다 · 진실 단 `data/`에 쓰지 않는다. 기본
  `init --fresh`(재구축의 바닥)는 남기고(보존 일곱) 클린 `init --fresh --all`은 지운다.
- **질의는 읽기 전용이다** — 그래프 · 큐 · 대장 · `data/` 쓰기 0(벡터 저장만 쓴다).

## 2. 두 갈래 — 판정 좁히기와 질의 벡터

둘 다 같은 임베딩 함수(`core/llm/embeddings.embed`)를 쓰지만 쓰는 자리 · 글 · 저장이 다르다. 명세의 이름 그대로 「판정용 임베딩」과
「질의 벡터」다(문서 5 §5.4 · 문서 7 §7.2).

| | A 판정 좁히기(판정용 임베딩) | B 질의 벡터 |
|---|---|---|
| 자리 | 인입의 판정 — 관문 뒤 후보가 `CANDIDATE_TOP_N`(12)를 넘을 때만 상위만 판정 LLM에 | 질의 · 뷰어 · `run.py vectors` |
| 코드 | `core/matcher.py`(`_narrow` · 글 `cand_text`) | `core/query/hybrid.py`(재료 · 색인 맞추기 · 검색) · `core/query/vectors.py`(저장) |
| 글 | 후보 `이름 \| 별칭: a, b` ↔ 표기(정의문 0) | 노드 · 청크 재료(아래 3) ↔ 질문 문장 |
| 저장 | 0(프로세스 메모리) | `work/vectors/vectors.sqlite` |
| 설정 | `CANDIDATE_NARROW`(`auto` · `embed` · `overlap` — 임베딩이 없으면 글자 2-gram 겹침) | `EMBED_BACKEND` · `EMBED_MODEL` |
| 인계 | 밖 | **대상** |

## 3. 재료 — 무엇을 어떤 글로 (B153 · 시스템 소유)

| 종류 | 글(재료 함수) | 예시 |
|---|---|---|
| 노드 | `맨 이름 \| 카테고리 \| 별칭: … \| 위치: 위 > … > 주인` — 정의문 0 · 관계 이름 0 · 경로는 위치에 한 번(`hybrid.node_texts`) | `노칭 정밀도 \| Property \| … \| 위치: 노칭 > 노칭 프레스` |
| 표 청크 | `[열 머리 글 · 주인 · 좌표] 원문` — 행 위치 0(`hybrid._chunk_text`) | `[대응계획 · 노칭 정밀도 · 노칭] 공정 정지 후 금형 점검` |
| 산문 청크 | `[경로 · 좌표 · 다루는 것] 원문`(PPT는 다루는 것이 머리 끝) | `[<시트> › <제목> · <공정>] 원문` |
| 질문 | 질문 문장 그대로 — 저장 0 · 해시 0 · 질의마다 임베딩(`vectors.question`) | `노칭 금형 교체 주기는?` |

- **입력 한도** — `embeddings.limit()`: 로컬 모델은 그 모델의 최대 토큰 · 게이트웨이 · mock은 손잡이 `embed_max_chars`(글자). 넘으면
  앞(머리)을 지키고 꼬리를 자른다(`embeddings.fit`) — 저장의 글은 **자른 뒤의 글**이다.
- **재료는 시스템(사용자)이 소유한다** — 규칙을 바꾸는 회차는 `hybrid.MATERIAL_VER`(지금 `m-1`)를 올린다. 올리면 지문이 같아도 색인을
  다시 쓴다(글이 같으면 만든 벡터 0).

## 4. 저장 구조 — 한 파일 표 셋

```
v     (backend, ver, kind, v)                                   보관함 — 글 해시 → 벡터(float32)
idx   (backend, kind, id, ver, layer, doc_id, text, len, cut)   색인 — 누가 어느 글 · 벡터를 쓰나
meta  (backend, kind, src_fp, mat_ver, lim, at)                 색인이 무엇으로 만들어졌나(종류마다 한 줄)
```

| 칸 | 뜻 |
|---|---|
| `backend` | 판 — 임베딩 갈래 · 모델(`embeddings.backend_id` — 예 `local:<모델>` · mock은 `mock-sha256-64`). 판이 다르면 다른 공간(섞이지 않는다 · 돌아온 판은 제 벡터를 다시 쓴다) |
| `ver` | 글 해시 — 자른 뒤 글의 sha256 앞 16(`vectors._ver`) · `v`의 열쇠 |
| `kind` | `nodes` · `chunks` |
| `id` · `layer` · `doc_id` | 노드 id(층) · 청크 id(문서) — 해당 없으면 빈칸 |
| `text` · `len` · `cut` | 임베딩한 글(자른 뒤) · 한도 단위로 잰 **원래** 길이 · 잘랐나(0/1) |
| `src_fp` | 넘겨받은 내용의 지문 — 노드: 층 이름 순 `[층, GraphStore.content_fp()]` 목록 · 청크: 청크 저장의 내용(`store.content_fp`). **파일이 아니라 메모리의 내용**이다(호출부가 메모리에서 바꾼 그래프를 넘기는 길이 있다 · 별칭 하나만 바뀌어도 다르다) · 직렬화는 저장과 같은 함수(그래프는 `core/graph.py` 안에서만) |
| `mat_ver` · `lim` | 재료 판(`MATERIAL_VER`) · 입력 한도(수 · 단위) |

- **노드 → 벡터를 찾는 길**: `idx`(판 · `nodes` · 노드 id) → `ver` → `v`(판 · `ver`) — 같은 글 노드 둘은 `idx` 둘 · `v` 하나.
- **쓰기 규율** — `v`와 같다: sqlite 잠금 · 묶음마다 커밋 · 프로세스 사이 동시 쓰기 안전 · 끊겨도 깨짐 0. 색인을 다시 쓸 때는 그 종류의
  `idx` 행을 그 판에서 **한 트랜잭션으로 통째로 갈고 `meta`를 마지막에** 쓴다 — `meta`가 있으면 그 `idx`는 완전하다(반쯤 쓰인 색인을
  읽는 자리가 없다).
- **동시 실행** — 읽는 자리(링킹 후보 · 문서 검색 · `show near` · `show dist embed`)는 기대한 지문을 넘겨 `meta` 확인과 읽기를 한 읽기
  트랜잭션에서 한다: 맞춘 뒤 읽기 전에 다른 자리가 다른 입력으로 색인을 갈아 끼웠으면 그 호출은 색인을 쓰지 않고 제 입력의 글로 찾는다
  (남의 판을 읽지 않는다). 색인을 갈아 끼우는 쪽은 프로세스 사이 공유 잠금(`work/vectors/gc.lock`) · `--gc`는 배타 잠금이라, 새 벡터가
  색인에 오르기 전(참조가 아직 없을 때)에 다른 프로세스의 `--gc`가 지우지 못한다.
- **참조 없는 벡터** — `idx`의 어느 행도 가리키지 않는 `v` 행(옛 글의 벡터). `run.py vectors` 끝 줄이 세기만 하고, 지우는 길은
  `run.py vectors --gc` 하나다(종류 둘의 색인을 맞춘 뒤 그 판만 · 다른 판의 행은 그대로). 인입 · 질의 · 뷰어 · 재구축은 지우지 않는다
  (판이 돌아오면 다시 쓰는 성질을 지킨다).
- **옛 저장** — `idx` · `meta`가 없는 저장(B161 전)은 처음 쓰는 길이 표를 세우고 색인을 채운다(`v`는 그대로 다시 쓴다 — 만든 벡터 0) ·
  옛 `nodes.json` · `chunks.json`은 처음 열 때 옮겨 담는다(B136).

## 5. 해시의 역할

- 해시는 **글에서** 나온다(임베딩에서 나오지 않는다) — 같은 글이면 같은 해시 · 한 글자만 달라도 전혀 다른 값이다. 그래서 해시는 가까움을
  재지 못한다 — 가까움은 벡터의 코사인이다.
- 해시는 **저장 단계의 열쇠**다 — 글이 바뀌면 새 열쇠라 무효화가 저절로 되고 · 재구축으로 노드 id가 바뀌어도 글이 같으면 다시 쓰고 ·
  같은 글은 벡터 하나다. 검색에는 쓰지 않는다.
- 정상 운영(벡터를 미리 만든 상태 · 그래프 그대로)에서 질의는 글마다 해시를 계산하지 않는다 — 지문이 같으면 색인에서 읽는다.

## 6. 질의 흐름 — 벡터로 진입점 · 그래프로 넓힌다

1. **벡터 준비**(`hybrid.warm` — 질의의 첫 단계 · 뷰어를 띄우면 배경으로 · `run.py vectors`가 같은 함수): 종류마다 지문 · 재료 판 · 한도를
   `meta`와 견준다 — 같으면 색인 그대로(글 조립 0 · 해시 0 · 빠진 벡터가 있으면 `idx.text`만 임베딩) · 다르면 재료 함수로 글을 조립해
   색인을 갈아 끼운다(`v`에 없는 글만 임베딩). 끝 줄 · 질의의 벡터 줄에 「색인 — 그대로 / 다시 씀」.
2. **질문 임베딩**(저장 0).
3. **질문 벡터 ↔ 전 노드 · 전 청크 코사인**(`idx JOIN v` · 파이썬 전수) — 노드 상위 `query_link_top_k` · 청크 상위 `query_doc_top_k`(문턱
   `query_doc_min_sim` 이상). 링킹 후보의 화면 정보(canonical · 카테고리 · 층 · 위치)는 그래프에서 상위 k만 낸다.
4. **LLM 선별**(지점 ⑥ — 후보 밖 id는 버린다) · 사전 히트와 함께(`query_link_mode` 보충 · 폴백).
5. **그래프 확장**(`query_traverse` — 코드 · LLM은 그래프를 직접 읽지 않는다) → 6. **답**.

- **문서 검색 채널**은 그래프를 거치지 않는다 — 청크 벡터 상위 k + BM25 상위 k(재료는 색인의 글 — 벡터와 같은 재료)를 합친다 · 링킹이
  빗나가도 돌고 · 두 채널이 다 비면 「근거 없음」이다.
- 벡터는 진입점을 찾고 그래프가 넓힌다 — 그래프에서 벡터로 가지 않는다.

## 7. 명령 · 손잡이 · 설정

| 이름 | 무엇 |
|---|---|
| `run.py vectors [--only nodes\|chunks]` | 색인을 맞추고 없는 벡터만 만든다(LLM 0) · 끝 줄에 만든 수 · 다시 쓴 수 · 판 · 색인 · 참조 없는 벡터 · 입력 한도 |
| `run.py vectors --gc` | 색인을 맞춘 뒤 참조 없는 벡터(이 판)를 지운다 — 지우는 유일한 길 |
| `show near [<층>] [--top N]` | 중복 후보 보고(읽기 전용) — 색인이 맞으면 색인에서 · 아니면 글을 조립해 글 해시로 찾는다 |
| `show dist embed` | 입력 길이 분포(읽기 전용) — 색인이 맞으면 `idx.len` · `cut`(다시 재지 않는다) · 아니면 다시 재고 머리 줄에 그 사실 |
| 손잡이(`knobs.json`) | `query_link_top_k`(20) · `query_link_mode`(보충) · `query_doc_top_k`(8) · `query_doc_min_sim`(50%) · `near_min_sim`(90%) · `near_top`(20) · `embed_max_chars`(4000자) |
| 설정 | `EMBED_BACKEND`(`gateway` · `local`) · `EMBED_MODEL` · `CANDIDATE_NARROW`(A 갈래) |
| 상수 | `hybrid.MATERIAL_VER`(재료 판) · `vectors.BATCH` · `SAVE_EVERY` |

## 8. 인계 경계와 미결

- **경계** — 시스템(사용자)이 재료를 정해 `idx.text`에 쓰고, 벡터 쪽은 그 글을 받아 임베딩 · 저장 · 검색 · 평가한다.
- **미결** — 골든셋 0(질의 벡터의 품질 측정이 없다) · 문턱 · 상위 수 손잡이 넷(`query_link_top_k` · `query_doc_top_k` · `query_doc_min_sim` ·
  `near_min_sim`)은 창작 기본값(사내 실측으로 정한다) · dense만(sparse · ColBERT 미사용 — 키워드는 BM25) · 검색은 파이썬 전수 코사인 ·
  전용 벡터 DB는 정본 DB 결정과 묶는다.
- **이연(B161이 하지 않은 것 — 이연대장)** — 검색 계산 바꾸기(numpy 행렬곱 · ANN) · 질의 단계별 시간 · 질의 중 중복 로드 · BM25 색인 매
  질의 재생성 · 긴 청크 여러 벡터(이연대장 cq) · 판정 좁히기(A) 변경 · 재료 규칙 변경 · 전용 벡터 DB.

# 00 · 칸 대장 — 시스템의 모든 자리를 번호 하나로 부른다

> **왜 이 파일이 있나.** 파트·칸 번호가 없어서 같은 자리를 문서마다 다른 이름으로 불렀다(파서 ①~⑨ · 성능모듈 01~11 · 05 지도 P/Q/R). 회차 요청문·이연대장·명세 개정이 **전부 이 번호를 단다.** **B78부터 파트가 곧 코드 폴더다**(`core/build/`=파트 3 · `core/llm/`=0.4 · `core/query/`=파트 4 · `core/state/`=0.1·0.3·1.7·3.7 · `cli/register/`=파트 1 · 접근 경계 3+`paths`는 `core/` 최상위) — 파일마다 첫 줄 머리말이 칸 번호를 말하고, 기계가 뽑은 파일 전수 지도는 `10_코드_지도.md`(생성물). 이 표는 「칸의 뜻·종류·지시문·손잡이」를 답하고, 「어느 파일이 어디 있나」는 10이 답한다.
> **구조는 사용자 발표 자료(2026-09 「문서가 지식이 되는 과정」)의 칸을 그대로 옮긴 것이다** — 등록 · 파싱 · 구축 · 질의 네 파트, 칸마다 종류 하나.
> **종류**: **H** 사람이 넣거나 본다 · **C** 결정적 코드 · **L** LLM이 판단한다 · **G** 검사 관문(막으면 다음으로 안 간다).
> **잠금**: 코드의 LLM 호출 지점(`point=`) 집합 == 이 표의 L칸 point 열 · `prompts/` 파일 집합 == 이 표의 지시문 열 (B63 어서션). 표에 없는 호출·파일이 생기면 회귀가 빨간불이다.
> **손잡이 전체 목록**은 `06_손잡이_대장.md` — 이 표의 「Prompt / knob」 열은 요약이고, 무엇을 어디서 바꾸나는 06이 답한다.
> **Role 열**: 처음 보는 사람을 위한 **쉬운 이름 + 역할 한 줄**이다 — Cell 열은 운영자·회차용 문면(함수·옵션 이름)이라 「무엇을 하는 자리인가」를 답하지 못한다(옛 `07_칸_해설`을 흡수 · 2026-09-28). 명세를 다시 쓰지 않는다 — 자세한 것은 Cell·Code·06이 답한다.
> **최종 갱신**: 2026-09-28 (hub_54 — Role 열 · Card 열 폐기(성능모듈 카드는 한 장에서 멈춰 지운다 — B88 ④)) · Code 열은 회차마다 구현 세션이 고친다

# B71 구현 요청문 — 추출 힌트도 mock 자산이다 · 사내 조건 스위트(`USE_MOCK=0`) · 칸 3.3 · 0.3

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-15) · **B70 마감·보고 뒤 착수** · **출처**: B70 발주 뒤 허브가 같은 병(mock 자산이 운영 경로에 가드 없이 섞임 · 없는 파일을 조용히 넘김)을 `cli/ core/ parser/ kit/ run.py` 전수로 훑었다. 남은 것이 하나 더 있고, 근본 원인이 하나 있다.
> **남은 하나**: `core/extract.py::extract()`가 **추출 힌트**(`tests/fixtures/extract_hints/<doc_id>.json` — mock 자산, 문서 7 §7.5 대체 표의 「추출」 행)를 `use_mock()`과 무관하게 먼저 본다(279~288행). 힌트 파일이 있으면 그 청크는 LLM을 부르지 않고 힌트를 쓴다. 사내 doc_id가 픽스처 이름(PPT02·QPPT01)과 겹치면 **실호출 결과가 조용히 mock 힌트로 바뀐다.** 지금은 안 겹치지만 B70과 같은 병이고, 같은 문장(문서 7 §7.5 「mock 자산은 운영 경로에 섞이지 않는다」)이 이미 답이다.
> **근본 원인**: 회귀 1196건이 전부 `USE_MOCK=1`로 돈다. 사내 조건(`USE_MOCK=0` · 픽스처 없음 · 등록 산출만 있는 폴더)을 실행으로 밟은 것은 사용자뿐이었다 — 그래서 잔재를 사용자가 찾는다. `test_2a_gateway`가 이미 `USE_MOCK=0`을 서브프로세스로 띄우는 틀을 갖고 있다(9지점 명시적 실패) — 그 틀 위에 **사내 조건 스위트**를 세운다.

## ① 추출 힌트는 `use_mock()`일 때만 (칸 3.3)

`_load_hints`를 `llm.use_mock()`이 참일 때만 부른다. `USE_MOCK=0`이면 힌트 파일이 있어도 읽지 않고 실호출 경로(`_candidates_for`)로 간다 — 설정이 없으면 `NotConfigured`로 **시끄럽게** 실패한다(지금 B70 ①과 같은 조건 하나).

**완료판정 ①**: 어서션(성질) — `USE_MOCK=0` + 힌트 파일이 있는 doc_id로 `extract()` → 힌트를 쓰지 않는다(실호출 경로에 도달해 `NotConfigured`가 난다 — 그것이 증거다) · `USE_MOCK=1`이면 지금과 같다.

## ② 사내 조건 스위트 — `USE_MOCK=0` · 픽스처 없음 · 등록 산출만 (칸 0.3)

서브프로세스 하나(`test_2a_gateway` 틀): 임시 폴더에 **등록 산출 넷만** 두고(`data/doc_types.json` 1건 · `adapters/<dt>.py` · `schemas/<dt>.json` · `review/<dt>/approval.json`) `USE_MOCK=0` · `ONTO_FIXTURES=<빈 폴더>`로 LLM을 부르지 않는 명령을 돈다:

| Command | Property |
|---|---|
| `platform doctypes` | 목록 == 등록부 1건 · 내장 이름(cp·pfmea·ipqc·ppt_*) 0 |
| `scan <표본>` | 대조 목록 == 등록부 어댑터 · 내장 0 |
| `ingest-file <표본> --dry-run` | 스캔으로 등록 dt 선택(`basis.by == "scan"`) |
| `register list` | 등록 1건 |
| 등록부 파일 하나를 지운 뒤 `scan` | 상태 거부 + 다음 줄(B70 ②) |
| `doctor.py` | 사내 전환 판정이 이 폴더에서 돈다(mock 자산 없이) |

- 판정은 **출력에 mock 자산 이름이 0**이라는 성질과 **등록부 집합 등식**이다 — 문면을 세지 않는다.
- 이 스위트는 이후 회차의 회귀에 상시 포함된다(`doctor.py` 회귀 목록). 「사내에서 처음 밟는다」를 없애는 장치다.

**완료판정 ②**: 스위트 초록 · 일부러 `ADAPTER_DIRS`의 가드를 빼면 붉어진다(보고에 붙이고 되돌린다) · 회귀 총수 증감.

## ① 층 공통 config — 카테고리 카탈로그 (칸 0.1) — **먼저**

- **자리**: `$ONTO_HOME/layers/common.json`(②등록 단 · 층 목록에 안 잡힌다 — 전제 2). 경로는 `core/paths.py`가 이름으로 준다. 레포 `layers/common.json`은 mock seed(자산 해시 대상).
- **모양**:
  ```json
  {"common_version": 1,
   "categories": {
     "Process":  {"home": "process"},
     "Unit":     {"home": "process"},
     "Property": {"home": "process"},
     "Failure":  {"home": "quality"},
     "FailureEffect": {"home": "quality"}},
   "canonical_scope": { …layers/process/config.json에서 옮긴 그대로… }}
  ```
  카테고리마다 `home`(집 — 노드가 사는 그래프) · 선택 `also`(겸 — ③) · 이름 규칙 `canonical_scope`는 **여기 한 곳**. 정의문은 여기 두지 않는다 — 정의문은 층의 렌즈다(층 config `categories`의 값 그대로).
- **읽는 자리**: `layer_of_category(cat)` = 카탈로그의 `home` · `coord_layer()` = `Process`의 집(추측·이름순 0). `entity_key`의 이름 규칙은 카탈로그의 `canonical_scope`.
- **`bootstrap` 거부(문면 + 다음 줄)**: ⓐ 공통 파일 없음(`USE_MOCK=0`) — **초안을 만들어 보이고 멈춘다**: 층 config들에서 카테고리 → 선언 층을 모아, 한 층만 선언한 것은 그 층을 `home`으로, 여러 층이 선언한 것은 `home` 빈칸으로, `canonical_scope`는 층 config에서 옮겨 `layers/common.draft.json`에 쓴다(자동 채택 0 — 사람이 빈칸을 채워 `common.json`으로 저장) ⓑ 층 config의 카테고리가 카탈로그에 없다 ⓒ `home`이 그 카테고리를 선언하지 않은 층이다 ⓓ 층 config에 `canonical_scope`가 남아 있다(「공통으로 옮겼다」 — 두 곳 0) ⓔ `also`가 카탈로그에 없는 카테고리나 없는 단(`main`·`sub`·`detail` 밖)을 가리킨다.
- **`doctor` 첫 줄**: `좌표 층 <Process의 집> · 공통 config v<n>`(없으면 「없다 — bootstrap이 초안을 만든다」).
- **이관**: 사내 루트는 ⓐ의 초안 흐름으로 옮긴다 — 코드가 사내 config를 고치지 않는다.

**완료판정 ①**: mock에서 네 벌 diff 0(카탈로그는 기존 선언의 복사다) · 거부 다섯 갈래가 각각 문면대로(어서션) · 초안 흐름 — 겹친 카테고리가 있는 테스트 세트에서 초안의 `home`이 빈칸이고 저장 전 `bootstrap`이 멈춘다.

## ② 전역 해소 — table·prose 한 길 (칸 3.2 · 3.4 · 3.5)

- **라우팅 한 자리**: 개체의 카테고리 C → **C의 집 빌더**(`for_layer(home(C))`)에서 매칭하고, 없으면 **집 그래프에** 만든다. prose(`prose.py` 50~51 — 지금 문서 층 빌더)와 table(`loop.py` 311·333 — 지금 `target_layer` 또는 자기 층)이 **같은 함수**를 부른다.
- **table의 `target_layer`**: 있으면 집과 같아야 한다 — 다르면 등록 관문 G4C 상세로 FAIL(새 태그 0 — 「`target_layer`=X는 C의 집 Y와 다르다」). 없으면 집이다.
- **엣지는 뽑은 층에** 저장한다(지금처럼 — 끝점이 다른 그래프면 걸침 엣지 · `commit_edge`의 `src_graph`/`dst_graph`). 삼항 검사는 **뽑은 층의 relation_patterns**다(층별 관계 — 사용자 확정).
- **따라 바뀌는 기록**: 판정 대장의 `layer` · 큐 payload(`auto_node`·`uncertain_match`)의 `layer`는 **집**이다(종결 명령이 그 층을 가리켜야 한다).
- **테스트 전용 층 세트**(`tests/fixtures/` 아래 · 레포 `layers/`는 건드리지 않는다): process + quality에 **quality가 `Unit`도 자기 정의문으로 선언**(카탈로그 `Unit.home = process`).

**완료판정 ②**: 테스트 세트에서 ⓐ quality prose 문서가 **process에 이미 있는 Unit**을 말하면 그 노드에 매칭 — quality 그래프에 Unit 노드 0 ⓑ quality 문서가 **새 Unit**을 말하면 process 그래프에 생기고 큐 `layer=process` ⓒ 그 문서가 만든 엣지는 quality 그래프에 · 끝점은 process 노드 ⓓ 같은 것을 table 문서로도 — 결과가 같다(두 경로 한 길 — 어서션) · mock 네 벌 diff 0.

## ③ 주·겸 카테고리 · 자기 좌표 규칙 (칸 3.3 · 3.4 · 3.6)

- **선언**: 카탈로그 `"Process": {"home": …, "also": {"Unit": ["sub", "detail"]}}` = 「그 단의 Process는 Unit 겸」. **노드에 저장하지 않는다** — 노드의 주 카테고리 + `tier`와 카탈로그에서 **계산**한다(config를 바꾸면 바로 따라온다 · 파생은 저장하지 않는다). `show node`·내보내기에는 「겸 Unit」으로 보인다.
- **겸이 인정되는 자리**: ⓐ **매칭 후보** — C로 해소할 때 주 카테고리가 C인 노드 + **C를 겸하는 노드** ⓑ **삼항 검사**(커밋 게이트) — 끝점의 카테고리 집합 = 주 ∪ 겸, 어느 조합이든 패턴에 있으면 통과(예: `Component part_of Unit`이 스테이션 노드에 바로 붙는다) ⓒ 그 밖에 **카테고리로 거르는 자리**는 전수 조사한다(`grep -rn '\["category"\] ==\|get("category") ==' core cli`) — 자리마다 겸을 넣었는지 · 뺐는지와 그 이유를 보고에 표로.
- **자기 좌표 규칙**: 청크·행의 좌표가 X이고, 뽑힌 개체(카테고리 C)의 표기가 사전에서 **X 자신**으로 해소되며(별칭 포함), X가 C를 겸하면 → **X다**(자식 노드 0 · 판정 대장 `path=self_coord`). 이름 규칙(`X::…`)으로 키를 만들기 **전에** 본다.
- **추출 입력**: 추출 지시문에 주입하는 카테고리 어휘에 겸을 한 줄로 싣는다(예: 「Unit — (스테이션 단 Process도 Unit이다: 좌표 자신을 가리키는 설비 표기는 좌표다)」 — 문안은 카탈로그에서 렌더). 템플릿(`prompts/3.3_extract.md`)에는 층 어휘를 적지 않는다 — 겸 자리의 **일반 문장 한 줄**만.
- **mock 카탈로그에는 `also`를 두지 않는다**(네 벌 diff 0). 겸은 테스트 세트에서.

**완료판정 ③**: 테스트 세트(`also` 선언 · 골격 ALIASES에 「… unit」 표기)에서 ⓐ 좌표 「ultrasonic welding」 아래 「ultrasonic welding unit」(Unit) → 스테이션 노드 자신(새 Unit 0) ⓑ 「Component part_of Unit」이 스테이션 노드에 붙는다 ⓒ `also`를 지우면 ⓐ가 지금처럼 새 Unit이 된다(겸이 데이터라는 증명) ⓓ 카테고리 거름 자리 전수 표.

## ④ 걸침 엣지 문장화 (칸 4.3)

- 층 L에 저장된 걸침 엣지가 **L의 층 안 확장**으로 닿았는데 반대 끝점이 다른 그래프에 살면 — 지금은 `facts`가 건너뛴다(전제 10). **저장한 층의 템플릿으로 문장화한다**(`cross_facts`와 같은 규칙) · 다리로도 닿은 엣지는 **한 번만**(중복 0).
- 먼저 **실물로 재현**한다(②의 테스트 세트 — quality에 저장된 `Property … Unit` 걸침 엣지를 quality 쪽 질의로 부른다) — 고치기 전 빠지는 것을 보인 뒤 고친다.

**완료판정 ④**: 전후 `query --json`의 `facts` · 같은 엣지 두 번 0 · mock 질의 스모크 불변.

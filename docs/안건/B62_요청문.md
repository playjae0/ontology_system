# B62 구현 요청문 — 시스템이 아는 값은 LLM이 쓰지 않는다 (헤더 위치 · 라운드 분리 · 판 번호 · 재시도 문면)

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-14) · **출처**: 사내 실측 — CSV 표본으로 `generate`가 관문 G52 `adapter_mismatch`로 **무조건** 막혔다. 원인을 코드로 확인했고(①-a), 같은 자리에서 「LLM이 받아 적은 값을 시스템이 글자로 대조한다」는 구조 결함 셋을 더 봤다. 원리 하나로 묶는다: **시스템이 이미 아는 값(헤더 문자열·판 번호)은 LLM이 쓰지 않고, LLM이 고른 자리(시트·행)는 시스템이 검증한다.**
> **B61보다 앞선다.** B61은 관문 통과 뒤의 문면이고, 이것은 관문 자체다.
> 명세 정본 `docs/spec/` · 가이드 `docs/가이드/2B_작업가이드.md` · 구조도 `docs/구조도/05_조절_지도.md`(이번에 「등록 단계 LLM 호출 셋」 절이 붙었다 — ②의 근거).

## ① 헤더 위치 — 선언 하나, 리더 하나, 대조는 시스템이

**증상**: CSV 표본으로 `generate` → 관문 G52 `[adapter_mismatch] 양식 표류` · `missing` = 선언 전부, `extra` = 빈 배열 · 같은 시점에 「스키마 대장에 없는 열 19건」.

**①-a 직접 원인 (대조표 1·2)**: `parser/preflight.py::header_labels`가 `format != "xlsx"`면 `[]`를 돌려준다. CSV는 `format: "csv"`라 **실물 헤더가 항상 빈 배열**이고, 선언한 19개가 전부 `missing`이 된다. LLM이 무엇을 썼든 무관하게 CSV table 어댑터는 preflight를 **통과할 수 없다** — 리더가 「xlsx로 위장하지 않는다」고 정직하게 낸 값을 preflight가 xlsx만 받아서 생긴 어긋남이다. 고침: `format`을 보지 않는다. `sheets`가 있으면 읽는다.

**①-b 시트 해석기 하나 (대조표 3)**: `expects.sheet` — 시트 **이름**, 또는 생략. 생략이면 「유일한 시트」이고, 시트가 둘 이상인데 생략이면 `adapter_mismatch`에 `sheet 선언이 필요하다 — 시트: [이름들]`. 이 해석은 함수 하나(`reader.sheet_of(raw, expects)` 같은 자리)가 하고, preflight·`_label_columns`·orphan·어댑터 스켈레톤·참조어댑터가 전부 그것을 부른다. **`sheets[0]` 직접 참조는 리더 안에만 남는다.** CSV는 시트가 하나라 생략이 맞고, 파일 이름이 시트 이름이 되므로 이름을 선언하면 다음 파일에서 깨진다 — 문서(템플릿·가이드)에 그 한 줄을 적는다.

**①-c 헤더 문자열은 시스템이 채운다 (대조표 4)**: **기계 관문에 들어갈 때마다**(`machine_gate` 입구 — `fix=True`·`fix=False` 둘 다, 즉 generate·status·confirm 전부) 어댑터의 `expects.header_row`(+`sheet`)로 표본을 읽어 `header_labels`를 **시스템이 덮어쓴다.** 초안 저장 시점이 아니라 관문 시점인 이유: 결정적·멱등이라 판단을 바꾸는 일이 아니고, **이미 만들어진 어댑터**(①-a 이전 코드로 생성한 사내 `review/<doc_type>/`)가 재생성 없이 `status` → `confirm`으로 확정될 수 있어야 한다 — LLM 0. LLM이 쓴 값과 다르면 화면에 한 줄(정보 — 「LLM 선언 19 / 실물 19 · 다른 것 3: …」). 덮어쓰기 **전에** 위치를 검증한다: `columns`가 가리키는 각 열의 헤더 셀이 비어 있으면 관문 FAIL — 문면은 `header_row 의심 — {sheet}!{row}행에서 읽힌 값: [앞 5개]`. 라벨 정규화 함수 하나(`strip` · 연속 공백/줄바꿈 접기 · NFKC)를 preflight·`_label_columns`가 공유한다 — 지금 하나는 `strip()` 하나는 `str(v)`라 같은 셀을 다르게 읽을 수 있다. 템플릿은 **v1.3 새 판**(옛 판 보존): `header_labels` 항목을 「시스템이 채운다 — 쓰지 마라(써도 덮인다)」로, 파일 첫 줄 제목의 판 번호를 파일명과 맞춘다(v1.2 파일이 지금 「v1.1」이라고 적혀 있다).

**완료판정 ①**: ⓐ CSV 표본(헤더 1행·열 6개 이상)으로 `generate` → G52 PASS · orphan 0 · `adapter.py`의 `header_labels`가 표본 실물과 같다 ⓓ **①-a 이전 코드로 만든 `review/<doc_type>/`**(어댑터에 LLM이 쓴 `header_labels` 포함, 일부러 한 글자 틀리게)를 그대로 두고 `status` → PASS, `confirm --by x` → 성공, LLM 호출 0 — 이것이 사내가 지금 만든 어댑터를 살리는 경로다 ⓑ 어서션(성질) — `format`이 csv인 raw로 `header_labels()`가 비어 있지 않다 · 시트 둘인 xlsx에 `sheet` 생략 → `adapter_mismatch`이고 detail에 시트 이름 목록 · `columns`가 빈 헤더 셀을 가리키면 관문 FAIL ⓒ `grep -rn 'sheets\[0\]' parser/ cli/ kit/ --include=*.py | grep -v reader.py` 0줄.

**사내에서 함께 확인할 것 (①과 별개)**: 사내 화면에 원본 열 「Center」가 「Cent」로 보였다. ①-a로 G52는 풀리지만 이 글자 차이의 출처는 아직 모른다. ① 적용 뒤 같은 표본으로 다시 돌려 `header_labels`에 「Cent」가 남으면 **그 사실만** 보고한다 — 남는다면 리더(`_delimiter`·인코딩)를 본다.

## ② 라운드 전문은 패키지 밖으로 — 대화는 이력, 판단은 정본 (대조표 6·7)

B60 ②는 system 프롬프트의 힌트 자리만 `[확정 사항]`으로 바꿨다. **user 메시지는 여전히 `input_package.json` 원문 통째**라 라운드 전문(사내 실측 3천 줄)이 그대로 모델에 간다. 문답 라운드는 패키지 안의 rounds + `지난_문답`으로 **같은 전문을 두 번** 보낸다.

- `human.hint.interview[]` 묶음에서 `rounds[]`를 뺀다 → `review/<doc_type>/interview_log.json`(묶음 순서·`at`으로 짝을 맞춘다). 패키지 묶음은 `{samples, at, stale?, decisions[]}`만.
- 쓰는 자리(`_persist`·`_failure_persist`·`on_round`)는 rounds를 로그에, decisions를 패키지에. `_prior_rounds`는 로그를 읽는다. 문답 라운드의 `지난_문답`은 **현재 묶음의 라운드만**(로그에서). `_summarize`는 요약이 목적이라 전문을 받는 것이 맞다 — 유일하게 남는 자리.
- **옛 패키지**(rounds 인라인)는 로드 시 한 번 로그로 옮기고 화면 한 줄. `--resume`이 그 경로로 들어온다.
- 생성 user 메시지·문답 `입력_패키지`는 손대지 않는다 — 패키지가 깨끗해졌으니 그대로 보내면 된다. 보내는 쪽에서 걷어내는 방식은 **쓰지 않는다**(잊을 자리가 하나 더 생긴다).

**완료판정 ②**: ⓐ 라운드 30개를 심은 로그 + 패키지로 `generate --resume` → `_sent_size`(생성 초안)가 라운드 0일 때와 같다 ⓑ 어서션(성질) — 생성 user 메시지에 문자열 `"rounds"`가 없다 · 옛 꼴 패키지를 읽으면 로그가 생기고 패키지에서 rounds가 사라진다 · decisions는 그대로 ⓒ `grep -n '"rounds"' cli/prompt.py` 0줄.

## ③ `adapter_version`은 시스템이 찍는다 (대조표 5)

지금 LLM이 템플릿 예시의 `"1.0"`을 베끼고 아무도 안 올린다 — `adapter_rev2.py` 안이 `1.0`이다. `state.revision`과 파일 안 판 번호가 서로 모르는 두 카운터.

- 초안 저장 시 `ADAPTER["adapter_version"] = f"1.{revision}"` (초회 `1.0`, 재생성 2회째 `1.2`, `--revise`는 revision을 이어간다). LLM이 쓴 값은 무시.
- 템플릿 v1.3 예시에 `# 시스템이 찍는다` 주석.

**완료판정 ③**: 어서션(성질) — 저장된 어댑터의 `adapter_version` 끝자리 == `state.revision`. 재생성 2회 뒤 파일 안 값이 `1.2`.

## ④ 「더 돌릴까?」 문면과 기본값 (대조표 8 · 이연대장 1-a #8)

자동 재생성 1회 뒤에도 FAIL이면 `더 돌릴까? [y/N]` 한 줄. 이미 한 번 고쳤다는 것, y가 문답을 여는 것, N이 FAIL로 끝나 confirm이 막힌다는 것을 말하지 않고 **기본값이 막다른 길**이다.

```
   자동 수정 1회 뒤에도 FAIL 3건 (G13 · G52 · G52)
   [Y] 문답을 열고 재생성한다 (LLM 호출)   [n] 여기서 끝 — 관문 FAIL이라 confirm은 막힌다.
       n 뒤에도 이어갈 수 있다:  python -m cli.register review <doc_type> --instruct "…"
   더 돌릴까? [Y/n]
```

- 기본값 **y**. 남은 FAIL이 `GATE_SELF`뿐이면 **묻지 않고** 종료(재생성으로 못 고친다) — 문면은 그 사실.

**완료판정 ④**: ⓐ 화면 ⓑ 어서션(성질) — GATE_SELF만 남으면 `_ask_more` 호출 0 · 비대화형 기본이 y.

## ① 구조 방식 손잡이 — 기본 `edit` (칸 2.4)

- `knobs.json` 닫힌 목록에 `structure_mode` — `rules`(B118 방식 · 규칙 나무 + 크기 구간 · 구조 LLM 0) · **`edit`(기본 — ②)** · `llm`(B124 방식 그대로 — LLM이 나무 · 구간을 새로).
- **규칙 나무가 빈 시트**(고정 규칙 제목 0)는 `edit`여도 그 시트만 `llm`으로 · 화면 · 기록에 방식이 시트마다 남는다.

## ② `edit` — 규칙 나무를 주고 고칠 곳만 받는다 (칸 2.4 · 2.5)

- **입력**: B124의 시트 전문(줄 전체 · 번호 꼴 · 빈 줄 · 표시) + **규칙 나무**(들여쓰기 개요 — 제목 줄 · 행 · 단) + **형태 단서**(지금의 형태 요약 + **번호 이어짐 · 다시 시작** — 예 「'1)' 18~40행 11개 이어짐」 · 「'1.' 17행 — '가.'(14행) 아래에서 다시 시작」 · 글자 크기 · 칠한 색은 어댑터가 읽을 수 있으면) + **문서 맥락**(문서 종류 · 문서 좌표 · 다른 시트 이름) + 층 힌트.
- **출력**: 고침 목록 `[{row, 무엇, 값, 이유}]` — 무엇 = 제목 더함 · 제목 뺌 · 부모 바꿈 · 역할 · 대상 · **붙임**(`from_row`~`to_row`는 한 청크로) + 제목마다 역할 · 대상과 **판단 이유 한 줄** · 고칠 것이 없으면 빈 목록.
- **코드는 검사만**: 그 줄이 시트에 있나 · 부모가 앞에 있나 · 이름이 글자 그대로인가 · 붙임이 겹치지 않나 — 어긋난 고침만 버리고 셈(시트 전체를 버리지 않는다).
- **자르기**: 고친 나무 위에서 **B118의 크기 구간**(`chunk_rows` · `chunk_max_chars`) · 붙임 고침은 지킨다(권장값의 `structure_chunk_over`배를 넘으면 형제 경계에서만 나눈다 — B124 함수 그대로).
- 사슬 · 소속 · 이름 · 값은 지금 그대로(고친 나무의 사슬).

## ③ 구조 확인 — 시트마다 전부 출력 → 힌트 → 다시 출력 (칸 0.3 · 2.4)

- **자리**: 파싱 · 좌표 다음 · 추출 예고 전(산문의 새 단계 — 단계 수 · 이름은 구현 판단 · `--step`일 때).
- **시트마다 전부 출력**: ⓐLLM에 준 것의 요약(규칙 나무 · 형태 단서) ⓑ**LLM의 판단과 이유**(고침 목록 · 제목마다 역할 · 대상 · 이유) ⓒ고친 뒤의 나무 ⓓ**청크마다 첫 줄 · 끝 줄 · 사슬**(라벨 잘림 없이 — 좁은 화면이면 줄을 접는다) · 같은 내용을 `export/split_<doc_id>.md`에.
- **묻는 꼴**(B118의 묻는 자리 한 함수): `c`(ㅊ) = 이 시트 확정 → 다음 시트 · `q`(ㅂ) = 멈춤(쓰기 0) · **그 밖의 글 = 힌트** → 그 시트를 같은 방식으로 다시 부른다(입력에 앞 출력 + 지금까지의 힌트 전부) → 다시 전부 출력 · `새로` = 그 시트를 `llm` 방식으로 다시(힌트도 같이).
- **확정 기록**: 시트마다 최종 나무 · 붙임 · 준 힌트 · 방식 · 판(`registry/` — 사람 판단 · 재생성 불가 · 자리 구현 판단 — 지금 `structure_fixes.json`과 합치거나 곁) → 재구축 · 재인입이 그대로 재생(LLM 0). 옛 고침 기록(줄 번호 고침)은 읽어서 옮긴다.
- `--step`이 아니면 고리 없이 ②의 결과로 · 기록 · 약한 구조 신호 · 형제 신호는 지금처럼.

## ④ 구조까지만 돌기 · 가이드 (cli · 문서)

- `ingest-file <파일> … --split-only` — 파싱 · 좌표 · 구조(③의 고리 포함)까지만 · 추출 0 · 그래프 쓰기 0 · `export/split_<doc_id>.md` · 확정한 시트는 기록(다음 인입이 재생) — 같은 문서를 `structure_mode` 셋으로 바꿔 가며 싸게 비교.
- 가이드: 운영 런북(확인 단계 읽는 법 · 힌트 치는 법 · `--split-only`로 방식 비교) · config작성 가이드 §1-c(`prompts.structure`는 힌트를 문서 종류 전반으로 남기는 자리) · 인입 이해 가이드.

**완료판정**(창작 표본 — 구조 · 고침 답은 mock 힌트 · LLM 품질은 사내에서 잰다):
ⓐ 바닥: 번호 위계가 분명한 표본에서 `edit`의 LLM이 「고칠 것 없음」이면 나무 · 청크가 `rules`와 같다 · `rules`는 B118 마감 판과 같은 청크.
ⓑ 고침: 규칙이 놓친 줄(번호 없는 유닛 줄) 표본에서 고침(제목 더함 · 부모 바꿈 · 대상) → 사슬에 유닛 · 이유가 화면 · md에 · 어긋난 고침 하나는 그것만 버림.
ⓒ 고리: `--step`에서 힌트 한 줄 → 둘째 호출 입력에 앞 출력과 힌트 → 다시 전부 출력 → `c` → 기록 → 재구축에서 구조 LLM 0 · 같은 나무.
ⓓ 형태 단서: 「1.」이 「가.」 아래에서 다시 시작 · 「1)~11)」 이어짐이 형태 단서에 수로 선다.
ⓔ 방식 · 빈 나무: 고정 규칙 제목 0 시트는 `llm`으로 · `structure_mode=llm`은 B124와 같은 결과.
ⓕ 구조까지만: `--split-only`에서 추출 0 · 그래프 쓰기 0 · md가 선다.
ⓖ 네 벌: A · B 전부 같다 · C는 바뀐 몫만(기본이 규칙 나무로 돌아온 몫 — 보고에 차이).

## 1. 확정

### A. 골격 카테고리 값 — 찾거나, 없으면 잠정 골격 노드로 세운다

- **어디에**: 골격 카테고리 이름이 들어오는 모든 곳 — 표의 공정 칸 · 산문에서 골격 카테고리로 뽑힌 이름 · 목차 제목 · PPT 공정 표기. core 한 함수 · 문서 형태 무관.
- **카테고리**: 층 config의 골격 선언을 따른다(겸 포함) — 새로 정하지 않는다.
- **anchor 역할의 정의를 바꾼다**: 「찾기만 · 못 찾으면 보류」 → **「찾거나, 없으면 잠정 골격 노드로 세운다 · 그 행의 자리가 된다」**. 역할 이름(anchor)과 스키마는 그대로.

| 같은지 판단(D) 결과 | 처분 | 그 행 |
|---|---|---|
| 사전에 있음 · LLM 같다 | 그 골격 노드 | 연결 |
| LLM 다르다 | 잠정 골격 노드 자동 생성 | 연결(잠정 노드 아래) |
| LLM 애매 | 잠정 골격 노드 자동 생성 + 「합칠 후보: ○○」 표시 | 연결 |
| 공정 이름 아님(「-」 · 「공통」 · 「전 공정」) | 값이 없는 것으로 본다 | 위 단 사다리(상위 공정 칸 → 문서 좌표)로 연결 |
| 위가 모두 없음 | B 규칙 | 유일하면 연결 · 아니면 보류 |

- **부모**: 문서가 주면 매단다(같은 행의 상위 칸 → 목차 → 문서 좌표 순) · 안 주면 **「부모 미정」**으로 세운다(이름은 부모와 무관 — 골격 이름은 전체에서 하나).
- **잠정 노드는 승격과 무관하게 동작한다** — 생기는 즉시 그 행의 자리 · 질의에 보임 · 다음 문서의 동의어 후보.
- **잠정은 잠정이다** — 자동으로 세운 노드의 부모 · 단 · 이름은 운영을 위한 추정이고, 골격의 확정(골격을 어떻게 늘릴지)은 사람의 승격만 한다. 추정의 규칙은 config(골격 선언 · 단 정의)와 스키마(열이 선언한 단)에서 온다 — core에 단 이름 · 공정 이름 0.

### A′. 잠정 골격 노드는 사람이 정한 것만 선다 (2026-11-11 사용자 확정 · B196 — A의 처분 표를 바꾼다)

- **까닭**: 오타 하나가 잠정 ref를 세우면 형제 ref가 후보에서 빠져 그 아래 값이 행 수만큼 새로 서고, 나중에 합치면 자식 이름이 옛 부모 접두로 남는다(`ops merge`에 자식 연쇄가 없다). 앞에서 막는 비용은 표기 종류 수다.
- **같은지 판단(D)은 그대로** — 사전 · LLM이 「같다」면 그 골격 노드. 문이 받는 것은 그 나머지(「다르다 · 애매」)뿐이다.

| D 결과 | 처분 | 그 행 |
|---|---|---|
| 사전에 있음 · LLM 같다 | 그 골격 노드(「LLM 같다」는 검토 줄에 보인다) | 연결 |
| LLM 다르다 · 애매 | **세우지 않고 보류** + 후보 | 사람이 정할 때까지 보류(재연결 재료) |
| 사람: 후보 · 이름 지정 | 그 표기를 그 골격 노드의 별칭으로 | 연결 |
| 사람: 새로 | 잠정 골격 노드를 세운다(A의 모양 그대로) | 연결 |
| 사람: drop(사유) | 세우지 않는다 | 보류 · 재연결이 다시 열지 않는다 |
| 사람: 건너뜀 · 사람 없는 실행 | 세우지 않는다 | 보류 |

- **모든 문서**(표 · 산문 · 제목 · PPT) — 같은 함수. 문서의 성격에 따라 자동으로 세우는 길은 두지 않는다.
- **쌍 어긋남**(ref는 골격에 있는데 행의 상위 칸 · 문서 좌표와 줄기가 다름) — 확인(`coord-ack`) 전에는 보류 · 처분은 확인 · 정정(그 상위 아래 노드 지정) · drop · 건너뜀. 극성 쌍은 그대로.
- **ref가 빈 행** — 상위 칸으로 붙인다(지금 그대로 · 검토 줄에 수).
- **ref 아래**(유닛 · 부품 · 관리항목) — 지금처럼 기계가 판단해 붙이거나 세운다. 승인 없음.
- 기준 문서: Project `안건/수정후확정구축_v0.2.md`(사용자 확정 2026-11-11 — 방법은 그 문서 · 문의 범위는 이 절).

### A″. 골격 단에 노드가 서는 모든 길에 문 — 겸 카테고리 값은 골격 노드로만 선다 (2026-11-11 사용자 확정 · B197 — A′의 범위를 넓힌다)

- **까닭**: B196의 문은 골격 카테고리 값에만 걸렸다. 산문 제목 · 본문에서 Unit으로 뽑힌 값(「전극 주행 설계」)이 상위 공정 바로 아래 — 골격 하위 공정 단과 같은 높이 — 에 승인 없이 섰다.
- **원칙**(사용자): **하위 공정과 Unit은 같은 것이다** — 「prewelding unit」과 「prewelding」 공정은 노드 하나다. 구분하면 안 된다.
- **규칙**: 골격의 어떤 단을 겸하는 카테고리(공통 config `also` — 예: `Process` 하위 단 = `Unit`)의 값이 **그 겸 단에 설 때**(골격 노드 바로 아래 · 그 단이 겸 단) — 맞는 골격 노드가 있으면 그 노드(별칭) · 없으면 문(A′와 같은 처분). 일반 auto 노드로 서지 않는다. 골격 맨 아래 단 **아래**에 서는 값은 지금처럼 자동이다.
- **어디에나**: 표(ref가 비어 상위 칸에 붙는 행의 겸 값) · 산문 제목 개체 · 산문 본문 개체 · PPT · 재연결 — 같은 함수.
- **처분 자리**: 판정 전 — 표 · 제목은 좌표 단계([3/8]), 본문 개체는 [5/8] 머리.
- **처분**: 합침(골격 노드의 별칭) · 새로(잠정 골격 노드 — 겸이라 Unit이기도 하다) · 승격 · **drop = 그 아래까지 넣지 않는다**(제목이면 그 아래 청크는 추출하지 않는다 · 사유 기록 — 표의 drop과 같은 뜻) · **올림 = 세우지 않고 그 아래 값은 위 공정에 바로** · 건너뜀 = 그 아래까지 보류(정하면 재연결).
- 겸 선언이 재료다 — 선언이 없으면 이 문은 골격 카테고리 값에만 걸린다(`bootstrap` 「골격 '<카테고리>': 겸 없음」 줄).

### A-승격. 승격은 연결 조건이 아니라 「사람 보증」 표시 정리

- **인입 중**: `--step` [3/7] 좌표 단계에 「잠정 공정 후보」 표 — 후보마다 표기 · 부모 · 단 · 행 수 · 합칠 후보 · 그 자리에서 **승격(부모 · 단 지정) / 합침(기존 골격으로) / 그대로**. 정한 것은 그 문서의 나머지 행부터 반영.
- **인입 뒤**: 판단이 필요했던 것(잠정 공정 · 애매 · 보류 · 합칠 후보)을 한 화면에서 몰아 처리하는 기능.
- 승격하면 골격 파일에 (부모, 이름) 줄이 쓰이고 같은 노드가 표시만 확정으로 바뀐다 — **이름 · 노드 id · 그 아래 노드 그대로**. 부모 미정 · 단 미정은 승격 때 정한다.

### B. 자리 없는 값 — 유일하면 붙인다

- **적용 범위**: 문서가 자리를 아예 말하지 않은 값만(행의 공정 칸 · 상위 칸 빔 · 문서 좌표 · 목차 좌표 없음). 공정 표기가 있는데 목록 밖이면 A로.
- 우선 대략 적용한다.
- **깨질 때**: 같은 이름이 다른 공정에 새로 생기면 「유일 추정」으로 붙인 것을 재연결 때 다시 보고, 둘 이상이면 보류로 되돌린다.

### C. 상위 개체만 따로 보던 판단을 없앤다

- 지금: 관리항목을 맞출 때 두 상위 설비가 다르면 설비 이름 임베딩 유사도 85% 이상일 때 LLM에 다시 묻는다(`owner_similar_pct`).
- 바꿈: 없앤다. 설비는 노드로 설 때 이미 같은지 판단을 받았다 — 다른 노드면 다른 설비. 잘못 갈린 설비는 사람 병합.

### D. 같은지 판단은 한 절차 — 모든 곳이 같은 순서

| 단계 | 하는 일 | LLM |
|---|---|---|
| 1 후보 모으기 | 견줄 후보를 모은다 — 곳마다 다른 것 ① | 0 |
| 2 사전 | 표기가 후보의 이름 · 별칭과 같은가 — 공백 · 대소문자 · 전각만 맞춘다(접미어 「설비」 · 「unit」은 떼지 않는다) · 같은 후보 하나면 「같다」로 끝 | 0 |
| 3 후보 없음 | 남은 후보 0이면 「다르다」로 끝 | 0 |
| 4 뜻 판단 | 남은 후보를 LLM에 — 같다 / 다르다 / 애매 (+ 확실한 정도) | 1 |
| 5 기록 | 「같다」로 정해진 표기는 사전에 쌓이고 다음엔 2단계에서 끝 — 쌓인 것의 지위는 곳마다 다른 것 ② | 0 |

| 곳 | ① 후보 | ② 기록의 지위 | 다르다 | 애매 |
|---|---|---|---|---|
| 골격 칸 | 골격 목록(잠정 포함) | 기계 판단 — 사람 승격하면 골격 별칭 | 보류 + 후보(A′) | 보류 + 후보(A′) |
| 닫힌 분류 | 그 목록 | 기계 판단 — 사람 승격 | 보류 | 보류 + 후보 동봉 |
| 개체 | 같은 공정 줄기 안 같은 카테고리 노드 | 바로 별칭 | 새 노드 | 새 노드 + 사람 검토 |

- **판단 재료는 모든 곳이 같다**: 표기 · 카테고리 · 정의문 · 들어온 값의 경로(행의 상위 칸 · 문서 좌표 포함) · 후보마다 이름 · 별칭 · 경로 · 애매일 때 원문(산문은 문장 · 표는 같은 행의 다른 칸).
- **숫자 기준(지금 0.85)은 보조** — LLM이 스스로 매긴 값이라 크게 믿지 않는다 · 안전장치는 「애매」 선택지와 판단 재료 · 값은 시범 뒤.
- **바꾸지 않는 것**: 노드를 만든 문서 · 사람 확인 여부.
- **지금과 달라지는 곳**: 골격 칸 — 4단계 답 꼴(같다 / 다르다 / 애매)과 판단 재료 · 「다르다」면 잠정 노드 / 닫힌 분류 — 4단계(LLM) 추가 / 상위 개체 — 따로 있던 임베딩 길 삭제(C) / 개체 — 그대로.

## 3. 구현 메모 — 지금 갈라진 자리(공통 함수로 모을 곳)

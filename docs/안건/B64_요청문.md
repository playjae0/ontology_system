# B64 구현 요청문 — `columns`는 시스템이 해석한다 (라벨·합치기·중복) · 관문 문면에 열 프로파일 · 칸 1.4 · 1.5 · 2.2

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-15) · **출처**: 사내 실측 넷째 — CSV 등록에서 `expects.columns`가 회차마다 막힌다. ① G26 FAIL 상세의 `empty_columns`에 **헤더 라벨 「Center」가 그대로** 떴다(열문자 자리에 라벨을 쓴 것) — 문면이 「header_row 의심」이라 문답 LLM이 사람에게 「원본이 비었나 매핑이 비었나」를 되물었다. ② 같은 이름의 열이 둘(「하나만 있으면 그 값, 둘 다면 첫째」)을 사람이 힌트로 줬는데 `columns`는 필드당 열문자 하나라 표현할 자리가 없고, `_label_columns`가 라벨을 dict 키로 써서 **중복 라벨의 둘째 열이 조용히 사라진다.**
> **원리는 B62 그대로**: 시스템이 아는 값(라벨↔열문자 대응)은 LLM이 계산하지 않는다. LLM은 **무엇을**(어느 헤더) 고르고, **어느 글자인지**(A·B·…·AA)는 시스템이 표본에서 정한다. 그리고 B61 계약 — 관문 문면은 원인과 다음 줄을 담는다 — 을 G26이 못 지켰다.

## ① `columns` 값 셋 — 열문자 · 헤더 라벨 · 리스트(합치기) — 시스템이 열문자로 확정한다 (칸 1.4 · 1.5)

`expects.columns`의 값으로 세 꼴을 받는다:

| Form | Example | Meaning |
|---|---|---|
| 열문자 | `"D"` | 지금과 같다 |
| 헤더 라벨 | `"Center"` | 시스템이 표본 헤더에서 열문자로 바꾼다 |
| 리스트 | `["Center", "K"]` / `["D", "K"]` | **합치기** — 앞에서부터 첫 비지 않은 값. 사람의 「둘 다면 첫째」가 이것이다 |

- 해석 자리는 **관문 입구 `stamp_system_fields`**(B62 ①-c와 같은 자리, 같은 시점 — generate·status·confirm 전부). 라벨은 `norm_label`로 대조해 열문자로 **덮어쓴다**(작업 사본). 이후 코드는 열문자만 본다 — 스켈레톤 `extract`·orphan·preflight는 해석된 값을 받는다.
- 리스트는 스켈레톤 `extract`가 합친다: `for col in cols: v = cells.get(f"{col}{row}"); if norm(v): break`. 열문자 리스트로 확정된 뒤의 일이라 결정적이다.
- **못 바꾸는 경우는 관문 FAIL이고 문면이 답을 담는다**(AUTO_FIX 대상):
  - 라벨이 헤더에 없다 → `G26  columns 값 'Centre'는 3행 헤더에 없다 — 헤더: ['Center', 'Process No', …]`
  - 라벨이 헤더에 **둘 이상** → `G26  columns 값 'Center'가 3행에 2개 (D · K) — 열문자로 지정하거나 ["D","K"]로 합쳐라`
  - 열문자의 헤더 셀이 비었다 → `G26  D열 3행이 비었다 — 2행 값: [...] · 4행 값: [...] — header_row 의심`
- orphan(대조표 6): 「쓴 열」 집합은 리스트를 펼쳐서 센다. 합쳐진 둘째 열은 **쓴 열**이지 orphan도 unmappable도 아니다.

**완료판정 ①**: ⓐ 표본 헤더에 같은 라벨 둘(D·K)을 심고 `columns: {"center": ["Center","K"]}` 로 `generate` → 관문 PASS · 저장된 어댑터의 값이 `["D","K"]` · 리허설 레코드의 center가 D 비면 K ⓑ 어서션(성질) — 라벨 → 열문자 확정 · 중복 라벨은 FAIL이고 상세에 후보 열문자 목록 · 리스트 합치기 첫 비지 않은 값 · orphan 집합이 리스트를 펼친다 ⓒ `columns: {"center": "Center"}`(라벨 하나)로도 PASS.

## ② G26 문면 — 두 원인을 가르고 **열 프로파일 한 줄**을 붙인다 (칸 1.5)

「header_row 의심」 한 문면으로 「매핑이 틀렸다」와 「행이 틀렸다」를 같이 말했다 — 그래서 문답 LLM이 사람에게 되물었다. ①이 원인을 셋으로 가른다. 여기에 더해 **G26·G25(미포함 헤더)·orphan FAIL 줄에는 관련 열의 프로파일을 한 줄 싣는다** — 패키지 `system.reader_head[].열_프로파일`에 이미 있는 값이다:

```
  [FAIL] G26  columns 값 'Center'가 3행에 2개 (D · K) — 열문자로 지정하거나 ["D","K"]로 합쳐라
              D 'Center'  비지 않은 행 118/120 · 고유 4 · 형태 code
              K 'Center'  비지 않은 행  37/120 · 고유 4 · 형태 code
```

- 사람이 「한 값도 안 읽혔는지」를 화면에서 바로 안다. 새 계산 0 — 패키지 값을 읽어 찍는다.
- 문답에 실리는 관문 원문에도 같은 줄이 간다(B59 ② — 원문 동봉).

**완료판정 ②**: ⓐ 화면 ⓑ 어서션(성질) — G26 상세에 관련 열의 `비지_않은_행수`가 있다 · 세 원인이 서로 다른 문면.

## ③ 중복 헤더 라벨 — 대응은 리스트다 (칸 2.2 · 1.5)

`_label_columns`가 `{라벨: 열문자}` dict라 같은 라벨의 둘째 열이 사라진다(대조표 3). `{라벨: [열문자, …]}`로 바꾸고, 쓰는 자리(orphan · 라벨 해석)가 리스트를 받는다. preflight의 `header_labels`(리스트)는 그대로 — 중복을 두 번 세는 것이 맞다(표류 감지는 개수도 지문이다).

**완료판정 ③**: 어서션(성질) — 라벨 둘인 표본에서 orphan 계산이 두 열을 다 본다(둘 다 안 쓰면 orphan 2).

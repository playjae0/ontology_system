## ① 고정 규칙의 번호 패턴을 넓힌다 — LLM 0 (칸 2.5)

- 제목 번호 패턴 **군(family)**: 점 찍은 숫자(`1.` `1.2` — 지금 그대로 · 점 개수가 깊이) · `제1장`/`제1절`/`제1조` · 로마 숫자(`Ⅰ.` `I.`) · 대문자(`A.`) · 한글(`가.` `나.`) · 괄호 숫자(`(1)` `1)`) · 원 숫자(`①`). 글머리표(`-` `•` `·`)는 **제목이 아니다**(목록이다).
- **군 사이의 레벨은 시트 안에서 처음 나온 순서**로 정한다(처음 본 군 = 1단계, 다음에 처음 본 군 = 2단계 …) — 한국 문서의 `Ⅰ. → 1. → 가. → (1)` 관행이 문서마다 섞여 쓰이는 것을 따라간다. 점 찍은 숫자는 제 깊이를 그대로 쓴다.
- **본문 번호 목록 오탐 방지**: 제목 후보는 **짧은 행만**(`HEADING_MAX_CHARS` — 러프하게 60자) · 긴 번호 행은 목록 항목·본문이다.
- 판정 순서(번호 > 가로병합 > 굵게 · 들여쓰기 단독은 제목 아님)와 신호 기록(`signal`)은 그대로 — 신호 이름에 군을 싣는다(`번호(가.)`).

**완료판정 ①**: 어서션(성질) — 점 찍은 숫자만 쓰는 기존 표본의 분할이 **바이트 동일** · `Ⅰ./1./가./(1)` 표본에서 제목 레벨이 처음 나온 순서대로 1~4 · 60자 넘는 번호 행은 제목 0 · 글머리표 행은 제목 0.

## ③ 행 우선 + 글자 상한 (칸 2.5 — `parser/struct_map.split` 공용)

- 레벨 선택은 **지금 그대로**(5~40행 · 중앙 22.5행 · 동점 얕은 쪽).
- 자른 뒤 청크마다 **글자 수**를 본다 — `CHUNK_MAX_CHARS`(**러프하게 3,000자** — `CHUNK_MIN/MAX` 옆 상수 하나 · 사용자 확정 「러프하게」). 넘으면: 안에 더 깊은 제목이 있으면 거기서 한 단계(지금 규칙) → 없으면 **행 경계**에서 상한 이하 조각으로(셀 중간은 자르지 않는다 · 한 행이 혼자 상한을 넘으면 통째로 두고 `meta.over_char_cap`).
- 글자 **하한은 없다**(작은 청크를 합치지 않는다 — 합치면 구조가 바뀐다).
- 자리는 `struct_map.split` 하나 — 지도 경로와 어댑터 경로가 같은 규칙을 탄다(분할 규칙 두 벌 금지). 화면 한 줄: `글자 상한 초과 n청크 → 행 경계로 m조각`.
- 상한 값은 가결정 — 구현 세션이 표본의 청크 글자 분포(최소·중앙·최대·상위 5%)와 추출 LLM 입력 크기를 보고 **3,000이 말이 되는지** 보고한다. 바꿀 근거가 있으면 바꾸고 근거를 적는다.

**완료판정 ③**: 어서션(성질) — 상한 이하 청크만 있는 문서는 분할 불변 · 상한을 넘는 청크는 모든 조각이 상한 이하(한 행 예외 표시 제외) · 조각 경계가 행 경계 · 조각을 이으면 원문과 같다(무손실).

## ② 규칙이 못 세우는 시트만 — LLM 규칙 선언 · 적용 · 기록 (칸 2.4 · 2.6)

- **언제**: ①까지 적용한 뒤 그 시트의 제목이 0이거나 레벨이 비단조(지금의 `flat_fallback` 조건)일 때만. `size_out_of_band`(계층은 섰는데 크기가 구간 밖)는 지금처럼 큐만 — LLM으로 넘기지 않는다.
- **배선**: 파서 주입에 `infer_rules` 하나(`cli/parse.injections` — `map_structure` 옆) → `pipeline.parse`가 어댑터에 훅 `struct_rule_fn(frame, sample)`으로 건넨다 → 어댑터는 위 조건에서만 부른다. mock이면 주입이 None → **지금과 같은 동작**(통째 + 큐).
- **지점·지시문**: ⑦ 구조 지도 패스의 호출 태그 `struct_rule` · 지시문 `prompts/2.4_struct_rule.md`(신설 — 칸 대장 2.4 행에 이 회차가 같이 적는다 · 지시문 집합 == 칸 대장 잠금). 9지점 실호출 본문 스모크(B79)에 이 태그를 더한다.
- **LLM이 보는 것**: 그 시트 본문 열 앞 `RULE_SAMPLE_ROWS`(러프하게 60) 비어 있지 않은 행 — 행 번호 · 글자(80자에서 자름) · 표시(굵게 · 들여쓰기 칸 수 · 가로병합 시작 · 글자 크기가 리더에 있으면). 문서 전체가 아니다(비용이 문서 크기와 무관).
- **LLM이 내는 것 — 규칙 선언(strict 스키마 · B44)**: `{heading_patterns: [{match, level}], bold_is_heading, merge_is_heading, heading_column (string|null), reason}`. 고정 어댑터가 이것을 **데이터로** 적용한다.
- **검증**: 정규식이 컴파일되고 `^`로 시작 · 길이 ≤ 120 · 패턴 ≤ 8 · 레벨 1~6. 어기면 선언을 버리고(로그) 통째 + 큐. 적용해도 계층이 안 서면 통째 + 큐(두 번째 호출 없음).
- **기록**: 구조 지도 보존 파일(`work/struct_maps/<doc_id>.json`)에 `rules[<시트>]` + 원본 해시. 같은 파일 재인입 = 재사용(호출 0 · 같은 경계). 파일이 바뀌면(해시 다름) 다시 판단.
- **예고와 화면**: 부르기 전에 `계층 규칙 — 고정 규칙으로 안 선 시트 n장 → LLM ≤ n회(재사용 m)` · 끝에 `규칙 선언 적용 k시트 · 여전히 통째 j시트` · `show doc`·검수 뷰에 시트마다 「고정 규칙 / 선언(패턴 목록) / 통째」.
- **generate는 파악만**: 등록 리허설(`cli/register/view.py`)은 `infer_rules`를 주입하지 **않는다** — 시트마다 「고정 규칙으로 선다 / 인입 때 선언 필요」만 보인다. 킷 관문도 주입하지 않는다(완주 검사).
- **재사용 판정**: 분할이 바뀐 문서의 옛 추출 체크포인트를 재사용하지 않는다 — 기본 어댑터 판본을 올리든 조각 해시를 키에 넣든 방법은 구현 세션이 정하되, **분할이 안 바뀐 문서는 재사용**(재추출 비용을 헛되이 쓰지 않는다). 보고에 방법과 근거.

**완료판정 ②**: 어서션(성질) — 제목 신호가 없는 표본(글자 크기로만 제목) 시트에서 스텁 선언이 적용돼 계층이 선다 · 선언이 보존 파일에 있고 재인입 호출 0 · 원본을 바꾸면 다시 부른다 · 잘못된 선언(컴파일 실패·`^` 없음)은 버려지고 통째 + 큐 · mock은 호출 0 · 등록 리허설·킷 관문에서 호출 0 · 9지점 스모크에 `struct_rule` 본문이 돈다 · 파서 패키지에 core import 0.

## ① 문항 파일 형태 · `golden init`

- `golden/queries.json` = `{"version": 1, "queries": [{id, type, q, expected_path, expected_linked?: ["process:노칭"], expected_docs?: ["CP01"]}]}`. `type`은 `Q1`~`Q8` · `noanswer` · `multihop` · `out` 닫힌 값. 스모크 12문항은 이 형태의 **부분집합**이라 그대로 읽힌다.
- `python run.py golden init` → `golden/queries.json`이 **없을 때만** §5.5-2 기준 구성대로 빈 틀을 쓴다: Q1~Q5·Q8 각 15 · noanswer 10 · multihop 10 · out 10 = 120건, `q`는 빈 문자열, `expected_path`는 유형에서 파생(Q1→chunk · Q2~Q5→graph_fact · Q8/noanswer/out→general_knowledge · multihop→both). 있으면 덮지 않고 건수·유형 분포만 찍는다.
- 형식 검사: `golden score`가 읽을 때 닫힌 값 밖·필수 키 누락은 **문항 단위로 건너뛰고 사유를 찍는다**(파일 전체 거부 아님 — 사내가 채워 가는 중간 상태를 허용).

## ② `golden score` — 채점 3축 + BM-25 나란히

```
python run.py golden score [--set golden/queries.json] [--k 8] [--json]
```

문항마다 `answer(q)` 1회(⑧ 미호출):

| Axis | Rule | Applies when |
|---|---|---|
| path | `expected_path == res["path"]` | 항상 |
| linking | `expected_linked` ⊆ `res["linked"]` (문자열 「층:canonical」 정확 일치) | `expected_linked` 있을 때 |
| evidence@k | `expected_docs` 중 하나라도 `res["chunks"][:k]`의 `doc_id`에 있다 | `expected_docs` 있을 때 |
| **bm25@k** | 같은 문항을 BM-25 상위 k 청크로 — `expected_docs` 적중 여부 | `expected_docs` 있을 때 |

- 화면: 유형별 집계표(path 일치율 · linking recall · evidence@k · bm25@k) + 전체 + **틀린 문항 목록**(기대 vs 실제). `--json`이면 같은 것을 JSON으로.
- `data/golden_log.json`에 `{at, set, n, path_rate, linking_recall, evidence_at_k, bm25_at_k, k, by_type}` 한 줄 append(최근 50) — **로그이지 큐가 아니다.** 측정 중 `link_miss` 적재는 끈다(§5.5 규율 4 — `cmd_gauges`가 쓰는 같은 스위치).
- mock 세트(스모크 12문항)로 돌면 머리에 「메커니즘 점검 — 품질 점수 아님」을 찍는다(`cmd_accuracy`와 같은 문면).
- `cmd_accuracy`의 골든셋 대조 부분은 **이 채점기를 부르도록** 바꾼다 — 같은 계산이 두 벌이 되지 않게. 큐 추이 부분은 그대로.
- 계기판 1(링킹 recall): 골든셋이 있으면 분모를 골든셋으로(5.5 산식 1) — `basis` 문자열이 「골든셋 N문항」으로 바뀐다.

## ③ BM-25 — `core/bm25.py`

- 표준 라이브러리만. 인덱스 대상 = `data/chunks.json`의 전 청크 `text`(store 경유). 토큰화: 소문자화 → 영숫자 연속은 단어, **CJK는 문자 2-gram**(형태소 분석기 없이 한국어 부분 일치를 잡는 최소 방법 — 근거: 「노칭프레스」와 「노칭 프레스」가 같은 2-gram 집합을 공유한다). k1=1.5 · b=0.75 상수는 파일 머리 한 곳.
- `search(query, k) -> [(chunk_id, score)]`. 인덱스는 호출 때 메모리에 만든다 — 저장하지 않는다(파생물 P5, 청크 수천 건이면 밀리초).
- **그래프·사전·골격을 읽지 않는다**(대조군의 정의 — §5.5-3). 어서션: `core/bm25.py`가 import하는 core 모듈은 `store`뿐.
- `run.py show bm25 "<질문>" [k]` — 대조군 결과를 사람이 직접 볼 창구(선택, 20줄).

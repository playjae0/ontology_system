# B155 구현 요청문 — 추출까지만(`--extract-only`) + 추출 md: 그래프 · 사전 · 큐 · 청크 · 문서 대장 쓰기 0으로 추출 결과를 본다 · 산문 전부 한 명령 · 칸 0.3 · 3.3 · 문서

> **수신**: 구현 세션 · **발신**: 허브 (2026-10-27 · PPT 대화 설계 인계 「회차 B」 + 허브 검토 · 사용자 확정 2026-10-27 「회차는 너의 판단으로」 — hub_130) · **B154 뒤** · **단독**(사내 PPT 그래프 인입이 이 도구로 추출을 본 뒤 간다) · LLM 지점 · 지시문 변경 0(추출 재사용 그대로) · 새 스위트 0(`tests/part_g6_extract_view.py`에 대표 사례).
> **목적(사용자 원칙)**: 문서를 이해한 결과를 **사람이 중간물로 확인 → 고칠 것 고치고 → 확정할 때 그래프에 쓴다**(바로 연결 = 그래프 오염). 메타는 `--split-only` · `export/split_<doc_id>.md`가 보이고, 이 회차는 그다음 중간물 — **추출 결과** — 를 같은 꼴로 보이게 한다. 뒤의 쪽 판독(B156)이 추출을 얼마나 바꾸는지 재는 도구도 이것이다(판독 전후 추출 md 비교).
> **지금 길과 한계(허브 확인 · `efb9e11`)**: `--step`의 [추출 결과·판정 예고]에서 멈추면 그래프 쓰기 0 · 추출 체크포인트는 남는다(전제 3 · 4) — 그러나 정확한 자리에서 쳐야 하고 · 화면뿐이고 · **문서 대장(인입 기록)이 남는다**(사람·관문의 멈춤은 `keep_registry` — 전제 4) · 내용은 `show extract <doc_id> --full`(전제 6)로 따로 본다.
> **`--step`과의 관계**: `--split-only` · `--extract-only`는 **어디까지 가나**(멈춤 자리) · `--step`은 **가는 길에 묻나**(고치는 자리 — 구조 관문 · 덱 표 · 추출 예고)다 — 같이 줄 수 있다. `--extract-only --step`이면 앞 관문들은 지금처럼 묻고 추출 뒤 관문은 묻지 않고 멈춘다(멈춤이 곧 그 자리).
> **명세와의 관계 — 개정 필요**: 아래 「명세 자리」 — 명세 패치 파일로 · 보고에 「패치 뒤 같은 grep으로 옛 뜻 0」.

## ① `--extract-only` — 추출까지만 (칸 0.3 · 3.3)

- `python run.py ingest-file <문서> [--doc-type <dt>] … --extract-only` — 파싱 · 메타(구조 · 덱) · 목차 노드화 · 추출(렌즈면 층마다 · 같은 문서의 렌즈 전부)까지 가고 **추출 뒤 판정 예고 자리(전제 3)에서 멈춘다** — 사람의 `--step` 멈춤과 같은 되돌림이되 **문서 대장도 시작 전으로**(새 멈춤 종류 — `Stopped`의 하위 · `keep_registry` 거짓) → 그래프 · 사전 · 큐 · 청크 · 문서 대장 쓰기 0 · 남는 것 = `parsed/` · 추출 체크포인트(정본 — `work/extract/<doc_id>[@층].json` · 전제 6) · 목차 노드화 체크포인트 · `export/split_<doc_id>.md` · **`export/extract_<doc_id>.md`**(새 보기 — ②).
- 확정 = 같은 줄을 플래그 없이 → 추출 재사용(LLM 0) → 그래프 쓰기(지금 길 그대로).
- **산문만**: 표 문서는 추출 단계가 없다 → 상태 거부 한 줄(「표는 추출이 없다 — `--split-only` 또는 플래그 없이」) · `--split-only`와 같이 주면 상태 거부(멈춤 자리는 하나) · `ingest-file` 하나에만(`--split-only`와 같은 규칙 — 전제 1).
- 끝 줄: `추출까지 — 그래프 쓰기 0 · 추출 md <자리> · ▶ 확정: <플래그 없는 같은 줄>`.

## ② 추출 md — `export/extract_<doc_id>.md` (칸 0.3)

- **보기일 뿐이다** — 봉투 · 추출 체크포인트 · 목차 노드화 체크포인트에서 찍는다(md에만 있는 정보 0 · 되돌려 읽지 않는다 · 쓰는 자리는 구조 확인 md와 같은 한 자리 — 전제 2) · `show extract <doc_id> --full`과 같은 재료 함수.
- **머리**: 문서 · doc_type · 렌즈(층) · 지시문 판 · 단위 수(부름 · 재사용 · 개체 없음으로 건너뜀 · 실패).
- **한눈에**: 단위 × 층 — 개체 수 · 관계 수 · 관련 링크 수 · **부른 단위인데 개체 0 ⚠**.
- **판정 예고(층마다 · LLM 0 · 쓰기 0)**: 판정 예고의 셈(전제 5)과 같은 재료로 표기마다 — 사전 일치 · 판정에 오름 · 보류 예상(좌표 목록 밖 · 좌표 없음) · 검사에서 버려짐(결정적 검사만 — 값 글자 대조(전제 7) · 소속 출처 대조 · 부모 후보 밖) · **판정에 오를 표기 목록**(새 노드인지 일치인지는 판정이 정한다 — 예고하지 않는다).
- **단위마다**(추출 호출 단위 — PPT 슬라이드 · PDF 쪽 · 엑셀 · 워드 구간 · 형태로 가르지 않는다): 추출이 받은 것(맥락 줄 · 원문 · 구조 사슬 · 부착 · 부모 후보 · 캡처 붙음 여부) / 층마다 개체 표(표기 · 카테고리 · 소속(출처 `from`) · 부모 · 값 · **글에서 찾은 자리**(그 표기 · 값이 원문에 있는 줄 — 없으면 「글에 없음」) · 판정 예고) · 관계 · 관련 링크.
- 원문은 extract md에도 싣는다(한 파일로 판단 — 사용자가 split md와 오가지 않게).

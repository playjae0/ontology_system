# B69 구현 요청문 — 인입의 좌표 태깅: 표기당 1회 · 예고와 진행 · 상한 손잡이 · 다음 줄 명령 실재 어서션 · 칸 2.8 · 3.1 · 0.3

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-15) · **이 회차 뒤 사내 이식**(B66~B69를 main으로) · **출처**: 사내 실측 아홉째 — CSV를 `parse run adapters/<dt>.py`로 넣자 `LLM 사용량 coord_tag …` 로그가 30줄 넘게 이어져 사람이 「무한」으로 읽고 껐다.
> **진단**: 무한이 아니라 **행당 1회**다. `parser/tagger.py::tag()`는 조각마다 `process_ref`를 골격 닫힌 목록과 정확 일치로 대조하고, 안 맞으면 **그 행마다** `pick(ref, choices)`를 부른다(143~144행). 같은 표기(「노칭」)가 200행에 있고 골격에 없으면 200회 — 온도 0이라 답은 200번 같다. 인입 경로(`ingest-file` · `parse run`)에는 예고도 진행 줄도 상한도 없다(`progress=None`). **B22가 이 증상을 등록 리허설(review)에서 고쳤다**(앞 200행 · 좌표 보조 기본 끔 · 무LLM 미스 건수 제시 뒤 동의) — 등록에서 막고 **운영에서는 뚫려 있다.**
> **원칙**: 호출 수는 「행 수」가 아니라 「목록 밖 표기 종류 수」여야 한다(결정적 dedupe — 결과 동일, 호출만 준다). 비용 결정은 화면에 오른다(B22의 정신). 배치인 인입에는 동의 프롬프트가 아니라 **상한 손잡이**가 맞다 — `ingest-dir`이 문서마다 멈추면 안 되고, 기본 끔이면 골격 표기가 조금만 달라도 전부 orphan이 된다.

## ① 표기당 1회 — dedupe (칸 2.8)

`tag()`가 조각을 돌기 전에 **미스 표기 집합**을 먼저 모은다(결정적: `ref`가 있고 `idx`에 없는 것). 표기마다 `pick`을 **한 번** 부르고 답(채택한 노드 또는 null)을 기억해 전 행에 배분한다. null 답도 기억한다 — 같은 표기를 다시 묻지 않는다. 결과(각 행의 `process_ref`·`process_group`·`coord_tag_source`)는 지금과 **같다** — 호출 수만 준다.

**완료판정 ①**: 어서션(성질) — 같은 목록 밖 표기 N행 → pick 호출 1 · 서로 다른 표기 k종 → 호출 k · 태깅 결과는 dedupe 전과 동일(행별 값 비교) · 정확 일치 행은 호출 0(지금과 같다).

## ② 예고 한 줄 + 진행 줄 — `ingest-file` · `ingest-dir` · `parse run` (칸 3.1)

호출 전에 무LLM으로 센 숫자를 먼저 찍는다(B22 — 비용은 화면에 오른다):

```
   좌표 태깅 — 조각 412 · 정확 일치 152 · 목록 밖 표기 37종(행 260) → LLM 최대 37회 (상한 100)
   [좌표 태깅] 표기 12/37 · 채택 5 · 목록 밖 7
```

- 진행 줄은 표기 단위(①의 루프)로 갱신 — 행 단위가 아니다. `progress` 콜백을 `ingest-file`·`ingest-dir`·`parse run`이 넘긴다(지금 `None`). mock(`pick=None`)이면 예고 줄만(「LLM 0회 — 정확 일치만」).
- 끝나면 한 줄: `좌표 태깅 끝 — 호출 37 · 채택 21 · 목록 밖 16(orphan_anchor 후보)`.

**완료판정 ②**: 화면(3 명령) · 어서션(성질) — 예고 줄의 「표기 종수」 == ①이 실제로 부른 횟수(상한 미만일 때) · mock에서 LLM 0.

## ③ 상한 손잡이 `--coord-llm` (칸 3.1 · 06 대장)

`--coord-llm off | <종수>` · 기본 `100`(종수). 상한을 넘는 표기는 **묻지 않고 그대로 둔다**(목록 밖 → 인입의 orphan_anchor — 설계대로) — 멈추지 않는다. 화면: `상한 초과 — 137종 중 100종만 물었다 · 나머지 37종은 목록 밖 그대로(orphan_anchor) · 다음: --coord-llm 200 또는 사전 alias 등록`. `off`는 0회(정확 일치만). 값의 정본은 `cli/ingest.py` 상수 하나 + 플래그 — 06 손잡이 대장 2.8 행은 허브가 적는다.

**완료판정 ③**: 어서션(성질) — 상한 n이면 호출 ≤ n · 초과분 행의 `process_ref`는 원문 그대로 · `off`면 0 · 초과 화면에 다음 줄이 있다(B61 계약).

## ④ 다음 줄의 명령이 실재하는가 — 스캐너 어서션 (칸 0.3)

B68 회차에 `python run.py doctor`(없는 명령)를 다음 줄로 주던 상태 거부가 발견됐다(D-147 ④). 스캐너가 접두만 봐서 초록이었다. `tests/exits_scan.py`에 검사 하나: 다음 줄이 `python run.py <cmd>`면 `<cmd>` ∈ `run.py`의 `_rc` 키 · `python -m cli.<mod>`면 `cli/<mod>.py` 실재 · `python <file>.py`면 파일 실재. **문면을 세지 않는다** — 명령 이름의 실재만.

**완료판정 ④**: 어서션 초록 · 일부러 `python run.py nosuch`를 한 줄 심으면 붉어진다(보고에 붙이고 되돌린다).

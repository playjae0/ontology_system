## ① 골격 카테고리의 집은 골격 층 — 자동 (칸 0.1)

골격을 가진 층마다 그 골격의 카테고리(`skeleton.category`)의 집은 **그 층**이다. 맞추기(`plan`)가 이것을 규칙 ①~⑤보다 먼저 본다.

| 경우 | 처리 |
|---|---|
| 카탈로그에 없는 골격 카테고리 — 여러 층이 선언해도 | **자동 추가** — `home` = 골격 층 · 화면 `[bootstrap] 공통 config + 'X' (home 층A — 골격이 층A에 있다)` · 빈칸·멈춤 0 |
| 카탈로그에 있고 `home`이 **빈칸** | **채운다**(사람이 정한 값이 아니다) · 화면 한 줄 · 로그 · `common_version` +1 |
| **처음**(파일 없음) | 같은 규칙으로 `common.json`에 바로 쓴다 |
| 골격이 아닌 카테고리 | 지금 그대로(한 층 → 자동 · 여러 층 → 빈칸 + 멈춤) |

- `--dry-run`도 같은 계획을 보인다(쓰기 0).
- 이미 채워진 `home`은 바꾸지 않는다 — 골격 층과 다르면 ②가 멈춘다.

## ② 골격 모순 거부 — 심기 전에 (칸 0.1)

- **ⓕ 두 층 이상의 골격이 같은 카테고리**: 멈춘다 — 「골격 카테고리 'X'를 층 [A, B]의 골격이 함께 가진다 — 같은 뜻 노드가 두 그래프에 두 벌 생긴다 · 골격은 한 층만 갖는다」.
- **ⓖ 채워진 `home` ≠ 골격 층**: 멈춘다 — 「'X'의 home은 B인데 골격은 A에 있다 — 골격 노드는 A 그래프에 심긴다 · home을 A로 고친다」. **첫 실행에서**(층 심기 전) 멈춘다 — 위 실험처럼 1회차가 통과하고 2회차에 엉뚱한 문면으로 멈추는 일이 없게 한다. ⓖ는 B92의 집 변경 검사보다 **먼저** 본다(문면이 원인을 말하도록).
- 자동으로 고치지 않는다(사람 값).

## ③ 겸 상태 표시 — `bootstrap` 끝 · `doctor` (칸 0.1)

골격 카테고리마다 자기 좌표 규칙이 켜졌는지 한 줄. **경고일 뿐 거부가 아니다**(종료 코드 0).

| 상태 | 판정 | 문면(예 — 일반어 · 층 어휘 0) |
|---|---|---|
| 켜짐 | `also`가 있고 겸 단 골격 노드에 별칭이 있다 | `골격 'Process'(층A): 겸 Unit(sub·detail) · 겸 단 별칭 n개` |
| 꺼짐 | `also` 없음 | `골격 'Process'(층A): 겸 없음 — 골격 노드 이름 + 다른 카테고리 표기는 새 노드가 된다(자기 좌표 규칙 꺼짐)` |
| 반쪽 | `also`는 있는데 겸 단 골격 노드의 별칭 0 | `⚠ 골격 'Process'(층A): 겸은 있는데 겸 단 별칭 0 — 별칭이 없으면 자기 좌표 규칙이 돌지 않는다` |

- `doctor`는 공통 config 판 줄 옆에 같은 상태를 싣는다(지금의 겸 집 불일치 경고 자리).
- 겸이 없는 flat 골격(품질층 등)도 「꺼짐」 한 줄이다 — 의도면 그대로 둔다.

## ④ 가이드 — 뼈대층 구성 절 (같은 커밋)

- **`골격작성_가이드`에 절 신설 「뼈대층(설비·공정)을 처음 세울 때」** — 머리에 **한정**을 적는다(통용 규칙이 아니다 — 설비·공정층의 config·골격을 처음 뽑을 때만 쓴다). 담을 것:
  1. 골격은 공정 두 단 — 상위 공정(설비 단위)과 하위 공정(unit 단위) · 둘 다 골격 `Process` 노드 · 겸 `Unit`(두 단) · 단은 깊이에서 파생(대공정이 1단이면 `["sub", "detail"]`).
  2. 카테고리를 나누는 기준 — **다른 엣지가 붙어야 하면 다른 노드·카테고리** · 지금은 나누지 않는다.
  3. 단별 설비 표기(「○○ 설비」·「○○ unit」 류)는 그 노드의 `ALIASES` — 정확 일치 · 변형마다(대소문자 포함).
  4. **구분은 그 아래부터** — `Component`(설비층 — 구성 기계·부품)와 `Property`(공정층 — 파라미터·관리특성)가 골격 노드에 갈라 붙는다.
  5. 공정층은 `Process` 골격을 갖지 않는다 — 렌즈로 선언하면 집은 ①로 설비층.
  6. 겸을 켜는 셋(`also` · `ALIASES` · 정의문)과 확인법(③ 화면 · `show node`의 「겸 Unit」 · 판정 대장 `self_coord`) · 왜(같은 실물이 두 노드가 된다).
  7. **요청문 틀** — 사내 LLM에 설비·공정층 config·골격 초안을 맡길 때 주는 프롬프트(이 절 + 공장의 공정 목록을 넣는다 · 출력: 층 config `categories` 정의문 · `skeleton.json`(두 단 + `ALIASES`) · `common.json`의 `home`·`also`). 예시 이름은 창작.
- **반대로 적힌 곳을 고친다**: 골격작성 §3 표 82행(「노칭 프레스·노칭 커터 — 골격에 두지 않는다 · 인입이 Unit」) · config작성 309행 Process 정의문 예시(「스테이션 아래 구성 기계(프레스·커터·로봇)는 Unit」) → 하위 공정(unit)은 골격 · 그 아래 구성 기계·부품이 `Component` · 골격에 없는 설비 표기는 인입이 Unit으로 만든다(뼈대가 빠뜨린 것 — 사람이 볼 자리).
- `config작성_가이드` §0-a는 이 절을 가리키는 한 줄 + 맞추기 표에 골격 행(①) · 멈춤 표에 ⓕⓖ. `2B_작업가이드` 시작하기 · `걸어가기_설비문서` §1-a에 ③ 화면.
- 구조도 `06_손잡이_대장` 0.1 · `00_칸_대장` 0.1 · `10_코드_지도`(생성).

**완료판정**: 테스트 세트(창작) — ⓐ 두 층이 골격 카테고리를 함께 선언 → 집 = 골격 층 자동(빈칸·멈춤 0) ⓑ 기존 빈칸 → 채움 · 판 +1 · 로그 ⓒ 두 층 골격이 같은 카테고리 → 멈춤 ⓓ 채운 `home` ≠ 골격 층 → **첫 실행에서** 멈춤(그래프 쓰기 0) ⓔ 골격이 아닌 카테고리의 겹침은 지금처럼 빈칸 + 멈춤 ⓕ 겸 상태 세 갈래 화면 · 종료 코드 0 · `doctor` 같은 상태 ⓖ `--dry-run` 쓰기 0 · mock 네 벌 diff 0.

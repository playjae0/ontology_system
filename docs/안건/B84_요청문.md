## ① 테마 · 라벨 대비 (칸 5.2)

- **밝은 테마가 기본**, 어두운 테마는 토글(머리 줄 버튼 · 브라우저 `localStorage`에 기억). 색은 전부 CSS 변수(`--bg`·`--fg`·`--dim`·`--line`·`--hi`)에서 오고 sigma의 `labelColor`·`edgeLabelColor`·기본 엣지 색을 **그 변수에서 읽어** 넘긴다 — 테마를 바꾸면 라벨도 따라간다. 노드 색(축별 결정적 색)은 그대로.
- 노드 크기는 tier로(main > sub > detail · seed는 테두리) — 지금은 `seed 6 · 나머지 4`뿐이다.

**완료판정 ①**: 어서션(성질) — 두 테마 각각에서 `labelColor`와 `--bg`의 대비비 ≥ 4.5(계산은 색 문자열에서 — 화면 캡처가 아니다) · sigma 설정에 넘긴 `labelColor`가 CSS 변수 값과 같다 · 테마 선택이 새로고침 뒤 유지된다(Playwright).

## ② 검색은 강조만 — 재배치 0 · 재생성 0 (칸 5.2)

- 검색 입력은 **보이는 노드의 강조/흐림만** 바꾼다(sigma `nodeReducer`/`edgeReducer` — 속성 갱신). `layout()`을 부르지 않고 `S.sigma`를 죽이지 않는다. 150ms 디바운스.
- `draw()`를 둘로 가른다 — **`rebuild()`**(데이터·필터·배치·축이 바뀔 때 — 그래프를 다시 만든다)와 **`restyle()`**(검색·강조·테마 — 리듀서만). 필터 체크박스도 가능하면 `restyle()`(hidden 속성)로.
- sigma 인스턴스는 **한 번** 만들고 `rebuild()`는 graphology 그래프 내용만 갈아 끼운다(`g.clear()` + 추가 · `S.sigma.refresh()`).

**완료판정 ②**: 어서션(성질) — 검색 문자열을 바꾸는 동안 `layout()` 호출 0 · `Sigma` 생성자 호출 1(페이지 수명 동안) · 검색 결과가 이름·별칭·id에 대해 지금과 같은 집합.

- 체크박스를 **선택기**로: `계층`(지금의 결정적 계층 좌표 — 검증·diff용 · 「같은 입력이면 같은 그림」) · `힘`(ForceAtlas2 — graphology-layout-forceatlas2를 npm tarball에서 **같은 방식으로 벤더링**(MIT · LICENSE · README 해시 갱신) · 고정 seed·고정 반복 수라 **결정적** · 계층 좌표를 초기값으로). 선택은 `localStorage`에 기억. 「다시 배치」 버튼 하나.

**완료판정 ③**: 어서션(성질) — 같은 그래프·같은 선택이면 좌표가 같다(두 번 계산 diff 0 · 두 배치 모두) · 선택이 새로고침 뒤 유지된다 · 벤더 README의 해시 == 실물(기존 어서션에 파일 하나 추가) · 외부 URL 0 그대로.

## ⑤ 질의 오류는 화면에 문면으로 (칸 5.3)

- `ask()`가 응답의 `error` 키(또는 HTTP ≥ 400)를 보면 답 자리에 **서버 문면 그대로**(`GatewayError: … POST <url> HTTP 400 …`)를 빨간 카드로 낸다. 조용히 비지 않는다. 질의 중 버튼 비활성 + 「묻는 중…」.

**완료판정 ⑤**: 어서션(성질) — 서버가 500 `{"error": X}`를 내면 화면 텍스트에 X가 포함된다 · 정상 응답이면 오류 카드 0 · 질의 도중 같은 버튼을 눌러도 요청이 1건.

## 왜 바꾸나

B41의 「감축 뒤에도 넘으면 보내지 않고 멈춘다」는 **폴백이 없는 지점**(⑤ 어댑터 생성 — 초안이 없으면 할 일이 없다)의 규칙이다. ⑦은 다르다 — 지도가 없어도 문서는 **평면으로 들어가 좌표 태깅까지 된다**(§6.2). 지금 구현은 산문 대문서 하나를 `RuntimeError` → 문서 실패로 떨어뜨려 **그 좌표 태깅까지 잃는다.** 조용하지는 않지만 명세가 준 길을 안 쓴 것이다.

## 작업 — 함수 셋

1. **`core/llm.py::map_structure`** — 예산 초과 시 `raise` 대신 **지도 형태로 사유를 돌려준다**:
   ```python
   {"doc_id": doc_id, "source": "live", "rows": [],
    "unavailable": reason,            # 이 키가 있으면 「지도 없음 + 사유」다
    "prompt_version": prompt_version("struct_map"),
    "meta": {"dropped": 0, "note": None, "행_앞자리": width, "감축": …}}
   ```
   `log.explicit_fail(...)`은 **그대로 남긴다** — 관측은 유지하고 귀결만 바꾼다. 모델이 정상 응답했는데 `headings`가 비고 `note`가 있으면 `unavailable`을 세우지 않는다(그건 모델의 판정이고 ③이 다룬다).
2. **`parser/struct_map.py::propose`** — `ask` 갈래에서 `m.get("unavailable")`이면 **`keep`하지 않고** 그대로 돌려준다. 보존하면 재인입이 영영 평면이다(예산을 올려도 보존분을 재사용).
3. **`parser/struct_map.py::validate`** — 맨 앞에: `unavailable`이 있으면 사유 목록은 `[그 사유]` 하나로 끝낸다(커버리지 검사까지 내려가 사유가 셋 겹치지 않게). 그리고 **헤딩 0건 + `meta.note`가 있으면** 사유 문면에 note를 붙인다 — `"헤딩 0건 — 모델: {note}"`. 큐 항목이 「왜」를 들고 검수 화면에 간다(§6.2 「판정 불가로 올린다」의 실물).

파서는 `unavailable`이라는 **데이터 키**만 본다 — core의 예외 타입을 import하지 않는다(A1).

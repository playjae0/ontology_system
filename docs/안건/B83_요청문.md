## ① 역할 셋과 기록 — `registry/sheet_roles/<doc_id>.json` (칸 0.3 · 2.2)

- 역할은 **닫힌 셋**: `prose`(지금의 동작 — 제목 단위 청크 → 추출 → 개체·관계 후보) · `ref`(참조 — **청크로 저장만** · 추출 0 · `linked=false` · 문서 열람·`show bm25`·뷰어 `/api/doc`에서 보인다) · `skip`(읽지 않는다). 이름을 `context`로 하지 않는 이유는 계약 A의 `context`(맥락 딕셔너리)와 겹치기 때문이다.
- 기록은 **②등록 단** `registry/sheet_roles/<doc_id>.json`(자리는 `paths.registry("sheet_roles", …)` · 폴더는 `ensure`) — 사람이 정한 것이라 백업·이관 대상이고 `init --fresh`가 지우지 않는다. 형태:
  ```json
  {"doc_id": "RFQ_설비A", "file": "RFQ_설비A.xlsx", "decided_by": "gate|flag", "at": "…",
   "sheets": {"사양_기계": "prose", "사양_전장": "prose", "요구사항": "prose",
              "도면목록": "ref", "가격": "skip", "일정": "skip", "표지": "skip"}}
  ```
- **적용 자리는 파서**다 — `parser/pipeline.parse(..., sheet_roles=None)`: `raw["sheets"]`에서 `skip`을 **빼고** 어댑터를 부른 뒤 `meta.frame`이 `ref` 시트인 조각에 `meta.sheet_role = "ref"`를 단다. 파서는 역할을 **데이터로 받을 뿐** 상태·기록·모드를 읽지 않는다(파서는 `core`를 import하지 않고 `USE_MOCK`을 모른다 — 기존 규율 · 기록을 읽어 넘기는 쪽은 CLI다). 역할이 없으면(None) 지금과 같다. 표 어댑터(`expects.sheet`)에는 적용하지 않는다 — 형태 `table`은 이 관문 밖이다.
- 이름 정합: 기록에 있는데 문서에 없는 시트는 로그 한 줄(무시) · **문서에 있는데 기록에 없는 시트는 미결**이다 — ③의 관문이 그 시트만 다시 묻는다(비대화형이면 거부). 조용히 `prose`나 `skip`으로 떨어지지 않는다.

**완료판정 ①**: 어서션(성질) — 역할 기록이 있는 문서의 청크에 `skip` 시트 프레임 0 · `ref` 시트 조각은 전부 `meta.sheet_role == "ref"` · `prose` 시트 조각에는 그 키가 없다 · 기록 파일은 `registry/` 아래(mock은 `state_mock/registry/`) · 파서 패키지에 `core` import 0 · `USE_MOCK` 문자열 0(기존 규율 그대로 — 역할은 인자로만 온다) · `sheet_roles=None`이면 산출이 지금과 바이트 동일.

## ② 시트 표와 제안 — 규칙으로, LLM 0 (칸 2.2 · 3.1)

- 시트가 **둘 이상**이고 형태가 `prose`인 엑셀에서, 관문(③)이 보이는 것은 **시트 전부의 표**다(사용자 확정 — 이름을 다 보여 주고 묻는다):
  ```
  ■ 시트 역할 — RFQ_설비A.xlsx · 32장 (기록 없음 — 이 문서는 처음이다)
     #  시트            행    열  글자셀  앞부분                          제안
     1  표지             12    3    40%  「RFQ / 설비A / 2026-09」          skip
     2  사양_기계       214    6    71%  「1. 개요 … 1.1 적용 범위 …」      prose
     3  사양_전장       180    6    68%  「1. 전장 사양 …」                 prose
     4  도면목록         96    8    22%  「DWG-001 … DWG-095」              ref
     5  가격            40    9    18%  「항목 / 단가 / 수량 …」            skip
     …
  ```
  열은 `reader`가 이미 내는 것에서만(행·열 수 · 값 있는 셀 중 글자 셀 비율 · 앞부분 셀 발췌) — 새 판독 0.
- **제안은 규칙**이다(LLM 지점을 늘리지 않는다 — 사람이 어차피 고치는 제안에 지점 하나(지시문·mock·실호출·도달성 어서션)를 열 이유가 없다 · 규칙이 못 미치면 그때 판단): 값 있는 셀 0 → `skip` · 글자 셀 비율과 행 수가 문턱 위(상수 하나 — `parser/form.py` 곁, 값은 구현 세션이 표본으로 정하고 보고에 적는다) → `prose` · 그 밖 → `ref`. 제안은 **제안**이라 표에만 뜨고 기록은 사람의 답이다.
- `ingest-file --dry-run`은 지금처럼 선택까지만이되, 시트가 둘 이상이면 이 표를 **보여만 준다**(묻지 않는다 · 기록 0).

**완료판정 ②**: 어서션(성질) — 표의 행 수 == 통합문서의 시트 수 · 각 행의 이름이 시트 이름과 같다 · 값 있는 셀 0인 시트의 제안은 `skip` · 표는 색을 벗긴 문자열에서 파싱된다 · `--dry-run`은 기록 파일을 만들지 않는다 · 시트 하나면 표도 관문도 없다.

## ③ 관문 — 물을 수 있으면 묻고, 없으면 거부 (칸 3.1)

- 자리는 인입 흐름의 **선택·형태 판정 뒤 · 파싱 앞**(`_step_gate`와 같은 자리 · `--step`과 독립). 조건: 엑셀 · 형태 `prose` · 시트 ≥ 2 · 기록 없음(또는 미결 시트 있음).
- **대화형(tty)**: ②의 표 뒤에 한 줄 입력 — 문법은 `<선택>:<역할>` 토큰을 공백으로. 선택은 표의 번호(`2` · `2-3` · `2,3,7`) 또는 시트 이름 · `*`는 「나머지」. **Enter만 치면 제안 그대로**. 역할이 안 정해진 시트가 남으면 다시 묻는다(조용한 기본값 0). 답은 기록(①)이 되고 화면에 `시트 역할 — prose 3 · ref 1 · skip 28 → registry/sheet_roles/<doc_id>.json` 한 줄. `q`면 그 문서 중단(그래프 쓰기 0 · 기록 0).
  ```
     역할 — 번호:역할 (예 2-3:prose 4:ref *:skip · Enter=제안대로 · q=중단): 2,3:prose 4:ref *:skip
  ```
- **비대화형(파이프 · `ingest-dir` 배치 · EOF)**: 묻지 않고 **상태 거부** — 문면에 시트 이름 전부와 ▶ 다음 줄(`ingest-file <문서> --sheets "…"`)을 싣는다. `ingest-dir`에서는 그 문서만 실패하고 나머지는 간다(문서 단위 독립 — 지금 규율).
- **`--sheets "<같은 문법>"`**(`ingest-file` · `parse run`)은 관문을 건너뛰고 같은 기록을 쓴다(`decided_by: flag` · 있으면 덮는다 — 사람이 다시 준 것이다). 문법 오류·미정 시트는 `[사용법]`.
- 관문은 **한 문서에 한 번**이다 — 기록이 있으면 표도 질문도 없다. 사람이 역할을 바꾸려면 `--sheets`로 다시 주거나 기록 파일을 지운다(다음에 다시 묻는다).

**완료판정 ③**: 어서션(성질) — 시트 ≥ 2 · 기록 없음 · 비tty에서 상태 거부이고 문면에 시트 이름 전부가 있다 · 그래프·청크·기록 쓰기 0 · `--sheets`로 넣으면 기록이 생기고 청크가 ①대로다 · 같은 문서 재인입은 관문 0 · 산출 동일(멱등 — 클린 2회) · 기록에 없는 시트가 새로 생긴 문서는 비tty에서 그 시트 이름만 문면에 싣고 거부 · `q`는 쓰기 0 · tty 스텁에서 Enter는 제안과 같은 기록.

## ④ 참조 청크의 처지 — 추출 0 · 구축 결함 아님 · 열람에는 보인다 (칸 3.3 · 3.5 · 0.3)

- `cli/extract.py`는 `meta.sheet_role == "ref"` 청크를 **부르지 않는다**(화면 `[추출] 청크 n · 참조 m 건너뜀`) · 구축(`build_prose`)은 참조 청크에 후보가 없는 것을 결함·큐로 보지 않는다 · 청크는 그대로 `chunks.json`에 `linked=false`.

- **질의 `answer()`에는 잡히지 않는다** — 청크 수집이 노드 기준이라(전제 11) 노드에 안 붙은 청크는 답의 근거가 되지 않는다. 이것은 **사실을 적는 것**이지 이번 회차의 요구가 아니다: 「같은 문서의 참조 청크를 문서 근거 보조로 붙일 것인가」는 질의 미스가 쌓인 뒤 판단한다(P7). 어서션은 「잡히지 않는다」를 잠근다 — 누가 조용히 붙이면 붉어야 한다.

**완료판정 ④**: 어서션(성질) — 참조 청크에 대한 추출 LLM 호출 0(mock 갈래에서 힌트 조회 0) · 구축 뒤 큐에 참조 청크 유래 항목 0 · `chunks.json`에 참조 청크 존재 · `linked == false` · `show doc`·`/api/doc`에 역할 표시 · `answer()`의 `chunks`에 참조 청크 0.

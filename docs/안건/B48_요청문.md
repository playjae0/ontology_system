## 0. 판정필요-15의 판정 — 왜 3안이 전부 아닌가

| Option | Rejected because |
|---|---|
| (가) 파서가 `core.llm`을 import | 「명세에 없는 코드 규율」이 아니다. **문서 1 A1**: *"단계 간 결합은 파일 계약(JSON)으로만 한다. 코드·DB 공유 없음"* (P1 미러 · A14로 문안 고정). docstring 문장을 grep해 0건이라 판단했지만 **문장이 없다고 규범이 없는 것이 아니다.** 위계 1 조항을 편의로 풀지 않는다 |
| (나) 호출자 주입 + 파서 환경변수 폴백 | 신고문 자신이 적었듯 읽는 곳이 2곳으로 남는다 — 갈림의 원인이 그대로다 |
| (다) 현행 유지 + 문서화 | §7.6-B-4의 조용한 오염을 사용법 주의로 남긴다 |

**채택 — 파서에서 판독을 없앤다.** 파서의 LLM 3지점은 **호출자가 만든 함수를 받거나(실호출) 받지 않거나(대체)**다. 파서에 「지금 mock인가」라는 질문 자체가 없다. ④·⑨는 이미 이 모양이다(`cli/parse.py:51-52`가 `llm.image_summarizer()`·`llm.coord_picker()`를 주입). **⑦만 아니었고, 그래서 사고가 났다.** 셋을 같은 모양으로 맞춘다.

이것이 임시가 아닌 이유: 「모드는 진입점에서 한 번 정하고 아래로 내려보낸다」 구조의 **파서 쪽 절반**이다. core 6지점(①②③⑤⑥⑧)의 인라인 `use_mock()` 분기를 같은 구조로 바꾸는 것은 **다음 회차**다(§7.6-B-2 문면 개정 동반 — 이번 회차 사내 실측 뒤 발주). 이번 회차는 core 6지점을 건드리지 않는다.

## ① 파서 무판독 — 함수 유무로만 (문서 7 §7.6-B-1 B48)

### 작업
1. `parser/pipeline.py::parse(...)` — `struct_map=None` 인자 신설. `_map_hook(doc_id, kept, made, seen, ask=None)`로 내려보낸다. **`_image_gate` 삭제** — `summarize`가 None이면 대체(고정 문자열 + `meta.image_summary_source=mock`), 함수면 실호출. 판독 없음.
2. `parser/tagger.py::complete_images` — `allow_mock` 인자 삭제. 「summarize 없음 + 실호출 모드 → RuntimeError」 갈래 삭제(팩토리가 `require()`로 이미 막는다 — 전제 대조표 8행). MOCK 로그(§7.8 3종)는 **summarize가 None일 때** 남긴다 — 조건이 「모드」에서 「함수 부재」로 바뀔 뿐 로그는 유지.
3. `parser/struct_map.py` — `apply(doc_id, lines, locator, sep=" > ", ask=None)` → `propose(doc_id, lines, ask=ask, src_hash=…)`. `propose` 안의 `os.environ.get("USE_MOCK")` 분기 삭제: **`ask`가 있으면 실호출·보존, 없으면 휴리스틱.** 「USE_MOCK=0인데 ask 없음 → RuntimeError」 삭제(같은 이유).
4. `cli/parse.py`·`cli/register.py`의 `parse(...)` 호출 전부에 `struct_map=llm.struct_mapper()` 추가(②가 만든다). 주입 자리는 지금 `summarize=`·`pick_coord=`가 있는 그 줄이다.
5. **파서 패키지 전수에서 `USE_MOCK` 문자열 0건** — 주석·docstring 포함. 지금 docstring들은 삭제되는 분기를 서술하고 있으므로 함께 고쳐야 맞다(`reader.py:43`의 「USE_MOCK=1 전체 실행」은 「모델 없는 실행」으로).
6. **회귀 어서션 신설**(test_p1): `parser/` 하위 `.py` 전수에 `USE_MOCK` 0건 · `os.environ` 판독으로 mock 여부를 정하는 줄 0건.

### 완료판정 ①
ⓐ `grep -rc USE_MOCK parser/` 전부 0 ⓑ 파일 설정만으로 `USE_MOCK: 0`을 준 상태에서 `cli/parse.py`가 파서에 **함수 3종을 전부 주입**하는 것을 실행으로 증명(로그 또는 디버그 출력 — `image_summarizer`·`coord_picker`·`struct_mapper` 셋 다 non-None) ⓒ 신설 어서션 초록 ⓓ 회귀 유지

## ② 지점 ⑦ 실호출 배선 (문서 7 §7.6-B-2 B48 · 문서 6 §6.2·§6.3)

### 작업
1. `core/llm.py` — `struct_mapper()` 팩토리 신설. **`image_summarizer()`·`coord_picker()`와 동형**: `use_mock()`이면 None · 아니면 `require("struct_map")` 후 `map_structure` 반환.
2. `map_structure(doc_id, lines) -> smap` — `prompts/struct_map.md`를 `prompt("struct_map")`으로 읽어 조립. 입력 `{{lines}}`는 `행번호<TAB>앞80자` 행 목록. **크기 예산은 B41의 감축 순서를 그대로 탄다** — 초과 시 감축하고 감축 사실을 지도 `meta`에 남긴다. 호출은 `chat(..., json_schema=STRUCT_MAP_SCHEMA, point="struct_map")`.
3. **스키마 — strict(B44)**. 코드에 선언하고 회귀의 strict 검사에 들어간다:
   ```json
   {"type": "object",
    "properties": {
      "headings": {"type": "array",
                   "items": {"type": "object",
                             "properties": {"row": {"type": "integer"},
                                            "level": {"type": "integer"},
                                            "title": {"type": "string"}},
                             "required": ["row", "level", "title"],
                             "additionalProperties": false}},
      "note": {"type": ["string", "null"]}},
    "required": ["headings", "note"],
    "additionalProperties": false}
   ```
4. **변환은 팩토리 쪽(core)이 한다** — 파서는 LLM 스키마를 모른다. LLM 산출 `headings`를 파서가 소비하는 지도 형식 `{"doc_id", "source": "live", "rows": [{"row", "heading", "level"}]}`으로 바꾼다: 목록에 있는 행은 `heading=true·level=LLM값`, 나머지는 `heading=false·level=0`. **입력에 없는 `row`·`level<1`은 버리고 `meta.dropped`에 센다**(지어낸 행 방지 — 지시문 규약 4). `note`가 비어 있지 않으면 `meta.note`로 실어 하류가 「판정 불가」로 올릴 수 있게 한다(문서 6 §6.2).
5. `prompt_version`을 지도에 기록한다(`sm-1.0` — 재현 조건 B36과 동형).
6. `propose`의 실호출 갈래는 종전대로 **보존(`keep`)**한다(§6.3 — 매 인입 새로 산출되는 것은 보존).
7. **`_map_hook`의 `seen`에 `source`·`prompt_version`을 함께 흘린다** — 지금은 분할 레벨·분포만 봉투로 나가서, 어느 지도가 휴리스틱이고 어느 것이 실호출인지 **디스크에 남는 자리가 없다**(휴리스틱 지도는 보존하지 않으므로 — 허브 실물 확인 `pipeline.py:74-79`). 검수 뷰와 사내 재인입 판정이 그 값을 본다.

### 완료판정 ②
ⓐ `USE_MOCK=0` + 게이트웨이 미설정에서 `cli/parse.py`가 **`NotConfigured("⑦구조 지도 패스 — 실호출 경로가 비어 있다")`로 파싱 전에 멈춘다** — 지금은 이 상황에서 RuntimeError(ask 없음) 또는 조용한 휴리스틱이다 ⓑ mock 하네스로 `map_structure`의 변환을 시험: 가짜 `chat` 응답 `{"headings":[{"row":2,"level":1,"title":"…"}],"note":null}` → `rows` 형식 정확 · 없는 row 버림 · `meta.dropped` 계수 ⓒ strict 검사에 `STRUCT_MAP_SCHEMA` 포함 ⓓ 회귀 유지

## ③ mock 관문 — 운영 명령 (문서 7 §7.6-B-1 B48)

### 작업
1. **CLI 진입점 한 곳**에 관문 헬퍼(예: `cli/_gate.py::require_live_or_allow(argv)`): `llm.use_mock()`이 참이고 `--allow-mock`이 없으면 **실행 전에** 멈춘다. 문면: `mock 모드입니다 — 실산출이 아닙니다. 계속하려면 --allow-mock (실호출: llm.json의 "USE_MOCK": 0 또는 USE_MOCK=0)`. 종료 코드 ≠ 0.
2. **대상**: `register generate/review/confirm` · `parse run` · `ingest-file/ingest-dir` · `build` · `query`. **비대상**: `doctor` · `init` · `bootstrap` · `llm-check` · `skeleton-confirm` · 테스트.
3. 관문은 `mode_line()`(B42 ⑤) **바로 다음**에 선다 — 표시 후 멈춤. 지점마다 두지 않는다(판독처가 다시 여럿이 된다).
4. 회귀·doctor가 서브프로세스로 운영 명령을 부르는 자리는 `--allow-mock`을 명시한다. **바뀐 호출 자리 수를 보고한다.**

### 완료판정 ③
ⓐ 설정 없이 `python -m cli.register generate cp process` → 관문 문면 + 종료 코드 ≠ 0 · LLM 지점 호출 0회(로그로) ⓑ `--allow-mock` 붙이면 종전대로 진행 ⓒ `doctor`·`init`·`bootstrap`은 플래그 없이 종전대로 ⓓ 회귀 유지

## ④ 탐침과 doctor [3] — 도달 가능성 (문서 7 §7.6-B-2 B48)

### 작업
1. `tests/test_2a_gateway.py`의 9지점 탐침 — 파서 3지점(④·⑦·⑨)은 **팩토리를 통해** 잰다: `llm.image_summarizer()`·`llm.struct_mapper()`·`llm.coord_picker()`를 미설정 + `USE_MOCK=0`에서 호출해 **`NotConfigured`**를 기대한다. **지금의 `struct_map.propose("D1", …)` 직접 호출은 삭제한다** — 그것이 미배선을 초록으로 만든 자리다. core 6지점은 종전 방식 유지(다음 회차 대상).
2. **변이 시험 신설** — 「배선을 하나 빼면 붉는가」: 테스트 안에서 `cli/parse.py`의 주입 조립을 호출하되 `struct_mapper`를 None으로 바꿔치기한 상태로 실호출 모드 파싱을 돌리면, **파서가 휴리스틱으로 조용히 떨어지는 대신** 어서션이 「실호출 모드에서 파서 함수 부재」를 잡아야 한다. 잡는 자리는 **주입 조립 지점**(cli)이다 — `use_mock()`이 거짓이면 3종이 전부 non-None이어야 한다는 어서션을 조립 함수에 둔다(이 어서션이 곧 「진입점이 한 번 정하고 전부 내려보낸다」의 기계 판정이다).
3. **`doctor.py` [3] 재작성** — 문자열 존재(`needle in src and "USE_MOCK" in src`)로 세지 않는다(CLAUDE.md §3). ①이 끝나면 파서에 `USE_MOCK`이 0건이라 현행 규칙은 ④⑦⑨를 「분기 없음」으로 보고할 것이다. 새 규칙: **실행으로** — 미설정 + `USE_MOCK=0` 서브프로세스에서 9지점 각각이 `NotConfigured`에 닿는지. 파서 3지점은 팩토리 경유. 문면도 「분기가 서 있다」→「실호출 갈래가 호출자로부터 도달 가능하다」로.

### 완료판정 ④
ⓐ 탐침 9지점 초록 · ⑦은 팩토리 경유로 `NotConfigured` ⓑ **변이 시험**: `struct_mapper` 주입을 빼면 붉고 되돌리면 초록 — 실행 결과 두 줄을 보고에 그대로 ⓒ doctor [3]이 실행 기반으로 `9/9`를 내고, `doctor.py`에 `"USE_MOCK" in src` 류의 문자열 계수가 0건 ⓓ 회귀 유지

## ⑤ fixture를 운영 코드 밖으로 (문서 7 §7.1 대체 표 ⑦행 B48)

### 작업
1. `parser/struct_map.py`의 `MAPS_DIR` 조회(`tests/fixtures/struct_maps/{doc_id}.json`)를 **운영 코드에서 삭제**. `propose`의 대체 갈래는 **번호 패턴 휴리스틱 하나**다.
2. 고정 지도가 필요한 시험(MAPMOCK_OK·MAPMOCK_BROKEN 사용처)은 `ask=lambda d, l: json.load(...)`로 **테스트가 직접 주입**한다. fixture 파일은 그대로 둔다(A11 — 자리만 바뀐다).
3. `core/fixtures.py`의 `STRUCT_MAPS` 항목은 사용처가 남지 않으면 제거하고 표를 갱신한다 — 남으면 사유를 보고한다.

### 완료판정 ⑤
ⓐ `grep -n "struct_maps\|MAPS_DIR" parser/*.py` → 0 (KEEP_DIR 보존 자리는 별개 — 남는다) ⓑ MAPMOCK 시험이 주입 방식으로 초록 ⓒ 회귀 유지

## 순서

**① → ② → ⑤ → ④ → ③.** ①·②는 한 커밋이어야 한다 — ①만 들어가면 파일 설정 갈래가 환경변수 갈래와 같아지면서 산문 인입이 「ask 없음」으로 죽는다(②가 그 죽음을 고친다). ⑤는 ①이 `propose`를 손댄 직후가 싸다. ④는 ①②⑤가 끝나야 잴 대상이 있다. ③은 독립이나 회귀 호출 자리를 바꾸므로 마지막에.

- ③에서 `--allow-mock`을 붙인 호출 자리 수.
- 명세 개정 필요 목록(고치지 말고).
- **사내 이관 주의(보고에 그대로)**: 이 회차 이후 파일 설정만으로 `USE_MOCK: 0`을 준 사내 환경에서 **산문 문서의 구조 지도가 처음으로 LLM을 부른다.** 종전 산문 인입분은 **전부 휴리스틱 지도다**(실호출 경로가 존재하지 않았으므로 — 세어 볼 필요가 없다). 청크 경계가 바뀌므로 **산문 doc_type 전수가 재인입 대상**이고, 재인입은 문서 4 §4.8의 회수→재적재를 탄다.

# 결정 — 극성은 값의 한정어다 (노드를 가르지 않는다)

> **상태**: 결정 끝(사용자 확정 2026-11-11) · 구현은 B197 머지 뒤 두 회차(P1 코드 · 명세 → P2 가이드 · 팩 · 화면) · 허브가 B197 머지 판에서 전수 목록 · 기대 차이를 먼저 만든다
> **관련**: 명세 C5 · C10 · F1 · F2 · F3 · F11 · 결정 `결정_동의어_골격수준.md`(B196 「후보는 개념 노드만」) · 이연대장 §4 15(펼친 흐름)

---

## 1. 까닭

- CP 행이 극성마다 갈려 들어갔다 — 같은 관리항목이 공통 · anode · cathode 세 노드가 된다(사용자: 「세 갈래는 맞지 않다 · 극성은 맨 아래(값) 단에」).
- 지금 코드는 극성으로 노드를 가르고(골격 분기 `@split` · `::축값` → 하강 부착 `descend_anchor` → 이름 결합 F1) 갈라진 것을 짝(F3 · mirrors)으로 다시 잇는다. 갈라서 다시 잇는 기구 전체가 복제를 만든다.

## 2. 확정

| # | 결정 |
|---|---|
| 1 | **극성은 노드의 정체성이 아니다** — 이름 · 일치 판정 · 판정 기억 열쇠에서 극성을 뺀다. 같은 관리항목 · 원인 · 고장은 노드 하나다 |
| 2 | **골격의 극성 분기를 없앤다**(안 1) — `@split` · `::축값` 인스턴스 0 · 공정 노드는 극성 없이 하나. 라인이 다르다는 것은 설비 노드와 값 · 엣지의 한정어가 말한다(명세 F2 「전극 ~ 노칭은 극성 라인 병렬」은 이 결정으로 바뀐다) |
| 3 | **극성이 들어가는 자리는 셋이고 뜻은 하나 — 비면 공통** |
| 4 | **값**: 값의 한정어(`context` — 지금 `{model: …}`가 있는 자리)에 `polarity` · 값 충돌은 같은 한정어끼리만(anode 규격과 cathode 규격은 충돌이 아니다) |
| 5 | **엣지**: 필요할 때만 생기는 칸 하나 — 출처마다 극성(`{출처: 극성}` · 극성이 적힌 출처만) · 칸이 없으면 공통(극성 없는 엣지는 지금과 바이트 같다) |
| 6 | **보이는 극성의 규칙**(엣지 · 노드 같다): **모든 출처가 같은 한 극성을 말할 때만 그 극성 · 그 밖은 공통**(두 극성이 다 나오거나 극성 없이 말한 출처가 하나라도 있으면 공통) · 넣는 차례와 무관 · 출처가 빠지면(재인입 회수) 남은 출처로 다시 센다 |
| 7 | **노드**: 극성 칸은 계산된 표시다(6의 규칙 — 「anode에서만 나옴」) · 정체성이 아니다 |
| 8 | **극성은 시스템이 쓴다** — 행 · 청크의 구조 필드 `electrode_type`(C10)에서 옮겨 적는다 · LLM · 스키마가 쓰지 않는다(B7 그대로) · 값의 이름은 골격 `AXIS_LABELS`의 키(닫힌 목록 그대로) |
| 9 | **걷는 것**: 골격 분기 · 하강 부착 · 이름 결합(`polarity.bind_categories`) · mirrors(엣지 · `mirror_asymmetry` 큐 · config `mirrors` 키) · 극성 좌표 쌍 검사(`coord-ack --polarity`) |
| 10 | **질의**: 물음에 극성이 걸리면 값 · 엣지를 거른다 — 보이는 극성이 공통이거나 그 극성인 것만 · 공통 값은 「공통」을 달고 함께 낸다(특정 극성 값이 공통 값을 덮지 않는다) |
| 11 | **펼친 흐름**: 질의 때 상위 흐름 × 줄기 안 흐름을 코드가 펼쳐 넘긴다(저장 없음 · 이연대장 §4 15) — 극성 인스턴스가 없어지므로 흐름에서 빠지는 공정은 `@unordered` · `@noflow`뿐 |

## 3. 바뀌지 않는 것

- `electrode_type` 구조 필드 · 어댑터 · 파서의 극성 태깅 · 극성 값의 닫힌 목록.
- 같은지 판단(D) · 골격 단의 문(A′ · A″) · ref 아래 자동 — 후보가 극성으로 갈리지 않게 될 뿐이다.
- 추출(산문 LLM) — 극성은 추출이 쓰지 않으므로 체크포인트를 그대로 다시 쓴다.

## 4. 재구축 영향

- 그래프는 다시 짓는다(노드 이름 · 골격 파일이 바뀐다) · 골격 `skeleton.json`에서 `@split` · `::축값`을 지운다(사람 · 팩).
- 판정 LLM은 상당 부분 다시 든다(판정 기억 열쇠에 극성 · 골격 판).
- 사람 기록 중 극성 이름(`<공정>::<축값>` 꼴)을 가리키는 것은 재생 자리가 없다 — 회차 보고에 그 수 · 목록.
- 사내 순서: B197 → CP 전까지 다시 짓기 → 극성 → CP → PFMEA(극성 문서의 판정이 한 번으로 끝난다).

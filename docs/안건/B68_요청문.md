# B68 구현 요청문 — 분할이 **무엇을 기준으로** 잘랐는지 화면이 말한다 · 칸 2.5 · 1.6

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-15) · **작은 회차 — B67 앞에 한다**(화면 둘 · 새 규칙 0 · LLM 0) · **출처**: 사내 실측 여덟째 — 산문 xlsx를 고정 어댑터로 등록. 관문 통과, 청크도 잘 잘렸다. 다만 **「무엇을 기준으로 잘랐나」가 검수 뷰에 없고, generate 화면에는 분할 정보가 한 줄도 없다.** 사용자 요청: 검수 뷰에 기준을, generate에 기준과 크기 분포를 **간단히**.
> **지금 있는 것**: 검수 뷰 구획 1에 「분할 크기 분포」 표(B45 — 청크 · 행수 최소~최대(평균) · 목표 구간 · 짧음/긺)와 「레벨 선택」 표(프레임 · 지도 출처 · 지시문 판본 · 고른 레벨 · 근거)가 이미 있다. **없는 것**: ①고정 산문 어댑터 경로에서 「지도 출처」가 비고, 헤딩을 **어느 신호**(번호·굵게·들여쓰기·가로병합)로 잡았는지 어디에도 기록되지 않는다 — `_rows_of`가 신호를 판정하고 버린다 ②generate 화면에 분할 줄 0 — 분포는 `report["split"]`에 있는데 뷰만 읽는다.

## ① 분할 기준을 기록한다 — 시스템 계산 · LLM 0 (칸 2.5)

- `basic_prose_xlsx._rows_of`: 행마다 `signal`을 남긴다 — `번호` / `가로병합` / `굵게+들여쓰기` / 없음. 판정 규칙은 **그대로**(순서도 그대로) — 무엇으로 정했는지 적을 뿐이다.
- `level_report` 항목에 두 키를 더한다: `분할_기준`(문자열 — `"어댑터 신호: 번호 12 · 가로병합 2 · 굵게+들여쓰기 5"` 처럼 신호별 헤딩 수) · `지도_출처: "adapter:basic_prose_xlsx"`. 같은 자리(`struct_map.adapter_level_picks` · 지도 경로의 pick)도 `분할_기준`을 낸다 — 지도 경로는 `"구조 지도(LLM · 판본 <n>)"` 또는 `"구조 지도(heuristic)"`. **한 필드 이름, 두 경로** — 화면이 둘로 갈리지 않게.
- 청크 `meta`에는 이미 `split_path` · `split_level` · `section_path`가 있다 — 건드리지 않는다.

**완료판정 ①**: 어서션(성질) — `level_report` 항목마다 `분할_기준`·`지도_출처`가 있고 **신호별 헤딩 수의 합 == 그 프레임의 헤딩 수** · 지도 경로 pick에도 `분할_기준`이 있다 · 계산 경로에 LLM 0.

## ② 화면 둘 — generate 한 줄/프레임 · 검수 뷰 한 열 (칸 1.6)

**generate**(고정 어댑터 경로 · LLM 생성 경로 둘 다 — 관문 결과 줄 다음, prose일 때만):

```
   분할 — <시트명>  기준 어댑터 신호(번호 12 · 가로병합 2 · 굵게 5) · 레벨 2 (평균 18.3행 · 목표 5~40) · 청크 19 · 행수 4~37 · 짧음 1 · 긺 0
```

프레임(시트)마다 한 줄. 값은 전부 `report["split"]`과 `level_report`에서 읽는다 — **새 계산 0**. 구간 밖(`분할_레벨_구간밖`)이면 줄 끝에 `· 구간 밖 — 최근접 레벨`. `status`도 같은 줄을 낸다(관문을 다시 도니 같은 재료가 있다).

**검수 뷰**: 레벨 선택 표에 「분할 기준」 열 하나(지도 출처 옆). 청크 목록(구획 1 `section`)은 이미 잘린 헤딩 경로를 보이니 그대로.

**완료판정 ②**: 화면 diff(generate · status · 뷰). 어서션(성질) — generate 화면의 분할 줄 수 == prose 프레임 수 · 줄의 청크 수 == `split_stats` 청크수. 문면은 세지 않는다.

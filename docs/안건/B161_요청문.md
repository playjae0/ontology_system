## 목적

질의 벡터 저장 `work/vectors/vectors.sqlite`는 지금 **보관함만 있고 색인이 없다** — 표 `v`(판 · 글 해시 → 벡터)뿐이라 어느 벡터가 어느 노드 · 청크의 것인지 저장에 없다. 질의는 매번 그래프에서 **전 노드 · 전 청크의 글을 다시 조립하고 해시를 떠서** 메모리에서 짝을 맞춘다(`_split`). 이 회차는 그 짝(`id → 글 해시`)을 같은 저장에 적어 둔다.

- 글 해시를 열쇠로 쓰는 **내용 주소 방식은 그대로**다(무효화 자동 · 재구축 생존 · 같은 글 한 벡터 — 맞는 설계).
- 빠진 것은 색인 하나다 — 그것이 없어서 ①저장만 보고는 누구 벡터인지 모르고(디버깅 · 이관 불가) ②지문이 같아도 매 질의 전량 재조립 ③옛 글의 벡터를 지울 기준이 없다.
- **인계 경계가 된다**: 재료(무엇을 어떤 글로)는 시스템(사용자)이 정해 `idx.text`에 쓰고, 벡터 쪽은 그 글을 받아 임베딩 · 저장 · 검색 · 평가한다.

## 원칙 (사용자 확정)

- **벡터는 찾기 색인이고 진실은 별칭 사전이다** — `idx` · `meta`도 파생물(`work/`) · 지워도 다시 만든다 · 기본 fresh가 남기고 클린 `--all`이 지운다(지금 `v`와 같은 규칙).
- **해시는 저장 단계의 열쇠다** — 검색(유사도)에 쓰지 않는다. 정상 운영(벡터를 미리 만든 상태 · 그래프 그대로)에서 질의는 글마다 해시를 **계산하지 않고** 색인에서 읽는다.
- **재료는 시스템이 소유한다** — 재료 규칙(B153 — `node_texts` · `_chunk_text`)은 이 회차에서 바꾸지 않는다.

## ① 저장 — 같은 파일에 표 둘을 더한다 (칸 4.1 · 4.3)

`work/vectors/vectors.sqlite` 안(새 파일 0 · `v`는 그대로):

```
v     (backend, ver, kind, v)                                   ← 그대로 — 보관함(글 해시 → 벡터)
idx   (backend, kind, id, ver, layer, doc_id, text, len, cut)   ← 새로 — 색인(누가 어느 글 · 벡터를 쓰나)
      PRIMARY KEY (backend, kind, id)
meta  (backend, kind, src_fp, mat_ver, lim, at)                 ← 새로 — 색인이 무엇으로 만들어졌나
      PRIMARY KEY (backend, kind)
```

- `idx`: `id` = 노드 id · 청크 id · `ver` = `v`의 열쇠와 같은 글 해시(**자른 뒤의 글** — 지금 규칙) · `layer`(노드) · `doc_id`(청크) — 해당 없으면 NULL · `text` = 임베딩한 글(자른 뒤) · `len` = 한도 단위로 잰 **원래** 길이 · `cut` = 잘랐나(0/1).
- `meta`: 종류(nodes · chunks)마다 한 줄 — 이 색인이 어떤 입력으로 만들어졌나.
  - `src_fp` = **넘겨받은 내용의 지문** — 노드: 층 이름 순으로 그 그래프 객체의 노드 · 엣지 내용 · 청크: 청크 저장의 내용. **저장 파일이 아니라 메모리의 내용을 잰다**(전제 9 — 호출부가 메모리에서 바꾼 그래프를 넘기는 길이 있다 · 파일을 재면 그 변경을 놓친다). 그래프 쪽은 `GraphStore` 메서드 하나(`content_fp()` — 직렬화 규칙은 저장과 같은 함수 · 경계 그대로: graph.py 밖에서 노드 · 엣지 구조를 직렬화하지 않는다) · 청크 쪽은 `store`의 한 함수. 수(count)나 파일 판(`stamp`)이 아니라 **내용** — 별칭 하나만 바뀌어도 달라져야 한다.
  - `mat_ver` = 재료 규칙의 판 — `core/query/hybrid.py`에 상수 하나(`MATERIAL_VER`) · `node_texts` · `_chunk_text`의 규칙을 바꾸는 회차가 올린다(코드가 바뀌면 지문이 같아도 색인을 다시 쓴다).
  - `lim` = 입력 한도(`embeddings.limit()`의 수 · 단위) — 한도가 바뀌면 자른 글이 바뀐다.
- 쓰기 규율은 `v`와 같다 — sqlite 잠금 · 묶음마다 커밋 · `INSERT OR REPLACE`(idx · meta) · 프로세스 사이 동시 쓰기 안전 · 끊겨도 깨짐 0.
- **색인을 다시 쓸 때는 그 종류의 `idx` 행을 그 판에서 통째로 갈아 끼우고 `meta`를 마지막에 쓴다**(한 트랜잭션) — `meta`가 있으면 그 `idx`는 완전하다.

## ② 쓰는 길 — `warm` 하나 (칸 4.3)

`hybrid.warm`(질의의 벡터 준비 · 뷰어의 미리 만들기 · `run.py vectors` — 셋이 같은 함수 그대로):

1. 종류마다 지금 입력의 `(src_fp, mat_ver, lim)`을 잰다.
2. `meta`와 같으면 **색인을 그대로 쓴다** — 글 조립 0 · 글 해시 계산 0 · 임베딩 0(`idx`가 가리키는 `ver`가 `v`에 다 있는지만 본다 — 빠진 것이 있으면 그 글(`idx.text`)만 임베딩).
3. 다르면 지금처럼 글을 조립하고(재료 함수 그대로) 해시를 떠서 **`idx`를 갈아 끼우고** `meta`를 쓴다 · `v`에 없는 글만 임베딩(지금 규칙 그대로 — 묶음 · 이어 저장 · 진행 줄).
4. 계측: 지금의 만든 수 · 다시 쓴 수에 **「색인 — 그대로 / 다시 씀」** 한 조각을 더한다(`cost_line` · `vectors` 끝 줄 · 뷰어 콘솔 줄).

## ③ 읽는 길 — 질의 · `show near` · `show dist embed` (칸 4.1 · 4.3)

- **질의**(`link_candidates` · `doc_search`): 벡터는 **색인에서** 읽는다 — `idx JOIN v`로 `{id: 벡터}`(벡터 준비가 방금 색인을 맞췄다). 노드 글 · 청크 글을 다시 조립하지 않는다.
  - 링킹 후보의 화면 정보(canonical · 카테고리 · 층 · `where`)는 지금처럼 그래프에서 — **상위 k만** 필요하다. 전 노드의 글을 조립하는 길(`node_texts`)을 화면 정보 때문에 다시 타지 않는다(상위 k의 화면 정보를 내는 방법은 구현 판단 — 닻 계산이 전 그래프를 요구하면 그 한 번은 괜찮다 · 가결정 번호로 보고).
  - 문서 검색의 BM25 재료는 `idx.text`(청크 — 벡터와 같은 재료라는 B153 ① 규칙이 저절로 지켜진다) · 청크 본문 · 위치 정보는 지금처럼 청크 저장에서.
  - 질문 문장은 지금 그대로(해시 0 · 저장 0 · 매번 임베딩).
- **`show near`**(`near.pairs` → `V.lookup`): 색인에서 읽는다(쓰기 0 그대로 · 색인이 없거나 지문이 다르면 지금처럼 「`run.py vectors`를 먼저」).
- **`show dist embed`**: 색인이 지금 입력과 맞으면 `idx.len` · `cut`으로 분포를 낸다(다시 재지 않는다) · 맞지 않으면 지금처럼 재고 그 사실을 머리 줄에 한 조각.

## ④ 정리 — 참조 없는 벡터 (칸 0.3 · 4.3)

- **보이기**: `vectors` 끝 줄에 `참조 없는 벡터 n(이 판)` 한 조각 — `idx`의 어느 행도 가리키지 않는 `v` 행(옛 글의 벡터).
- **지우기는 명시할 때만**: `python run.py vectors --gc` — 먼저 색인을 지금 입력에 맞춘 뒤(②) 그 판의 참조 없는 `v` 행만 지운다 · 다른 판(backend)의 행은 건드리지 않는다 · 끝 줄 `정리 — 지운 벡터 n`.
- 자동 삭제 0(인입 · 질의 · 뷰어 · 재구축은 지우지 않는다) — 판이 돌아오면 다시 쓰는 지금 성질을 지킨다.

## ⑤ 옛 저장과의 호환 (칸 4.3)

- `idx` · `meta`가 없는 옛 `vectors.sqlite`(사내 지금 상태)는 처음 쓰는 길이 표를 세우고 ②의 3으로 색인을 채운다 — **`v`는 그대로 재사용**(사내 청크 벡터를 다시 만들지 않는다 · 만든 수 0이 정상).
- 옛 JSON 이관(`_migrate`)은 그대로.

## 완료판정 (창작 표본 · mock — 해시 벡터는 메커니즘만 · 수치는 근거가 아니다)

ⓐ **색인이 선다**: `run.py vectors` 뒤 `idx` 행 수 = 노드 수 + 청크 수 · 각 행의 `ver`가 `v`에 있다 · `text`가 재료 함수의 출력(자른 뒤)과 같다 · `meta` 두 줄.
ⓑ **같으면 조립 0**: 그래프 · 청크가 그대로일 때 두 번째 `vectors` · 질의에서 재료 함수(`node_texts` · `_chunk_text`) 호출 0(계측 · 대역으로) · 「색인 — 그대로」 · 질의 결과(링킹 후보 · 문서 검색)가 색인 전과 같다(같은 표본 · 같은 순위).
ⓒ **바뀐 것만**: 메모리 그래프에 별칭 하나 더해 넘기면(전제 9의 꼴) 색인 다시 씀 · 만든 벡터 1 · 청크는 그대로 — **B136 ⓐ 그대로 초록**.
ⓓ **재료 판 · 한도**: `MATERIAL_VER`를 바꾸거나 `embed_max_chars`를 바꾸면 색인을 다시 쓴다(지문이 같아도).
ⓔ **정리**: 별칭을 바꿔 저장 → `vectors` 끝 줄 「참조 없는 벡터 1」 → `--gc` 「지운 벡터 1」 → 다시 0 · 다른 판의 행은 남는다 · `--gc` 없이는 어느 길도 지우지 않는다.
ⓕ **옛 저장**: `idx` · `meta` 없는 옛 sqlite(지금 꼴)에서 `vectors` → 색인이 서고 만든 벡터 0(다 다시 씀).
ⓖ **읽기 전용**: `show near` · `show dist embed`가 색인에서 읽고 상태 지문 전후 같다(쓰기 0) · `dist embed` 넘은 수 = `vectors` 끝 줄 「넘어 자른 글」.
ⓗ **동시 쓰기**: B136 ⓔ(두 프로세스) 그대로 초록 — 색인 갈아 끼우기 중 다른 프로세스가 읽어도 반쯤 쓰인 색인을 보지 않는다(`meta`가 마지막).
ⓘ **경계**: graph.py 밖에서 그래프 노드 · 엣지를 직렬화하는 코드 0(정적 점검 한 줄) · 층 어휘 정적 점검 초록 · 네 벌 대조 초록(벡터는 파생물).
ⓙ **문서**: `11_벡터.md` 여덟 절 · 04 절 축소 · 전체 지도 11 행 · 명세 패치 5항목 **고치지 않고** `--apply` 통과 · 렌더 붙음 0(모양 점검 「붙음」 기준 그대로) · 경로 · 가이드 · 문면 점검 0 · 구조도 `11_벡터.md`의 서술이 명세 §7.8 · §7.2 · 문서 5 §5.4와 갈리지 않는다(갈리면 명세가 이긴다).

## ① 재구축 보존 — fresh 기본 보존 · 클린은 `--all` · 재구축 한 명령 (칸 0.3)

- **`init --fresh`(기본)는 비용이 든 산출을 남긴다** — 넷: `work/extract/`(산문 추출) · `work/struct_maps/`(구조 지도) · `work/ingest_log/`(판정 대장 = ② 재생 재료) · `data/coord_learned.json`(좌표 학습). 나머지 ③④⑤는 지금처럼 지운다(②등록·⓪원본·`golden/`은 원래 남는다). 화면: 남긴 것 · 지운 것 · 크기 한 줄씩 + 「전부 지우려면 `--all`」.
- **`init --fresh --all` = 클린**(회귀 바닥 — 지금의 정의 그대로) · `doctor`·회귀·시험의 클린 호출을 **전부** 이것으로(전제 2의 35개 — 남은 기본 호출 0을 grep으로 보고 · 클린 2회 동일 그래프 판정 불변).
- 남긴 산출의 재사용 판정은 지금 것 그대로(추출 = 문서 해시·어댑터·지시문·config 판 · 해시 없는 지도는 재사용 안 함 · 좌표 학습은 대상이 골격에 있을 때만).
- **재구축 한 명령**(이름은 구현 판단 — 예 `python run.py rebuild`): ①지우기 **전에** 문서 대장에서 문서 목록 · **처음 인입 순서** · 원본 경로 · doc_type · 사람 판단(`duplicate_ok` · 그림 뺌) · 개정 번호를 읽어 ④에 남긴다 ②`init --fresh`(보존) ③`bootstrap` ④문서마다 **같은 순서**로 인입(문서 좌표는 ②등록 `doc_coords.json`이 이미 갖는다 · 시트 역할도) ⑤`ops replay`(③) ⑥보고: 문서 수 · 판정 재생 n · 재판정 m(사유별) · LLM 호출(추출·판정·태깅) · 사람 판단 재생 k · 대상 없음 목록. 원본이 없는 문서는 건너뛰고 목록에. **비대화형은 계획만**(지금 `ops review` 규칙 — 실행은 `--yes`) · 계획은 「지울 것 · 남길 것 · 다시 넣을 문서 순서」.

## ② 판정 재생 — LLM 판정을 다시 부르지 않는다 (칸 3.4 · 한 자리)

- 인입의 값 판정 순서: 골격 · 사전 → **재생** → (지금의) 좁히기 + LLM. 재생 재료는 남긴 판정 대장(`work/ingest_log/<doc>.json`)이다.
- **키** = (문서 · 위치 `locator` · 열 `field` · 표기 · 부모 좌표(스코프 — 이름 규칙의 부모 canonical) · 층 · 카테고리). 대장에 키의 몫이 없으면 대장에 더한다(장부라 모양은 늘어도 된다).
- **결과**: `match` → 그 행이 붙었던 노드의 **canonical**이 지금 살아 있으면 그 노드로(LLM 0) · `new` → 지금처럼 새 노드(LLM 0 — 같은 canonical이 이미 있으면 사전 단에서 이미 붙었다) · `uncertain` → 지금처럼 불확실(새 노드 + 큐 — LLM 0) · 그 밖(골격 밖 · 보류)은 재생하지 않는다(코드가 다시 판정한다).
- **재생하지 않는 경우**(→ 지금처럼 LLM): 키가 대장에 없다 · 대상 canonical이 없다(골격 이름·부모가 바뀌었다 등) · `--no-replay`(문서 하나 또는 전부). 화면의 판정 끝 줄에 「재생 n · 재판정 m(키 없음 a · 대상 없음 b · 끔 c)」.
- 대장 경로에 닫힌 값 하나를 더한다(예 `replay` — 이름은 구현 판단 · `PATHS`). 재생으로 붙은 행도 대장에 다시 적혀 다음 재구축의 재료가 된다.
- 표·산문·렌즈 **한 자리**(판정 함수의 입구) — 갈래마다 따로 넣지 않는다.

## ③ 사람 판단 재생 — 이름으로 남기고 이름으로 되살린다 (칸 0.5 · I축)

- **기록의 자리를 ②등록으로**: `ops_log.json`을 `registry/`로 옮긴다(사람만 쓰는 기록이다 — `--actor` 필수 · 재생성 불가 · `coord_acks.json`과 같은 단) · 운영 루트의 옛 `data/ops_log.json`은 첫 실행에서 옮긴다(`migrate`의 결 · 두 벌 금지).
- **기록에 이름을**: 연산마다 대상 전부의 **층 · canonical**(merge는 없어지는 쪽과 남는 쪽 둘 다 · rename·transfer는 전후 · edge:delete는 양끝과 관계 · 사람이 닫은 큐 항목은 kind와 결정)을 적는다. id는 참고로 남는다.
- **`ops replay`**(`--dry-run` = 계획): 기록 순서대로 이름으로 대상을 찾아 지금 손(`ops.merge`·`confirm`·`alias`·`obsolete`·`rename`·`transfer`·`delete_edge` — 두 벌 0)으로 다시 한다 · **이미 그 상태면 건너뛴다**(멱등 — 두 번 돌려도 같다) · 재생은 기록을 늘리지 않는다(재생 보고는 ④) · `split`은 재생이 어렵다면 목록으로(구현 판단 · 보고).
- **대상 없음**: 이름이 지금 그래프에 없으면 그 연산은 하지 않고 「대상 없음」 목록(연산 · 대상 canonical · 행위자 · 시각 · 사유) — **기록은 지우지 않는다**(다음 재생에서 다시 시도). 구판 기록(이름 없음)은 「기록에 이름 없음」으로 따로 센다.
- 사람이 닫은 큐 항목(`resolution`)은 재생 뒤에도 같은 결정으로 닫혀 있다(재인입이 다시 실은 같은 항목 — 쌍 키는 문서 7 §7.5-4).

## ④ 문서 단위 일괄 확인 (칸 0.5 · I축)

- `ops confirm`에 문서 단위(예 `--doc <doc_id>` — 이름은 구현 판단): **그 문서 실행이 만든 `auto` 노드**(B101의 「같은 문서 실행이 만든 auto」와 같은 판정)를 한 번에 `confirmed` · 그 노드의 큐 항목에 지금처럼 `resolution`.
- 계획 먼저(수 · 위 몇 개 · 카테고리별 수) · **비대화형은 계획만**(실행은 `--yes`) · `--actor` 필수 · 기록은 노드마다 이름으로(③이 재생한다).
- 불확실(`uncertain_match`)은 넣지 않는다 — 그것은 고르는 일이라 `ops review`의 몫이다(다음 줄로 안내).

## ⑤ 문서 좌표를 상위로 — 상위 열이 없는 행의 대조 (칸 2.8 · B105의 한 함수)

- 행에 상위(`process_group`)가 **없고** 문서 좌표가 있으면, 문서 좌표를 상위로 삼아 **같은 판정 함수**(`parser.coord_pairs.verdict`)로 대조한다 — 하위가 문서 좌표 노드 자신이거나 그 아래면 맞음 · 밖이면 어긋남.
- 표기: 「문서 좌표 'X' ↛ 하위 'Y'」(행의 상위와 구별 — 큐 payload에 출처 표시) · 쌍 열쇠는 (X, Y)라 `ops coord-ack`도 같은 쌍 · 좌표 단계 쌍 표 = 구축 큐(같은 수).
- 행에 상위가 **있으면** 행의 상위로만 대조한다(문서 좌표 대조 안 함) · 하위를 바꾸지 않는다(붙는 자리는 그대로 — 보이기만) · 등록 관문 G4I는 그대로(등록 표본에는 문서 좌표가 없다).

ⓓ 재생 끄기 · 순서: `--no-replay` ⇒ 판정이 LLM으로(호출 > 0 · 대장 경로가 재생 아님) / 재구축이 넣는 순서 = 처음 인입 순서 / `ops replay` 두 번 = 한 번(멱등).
ⓔ 문서 단위 확인: 계획의 수 = 그 문서 실행이 만든 auto 노드 수 · 실행 뒤 전부 `confirmed` · 다른 문서의 auto는 그대로 · 비대화형은 계획만(쓰기 0) · 재구축 뒤에도 `confirmed`(③).
ⓕ 문서 좌표 상위: 상위 없는 행 + 문서 좌표 X + 하위 Y가 X 밖 ⇒ 쌍 표·큐에 「문서 좌표 'X' ↛ 하위 'Y'」 · 좌표 단계 수 = 구축 큐 수 / Y가 X 안이면 0 / 행에 상위가 있으면 그 상위로만 / `coord-ack` 같은 쌍.
ⓖ mock 네 벌: 첫 인입 산출이 바뀌는 것 전수 보고(재생은 대장이 없을 때 0 · ⑤는 문서 좌표 없는 표본에서 0).

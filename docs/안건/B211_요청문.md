## ① 표 판정 화면 — 판단이 있었던 행만 · 한 줄의 표 (전제 2)

```
   행    공정          고장모드            원인              관리항목            값                    판단
   ────  ────────────  ──────────────────  ────────────────  ──────────────────  ────────────────────  ──────────────────
   R4    노칭 ✓        전극 치수 불량 +새   금형 마모 +새      금형 클리어런스 +새   심각도 8 · 예방 …      관문 끝 3
   R5    노칭 ✓        전극 치수 불량 =     타발 속도 과다 +새  타발 속도 +새         심각도 8 · 예방 …      관문 끝 2
   R16   레이저노칭 ✗  — 사람 확인 전 공정 표기 → 행 보류(값 3)
   R31   탭용접 ✓      탭 들뜸 ?           가압력 부족 =      용접 가압력 =         심각도 8 · …           LLM 1
           └ 탭 들뜸 — 애매 0.55 · 후보 2(탭 접힘 · 탭 변형) · <까닭>
   [그룹 끝] 노칭 — 판단 있는 행 41 · 사전으로만 붙은 행 2,318(줄 없음) · LLM 6
```

- **머리 줄 + 열 정렬**(동아시아 폭 — 지금 `_screen` 함수 · 터미널 폭에서 자른다) · 그룹(공정 구간)마다 머리 한 번.
- **열** = 행 · 공정(좌표 결과 기호) · **스키마의 개체 열 차례 그대로**(열 이름은 스키마 필드 이름 — 열이 많으면 앞 n과 「열 n 더 — md」) · 값(attribute 열의 실제 값 — B208 그대로) · 판단(그 행에서 정한 방법: 관문 끝 n · LLM n · 사람 문).
- **칸** = 이름 + 결과 기호(`+새` · `=` 있는 노드에 붙음 · `?` 애매 · `✗` 보류 — 지금 결과 색 표 · 기호).
- **찍는 행**: 칸 하나라도 판단이 있었던 행(새로 · LLM · 애매 · 보류 — 사전 히트 · 앞 행에서 이미 정한 표기는 판단 아님) · **기본**: LLM · 애매 · 보류가 있는 행만 · **`-v`**: + 새로 있는 행 · 전부 사전인 행은 줄 0(그룹 끝 수).
- LLM · 애매 · 보류인 칸만 그 행 아래 `└`(확실도 · 후보 · 까닭 — 지금 칸 그대로) · 관계 줄 0.
- 머리 「원본 n행 → 나눈 m행」(B209 ②) 그대로.

## ② 한 셀의 짝 값 전개 — 공용 코어 (전제 3 · 4)

- `normalizer.split_multi`에 **짝 묶음**: `expects.multi_value_groups: [["<칸 A>", "<칸 B>", …]]` — 한 레코드에서 그 칸들을 같은 구분자로 나눠 **같은 차례로** 행 전개(짧은 쪽은 빈 값) · 위치 `#n` · 묶음 밖 칸은 복사.
- 이름은 그대로 `split_multi` 하나(새 이름 0 — 지시문 「이 셋뿐」) · 인자 하나 더(`groups=`) · 파이프라인이 `expects.multi_value_groups`를 같이 넘긴다.
- 어댑터는 자기 정리 함수(예: 한 셀에서 이름 목록 · 설명 목록을 얻는 함수)를 그대로 쓰고 **두 칸에 구분자로 이은 글**을 넣으면 된다 — 전개는 공용 코어.

## ③ 목록 값은 등록 관문에서 (전제 5)

- 하네스 ③ · ⑤ 산출 레코드에서 스키마 role이 entity · anchor · attribute인 칸의 값이 목록 · 튜플 · 딕셔너리면 **FAIL**(새 관문 번호 — 관문 표에 한 줄) · 문면: `'<칸>' 값이 목록 n행(예 <위치>) — 한 칸 복수값은 expects.multi_value_fields · 짝이면 multi_value_groups로 행 전개(직접 목록을 만들지 않는다)`.
- `context` · `meta`는 대상 밖.

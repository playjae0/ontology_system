# B53 구현 요청문 — PPT 판독 전면 · ④ 이미지 요약 = 바이트+맥락 · 슬라이드 렌더 · 기본 PDF 어댑터

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-09) · **전제**: `handover_b53.zip` 배치 (f13951a 위) — 문서 2·5·6·7 · 개정대장 §AJ(+[정정] 41) · 가이드 · 구조도 00/02.
> **한 줄**: `read_pptx`는 텍스트 프레임과 노트만 읽는다(12줄). 표·차트·그림·그룹·SmartArt를 읽고, 제목으로 구획을 세우고, shape까지 근거를 내리고, **④가 실제 이미지를 보게** 한다. PDF도 같은 의존(PyMuPDF)으로 같이 연다.
> **결함 하나를 먼저 인정하고 간다**: `core/llm.py:622 summarize_image`가 모델에 보내는 것은 `"이미지 참조: img_001"` **문자열**이다. 실호출을 켜면 모델이 요약을 지어낸다. 「9종 도달 가능」 어서션은 통과했다 — 도달과 내용은 다르다. 이번에 닫는다.

## 설계 원칙 (전부 명세에 있다 — 좌표)

- 파서는 층 어휘를 모른다(A1). 표·차트를 **텍스트로 푸는 것**은 형태 변환이지 의미 판정이 아니다 — 파서 몫. 무엇이 개체인지는 여전히 추출(①)이 정한다.
- 어댑터는 순수 함수(§6.4-2). LLM은 ④·⑦·⑨만, **주입**으로(B48). 이번에 ④의 **입력 형태**가 바뀔 뿐 배선 모양은 그대로다.
- 이미지 사본을 `data/`에 두지 않는다(문서 5 §5.2-2 — 원본 바이너리 비저장, `source_path` 참조). 요약은 `extract/struct_maps/{doc_id}.json`에 보존(§6.3 — 재인입 재사용, chunk_id 결정성).
- 조용히 다르게 돌지 않는다: 렌더가 없으면 `meta.slide_render="none"`, 게이트웨이가 이미지를 못 받으면 `NotConfigured`.

## a. 결정적 판독 — LLM 0

### a-1 `parser/reader.py::read_pptx` — 원시 추출 확장

슬라이드마다 `shapes`를 **문자열 배열이 아니라 shape 레코드 배열**로 낸다(구형 문자열 배열을 쓰는 곳은 `basic_ppt` 하나 — 함께 고친다):

```json
{"index": 8, "hidden": false, "title": "노칭 설비 구성",
 "shapes": [
   {"id": "S8-T1",  "kind": "title",   "text": "노칭 설비 구성", "top": 0.4, "left": 0.5},
   {"id": "S8-B1",  "kind": "text",    "text": "…"},
   {"id": "S8-TB1", "kind": "table",   "text": "헤더A | 헤더B\n값1 | 값2\n…", "rows": 5, "cols": 2},
   {"id": "S8-CH1", "kind": "chart",   "text": "[차트: 월별 불량률] 종류 line · X 월 · Y %\n1월: A 0.8 · B 1.1\n…", "chart_type": "line"},
   {"id": "S8-P1",  "kind": "picture", "image_ref": "S8-P1", "mime": "image/png", "bytes_len": 48213},
   {"id": "S8-SA1", "kind": "smartart","text": "…"}
 ],
 "notes": "…"}
```

| Kind | How | Note |
|---|---|---|
| `title`/`subtitle`/`text` | 플레이스홀더 타입(`PP_PLACEHOLDER.TITLE`·`CENTER_TITLE`·`SUBTITLE`)으로 구분, 나머지 텍스트 프레임은 `text` | `slide["title"]`에 첫 title 텍스트 |
| `table` | `shape.has_table` → 셀 텍스트를 행 단위 ` \| ` 이음, 병합 셀은 `normalizer` 규약대로 전개하지 않고 **원문 위치 그대로**(빈 칸은 빈 문자열) | 행 수·열 수 기록 |
| `chart` | `shape.has_chart` → `chart.chart_type` · `chart.has_title`이면 제목 · 축 제목(`category_axis`/`value_axis` `has_title`) · `plots[].categories` · `series[].name`/`.values` — 값은 있는 그대로(반올림 금지) | 값이 없는 차트(외부 링크)는 `text`에 `[차트: 제목 — 값 없음]` |
| `picture` | `shape.shape_type == PICTURE` (플레이스홀더 안 그림 포함) → `shape.image.blob`·`content_type`. **바이트는 raw dict에 싣되 계약 JSON에는 안 나간다** — `image_ref`만 | 리더 결과에 `raw["_images"][ref] = (bytes, mime)` |
| `group` | `GROUP` → `shape.shapes` 재귀. 자식 id는 `S8-G1-…` | 깊이 제한 없음 |
| `smartart` | `graphicFrame`의 diagram — `python-pptx`가 안 열므로 슬라이드 part의 rels에서 `diagramData` 파트를 열어 `<a:t>` 텍스트를 순서대로 | 실패면 `kind=smartart, text=""` + `meta.unresolved_reasons` |
| 순서 | shapes를 `(top, left)`로 정렬 — **시각 순서**. 그룹은 그룹 위치 기준, 안에서는 다시 정렬 | |
| 숨김 | `slide._element.get("show") == "0"` → `hidden: true` — 어댑터가 건너뛴다 | |

### a-2 `parser/adapters/basic_ppt.py` — 청크 규칙

- `section` = 슬라이드 제목(없으면 「슬라이드 N」). `meta.section_path` = **덱 제목 › 구획 › 슬라이드 제목**. 구획은 ①레이아웃 이름에 `Section`/`구획`이 들어간 슬라이드 ②제목만 있고 본문이 비어 있는 슬라이드 ③목차 슬라이드(제목에 `목차`/`Agenda`/`Contents`)의 항목 — 셋 다 결정적. 판정 안 되면 경로는 덱 제목 › 슬라이드 제목 두 단.
- 임계 이하 슬라이드 = 청크 1개(지금과 같음). 본문에 표·차트가 있으면 **표·차트는 각각 별도 청크**로 낸다(`shape_kind`가 그 값) — 표 하나가 3천 자를 넘는 것이 흔하고, 슬라이드 본문에 섞이면 근거 좌표가 뭉개진다. 그림은 placeholder 조각(`{source_locator, image_ref, section, context}`). `context` = 같은 슬라이드의 제목·본문·표·차트 텍스트(앞 1,500자).
- `source_locator`: 슬라이드 청크 `PPT01-S8` · shape 청크 `PPT01-S8-TB1`·`-CH1`·`-P1`. `meta.shape_kind`·`meta.shape_id`. 기존 `frame_format`은 유지(구형 `-F2`는 shape 분할 경로의 텍스트 shape에 그대로).
- 숨김 슬라이드 제외. 노트는 `meta.notes` 그대로.
- **기존 fixture 산출과의 관계**: 텍스트만 있는 슬라이드의 청크 텍스트·`source_locator`는 **바이트 동일해야 한다**(회귀 유지). 바뀌는 것은 새 shape 종류의 추가와 `section`(제목이 있는 슬라이드)뿐 — `section`이 바뀌면 chunk_id가 바뀐다는 것을 어서션이 **의도된 변화로** 기록한다.

## b. ④ 이미지 요약 = 바이트 + 맥락

### b-1 `core/llm.py`

- `chat()`이 **멀티모달 메시지**를 받는다: `content`가 문자열이면 지금처럼, 리스트면 OpenAI 호환 형태(`[{"type":"text","text":…},{"type":"image_url","image_url":{"url":"data:<mime>;base64,…"}}]`) 그대로 전송. 다른 자리는 변화 0.
- `summarize_image(image_ref, *, image: bytes, mime: str, context: str, page: bytes|None = None)` — `prompts/image_summary.md`(판 i-2.0: 「이 그림이 슬라이드 맥락에서 무엇을 보여주는가 — 축·수치·화살표·표기를 있는 그대로, 맥락에 없는 것은 지어내지 않는다」)를 system으로, user에 `[맥락]` 텍스트 + 그림(+ `page`가 있으면 슬라이드 전체 그림을 「전체 화면」으로 두 번째 이미지). 응답 텍스트.
- 게이트웨이가 이미지 content를 거부(400)하면 **`NotConfigured("image_summary: 게이트웨이가 이미지 입력을 받지 않는다")`** — `require()` 체계와 같은 명시적 실패. `llm-check`에 ⑥「이미지 입력」 단계를 더한다(1×1 PNG 1회 왕복).
- `image_summarizer()`는 그대로(mock이면 None).

### b-2 `parser/tagger.py::complete_images`

- `summarize(ref, image=…, mime=…, context=…, page=…)`로 부른다. 바이트는 `pieces`가 아니라 **리더 raw의 `_images`**에서 — `pipeline.parse`가 raw를 들고 있으므로 `complete_images(pieces, summarize, kept=, images=raw["_images"], pages=…)`.
- mock 문자열은 그대로 `MOCK 요약: {image_ref}` — 단 `meta.image_bytes_len`을 남겨 「바이트가 실제로 도달했다」를 mock에서도 어서션으로 잰다.
- 보존(`kept`) 규칙 그대로 — 요약 텍스트가 chunk_id 성분이므로 재인입 재사용.

### b-3 슬라이드 전체 렌더 (있으면)

- `parser/render.py` 신설: `render_pages(path) -> {page_no: png_bytes} | None`. 순서: ①같은 폴더 같은 stem의 `.pdf`가 있고 mtime이 원본보다 뒤면 그것 ②`shutil.which("soffice")`가 있으면 `soffice --headless --convert-to pdf --outdir <tmp>` ③둘 다 없으면 `None`. PDF → PNG는 **PyMuPDF**(`fitz`, 지연 import, 없으면 `None`). 해상도 상한(긴 변 1600px)·상한 초과 파일은 축소.
- 결과는 청크 `meta.slide_render = "page" | "none"`으로 남긴다. ④ 호출에 `page=` 전달. **렌더 바이트는 어디에도 저장하지 않는다** — 요약만 보존.
- PPTX→PDF 변환 실패는 문서 실패가 아니다 — `none`으로 계속 + 결함 로그 1줄.

**완료판정 b**: ⓐ mock: 픽스처 그림 청크에 `image_summary_source=mock`·`image_bytes_len>0`(어서션 — 바이트가 tagger까지 왔다) ⓑ `chat()` 멀티모달 페이로드 형태 어서션(전송 직전 dict를 잡아 `image_url` 항목이 base64 data URI인지) ⓒ 실호출 없이 판정 불가한 것은 **표시** — 「④ 실호출 품질은 사내 첫 실행에서 사람이 본다」를 §7.5 「실호출로만 검증되는 항목」 목록에 어서션 이름으로 등재 ⓓ `soffice` 없는 환경에서 `slide_render=none`이고 문서가 완주한다(어서션) ⓔ `llm-check` ⑥ 단계 문면 ⓕ `NotConfigured` 문면(게이트웨이 400을 흉내 낸 시험).

## c. 기본 PDF 어댑터

- `parser/reader.py::read_pdf` — PyMuPDF: 페이지마다 `{"index": n, "text": page.get_text("text"), "images": [{ref, mime, bytes_len}], "outline": …}` + `_images` + 목차(`doc.get_toc()`) → `{"format": "pdf", "pages": [...], "toc": [...]}`. 받는 확장자에 `.pdf` 추가. PyMuPDF 부재는 지연 import 실패 → `parse_failure` 사유에 「PyMuPDF 없음」.
- `parser/adapters/basic_pdf.py` — 페이지 = prose 청크(`shape_kind=page`), `source_locator` `PDF01-P12`, `section` = toc가 있으면 그 페이지를 덮는 가장 깊은 항목(경로 ` > ` 이음), 없으면 「페이지 N」. 그림은 placeholder(페이지 텍스트가 context). **페이지 렌더를 항상 ④ 맥락으로**(`page=`) — PDF는 `render_pages`가 원본 그대로라 변환이 없다. 텍스트가 0자인 페이지(스캔본)는 그림 placeholder 하나로 낸다.
- `register generate --use-basic`이 `.pdf` 전부일 때도 뜨게(`basic_adapter_proposal`) — PPT와 같은 위임 래퍼 방식(D-111).
- `cli/scan.py` 지문: PDF는 지문 대상 아님(구조 없음) — `--doc-type` 지정 또는 basic 등록분이 유일하면 자동.

**완료판정 c**: ⓐ 픽스처 PDF를 **PyMuPDF로 생성**(3페이지·목차 2항목·그림 1) → `parse run` 결과 페이지 청크 3 + placeholder 1 ⓑ `section`이 toc에서 온다 ⓒ `--use-basic` 등록 → 검수 → 확정 → `ingest-file` 완주(mock) ⓓ 회귀 유지.

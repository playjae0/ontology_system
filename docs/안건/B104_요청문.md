## ① 공유 별칭의 범위 안 해소 (칸 2.8 — 파서 · 한 함수)

- 표기가 **전역에서는 골격 노드 여럿**이 나눠 갖지만 **문서 좌표 범위 안에서는 하나**로 정해지면, 조각 좌표를 **그 노드의 canonical**로 바꿔 쓴다(`meta`에 원 표기 — 태깅 채택과 같은 길). 시트명·제목 대조(`coord_from_section`)와 좌표 태깅(`tag`)이 같은 함수 · 그 밖의 맞음은 지금 그대로(표기 유지 — 네 벌 영향 0).
- 보류 문면은 실제 사유를 말한다 — 표기 모호면 「표기 모호(골격 노드 여럿)」 · 목록 밖이면 지금 문면.

## ② 질의 링킹 — 임베딩 후보 + LLM 선별 (칸 4.x)

- **후보**: 질문 문장 임베딩 ↔ 노드 임베딩(canonical · 별칭 · 정의 · **닻까지의 길** — 「어디의 무엇」) 상위 k(손잡이 `query_link_top_k` · 기본은 가결정 — 창작 기본값). 노드 벡터는 ③의 캐시와 같은 자리.
- **선별**: LLM이 **후보 안에서만** 고른다 — 노드마다 이유 한 줄 · 없으면 빈 목록 · 후보 밖 id는 버린다. 지금의 「노드 전부를 후보로」 폴백을 이것으로 바꾼다(지시문 `4.1_link` 판을 올린다).
- **단계**: 사전 스캔 → 임베딩 후보 + LLM 선별. 손잡이 `query_link_mode` — `보충`(기본 · 사용자 결정: 사전이 잡은 노드가 있어도 질문이 가리키는 노드를 더 찾는다 · 사전 노드는 그대로 두고 선별은 추가만) | `폴백`(사전 미스일 때만 — 지금의 규칙). **링킹 미스율(계기판 5)은 사전 단 기준으로 계속 센다**(정의 불변 · trace에 단계가 있으니 따로 셀 수 있다).
- trace `linking[]`: 노드마다 `method`(`dict` · `embed+llm`) · 임베딩 점수 · 선별 이유. 확장·수집은 지금 그대로(코드).
- mock: 임베딩은 지금의 해시 벡터 · 선별은 결정적 규칙(시험 주입) — 실호출 갈래는 가짜 게이트웨이로 잰다.

## ③ 문서 검색 채널 (칸 4.x)

- 질문 임베딩 ↔ **청크 임베딩** 상위 k + BM25 상위 k(합쳐 중복 제거 · 손잡이 `query_doc_top_k`) → **[문서 검색]** 묶음 — 그래프 채널(링킹·확장 노드의 근거 청크)과 **따로** 답변에 넘긴다. 링킹이 빗나가도 이 채널은 돈다(「근거 없음」은 두 채널이 다 비었을 때만).
- **청크 벡터 캐시**: ④단계 `work/`(재생성 가능 — 청크 id · 판 · 벡터 · 노드 벡터도 같은 자리) · 처음 필요할 때 만들고 청크·노드가 바뀐 몫만 다시 · 만든 수·시간·백엔드를 화면 한 줄(`embeddings.cost_line` 결) · `init --fresh`가 지운다(파생물).
- ref 시트 청크도 포함하고 표시한다(「찾아볼 시트」).

## ④ 답 — 짧게 · 쓴 근거를 고른다 · 링크 결과와 나란히 (칸 4.x · 5.3)

- 답변 지시문(`4.4_answer` 판을 올린다): **짧게(기본 5줄 이내)** · 그래프 사실을 먼저 · 근거 번호 인용 · 근거 밖은 모른다 · 반환에 `used_facts` + **`used_chunks`**(노드 근거 · 문서 검색에서 쓴 것).
- **CLI(`query`)와 뷰어 질의 패널이 같은 묶음을 나란히**: ⓐ 링킹(노드 · 어디의 무엇 · 단계 · 점수 · 선별 이유) ⓑ 확장 경로(엣지 — 홉) ⓒ 그래프 사실(쓴 것 표시) ⓓ 노드 근거 청크 ⓔ 문서 검색 청크(점수 · 쓴 것 표시) ⓕ **LLM 답**. 뷰어는 지금의 경로 오버레이에 LLM이 고른 노드를 다른 표시로 · 청크를 누르면 원문.
- `--json`(trace)에 위 전부 · 화면은 trace의 투영.

## ⑤ 채점 — 새 하네스 없이 골든셋 축으로 (칸 4.x)

- `golden` 채점에 축 둘: 링킹(사전만 vs 보충 — 맞은 노드 비율) · 문서 검색 recall@k — **BM25 대조군과 나란히**. 별도 하네스를 만들지 않는다. 가이드에 「사내 질문 10~20개로 골든셋을 만들어 전후를 본다」.

## ⑥ 가이드·구조도 (같은 커밋)

- `2B_작업가이드` 질의·뷰어 절(링크 결과 읽는 법 · 두 채널 · 손잡이 셋) · 구조도 `04`(링킹 단 · 문서 채널 · 답 · 채점) · `06`(손잡이) · `00` · `10`(생성).

ⓐ 공유 별칭: 문서 좌표 범위 안에서 하나인 공유 별칭 시트의 조각 좌표가 그 노드 canonical(원 표기 `meta`) · 구축 보류 0 · 그 시트의 개체가 그 노드 아래 · 범위 안에서도 여럿이면 지금처럼 건너뜀 · 문면 「표기 모호」 ⓑ 링킹: 사전에 없는 표현(동의 표현)의 질문이 임베딩 후보 + 선별로 노드에 닿는다(가짜 게이트웨이) · 후보 밖 id 0 · 보충 모드에서 사전 노드 유지 + 추가 · 폴백 모드는 지금과 같다 · 미스율은 사전 단 기준 · LLM 후보 수 ≤ k(노드 전부를 보내지 않는다) ⓒ 문서 채널: 링킹 0인 질문에 문서 검색 청크로 답(「근거 없음」 아님) · 캐시 재사용(두 번째 질의에 벡터 재계산 0) · 청크 추가 시 그 몫만 ⓓ 답: 5줄 이내 · `used_facts`·`used_chunks` · CLI·뷰어에 ⓐ~ⓕ가 나란히 · `--json`과 화면이 같은 수 ⓔ 채점 두 축이 BM25 대조군 옆에 ⓕ 쓰기 0(질의는 읽기 전용 — 캐시는 `work/`) · mock 네 벌 diff 0(구축 경로는 ①만 — 공유 별칭 표본이 mock에 없으면 0).

# B76 구현 요청문 — LLM 산출의 **모양**을 관문이 잠근다(G4F 형 검사) · 열 판정 대장은 스키마 필드 전부를 덮는다 · 등록 흐름의 예외는 문면으로 죽는다 · 스켈레톤·공용 코어는 `None`에 죽지 않는다 · 칸 1.5 · 1.4 · 0.3 · 2.3

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-16 · 사용자 확정 2026-09-16) · **B75 뒤(`8be335c`)** · **출처**: 사내 실측 열다섯째 — `generate <dt> <층> <표본> --revise`(B72 템플릿 v1.6으로 재생성)가 **기계 관문 PASS · 뷰 확인 통과 · 파싱 OK** 뒤에 `TypeError: unhashable type: 'list'`로 죽었다. 마지막 프레임 `cli/register.py:2177 role_table — s = sug.get(col) if col else None`.
> **원인(확정)**: `col = _led_cols.get(field) or ADAPTER["expects"]["columns"][field]` — 열 판정 대장에 그 필드의 행이 **없어서** 어댑터 `columns`로 떨어졌고, 재생성된 어댑터가 그 필드를 **합치기 리스트**(`["D","E"]`)로 냈다. 리스트를 dict 키로 넣었다. 바로 위 주석이 「합치기면 리스트라 열 하나를 가리키지 못한다」라고 적어 놓은 자리다.
> **진단 — 이것은 한 줄의 결함이 아니다**: ⓐ LLM 산출(스키마·어댑터)은 모양이 흔들리는 것이 정상인데, 관문 G4A~G4E는 **키의 존재·어휘**만 재고 **값의 형**은 재지 않는다 — 리스트가 와도 되는 자리와 안 되는 자리가 코드에만 암묵으로 있다. 그래서 관문 PASS 뒤의 코드가 형을 가정하다 죽는다. ⓑ 열 판정 대장(B67)은 열 프로파일(`input_package.json::reader_head.열_프로파일`)에 있는 열로만 세워져, 스키마 `fields`에 있어도 대장에 행이 없는 필드가 생긴다 — 그 필드는 `role_table`의 기계 제안 대조·B67의 「이어가기」에서 빠진다. ⓒ 등록 흐름(`generate`·`review`·`confirm`)은 미포착 예외를 traceback으로 낸다 — 사람이 스크롤을 올려 프레임을 읽어야 했다(M9 「실패는 문면이 답을 담는다」 위반). 사용자: 「이 문서 말고 다른 문서에서도 잡혀야 한다」 — 그래서 고치는 자리는 2177행이 아니라 관문·대장·예외 경계 셋이다.
> **사내 실측 열여섯째(같은 날 · ④의 출처)**: 임시 패치 뒤 `--revise`를 다시 돌린 새 초안이 **기계 관문 G31에서 `TypeError: argument of type 'NoneType' is not iterable`**(G52 연쇄). 허브 재현: 스켈레톤 `kit/어댑터_스켈레톤.py:126`이 `expects`에 `ditto_mark`가 없으면 `marks=None`을 넘기고, 공용 코어 `parser/normalizer.py:68`의 기본값 `marks=DITTO`는 인자를 **안 줄 때만** 살아 79행 `v.strip() in None`으로 죽는다 — **문자열 셀 하나만 있어도** 터진다. 참조 어댑터 셋은 전부 `"ditto_mark": "〃"`라 한 번도 드러나지 않았고, 스켈레톤을 그대로 채운 어댑터는 회귀 대상이 아니었다. 사내 임시: `expects`에 `"ditto_mark": "〃"` 한 줄.
> **사내 임시 패치(사용자 적용 중)**: 2177행을 `_cs = col if isinstance(col, (list, tuple)) else [col]` / `s = next((sug.get(c) for c in _cs if sug.get(c)), None) if col else None`로. 이 회차의 ①이 같은 자리를 정식으로 덮는다.

## ① 형 검사 관문 G4F — LLM 산출의 키마다 허용 형을 닫힌 표로 (칸 1.5)

- 표 하나(`kit/run_adapter.py` 상수 · 06 대장 1.5 행)가 정본이다 — **스키마**: `fields.<f>.role` ∈ 5값 · `category`·`attach_to_field`·`attr_name`·`정의문` str · `edges[]` 각 원소의 `from`·`rel`·`to` str · `unmappable[].field` str · `unmappable[].kind` ∈ {excluded, undecided} · `unmappable[].reason` str. **어댑터 `ADAPTER`**: `doc_type`·`payload_kind`·`adapter_version` str · `expects.columns` 값은 **str 또는 str 리스트**(합치기 — 허용) · `expects.header_labels` str 리스트 · `expects.header_row` int · `sample_path` str. 표에 없는 키는 WARN(모양이 늘었다 — 보고), 표에 있는 키의 형이 다르면 **FAIL** 문면 `G4F  <키> — 받은 형 <type> · 허용 <형> · 값 <앞 60자>`.
- 관문은 **생성 직후 · 검수 뷰 앞**(G4A~E와 같은 자리)에서 돈다 — 형이 틀린 산출은 사람에게 올라가지 않는다.
- **리스트가 허용된 자리는 소비하는 코드가 리스트를 받는다**: `role_table`의 열문자 대조(2177)는 합치기 리스트의 열 중 기계 제안이 있는 첫 열로 대조(임시 패치와 같은 뜻) · 대조표 5의 다섯 자리는 str 아니면 관문에서 이미 막혔으므로 그대로 두되 **assert가 아니라 관문이 막는다**는 사실을 주석에 적는다.

**완료판정 ①**: 어서션(성질) — `unmappable[].field`를 리스트로 바꾼 스키마 변이 → G4F FAIL이고 문면에 키·형 · `columns` 값을 리스트로 낸 어댑터 → PASS(허용) · `columns` 값에 int → FAIL · 내장 참조 자산(cp·pfmea·ipqc) 전부 PASS · 합치기 리스트 필드로 `role_table`이 죽지 않고 기계 제안 대조가 된다.

## ② 열 판정 대장은 스키마 `fields` 전부를 덮는다 (칸 1.4)

- `sync_ledger`가 대장을 세울 때 **프로파일 열 + 어댑터 `columns`가 가리키는 열 전부**를 합집합으로 돈다 — 프로파일에 없는 열(리허설 `--rows` 밖·머리 읽기 밖)도 어댑터가 쓰면 대장 행이 생긴다(`label`은 실물 헤더에서 · 없으면 null). 합치기 리스트는 열마다 행 하나(같은 `field`).
- **커버리지 어서션을 관문에 건다**: 스키마 `fields`의 필드마다 대장 행이 ≥1 — 없으면 FAIL 문면 `G4G  대장에 없는 필드 <f> — 어댑터 columns <…> · 프로파일 밖`(사람이 판정한 것이 아니라 기계가 빠뜨린 것이라 질문이 아니다).
- `role_table`의 열문자는 이제 **대장에서만** 읽는다 — 어댑터 `columns` 폴백을 없앤다(폴백이 있으면 대장이 빈 필드가 조용히 통과한다 — 이번 사고의 둘째 원인).

**완료판정 ②**: 어서션(성질) — 프로파일 밖 열을 쓰는 어댑터로 대장을 세우면 그 필드 행이 있다 · 스키마 필드 전부에 대장 행 ≥1(내장 셋 · 픽스처 전부) · 대장 행이 없는 필드를 심으면 G4G FAIL · `role_table`이 어댑터 `columns`를 읽지 않는다(`grep` 0).

## ③ 등록 흐름의 미포착 예외는 문면으로 죽는다 (칸 0.3)

- `cli/register.py::main`(진입점 한 곳)에 예외 경계 — traceback 대신 **한 줄** `[결함] <파일>:<줄> · <예외명>: <메시지 앞 120자> · 단계 <generate|review|confirm|…> · doc_type <dt>` + `defects.log`(`store.append_defect`)에 **전체 traceback**. 종료 코드는 상태 거부(B61 계약)와 같다. `ONTO_TRACEBACK=1`이면 지금처럼 전체 traceback을 화면에도(개발용).
- 이 경계는 **파이썬 예외**만 잡는다 — 관문 FAIL·상태 거부(`SystemExit`)는 지금 문면 그대로 지난다(그것은 결함이 아니라 판정이다).
- 같은 경계를 `cli/ingest.py`의 문서 단위 except(B75 ③ ⓐ)에도 맞춘다 — 거기는 이미 한 줄이지만 **파일:줄**이 없다 · `defects.log`에 traceback을 남긴다.

**완료판정 ③**: 어서션(성질) — 등록 흐름 안에서 예외를 심으면 화면에 `[결함] 파일:줄` 한 줄이 있고 traceback은 `defects.log`에 있다 · 관문 FAIL·상태 거부는 이전과 같은 문면 · `ONTO_TRACEBACK=1`이면 화면에도 traceback · 상태 거부 스캐너 수 불변.

## ④ 스켈레톤·공용 코어는 `None`에 죽지 않는다 · G31은 줄을 말한다 · 셀은 헬퍼로만 (칸 2.3 · 1.4 · 1.5)

- ⓐ **공용 코어 방어**: `normalizer.resolve_ditto`가 `marks=None`을 「상동 없음」으로 받는다(`marks = set(marks or ())` — 빈 집합이면 치환 0). 호출자의 `None`에 공용 코어가 죽으면 그 위의 어댑터 전부가 죽는다.
- ⓑ **스켈레톤 126행**: `marks={exp["ditto_mark"]} if exp.get("ditto_mark") else set()`. 템플릿 규약 10 옆에 「`ditto_mark`는 문서에 상동 기호가 있을 때만 적는다 — 없으면 키를 빼라(빼도 돈다)」.
- ⓒ **스켈레톤 최소 어댑터를 회귀 픽스처로**: 스켈레톤을 그대로 채운 어댑터(`ditto_mark` 없음 · `columns` 2개 · 상동·병합 없는 표본)가 관문 전체(G31·G52 포함)를 지나는 것을 상시 회귀에 건다 — 지금은 스켈레톤이 호출부 **문자열**로만 회귀에 들어 있어(`tests/test_p3.py:363`) 실행되지 않았다. `ditto_mark`를 뺀 변이 = 이번 사내 사고의 재현.
- ⓓ **G31 문면**: 예외명·메시지에 더해 **어댑터 파일 안의 마지막 프레임 `파일:줄` + 그 줄 소스**(traceback을 어댑터 파일로 거른다 · 공용 코어에서 죽었으면 어댑터의 호출 줄과 코어의 줄을 둘 다). 지금은 `TypeError: …`만 나와 사람이 원인을 짚을 수 없었다(M9).
- ⓔ **셀 접근 규약**: 템플릿에 한 줄 「셀 값은 스켈레톤의 읽기 헬퍼(`cells.get` → `""` 정규화)로만 읽는다 — 어댑터 코드가 셀에 직접 `in`·`startswith`·`strip`을 걸지 않는다」 + 관문 변이: 표본 셀 하나를 `None`으로 바꿔 extract가 살아남는지(표본에 빈 셀이 없으면 G31이 못 잡는다).

**완료판정 ④**: 어서션(성질) — `resolve_ditto(..., marks=None)`이 치환 0으로 돈다 · `ditto_mark` 없는 스켈레톤 어댑터가 관문 전체 PASS · 그 변이가 회귀에 상시 · G31 FAIL 문면에 어댑터 `파일:줄`이 있다(예외를 심어 잰다) · 셀 `None` 변이에서 참조 어댑터 셋 + 스켈레톤 어댑터 PASS · 템플릿 `version` 갱신.

## 넣지 않는 것
- 새 층 등록 도구 — **B77 후보**(사용자: 뷰어·비용 뒤에).
- 어댑터 `columns` 합치기 자체의 허용 여부 판단 — 허용한다(B64 ①). 합치기가 **의도한 것인지**는 검수 뷰의 사람 몫이고, 이 회차는 뷰가 그 열들을 보이게 한다(`role_table` 행에 `columns` 열 표시).
- 골격 확장 — 보류.

## 순서
**④ → ① → ② → ③.** ④ⓐⓑ가 사내 재생성을 오늘 지나가게 한다(두 줄). ①이 같은 종류를 막는다. ②는 둘째 원인. ③·④ⓓ는 같은 결(문면).

## 어서션
성질만. 화면 문면·수를 세지 않는다. 변이(형을 틀리게 심은 스키마·어댑터)로 관문을 잰다.

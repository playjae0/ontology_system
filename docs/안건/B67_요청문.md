# B67 구현 요청문 — 이어하기는 코드가 아니라 **판단**을 이어받는다 · 열 판정 대장 · `--resume`에 지난 실패 · 칸 1.4 · 1.5 · 1.8

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-15) · **B66 마감·보고 뒤 착수** · **출처**: 사내 실측 일곱째 — 관문 G31(`AttributeError` — 코드 실수) → G52로 끝난 등록을 `generate <dt> --resume`으로 이어가자 **같은 G31이 그대로** 났다. 사용자 판단: 「이전 코드까지 그대로 가져오는 느낌 — 열 판단 요약만 가져와 새 코드를 써야지, 오류까지 이어받으면 이어하기가 무의미하다」.
> **진단**: 코드를 가져오는 자리는 없다. `--resume`(`cli/register.py` 1101행)이 `draft(doc_type)`를 **지시·이력 없이** 부르고, 생성은 `temperature=0`이라 **같은 입력 → 같은 코드 → 같은 실패**다. 한 번의 generate 안에서 도는 자동 재생성(1966~1972행)은 FAIL 문면과 지시 이력을 `draft(revision, instruction, history)`로 넘기는데, 프로세스가 끝나고 `--resume`으로 들어오면 `state.json::instructions`는 남아 있으되 **draft에 안 넘긴다**. 이어하기가 재생성이 아니라 **재현**이다.
> **더 깊은 병**: 생성 LLM이 열마다 내린 판단(role · 필드↔열 대응 · 안 쓰는 열)이 **코드 안에만** 산다(`adapter.py`·`schema.json`·`generation_report`). 코드를 버리면 판단도 버려지고, 코드를 살리면 오류도 산다. 확정 사항(`decisions[]`)은 문답 끝(1335행)과 관문 문답 끝(1947행)에만 남고, 생성 자체·자동 재생성·`--instruct` 회차의 열 판단은 어디에도 요약되지 않는다. **판단과 코드를 가른다** — B60 ②「생성의 입력은 요약뿐」· C38「LLM은 고르고 시스템이 쓴다」의 연장이다.

## ① `--resume` = 같은 패키지 + 열 판정 대장 + **지난 실패** (칸 1.8)

- 초안(`review/<dt>/adapter.py`)이 있으면 **관문을 먼저 돌린다**(B60 ① — 저장 판정을 믿지 않는다).
  - FAIL → 그 문면(AUTO_FIX 갈래 문면 · 자동 재생성 경로와 같은 재료)과 `state.json::instructions` 이력을 재생성 지시로 실어 `draft(revision+1, instruction, history)`. 화면: `[이어하기] 지난 초안 관문 FAIL 2건(G1B · G52)을 지시로 싣는다 · 지시 이력 3건`.
  - PASS → **초안을 다시 받지 않는다**(LLM 0). 통과한 초안을 이유 없이 갈지 않는다. 다음 줄 = `review` / `confirm`.
- 초안이 없으면 지금과 같다(패키지로 초회 초안).
- 「처음부터」는 별도 플래그를 만들지 않는다 — `--resume` 없이 치면 된다(문답이 다시 돈다). 화면이 두 길을 한 줄로 말한다: `이어하기 = 같은 입력 + 지난 실패 · 처음부터 = --resume 없이`.

**완료판정 ①**: ⓐ 화면 ⓑ 어서션(성질) — 관문 FAIL 상태의 `--resume`이 보내는 system 메시지에 **지난 FAIL 태그와 이력 지시가 있다** · PASS 상태의 `--resume`은 LLM 호출 0 · 초안 없는 `--resume`은 초회와 같은 입력.

## ② 열 판정 대장 — 열마다 한 행, 시스템이 적고 템플릿이 렌더한다 (칸 1.4 · 1.5)

`review/<dt>/columns.json`. 한 열에 한 행: `col`(열문자) · `label`(헤더 라벨) · `role` · `field`(대상 필드 · 없으면 null) · `by`(판단 출처 — `interview r2` / `generate rev1` / `instruct rev3`) · `status`(`decided` / `open:G26` 같은 미해결 태그).

| Source | Who writes | When |
|---|---|---|
| generation output — `schema.json` role per field · 확정된 `expects.columns`(C38 스탬프 뒤 열문자) · `unmappable[]` | system, deterministic (LLM 0) | 관문 입구 `stamp_system_fields` 직후 — 초회·재생성 매번 |
| interview `decisions[]` whose `topic`이 열문자 또는 헤더 라벨을 담는다 | system, string match (B60 ② 규칙 그대로) | `iv_finalize` 직후 |
| `--instruct` with 열문자/라벨 in the text | system — `apply_instruction_to_decisions`와 같은 매칭을 대장 행에도 | `cmd_review --instruct` |
| gate FAIL naming a column (G25 · G26 · orphan) | system | 관문 판정 직후 — 해당 행 `status: open:G26` |

- **LLM이 대장을 쓰지 않는다** — 요약을 또 시키지 않는다. 대장은 산출·판정·지시에서 시스템이 **뽑는** 것이다(C38).
- 템플릿 `[확정 사항]`은 대장을 **열 단위 표**로 렌더하고(열문자 · 라벨 · role · 필드 · 출처), 열을 가리키지 않는 decisions는 지금처럼 자유문으로 뒤에 둔다. 문면: 「이 표의 판단을 지켜 코드를 **새로** 써라 — 앞 초안의 코드를 재현하는 것이 목표가 아니다」.
- 재생성·`--resume`의 입력 = 패키지 + 대장 + 지난 FAIL. 코드는 매번 새로 나오되 판단은 이어진다 — 이것이 「열 요약만 가지고 새 코드로」다.
- 대장 행이 없는 열(생성이 빠뜨린 열)은 orphan과 같은 뜻이다 — 이미 있는 orphan 계산이 대장을 읽게 하면 된다. 새 계산을 만들지 않는다.
- 자유문 지시가 어느 열인지 시스템이 못 정하면 대장은 건드리지 않고 이력에만 싣는다(①). **추측으로 행을 고치지 않는다.**

**완료판정 ②**: ⓐ `columns.json` 실물(사내 CSV 표본 기준 열 수 == 프로파일 열 수) ⓑ 어서션(성질) — 초안에 **코드 오류만** 심고(예: 없는 함수 호출) 재생성하면 **대장의 role·필드 대응은 그대로**이고 코드만 바뀐다(판단과 코드의 분리가 성질이다) · 대장 행 수 == 열 프로파일 수 · 대장 쓰기 경로에 LLM 호출 0 · `--instruct "D열은 attribute"`가 D행을 갱신하고 `by`가 `instruct rev N`.

## ③ 열 판정 대장을 화면에 (칸 1.6)

관문 화면(PASS·FAIL 공통)과 `status`에 대장을 한 줄에 한 열로 찍는다 — B64 ②의 열 요약(열문자 · 라벨 · 비지 않은 행/전체 · 형태) 옆에 role · 필드 · 출처 · 상태. 사람이 「어느 열이 무엇으로 정해졌고 무엇이 미해결인지」를 `columns.json`을 열지 않고 본다. 검수 뷰(`render_review`)의 갈린 열·경계선 절도 같은 대장에서 읽는다 — `generation_report`와 대장이 어긋나면 대장이 정본.

**완료판정 ③**: 화면 diff. 어서션 없음(문면).

## 넣지 않는 것
- 대장을 LLM이 쓰거나 요약하게 하는 것 — C38.
- 「처음부터」 플래그 — `--resume` 없이 치는 길이 있다.
- 자유문 지시의 열 매칭에 LLM을 쓰는 것 — 못 정하면 이력에만.
- 문답 질문 수·`extract: true`(PFMEA) — 별도 확정 대기.

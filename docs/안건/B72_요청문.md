# B72 구현 요청문 — 등록이 인입을 막지 않게(G39 · 템플릿 · few-shot) · 인입 화면(예고 · 큐 집계 · 요약 · orphan 다음 줄) · `--step` · 칸 1.4 · 1.5 · 3.1

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-15 · 사용자 확정 2026-09-15) · **출처**: 사내 실측 열한째 — 첫 실인입. ①`ingest-file`이 「스키마에 없는 필드 'meta'」를 **행마다** 찍었다(어댑터가 meta 열들을 `rec["meta"] = {...}` 딕셔너리로 냈고 스키마 `fields`에는 없다) ②골격 밖 좌표가 `orphan_anchor`로 쌓였는데 몇 개인지·드랍인지·어떻게 잇는지 화면이 말하지 않았다 ③「선택만」의 뜻이 없었다 ④2만 토큰을 쓰고 나서야 비용을 알았다.
> **진단 ①**: `core/pipeline.py::_check_fields`(59행)가 **record마다** 스키마 밖 필드를 `unknown_field`로 enqueue한다(417행 루프 안). 등록 관문에는 「어댑터가 내는 키 ⊆ 스키마 `fields` ∪ 구조 필드」 검사가 없다(G3x 조각·locator, G4x 스키마 내부, G52 self-check) — 템플릿 규약 7(「조각 출력의 키 이름은 fields 키와 정확히 일치」)이 있는데 기계가 안 잰다. 그리고 템플릿 자체가 갈린다: 「role 배정 대상이 아닌 필드 — fields에 넣지 마라」 표 안에 「사내 번호 계열은 meta다」 행이 있어 meta를 fields에 넣으라는지 말라는지 모호하고, few-shot `kit/참조어댑터/cp.json`에는 role: meta 필드가 **0건**(ipqc 3건). LLM은 본보기와 문면대로 냈다.
> **진단 ②**: anchor 해소는 설계상 정확 일치·alias뿐(문서 2 §2.4 ①). 행은 드랍되지 않고 **보류**된다 — alias가 생기면 다음 인입의 `retry_orphans`가 붙인다. 허브 실측(mock): seed `ALIASES`에 표기를 더하고 **`bootstrap`만** 돌리면 노드 46 유지 · alias 추가. 가이드 §7의 `init --fresh`는 그래프와 사전을 지운다 — 정정(허브).
> **원칙**: 비용은 쓰기 전에 화면에 오른다(B22·B69) · 큐는 사람이 판정할 사실 단위다 · 사람이 단계마다 멈춰 볼 수 있어야 한다(사용자: 지금은 자동화보다 이해가 먼저).

## ① 등록에서 막는다 — G39 · 템플릿 · few-shot (칸 1.5 · 1.4)

- **G39**(extract 단): 리허설 조각의 키 합집합 − (`schema.fields` ∪ `pipeline.STRUCTURAL`) ≠ ∅ → FAIL(AUTO_FIX). 문면: `G39  어댑터가 내는 필드 1종이 스키마에 없다 — ['meta'] · 열마다 fields에 role을 선언하라(meta면 role: meta) · 딕셔너리로 묶지 마라`. 반대(fields에 있는데 어댑터가 한 번도 안 내는 필드)는 WARN. `STRUCTURAL`은 pipeline의 것을 읽는다.
- **템플릿 `prompts/1.4_generate.md`**: 「role 배정 대상이 아닌 필드」 표에서 「사내 번호 계열은 meta」 행을 **뺀다**(`process_no`는 구조 필드다 — 그 표의 좌표 블록 행에 합친다). 규약 7 옆에 한 문장: 「**어댑터가 내는 모든 키는 fields에 role을 가진다 — meta도 role이다. 여러 meta 열을 `meta` 딕셔너리 하나로 묶지 마라**(table 레코드에 `meta` 고정 키는 없다 — prose 청크의 것이다)」. `version: 1.6`.
- **few-shot `kit/참조어댑터/cp.json`**: role: meta 필드를 최소 1건 둔다(예: 개정일) — 어댑터 `cp.py`도 같은 열을 낸다.

**완료판정 ①**: 어서션(성질) — 산출 키 밖 필드가 있는 쌍은 FAIL이고 문면에 그 이름 · 없으면 PASS · `meta` 딕셔너리를 내는 어댑터 변이가 FAIL · 기존 픽스처 전부 PASS(어긋나면 그것이 발견 — 보고) · 템플릿 `version` 갱신.

## ② 인입 화면 — 예고 · 큐는 사실 단위 · 요약 한 줄 (칸 3.1)

- **판정 예고**(LLM 0 · 파싱 직후 · 판정 전): `판정 예고 — entity 표기 k종(사전 히트 h · 문서 내 중복 제외) · 목록 밖 좌표 m표기 → LLM ≤ k−h회`. 좌표 태깅 예고(B69 ②)와 나란히.
- **큐 집계**: `unknown_field` · `missing_field` · `orphan_anchor` · `orphan_attach`는 **문서 × 필드(또는 표기) 단위 1건**, payload에 `rows`·`locators`(앞 N). 큐 kind 20종 불변. `platform queue <kind>`는 표기/필드별 + 행 수. 재인입은 이전 항목 회수 후 다시 센다.
- **문서 끝 요약 한 줄**: `인입 끝 — 노드 +n(auto a) · 엣지 +m · 저해상도 부착 r행 · 큐: unknown_field 1종(meta 118행) · orphan_anchor 3표기(41행) · LLM 호출 k · 토큰 t`.

**완료판정 ②**: 어서션(성질) — 예고 종수 == 실제 판정 호출 수(사전 히트 제외) · 같은 필드 N행 → 큐 1건 `rows == N` · orphan 표기 k종 → k건 · 요약 줄의 수가 그래프·큐 실물과 같다 · 큐 kind 20종 불변.

## ③ `orphan_anchor`의 다음 줄 (칸 3.6 · 0.1)

큐 줄 다음과 `platform queue orphan_anchor`에(B61 계약):
```
 ▶ 다음 줄 — 골격 표기를 잇는다:
    layers/<층>/skeleton.json  ALIASES["<골격 canonical>"] 에 "<표기>" 추가
    python run.py bootstrap                 ← 그래프·사전을 지우지 않는다 · alias만 붙는다
    python run.py ingest-file <같은 문서> --doc-type <dt>   ← 재인입이 보류분을 붙인다
    (골격에 없는 공정이면 seed에 노드를 더한다 — 골격작성_가이드 · 사람 판단)
```
좌표 태깅 LLM이 냈다가 목록 밖이라 버린 후보(`report["coord_tag"]`)가 있으면 표기 옆에 `(LLM 후보: 노칭)`로 붙인다 — 사람 재료이고 자동으로 잇지 않는다.

**완료판정 ③**: 화면 · 어서션(성질) — seed alias 추가 + `bootstrap`(fresh 없이) 뒤 노드 수·사전 불변 · 재인입 뒤 보류분이 붙고 큐가 준다.

## ④ `ingest-file --step` — 단계마다 멈춰 본다 (칸 3.1)

단계 7: 선택 → 파싱(조각 수·형태) → 좌표(정확 일치/저해상도/목록 밖 수) → **판정 예고**(②) → 판정(호출·매칭/신규/불확실) → 부착·엣지(attribute 붙음/보류 · 엣지 · 게이트 거부) → 큐·요약(②). 단계마다 **한 문단 설명**(무엇을 했고 다음이 무엇인지 — 문면은 `kit/`가 아니라 `cli/ingest.py` 상수 한 자리) + 숫자 + `[계속 c / 멈춤 q]`. `q`면 그 단계까지의 산출(체크포인트)을 남기고 상태 거부로 끝난다 — 다음 줄은 「`--step` 없이 다시」 또는 「alias·스키마 고치고 재인입」. 비대화형·`ingest-dir`에서는 `--step`을 무시한다(문면 한 줄). 판정에 사람 자유문을 넣는 자리는 두지 않는다 — 멈춘 자리에서 alias·스키마를 고치고 계속하는 것이 사람의 개입이다.

**완료판정 ④**: 화면(7단계) · 어서션(성질) — `q`에서 그래프 쓰기 0 · 비대화형에서 무시 · 단계 수 7.

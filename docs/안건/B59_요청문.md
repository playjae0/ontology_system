# B59 구현 요청문 — 기계 관문이 막을 때 사람이 다음 줄을 안다 (실측 첫 결함)

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-11) · **출처**: **사내 실측.** 엑셀 표본으로 `generate` → 관문 FAIL → `confirm`이 「검수를 먼저 통과시켜라」 → `review`도 1 → **막다른 길.** 사내는 복사·붙여넣기가 안 되는 환경이라 FAIL 줄을 밖으로 못 가져왔다 — 그것도 결함의 일부다.
> **한 줄**: 관문 FAIL은 설계대로다(통과분만 확정). **설계대로가 아닌 것은 화면이다** — 왜 막는지·무엇을 치면 되는지를 사람에게 안 준다. C27(사내는 코딩하지 않는다) 위반의 실물이고, B50이 하네스를 생성으로 옮긴 취지를 화면 문안이 되돌리고 있다.
> **LLM 0.** 넷 다 화면·분류표·명령이다.

## ① 막을 때 이유와 다음 줄을 준다 — `confirm` · `review` · `generate` 셋 다

관문 FAIL 상태에서 어느 명령을 치든 **같은 블록**이 뜬다:

```
■ 기계 관문 FAIL — <doc_type>
  [FAIL] G10  규약 10 — 자기완결 연산을 재구현했다 (parser.normalizer를 불러라)
  [FAIL] G51  ⑤ 파서 전 구간 — tagger에서 예외: KeyError 'process_ref' (행 12)

  ▶ 다음 줄:
     python run.py register review <doc_type> --instruct "규약 10: _expand_merged 대신 parser.normalizer.expand_merged를 불러라"
     (표본이 전부 pptx/pdf/목차형 xlsx면)  python run.py register generate <doc_type> <층> <표본> --use-basic
```

- **FAIL 줄 원문을 다시 찍는다** — `state.json`의 `harness_out`에서 `[FAIL]` 줄만. 사람이 파일을 열게 하지 않는다.
- **줄마다 짧은 태그**(`G10`·`G51` …) — **복사가 안 되는 환경에서 사람이 읽어서 전달할 수 있게.** 태그는 `run_adapter.py`의 `show()` 라벨에 1:1로 박는다(단 순서·번호가 아니라 **라벨에 붙은 고정 코드** — 단이 늘어도 안 밀린다).
- **다음 줄은 완성된 명령**이다. 「검수를 통과시켜라」 같은 동사가 아니라 **칠 수 있는 한 줄**. `AUTO_FIX` 문면이 있으면 그 문면을 `--instruct` 안에 넣어서 준다.
- **용어를 가른다** — 화면 전반에서 「검수」를 쓰지 않는다. 자동 검사는 **「기계 관문」**, 사람이 보는 것은 **「뷰 확인」**. 「검수를 통과시켜라」는 사람이 할 수 없는 일이라 문장 자체를 없앤다.
- 새 명령 **`register status <doc_type>`** — 위 블록만 찍고 끝. 화면이 흘러간 뒤 다시 볼 자리.

**완료판정 ①**: ⓐ 관문 FAIL 상태에서 `confirm`·`review`·`status` 셋이 같은 블록을 찍는다(화면) ⓑ 어서션 — 셋이 **같은 함수**를 부른다 ⓒ 어서션 — FAIL 줄마다 태그가 붙고, 태그는 `show()` 라벨 집합과 1:1 ⓓ `grep -c '검수' cli/register.py`의 **사람 화면 문면**에서 「검수」가 「기계 관문」/「뷰 확인」으로 갈렸다(주석·docstring은 대상 아님).

## ② `AUTO_FIX`를 관문 범위에 맞춘다 (B58 ②의 반쪽)

관문에 ⑤단을 붙였는데 자동 해소 표는 8줄 그대로다. **새 단의 실패는 전부 문답으로 가고, 사내는 「왜 tagger가 죽었는지」를 답할 수 없다.**

- ⑤단 `show()` 라벨을 전부 열거하고 **문면이 답을 담는 것**은 `AUTO_FIX`에 넣는다(B50 기준 그대로 — 「문면이 고칠 방법을 담는가」).
- **답을 담을 수 없는 것**(「파서 전 구간이 예외 없이 완주」·「validator 결함 0」)은 **예외 원문·validator 결함 목록을 문답 지시에 그대로 싣는다.** 문답 LLM이 그것을 보고 「어댑터의 어디를 고치라」로 통역한다 — 사람에게 통역시키지 않는다.
- `AUTO_FIX`에 없는 라벨이 ⑤단에 남으면 그 사유를 보고(무엇이라 답을 담을 수 없는가).

**완료판정 ②**: ⓐ ⑤단 라벨 전수표 — 각각 auto / 문답(+원문 동봉) 중 어디로 가는지 ⓑ 어서션 — ⑤단 라벨 중 `AUTO_FIX`에도 없고 원문 동봉도 안 되는 것이 **0** ⓒ 변이 시험 — tagger를 일부러 죽이는 표본에서 문답 지시에 예외 원문이 실린다.

## ③ 표본이 prose 포맷이면 `--use-basic`을 먼저 권한다

표본이 **전부** `.pptx`/`.pdf`/(형태 판정이 prose인 xlsx·csv)인데 `--use-basic` 없이 `generate`를 부르면:

```
  표본이 전부 산문 포맷이다 — LLM 생성 대신 고정 어댑터를 쓰는 것이 기본이다:
     python run.py register generate <doc_type> <층> <표본> --use-basic
  그래도 LLM 생성으로 가려면 --no-basic 을 붙여라.
```

**멈추고 묻는다** — 비대화형이면 `--use-basic`으로 간다. 근거: 사내가 PPT 하나 넣으려다 LLM 생성 → 관문 FAIL → 막다른 길로 갔다. **애초에 그 길로 안 들어가게 하는 것이 먼저다.**

**완료판정 ③**: ⓐ pptx 표본으로 플래그 없이 `generate` → 위 안내 + 멈춤(화면) ⓑ `--no-basic`이면 LLM 생성으로 간다 ⓒ 어서션 — 전부 prose 포맷이고 플래그 없으면 LLM 호출 0.

## ④ 폴더를 나눠 쓸 때 — 어느 코드로 돌았는지 찍는다

사내가 코드 폴더를 나눠 가며 갱신하고 있다. 관문이 **어느 폴더의 `parser/`·`kit/`으로 돌았는지**를 `harness_out` 머리에 한 줄로 찍는다(`ROOT` 절대경로 + `git rev-parse --short HEAD`가 되면 그것도). `state.json`의 경로가 상대인 것은 그대로 둔다 — 그건 옳다.

**완료판정 ④**: ⓐ `harness_out` 첫 줄에 ROOT와 커밋이 찍힌다 ⓑ 다른 폴더에서 돌리면 다른 값이 찍힌다.

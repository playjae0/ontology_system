## ① prose 검수 뷰 — ②구획에 추출 리허설 (문서 6 §6.6 · M9 B51)

**왜**: table은 role 배정표(「이 열이 attribute가 된다」)를 보고 승인한다. prose는 **청크 분할만** 보고 승인한다 — 층 어휘가 이 문서에 어떻게 적용되는지를 한 번도 안 본 채 확정된다. 그 결과를 처음 보는 시점이 운영 인입 뒤 `show extract`다.

**설계 원칙 — 리허설은 운영과 같은 함수·같은 파일이다.** 별도 「리허설 추출」을 만들지 않는다. `cli.extract.run()`을 표본에 부르고 그 체크포인트를 그대로 뷰에 싣는다. 확정 뒤 같은 문서를 운영 인입하면 **재사용**된다 — LLM 호출 추가 0회.

### 작업
1. `cmd_review` — prose이고 `machine_gate == PASS`이면 리허설 파싱 뒤 **`cli.extract.run([parsed 경로])`**를 부른다. 표본 doc_id는 지금 리허설 규칙(`{DOC_TYPE}{i:02d}`) 그대로.
   - **비용 관문**: 청크 수 N을 세어 `추출 리허설 N청크 → LLM N회. 켤까? [y/N]` — 좌표 보조와 동형(`_ask_llm_coord` 재사용 가능). `--extract`/`--no-extract`로 미리 정할 수 있게. 기본은 **켬**(prose 승인의 근거이므로) — 다만 비대화형이면 끄고 뷰에 「추출 리허설 없음」을 표시.
   - mock이면 mock 추출(문형 규칙)이 돈다 — 그 사실을 뷰에 표시.
2. **부분 리허설 판정** — 리허설 파싱이 `--rows N`으로 잘렸으면 체크포인트를 **저장하지 않는다**(운영이 부분 체크포인트를 재사용하면 안 된다 — `EX.invalidate` 후 뷰용으로만). **prose의 리허설 기본은 전량**으로 바꾼다 — 부분 리허설의 근거(PFMEA 좌표 미스 비용)는 table의 것이고 prose엔 해당 없다. table 기본 200행은 그대로.
3. **뷰 데이터 — ②구획**(D-79 확장): `sections.role_table` 자리에 prose면 `sections.extract_rehearsal`:
   ```json
   {"source": "live|mock|none", "prompt_version": "e-1.0", "config_version": "…",
    "totals": {"chunks": N, "entities": N, "relations": N, "attach": N, "unresolved": N},
    "by_chunk": [{"chunk_id": "…", "section": "…", "excerpt": "앞 60자",
                  "entities": [{"surface": "…", "category": "…"}],
                  "relations": [{"src": "…", "rel": "…", "dst": "…"}],
                  "attach": [{"surface": "…", "attach_to": {…}|null}]}],
    "category_counts": {"Unit": N, "Property": N, "…": N}}
   ```
   `DECISIONS.md` D-79 이력에 적는다.
4. **렌더러** — ②구획 제목을 prose면 「추출 리허설 — 층 어휘가 이 문서에 적용된 결과」로. `category_counts`를 먼저(한눈에), `by_chunk`는 접이식. **카테고리가 config에 없는 후보**(있을 수 없지만)는 경고색.
5. 승인 기록(`approval.json`)에 `totals`·`category_counts` 요약을 싣는다 — 「무엇이 뽑히는 것을 보고 승인했나」.

### 완료판정 ①
ⓐ prose 표본으로 `review` → 관문 `[y/N]` → 뷰 HTML에 청크별 후보와 카테고리 집계가 보이는 화면(텍스트 발췌) ⓑ 확정 후 같은 표본을 `ingest-file` → `[추출 체크포인트 재사용]` (리허설 = 운영) ⓒ `--rows 50`으로 부분 리허설이면 체크포인트가 **안 남는다** ⓓ 비대화형에서 뷰에 「추출 리허설 없음」 ⓔ `approval.json`에 요약 ⓕ 회귀 유지 + 어서션(ⓑⓒ)

## ② `parse run` doc_id 파생 (문서 7 §7.1 B51)

**왜**: `ingest-file`은 doc_id를 파일명에서 파생하는데 `parse run`은 수동이라 **규칙이 둘**이다. 사용자가 헷갈렸다.

### 작업
1. `cli/parse.py::cmd_run` — 인자 형태를 갈라 받는다: 새 형 `<adapter> <문서> [<출력>] [--doc-id X]` · 구형 `<adapter> <doc_id> <문서> [<출력>]`. 구분: 둘째 인자가 **존재하는 파일**이면 새 형. `--doc-id` 없으면 **`cli.ingest`의 파생 함수를 그대로 부른다**(복제 금지).
2. 화면에 `doc_id = {값} (파일명 파생)` 또는 `(지정)` 한 줄.
3. 사용법 문안·`run.py` 도움말 갱신.

### 완료판정 ②
ⓐ `parse run adapters/x.py 문서.xlsx` → 파일명 doc_id로 산출 ⓑ 구형 4인자 그대로 ⓒ `--doc-id`가 이긴다 ⓓ 파생 함수 호출부가 `cli/ingest.py` 것 하나(grep) ⓔ 회귀 유지

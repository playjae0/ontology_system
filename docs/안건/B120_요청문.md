## ① 산문 「항목 = 값」 → 주인 노드의 attrs (칸 3.3 · 3.4)

- 추출 계약: **값을 받는 카테고리**(②)의 개체는 선택 필드 `value`(청크 원문 글자 그대로 — 단위 포함 · 범위 · 조건 꼴 그대로)를 낼 수 있다 · 같은 청크에서 그 항목에 걸린 값만 · 없으면 비운다(지어내지 않는다).
- 구축: 개체가 노드로 서면(이름은 B119 ④ — 주인 아래) 그 노드 attrs에 `{value, provenance(청크)}` · **표의 attribute와 같은 함수**로 싣는다(맥락형 · 충돌 규칙 그대로 — §4.6-4·5).
- 대조: `value`가 청크 원문에 글자 그대로 없으면 버리고 결함 로그(조용한 절단 0 · 수는 맞춤표).
- 지시문 3.3 판 올림(추출 다시 — 사내 재구축 한 번).

## ② 값을 받는 카테고리 — 층 config 선언 (config)

- 층 config에 선택 키 하나(이름 구현 판단 — 예 `value_categories`): 값을 받는 카테고리 목록 · **없으면 산문 값 0**(지금 동작 그대로).
- mock 층 config에 선언(예: process 층의 사양 카테고리) · 사내 config 줄은 ⑤ 가이드에 정확히.

## ③ config 판 자동 (칸 3.3)

- 추출 재사용 조건의 층 config 판을 **추출 입력에 실제로 들어가는 부분**(카테고리 · 정의문 · 관계 이름 · 값을 받는 카테고리 등 — 구현이 조립 자리에서 정한다)의 해시로 — 사람이 적는 `config_version`은 기록용으로 남기되 재사용 판정에 쓰지 않는다. 게이트 · 구축만 바꾸는 키(`relation_patterns` · `category_pair_map` · `canonical_scope`)는 판에 들지 않는다 — B118 ⑥ 영향 범위와 같은 분류(한 함수).
- 처음 적용은 모든 산문을 한 번 다시 뽑는다 — 이 회차는 어차피 지시문 판이 올라 다시 뽑으므로 비용이 더 들지 않는다.

## ④ 화면 (화면)

- 맞춤표에 `값(attrs) n = 실림 a + 버림(글자 밖) b + 충돌(spec_conflict) c` · 판정 예고 값 표에 값 칸 · `show node` · 뷰어 노드 상세의 attrs에 산문 값이 보인다 · B118 `show summary`의 값 수.

## ⑤ 가이드 (같은 커밋)

- **config작성 가이드에 사내가 바꿀 줄을 정확히**: ⓐ층 config — 값을 받는 카테고리 선언 한 줄 ⓑ`relation_patterns`에 `(유닛 카테고리, has_property, 사양 카테고리)`가 있는지 확인 · 없으면 한 줄(게이트만 — B118 거부 묶음이 제안하는 줄과 같다) ⓒ사양 카테고리 정의문은 「이름」이고 값은 attrs라는 문장(지금 mock 정의문 그대로) ⓓ`config_version`은 이제 자동 — 올리지 않아도 된다.
- 운영 런북 · 인입 이해 가이드: 값이 어디에 보이는지 · 충돌 큐.

**완료판정**: 테스트 세트(창작) — **산문 × 층 둘**(+ 표는 불변).
ⓐ 값: 「항목 = 값」 청크에서 그 항목 노드(주인 아래 이름)의 attrs에 원문 그대로의 값 · 출처 청크 · 같은 청크의 날짜 · 쪽수 같은 숫자는 값이 아니다.
ⓑ 버림 · 충돌: 원문에 없는 값은 버림(결함 로그 · 맞춤표 수) · 같은 노드 같은 맥락의 다른 값은 `spec_conflict`(덮어쓰기 0) · 맥락이 다르면 병렬.
ⓒ 선언: 값을 받는 카테고리 선언이 없는 층은 값 0(지금 동작) · 선언하면 실린다.
ⓓ config 판: 정의문을 바꾸면 추출 다시 · `relation_patterns`만 바꾸면 추출 재사용(LLM 0) · 사람이 적는 `config_version`을 바꿔도 판정은 그대로.
ⓔ 재구축: 값 · 대장이 재생된다(추출 · 판정 LLM 0) · 표(CP · PFMEA)의 attrs 불변(네 벌 A · B 전부 같다).

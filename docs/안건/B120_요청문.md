## ① 산문 「항목 = 값」 → 노드 attrs (칸 3.3 · 3.4)

- 추출 계약: 값을 받는 카테고리(②)의 개체는 선택 필드 `value`(청크 원문 글자 그대로 — 단위 · 범위 · 조건 꼴 그대로)를 낸다 · 같은 청크에서 그 항목에 걸린 값만 · 없으면 비운다. 지시문 3.3 판 올림.
- 구축: 개체가 노드로 서면(이름은 B119 그대로) 그 노드 attrs에 `{value, provenance(청크)}` — **표의 attribute와 같은 함수**(맥락형 · 충돌 규칙 그대로 — §4.6-4·5).
- 대조: `value`가 청크 원문에 글자 그대로 없으면 버리고 결함 로그 · 수는 맞춤표와 B118 한 줄 요약(`값 n = 실림 a · 버림 b · 충돌 c`) · `show node` · 뷰어 노드 상세의 attrs. **판정 예고 표에는 칸을 더하지 않는다**(120칸 — B118 · B119에서 위치 칸이 잘렸다).

## ② 값을 받는 카테고리 — 층 config 선언 (config)

- 층 config에 선택 키 하나(이름 구현 판단 — 예 `value_categories`) · **없으면 산문 값 0**(지금 동작 그대로) · mock process 층에 사양 카테고리 선언.

## ③ config 판 자동 (칸 3.3)

- 추출 재사용 조건의 층 config 판 = `config_scope`의 **추출 갈래 칸 해시**(값을 받는 카테고리 키는 추출 갈래에 든다) · 사람이 적는 `config_version`은 기록용으로만 남기고 판정에 쓰지 않는다 · 게이트 · 구축 칸(`relation_patterns` · `category_pair_map` · `canonical_scope`)은 판에 들지 않는다 — B118 영향 범위와 같은 함수라 `bootstrap`의 「추출 다시」 알림과 실제 재추출이 늘 같다.
- 처음 적용은 모든 산문을 한 번 다시 뽑는다 — 이 회차는 어차피 지시문 판이 올라 다시 뽑는다.

## ④ 가이드 (같은 커밋)

- config작성 가이드 §1-b에 사내가 바꿀 줄: ⓐ값을 받는 카테고리 선언 한 줄 ⓑ`relation_patterns`에 `(유닛 카테고리, has_property, 사양 카테고리)` 확인 · 없으면 한 줄(B118 거부 묶음의 제안 줄과 같다) ⓒ`config_version`은 이제 자동 — **B119 가이드의 「config_version을 올린다」 줄을 지운다**. 운영 런북: 값이 어디에 보이는지 · 충돌 큐.

**완료판정**(대표 사례 — B119 창작 표본 ⓑ `FWC3`(TW 꼴 — 언와인더 · 리와인더 아래 같은 이름 사양)에 값을 넣어 쓴다 · 표 불변은 네 벌 A · B):
ⓐ 값: `노칭::언와인더 unit::장력`과 `노칭::리와인더 unit::장력`이 각자 원문 그대로의 값과 출처 청크를 갖는다(충돌 0) · 같은 청크의 날짜 · 쪽수는 값이 아니다.
ⓑ 버림 · 충돌: 원문에 없는 값은 버림(결함 로그 · 수) · 같은 노드 같은 맥락의 다른 값은 `spec_conflict`(덮어쓰기 0).
ⓒ 선언 · 판: 선언이 없는 층은 값 0 · 정의문을 바꾸면 추출 다시 · `relation_patterns`만 바꾸면 추출 재사용(LLM 0) · `config_version`만 바꾸면 판정 그대로.
ⓓ 재구축: 값이 재생된다(추출 · 판정 LLM 0) · 네 벌 A · B 전부 같다(표 attrs 불변) · C는 값이 더해진 몫만.

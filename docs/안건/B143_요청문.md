## ① 결함 — 목록 공정에서 등록 뷰가 죽지 않는다 (칸 1.x)

- 좌표 쌍 표가 **공정 목록**을 받는다 — 목록이면 원소마다 같은 판정(`parser.coord_pairs.verdict` 한 함수) · 덱 구조가 「없음」을 낸 빈 목록은 대조 0 · 판정 꼴은 구현 판단(보고).
- **같은 가정이 남은 자리를 이 회차에서 전수**한다 — `process_ref`를 글자로 다루는 곳(사전 열쇠 · 집합 · 비교 · 화면) 중 산문 청크가 지나는 곳 전부(등록 뷰 · 리허설 · 킷 · `show` · 질의 머리). 목록을 고친 자리 수와 그대로 둔 자리(표 전용 등)를 보고에.

## ② 덱 판단을 parsed JSON 한 곳에 (칸 2.6 · 2.4)

- 봉투에 **덱 블록**: `deck.overview` + `deck.slides[]` — 슬라이드마다 번호 · 보이는 쪽 번호 · 제목 초안(placeholder) · 판단 제목 · 구획 · 이어짐 · 다루는 공정(목록 · 판정 없음과 「없음」을 가른다) · 언급 공정 · 개체 없음 · 버림(검사에 어긋난 칸) · 사람 고침 여부 · 그 슬라이드의 근거 청크 위치 목록. 칸 이름은 가결정 — **모양은 사내 결과를 보고 다시 판단한다(사용자)**: 칸을 고정하는 어서션을 두지 않는다 · 성질만.
- 청크의 지금 칸(`process_ref` 목록 · `meta.mentions` · `no_entities` · `section_path` · 그림 요약 글 · 노트)은 그대로 — 덱 블록은 슬라이드 단위 판단의 정본 · 청크 칸은 추출이 쓰는 투영(어긋나면 결함).
- `doc_overview`는 `deck.overview`로 옮기고 맥락 줄 · 개요 칸 소비부를 따라 고친다(옛 키를 읽는 자리 전수).

## ③ 추출의 입력은 JSON + 캡처만 (칸 3.3)

- 추출(슬라이드 단위 호출)이 덱 판단(경로 · 이어짐 · 공정 · 언급 · 개체 없음 · 개요)을 **parsed JSON에서만** 읽는다 — `struct_maps/`의 `deck`은 같은 파일 · 같은 판 재사용(LLM 0)의 보존분으로만 남는다.
- 원본 파일은 캡처 렌더에만 연다(지금 그대로 · 바이트 비저장).

## ④ `--split-only`가 PPT도 · 사람용 md는 JSON에서 (칸 0.3)

- PPT `ingest-file … --split-only`: 파싱 · 덱 판단 · 그림 요약까지 → parsed JSON → **md `export/split_<doc_id>.md`** → 멈춤(추출 0 · 그래프 쓰기 0).
- **md 자리는 B141이 만든 한 자리 `cli/structure_screen.py` `md_of`(132 — 산문 인입마다 md)다** — 거기에 PPT를 싣는다 · 새 자리를 만들지 않는다(`--split-only` · 일반 인입 · 재구축이 같은 길).
- md는 **parsed JSON(봉투)만 읽어** 찍는다 — 봉투를 받아 찍는 꼴을 **PPT 전용으로 만들지 않는다**(포맷 공통 꼴 · B144가 엑셀 · Word md도 같은 함수로 JSON에서 찍게 이어 쓴다 — 이 회차에서 엑셀 · Word md의 재료는 지금 그대로). 머리에 덱 개요 · **슬라이드 표**(번호 · 제목(초안 → 판단) · 이어짐 · 다루는 공정 · 언급 · 개체 없음 · 근거 조각 · 글자) · 슬라이드마다 `[본문]` · `[표 S#-TB1]` · `[차트 …]` · `[그림 요약 S#-P#]` · `[노트]` · 캡처 쪽 번호 · 버림 · 사람 고침. 엑셀 · Word의 구조 확인 md와 같은 자리 · 같은 이름 꼴.
- 운영 런북 §3: PPT `--split-only` 한 줄 · md 읽는 법 몇 줄(사람이 치는 명령이 바뀐다 — 같은 커밋).

**완료판정**(창작 표본 — 덱 구조 · 그림 요약 · 추출은 mock 힌트 · 품질은 사내에서 잰다 · 표본은 `tests/fixtures/make_ppt.py`의 덱에 공정 목록 · 이어짐 · 노트 · 표가 든 힌트):
ⓐ 결함: 공정 목록이 둘 이상인 슬라이드가 든 덱으로 `register generate <dt> <층> <표본> --use-basic` → `status`가 끝까지 돈다(좌표 쌍 표 · 관문 줄) · 전수 결과를 보고에.
ⓑ 덱 블록: parsed JSON 하나에 슬라이드마다 이어짐 · 제목 초안과 판단 · 공정 목록 · 언급 · 개체 없음 · 버림이 있다 · 청크 칸과 어긋나지 않는다.
ⓒ 추출 입력: parsed JSON의 덱 블록 한 칸(예: 이어짐 또는 공정)을 사람 고침으로 바꾸면 추출 입력(맥락 줄)이 그 값을 따른다 · 원본은 캡처 렌더에서만 열린다.
ⓓ `--split-only`: PPT에서 추출 호출 0 · 그래프 쓰기 0 · parsed JSON과 md가 남는다 · md의 슬라이드 표 행 수 = 덱 블록 슬라이드 수.
ⓔ md ⊆ JSON: md를 쓰는 함수가 parsed JSON(봉투) 밖을 읽지 않는다(대표 어서션 하나).
ⓕ 호환: 엑셀 · Word의 구조 확인 md는 바이트 그대로(이 회차 안에서 — 바꾸는 것은 B144) · 네 벌 A · B 전부 같다 · C는 바뀐 몫만(보고에 차이).

# B125 구현 요청문 — PPT: 슬라이드가 추출 단위 · 슬라이드 캡처를 추출에 · 덱 구조 판단 1회(제목 · 이어짐 · 공정 목록 · 덱 개요) · 청크 공정은 목록 · 칸 2.4 · 2.6 · 3.3 · 3.4 · 문서

> **수신**: 구현 세션 · **발신**: 허브 (2026-10-19 · 사용자 결정 2026-10-19 — 「shape 조건이 타이트하게 하는 것이면 제외」 · 「표 · 차트 · 노트 맥락은 넣어야」 · 「슬라이드를 캡처해서 전체 배치 문맥을 파악하는 것은 당연히 반영돼야 — 이미지를 보고 표나 그림이나 글자들이 무엇을 말하는지 안다」 · 「제목 인식 · 문서 좌표는 예외가 있을 것이라 강제하면 안 되고 LLM이 판단할 수 있게」 · 「한 슬라이드가 한 공정이 아닐 수 있다 — 여러 개가 나올 수 있다 · 판단도 LLM에게 권한을 준다」 · 「제목 · 이어짐 · 공정 · 덱 개요를 한 번에 판단하게 — 동의」) · **B124 뒤**(같은 구조 호출 ⑪ · 역할 중립 위에 얹는다) · **가벼운 회차**.
> **출처 — 허브 실측(2026-10-19 · origin `4af5505` · 창작 표본 — 동작 확인용이고 수치는 근거가 아니다)**: ①제목 + 작은 상자 6개(합 70자)인 슬라이드가 **상자마다 청크 7개**로 나뉜다 — 「마모 0.05mm」 · 「→ 버 발생」이 주인 없이 따로 추출에 간다(`_over`가 「글자 600 **또는** 상자 5 초과」 · 넘으면 상자가 둘 이상일 때 상자 분할) ②표 · 차트는 별도 청크라 같은 슬라이드 본문(「아래 표는 …」)을 못 본다 ③노트는 리더가 `meta.notes`에 싣지만 **읽는 곳 0** ④슬라이드 캡처는 **그림 요약(④)에만** 붙고 그림이 없는 덱은 캡처를 뜨지 않는다 · **추출(①) 입력에 이미지 0** ⑤제목은 제목 placeholder만 — 사내 양식이 글 상자 제목이면 경로 · 구획 · 개요가 빈다 ⑥「상기 호기」 · 「(계속)」은 앞 슬라이드를 모른다(맥락은 덱 제목 › 구획 › 슬라이드 제목뿐) ⑦청크 공정은 하나(`process_ref` 문자열 · 부착 후보 · 다른 공정 가드가 그 하나의 계보) · `ingest-dir`에 `--coord` 없음.

## ① 슬라이드 = 추출 1회 · 상자 분할 폐지 (칸 2.6 · 3.3)

- 상자 수 조건을 뺀다(`max_shapes` · 상자 단위 분할 삭제). 임계는 글자 수만 · 자리는 `knobs.json`(기본값은 구현 판단 — 「보통 슬라이드는 통째」).
- 추출 단위와 근거 단위를 가른다: 추출 호출은 슬라이드마다 1회(본문 · 표 · 차트 · 노트 · 그림 요약 + 캡처 + 맥락 줄) · 근거 청크는 지금처럼(위치 꼴 불변) · 본문이 임계를 넘을 때만 본문 근거 청크를 구조 지도로 나눈다.
- 개체의 출처 청크 = 그 표기 · 값 글자가 든 근거 청크(없으면 본문 청크) · 값은 원문 글자(본문 · 표 · 차트 · 노트)에서만 — 그림 요약 · 캡처에서 온 값은 버림.
- 표지 · 제목만 있는 슬라이드는 덱 구조가 「개체 없음」으로 표시하면 추출 0(화면 수).

## ② 슬라이드 캡처를 추출에 (칸 2.6 · 3.3)

- PPT · PDF는 그림 유무와 무관하게 쪽 렌더 → ①의 슬라이드 추출에 첨부 · 지시문 3.3: 「캡처는 배치 · 화살표 · 무엇이 무엇에 붙었나 · 표가 무엇을 설명하나를 보는 근거 — 이름과 값은 글자에 있는 그대로」.
- `soffice`가 없으면 캡처 없이 진행 · 기록 `slide_render=none` · 화면 한 줄(`캡처 — 있음 n · 없음 m(soffice 없음)`) · 게이트웨이가 그림을 받지 않으면 지금 그림 규칙 그대로(`--no-images`면 캡처도 끈다).

## ③ 덱 구조 판단 1회 — 제목 · 이어짐 · 공정 목록 · 덱 개요 (칸 2.4 · ⑪)

- 지점 ⑪의 PPT 입력 꼴(새 지점 0) · 문서당 1회 · 입력: 슬라이드마다 상자 글(placeholder 제목 표시 = 힌트) · 노트 앞부분 · 표 · 차트 머리 + 문서 좌표(힌트) + 골격 닫힌 목록 · 양은 B124의 손잡이.
- 출력: 슬라이드마다 제목 · 구획 · 이어짐 · 다루는 공정(목록) · 언급 공정 · 개체 없음 + 덱 개요 · 코드는 검사만 · 이어진 슬라이드는 앞의 경로 · 공정을 잇는다.
- 쓰는 곳: 경로 → 개요 · 맥락 줄 · 청크 공정 · 덱 개요는 맥락 줄의 칸(포맷 전부 한 함수).
- 화면 · 고침: `--step` 구조 표에 슬라이드 줄 · 고침 → `structure_fixes.json` · 재구축 재생 · 끝 줄 `덱 구조 — 슬라이드 n · 제목 초안과 다름 a · 이어짐 b · 공정 하나 c · 둘 이상 d · 없음 e · 문서 좌표와 다름 f · 버림 g` · 같은 파일이면 LLM 0.

## ④ 청크 공정은 목록 — 공통 통로 (칸 2.8 · 3.3 · 3.4)

- 조각 · 청크 공정을 목록으로(두 번째 필드 0) · 단수를 가정한 자리를 이 회차에서 전수 · 부착 후보 = 목록 공정들의 하위 트리 합 · 다른 공정 가드 = 목록 전체의 계보 밖 · 추출이 개체마다 소속 공정을 목록 안에서 고른다.
- 언급 공정은 노드 0 · 청크 → 그 공정 `about` 관련 링크 · `--coord`는 힌트 → `ingest-dir`로 PPT를 넣을 수 있다 · 표 · 엑셀 산문 · Word의 지금 동작은 그대로(목록 한 개).

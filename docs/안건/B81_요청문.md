# B81 구현 요청문 — 인입 화면: 값마다 결과 한 줄 · 로그는 파일로 · 특이점에 색 · 보폭 손잡이 · 누적 토큰 · 뷰어에 연결 현황(깔때기 · orphan) · 칸 3.1 · 0.3

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-22 · 사용자 확정 2026-09-22) · **B80 뒤** · **출처**: 사내 실측 — 첫 실인입에서 「화면에 눈에 들어오는 게 없다」. 지금 화면은 INFO 로그(`onto.gateway ②개체 동일성 판정 …` · `onto.store 큐 auto_node …`)가 값마다 두 줄씩 흘러가고, 사람이 알고 싶은 것(이 값이 **붙었나 · 새로 생겼나 · 불확실한가** · 토큰이 얼마나 쌓였나)은 그 사이에 묻힌다. 진행 줄은 10%마다라 텀이 길고, 글자가 다 같아서 특이점(NEW·uncertain·orphan·실패)이 안 보인다. 사용자: 「생성·불확실·확실과 결과 · 토큰은 누적으로 · 색은 특이점에 · 중간 요약은 눈에 띄게 · 중간 보고 텀이 길다」.
> **원칙**: 판정·그래프 동작 변경 0. 화면 문면이 바뀌므로 **어서션은 색 코드를 벗긴 문자열로 재고, 문면·수를 세지 않는다**(CLAUDE.md §7). 로그 규격(문서 7 §7.8 — MOCK·큐 적재·명시적 실패는 로그로 남긴다)은 **파일**에서 그대로 성립한다 — 「남긴다」이지 「화면에 찍는다」가 아니다.
> **허브 실측(2026-09-22)**: 진행 보폭 `stride = total // 10`(`cli/ingest.py:344`) · 콘솔 핸들러 INFO(`core/state/log.py:39`) · 파일 로그는 `ONTO_LOG_FILE`이 있을 때만(:42) · ANSI 색 0곳 · `isatty` 검사 5곳(입력용) · 판정 대장 행에 `verdict`(닫힌 9값)·`path`·`candidates_n`·`confidence`·`llm`·`queue_kind`가 이미 있다(`core/build/ledger.py:22~26` · `ledger.add` — `loop.py:368·372`).

## ① 값마다 결과 한 줄 — 판정 대장 행에서 (칸 3.1)

- 판정 단계에서 **대장 행이 기록될 때** 화면에 한 줄. 새 정보 0 — 대장 행의 `verdict`·`path`·`candidates_n`·`confidence`·`queue_kind`를 그대로 찍는다(화면은 대장의 투영이다 — 두 벌이 갈리지 않는다).
- **찍는 값**: `path`에 LLM이 든 값(`scope+judge`·`embedding+judge`·`overlap+judge`) 전부 + `verdict`가 `new`·`uncertain`·`orphan`·`lowres`·`gate_reject`인 값 전부. **사전·스코프로 끝난 값(`dictionary`·`skeleton`·`none` 경로의 `match`·`anchor`)은 줄을 찍지 않고 수로만** — 사람이 볼 건 판단이 갈린 자리다(사용자 확정: 「생성·불확실·확실과 결과」). `-v`면 전부.
- 줄 형태(기호 · canonical · verdict · 경로 요약):
  ```
    ✓ 탭용접::용접 가압력        match      LLM · 후보 7 · 확신 0.92
    + 노칭::금형 클리어런스      new        후보 0 (스코프)            → 큐 auto_node
    ? 패키징::실링 온도          uncertain  LLM · 후보 3               → 큐 uncertain_match
    ✗ 스태킹::적층 정렬도        orphan     좌표 미해소                → 큐 orphan_anchor
  ```
  기호는 verdict에서 닫힌 표로(`match`·`attached`=✓ · `new`=+ · `uncertain`·`lowres`=? · `orphan`·`gate_reject`=✗ · `anchor`=·). 큐에 올라간 값은 줄 끝에 `→ 큐 <kind>`.

**완료판정 ①**: 어서션(성질) — 값 줄의 수 == 대장 행 중 「LLM 경로 ∪ 특이 verdict」의 수 · 각 줄의 verdict·후보 수·큐 kind가 그 행과 같다(색 벗긴 문자열에서 파싱) · `-v`면 줄 수 == 대장 행 수 · 사전 히트만 있는 문서는 값 줄 0.

## ② INFO 로그는 파일로 · 화면은 WARNING 이상 (칸 0.3)

- `log.setup()`의 기본: 콘솔 핸들러 **WARNING** · 파일 핸들러 **INFO**를 `work/logs/<명령>_<YYYYMMDD>.log`(`paths.work("logs", …)` — 자리 소유자 · `ensure`)에 **언제나**. `ONTO_LOG_LEVEL`·`ONTO_LOG_FILE`은 그대로 남긴다(둘 다 덮어쓰기 손잡이). `-v`/`--verbose`면 콘솔도 INFO(지금 화면).
- mock 실행(`state_mock/`)도 같은 규칙 — 로그가 운영 루트에 가지 않는다(자리 소유자가 정한다).
- `ingest-file` 끝 요약에 「로그 <경로>」 한 줄.

**완료판정 ②**: 어서션(성질) — 기본 실행에서 stdout/stderr에 `onto.gateway`·`onto.store` INFO 줄 0 · 같은 실행의 파일 로그에 그 줄 ≥1(MOCK 경고·큐 적재·명시적 실패 3종 — §7.8 로그 규격 불변) · `-v`면 콘솔에도 · mock 실행의 로그 파일은 `state_mock/work/logs/`.

## ③ 색 — 특이점에만 · 터미널일 때만 (칸 0.3)

- `cli/_screen.py`(또는 기존 화면 공용 자리 하나)에 `paint(text, kind)` — ANSI 표준 라이브러리만. **켜지는 조건**: `sys.stdout.isatty()` and `NO_COLOR` 환경변수 없음 and `--no-color` 없음. 파이프·리다이렉트·로그 파일에는 색 코드 0.
- 색은 **특이점에만**(사용자 확정): `new`=노랑 · `uncertain`·`lowres`=빨강 · `orphan`·`gate_reject`·`[결함]`·`[FAIL]`·`실패 —`=빨강 굵게 · `match`(LLM)=초록 · LLM 0인 줄·기타=기본색. **중간 요약·끝 요약은 배경 반전(reverse)** 한 줄로 눈에 띄게.
- 문면 검사·어서션·스캐너는 `strip_ansi()` 하나를 거쳐 잰다 — 색이 문면을 바꾸지 않는다.

**완료판정 ③**: 어서션(성질) — 비-tty(파이프)에서 출력에 ESC 0 · `NO_COLOR=1` tty에서 ESC 0 · tty 스텁에서 `new` 줄에 노랑 코드, `uncertain` 줄에 빨강 코드 · `strip_ansi(색 출력) == 비-tty 출력` · 상태 거부 스캐너·문면 검사 수 불변.

## ④ 진행 보폭 손잡이 · 누적 토큰 · 중간 요약 (칸 3.1)

- 진행 줄 보폭: `--progress-every N`(값 N개마다 · **기본 25**) — `stride = total // 10`을 대체. 설정 키 `PROGRESS_EVERY`도 같은 이름으로(`llm.json`). 값 수가 N 미만이면 시작·끝 두 줄.
- 진행 줄에 **누적**을 싣는다(지금도 있다 — 유지): `[판정] 값 i/N · 호출 k · 누적 토큰 t(입력 a · 출력 b) · 사전 h · NEW n · 불확실 u · 큐 q` — 뒤 넷을 더한다(대장에서 집계). 배경 반전으로.
- `--step-every N`은 그대로(멈춤은 별개 손잡이 · B75 ③).

**완료판정 ④**: 어서션(성질) — `--progress-every 5`에서 진행 줄 수 == ⌈N/5⌉(+시작) · 진행 줄의 누적 토큰 == `gateway.usage_total()` 그 시점 · NEW·불확실·큐 수 == 대장 집계 · 기본값이 설정 키로 바뀐다.

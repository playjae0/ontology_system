# B73 구현 요청문 — 후보 검색은 전량이 아니다(스코프 근처 → 임베딩 top-N · 명세대로) · retry는 조건부 · auto 노드는 후보에서 표시된다 · 자동 노드의 사람 확정 · 칸 3.4 · 3.1 · 0.3

> **수신**: 구현 세션 · **발신**: 허브 (2026-09-15 · 사용자 확정) · **B72 뒤** · **출처**: 사내 실측 열두째 — 첫 실인입에서 판정 호출의 **입력 토큰이 누적 증가해 2만**(출력 40 이하). 사용자: 「노드를 어디에 연결할지 찾는 것 아닌가」 — 맞다.
> **진단 ①**: `core/matcher.py::candidates()`가 같은 카테고리·층의 live 노드 **전량**을 후보로 판정 LLM(`_judge_live` · `"candidates": pool`)에 보낸다 — 상한도 유사도도 없다. 노드가 늘수록 매 호출이 커진다. 명세는 다르다: 문서 4 §4.2 ②「후보 검색 — 사전 미스 시 **임베딩 유사도**」. `core/embeddings.py::embed()`는 정의만 있고 **호출부 0**. 사전(`exact`)은 작동한다 — 같은 표기 2회째는 LLM 0.
> **진단 ②**: `core/retry.py::retry_orphans`가 **매 인입 finalize마다 큐 전량**을 다시 돈다. `orphan_anchor`는 무LLM이지만 `orphan_attach`·`orphan_chunk_link`는 `_pick_cat`/`_pick_any`가 `matcher.match`를 다시 불러 **LLM 재판정** — 카테고리를 돌면서 전량 후보로. 문서 하나마다 「그 문서 + 쌓인 orphan 전부」가 돈다. 항목에 재시도 횟수·최초 발생이 없어 「한 번 해결하고 다시 도는지」를 사람이 볼 수 없다.
> **진단 ③**: 신규(`status: auto`) 노드가 만들어지는 즉시 다음 판정의 후보에 들어가고 판정 프롬프트는 그것이 auto인지 모른다 — 오판 하나가 다음 문서를 끌어당기는 연쇄. 사람이 auto 노드를 「맞다/아니다」로 종결하는 경로가 없다(감사 H12 — `resolve_item` 호출 0 · `confirmed` 생산자 0).

## ① 후보 검색 = 사전 → **스코프 근처** → 임베딩 top-N → 판정 (칸 3.4)

문서 4 §4.2 ②를 구현하되 결정적 단계를 앞에 둔다:
1. 사전 히트(`exact`) — 지금처럼 앞에, 상한과 무관하게 포함.
2. **스코프 근처**(LLM 0): 스코프가 있는 카테고리(`canonical_scope.bind_categories` — 공정 아래 관리항목·설비)는 **같은 부모 좌표 아래 노드**를 먼저 후보로 — `candidates()`가 이미 `parent`·`scoped`를 안다. 부모가 같은 노드가 N개 이하면 그것으로 끝(임베딩 호출 0).
3. 그래도 많거나 스코프 없는 카테고리면 **임베딩 top-N**: 표면형과 후보(canonical + 정의문 — 명세 「임베딩 대상은 노드의 canonical과 정의문」)를 `embeddings.embed()`로 벡터화해 코사인 상위 N. 노드 벡터는 저장하지 않는다(P5 — 프로세스 캐시). mock(`use_mock()`)은 임베딩 대신 **결정적 어휘 겹침**(정규화 문자 2-gram 교집합 비율) top-N — 회귀는 그대로 돈다.
4. 상한 `CANDIDATE_TOP_N` 하나(기본 12 · `core/matcher.py` · 06 대장).
- 화면: 문서 끝 요약(B72 ②)에 `판정 — 호출 k · 사전 h · 스코프로 끝 s · 임베딩 e · 후보 평균 n.n(상한 12)`. **판정 중에도 비용이 보인다**(사용자 요청 2026-09-16 — 추가): 진행 줄 `[판정] 값 i/N · 호출 k · 누적 토큰 t(입력 a · 출력 b)` — 좌표 태깅 진행 줄(B69 ②)과 같은 자리·같은 콜백, 호출마다 갱신. `ingest-dir`는 문서마다의 요약에 더해 끝에 **총계 한 줄**(`전체 — 문서 n · LLM 호출 k · 토큰 t`). `--step`의 [5/7] 판정 단계도 같은 진행 줄을 쓴다.

**완료판정 ①**: 어서션(성질) — 후보 수 ≤ N · 사전 히트 항상 포함 · 같은 부모 아래 후보가 있으면 다른 부모의 노드가 먼저 오지 않는다 · 노드 500개 그래프에서 판정 입력 바이트가 노드 수와 무관 · 실호출 경로에 `embed()` 호출부 ≥ 1(실호출 어서션은 `NotConfigured` 도달로 잰다) · mock LLM 0.

## ② retry는 조건부 · 항목에 이력 (칸 3.1)

- `retry_orphans`는 kind마다 **후보 집합이 바뀌었을 때만** 돈다: `orphan_anchor`는 골격 alias·노드가 바뀐 뒤(bootstrap 시각 > 항목 시각) · `orphan_attach`·`orphan_chunk_link`는 그 카테고리·층에 노드가 늘었을 때만(그래프 노드 수·마지막 변경 시각으로 판정 — LLM 0 조건).
- 항목에 `attempts`·`first_seen`·`last_tried`. `platform queue`가 `N회 재시도 · 해소 0 · 첫 발생 <doc_id>`를 찍는다. `attempts` 상한(예: 5)을 넘으면 더 안 돌고 「사람 판정 대기」로 표시(큐 kind는 그대로).
- 재시도가 LLM을 부르면 그 호출도 인입 요약 줄의 `LLM 호출 k`에 **재시도 몫으로 따로** 센다.

**완료판정 ②**: 어서션(성질) — 노드 집합 불변이면 재시도 LLM 0 · 항목 `attempts` 증가 · 상한 뒤 정지 · 화면에 이력.

## ③ auto 노드는 후보에서 **표시**된다 (칸 3.4)

후보 dict에 `status`(auto/confirmed)와 `provenance` 건수를 싣고 판정 프롬프트(`prompts/3.4_judge.md`)에 「status: auto인 후보는 아직 사람이 확인하지 않은 노드다 — 표기가 같지 않으면 매칭하지 마라」 한 줄. auto끼리 MATCH가 나면 결과를 `uncertain_match`로 내린다(노드는 만들지 않고 큐). 지시문 `version` 갱신.

**완료판정 ③**: 어서션(성질) — 후보에 `status` 있음 · auto↔auto 매칭은 `uncertain_match` · confirmed 후보는 지금과 같다.

## ④ 자동 노드의 사람 확정 — 큐 종결 (칸 0.3 · H12)

```
python run.py ops confirm  <층> <node_id|canonical> --by <이름>              ← 맞다: status auto → confirmed · auto_node 항목 종결
python run.py ops merge    <층> <node_id> --into <기존 node_id> --by <이름>  ← 이미 있는 것(기존 연산)
python run.py ops obsolete <층> <node_id> --by <이름>                        ← 아니다(기존 연산)
```
`confirm`은 I축 4연산(그래프를 바꾸는 것 · 문서 1 L5)에 더하는 것이 아니라 **큐 종결 + status 변경**이다 — 명세 자리는 문서 4 §4.7 큐 처리(허브가 한 줄). `uncertain_match`도 같은 셋으로 종결. `platform queue`는 종결분을 빼고 센다. `platform queue auto_node`가 항목마다 위 세 줄을 다음 줄로 준다(B61 계약).

**완료판정 ④**: 어서션(성질) — `confirm` 뒤 status confirmed · 큐에서 빠짐 · ops_log 5요소 · 툼스톤·타층 id 거부 · `resolve_item` 호출부 ≥ 1.

## ⑤ 부속 — B72 ①의 발견: `pfmea` 쌍이 G39에 걸린다 (칸 1.5)

`schemas/pfmea.json`에 없는 `비고` 열을 어댑터가 낸다 — `verify_roundtrip` 어서션이 의도한 `unknown_field` 재료였다. 허브 판정 **ⓐ**: `비고`를 role: meta로 선언하고, roundtrip 어서션의 재료는 픽스처가 아니라 **시험 안에서 키 하나를 심어** 만든다(시험 재료가 자산의 결함에 기대면 자산을 고칠 때마다 시험이 깨진다). 내장 참조 자산은 관문 대상이다 — 「비대상」 예외를 두지 않는다(ⓑ 기각: 예외가 하나 생기면 다음 잔재가 거기 산다).

**완료판정 ⑤**: pfmea 쌍 G39 PASS · roundtrip 어서션 초록(재료 자급).

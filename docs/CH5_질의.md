# CH5 · 질의 — RAG로 작동하기

> 축3의 전부다. 질의는 읽기 전용이며(P6), LLM은 마지막 답변 생성 한 곳에만 있다.
> 서술 규격: 00_챕터_대장 §3.

## 5.1 질의 4단 파이프라인 [확정]

### 무엇인가 (구조)

```
질문 → ①링킹 → ②확장 → ③수집 → ④답변(LLM)
```

시스템(코드)이 그래프 연결성으로 근거를 고르고, LLM은 받은 근거를 읽고 문장으로 답한다. **LLM은 그래프를 직접 읽지 않는다.**

### 규약

1. **①링킹**: 질문 속 표기 → 그래프 노드. **사전 스캔 우선**(무LLM, 긴 표면형 우선 매칭) → 미스 시 LLM 폴백 → 3단은 임베딩 검색 훅(이연, 5.4). 단일 진입점 라우터가 전역 링킹 후 layer별 질의를 호출한다(§8-R1).
2. **질의는 읽기 전용이다(P6).** 질문에 나온 표기를 사전에 배우지 않는다 — 사용자 입력은 비검증이라 사전을 오염시킬 수 있다.
3. **극성 링킹은 넓게**: 극성 제거 표면형이 양 극성 노드를 가리키면 **읽기는 양쪽 다** 링킹한다(쓰기는 좁게 — CH3B 3.5와 대칭).
4. **②확장**: config의 query_traverse 스펙대로만 뻗는다. 공정층: part_of 하향 재귀·상향 1홉, has_property 양방향 1홉. 품질층: causes·affects 양방향 1홉. cross(occurs_in·controlled_by): **1홉·비재귀·양방향 브리지**. `precedes`는 확장에서 제외한다(순서 정보는 그래프 사실 채널과 flow 특례가 담당). `mirrors`는 기본 확장에 없다(비대칭 조회 시에만 명시 확장 — 훅).
5. **확장은 프론티어 전파다**: 새로 발견된 노드에도 관계 규칙이 적용된다. `recursive: false`는 "같은 관계를 연달아 재추적하지 않음"일 뿐, 다른 관계로 도달한 노드에 그 관계를 적용하는 것은 막지 않는다 — 공정→(part_of 하향)→설비→(has_property)→인자 2홉이 성립하는 근거. 방문 집합으로 순환을 방지한다.
6. **③수집**: 2-tier(직접 링킹 노드의 근거 > 확장 노드의 근거), 상한 8, 최신순. 초과분은 바깥(tier2)부터 잘리고 **잘림은 로그로 남긴다**(계기판 재료).
7. **④답변**: 이원 근거 채널(5.2)을 받아 생성. 근거에 없는 것은 모른다고 답한다.

### 경계와 오해

- **넓은 질의는 층별 요약으로 받는다(카드 J9).** "노칭 관련 전부"류는 전부 긁지 않고 층별 건수 요약을 제시해 좁히게 한다. 허브 폭증의 질의측 방어다.
- **확장 규칙은 전부 config 소유다.** 관계별 방향·재귀는 층의 값이며 core는 스펙을 인자로 받는다 — 층이 늘어도 질의 코드는 불변.

## 5.2 이원 근거 채널과 답변 3단 [확정]

### 규약

1. **채널 1 — [그래프 사실]**: 링킹·확장된 노드의 엣지와 값(필드)을 config의 fact_templates로 문장화한다. 예: "노칭 다음 공정은 스태킹이다"(precedes), "노칭::노칭 정밀도의 규격: ±0.1mm (출처: CP01)"(맥락형 attr는 context 그룹별 한 줄). cross 브리지 엣지의 문장화는 품질층 템플릿을 쓴다(§8-R4). **순서·규격은 이 채널에만 있다** — 청크 단채널이면 "노칭 다음은?"에 답하지 못한다.
2. **채널 2 — [문서 근거]**: 수집된 청크 원문(청크 id·문서·섹션 표기). 서술형 질문의 답. **이 채널이 "노드에서 원본으로 돌아가는 길"이다** — 노드·엣지·값의 provenance(G2, 예외 없이 기록)가 청크를 가리키고, 청크는 원문 무손실 + source_locator(원본 내 위치 표기)를 갖는다. 답변에는 출처(문서·위치)가 표기된다. 원본 파일 바이너리는 저장하지 않으며(source_path 참조) 근거 제공 단위는 청크다.
3. **답변 3단**: 근거 있음 → 근거 기반 답 + 출처 표기, 근거에 없는 내용은 "모른다" / 근거 없음 → "사내 문서에서 근거를 찾지 못했다"를 먼저 밝히고 **[일반지식 — 사내 검증 필요]** 표시와 함께 일반지식 답 제공 / 링킹 미스 → 로그 축적(하이브리드 도입 판정 데이터).
4. **flow 특례**: "전체 공정 흐름" 류 질문은 골격 트리+precedes 체인을 통째로 근거에 공급한다(얇은 골격이라 저비용).

### 원천
명세 §5.6.4, §8-R4. 카드 K6·K7, G2. 문서 노드의 그래프 실체화 여부는 미결 R8 — 출처 추적은 그것 없이 성립.

| # | 유형 | 예 | 답의 소재 | 지원 |
|---|---|---|---|---|
| Q1 | 개체 서술형 | "노칭 프레스 금형 관리 어떻게?" | 청크 | 지원 |
| Q2 | 구조 조회형 | "노칭 다음은?" / "스태킹에 무슨 설비?" | 엣지 | 지원 |
| Q3 | 전역 구조형 | "전체 공정 흐름 설명해줘" | 엣지 전체 (flow 특례) | 지원 |

| Q6 | 개체 없는 열린 질문 | "수율 올리려면 뭘 봐야?" | 청크 (개체 경유 불가) | **훅만** — 링킹 미스율이 정당화하면 하이브리드 도입 |

## 5.4 이연 항목과 벡터 대비 [확정 — 이연 구조 · 임베딩 대상 선택은 미결 R6]

### 규약 — 이연은 "훅 + 트리거 + 준비물"의 세트다 (P7)

| 기능 | 현재 | 도입 트리거 | 준비된 것 |
|---|---|---|---|
| 하이브리드 서치 (링킹 실패 시 청크 임베딩 검색) | 링킹 3단 훅만 | 링킹 미스율 | 전 청크 보존(계약), 물리 사다리 확정: numpy → faiss → 전용 벡터DB |
| 랭킹 고도화 (유사도 정렬) | 최신순뿐 | 청크 잘림률 | 2-tier 수집 구조 |
| 판정 에이전트화 (어려운 판정에 읽기 전용 도구) | 단발 판정 | 판정 보류율 | 범위가 판정 1지점+읽기 전용이라 오염 불가 |
| Q7 집계 | 플랫폼 소관 | 사내 빈출 | 질의 이연 목록 |
| 맥락 크로스 필터 ("M2 라인만") | 노드별 맥락 값 표시는 됨 | 질의 수요 | 저장이 이미 맥락형 |
| **저장 계층 전환 (B-1 샤딩/B-2 SQLite — R10)** | GraphStore 경계만(틀 A8) | **계기판 7·8번 알람선(200MB/30초)** | 경계 뒤 교체라 파이프라인 무수정 |

### 규약 — 벡터 대비: 되돌릴 수 없는 것만 고정 (틀 A1, 카드 N그룹)

임베딩 인덱스는 진실에서 재생성 가능한 **파생물**이다(P5). 모델·리트리버·융합·랭킹은 되돌릴 수 있으므로 측정 후 정한다. 지금 고정된 것은 넷뿐이다:
1. **청크 id 안정성** — 결정적 id(occ 포함 산식, CH6.1). 재적재마다 id가 바뀌면 인덱스가 전량 무효.
2. **전 청크 보존** — 링킹 0건 청크도 보존. 인덱싱할 원본이 없으면 하이브리드를 켤 수 없다.
3. **원문 무손실 보존** — 정규화·요약본은 별도 필드. 원문을 덮으면 다른 임베딩 모델이 원문을 못 본다.
4. **어댑터 버전 기록** — 분할 규칙 변경은 이후 문서에만 적용, 기존 문서 재파싱 없음(카드 N6).

**[미결 R6] 무엇을 임베딩할 것인가** — 청크 / 노드(canonical+정의문) / 경로 직렬화 중 무엇을(복수 가능). 현재 저장 구조가 셋을 모두 지원하므로 지금 고를 필요가 없다. 판정용 임베딩(노드)은 비저장, 청크 인덱스는 재생성 캐시(§5.6.6 임베딩 2종 구분).

### 원천
명세 §5.6.6, §10(P7). 틀 A1·A8. 카드 N1·N4~N7, B6.

## 5.5 계기판과 골든셋 [확정 — BM-25·계기판 8종 · 골든셋 구성은 가결정]

### 규약 — 계기판 8종 (P7의 실행 장치)

| # | 지표 | 무엇을 말하나 | 연결된 결정 |
|---|---|---|---|
| 1 | 링킹 recall (골든셋 기반) | 질문이 노드에 잘 걸리는가 | 품질 기준선 |
| 2 | plateau (문서별 신규 개체율 수렴) | 층 구축이 끝났는가 | 층 완료 선언·다음 층 착수 |
| 3 | 판정 보류율 (큐 유입률) | 판정이 얼마나 막히는가 | 판정 에이전트화 도입 |
| 4 | 청크 잘림률 | 근거가 상한에서 얼마나 잘리는가 | 랭킹 고도화 도입 |
| 5 | 링킹 미스율 | 질문이 그래프 밖으로 얼마나 나가는가 | 하이브리드 도입 |
| 6 | 허브 노드 차수 (카드 J9) | 공정 허브에 유형이 얼마나 몰리는가 | J8 경유 규칙 점검·층 설계 |
| **7** | **graph 저장 크기 (층별 최대 파일 — 신설 08-06)** | 저장 계층이 한계에 얼마나 다가갔는가 | **알람선 200MB → 저장 전환(R10) 판정 개시 (틀 A8-3)** |
| **8** | **build 소요 시간 (신설 08-06)** | 동상 — 쓰기 비용의 직접 관측 | **알람선 30초 → 동상** |

- 7·8은 질의 품질 지표가 아니라 **저장 계층의 운영 지표**다 — 계기판에 두는 이유는 "이연 기능의 도입 여부를 지표가 판정한다"(P7)는 계기판의 정의에 정확히 부합하기 때문이다(도입 대상이 질의 기능이 아니라 저장 전환일 뿐).

### 규약 — 골든셋

1. 질문 유형표(5.3)를 뼈대로 유형별 문항을 구성한다. 실데이터 문항은 사내 진입 후(국면 2). mock 스모크 12문항은 별개(메커니즘 검증용 — 구현문서 §6.4).
2. **골든셋 기준 구성 [⑹-① 가결정 — 세션 N, 07-30]**: 지원 유형(Q1~Q5·Q8) **유형당 15문항**(=90 — recall 차이 ~7%p를 변별하는 최소 수준) + **무답 문항 10**(답변 3단의 "사내 근거 없음" 선언 검증 — 환각 검증용) + **멀티홉 문항 10**(프론티어 전파·cross 브리지 검증) + **범위 밖 확인 10**(Q6·Q7류 — 링킹 미스율 재료) = **기준 120, 허용 100~150.** **가결정인 이유**: 골든셋·계기판은 메인 파이프라인(인입·질의) 밖의 측정 장치라, 이 절만 수정해도 다른 곳이 흔들리지 않는다 — 국면 2에서 실물 문항을 만들며 구체화·조정한다(사용자 결정: "우선 넣어놓고 해보면서 구체화").
3. **BM-25 상시 대조군 [⑹-② 확정 — 세션 N, 07-30]**: 같은 골든셋을 BM-25(키워드 검색 — 전 청크 인덱스, 그래프·임베딩 없음)로 병행 채점한다. 근거: ①P7의 모든 도입 판정이 "무엇 대비"의 측정을 요구 — 대조군 없는 점수는 인상이지 측정이 아니다 ②"일반 검색으로 되지 않느냐"는 사내 질문에 대한 데이터 답변(특히 Q2~Q5 구조·값 조회의 격차가 이 시스템의 존재 증명) ③비용 사실상 0 — 전 청크 보존(N5)이 이미 계약이라 인덱스 재료가 준비돼 있다. **외부 벤치마크 도입이 아니라 내부 대조군이므로 "벤치마크 기본 미반영·개별 논의" 원칙과 충돌하지 않는다.**

### 경계와 오해

- **골든셋은 파이프라인이 아니다.** 골든셋이 없어도 인입·질의는 돈다 — 골든셋은 성적을 매기는 자(尺)이고, 규모·구성의 수정은 이 절 하나의 개정으로 끝난다.
- **BM-25 대조군 ≠ 하이브리드 서치.** 대조군은 우리 시스템 **밖**의 비교 기준(상시 채점 상대)이고, 하이브리드는 우리 시스템 **안**의 확장 기능(5.4 이연 — 트리거는 링킹 미스율)이다. 청크 벡터화 파이프라인은 하이브리드 도입 시점의 구현이며, 그 전제조건 4개는 이미 고정돼 있다(5.4).

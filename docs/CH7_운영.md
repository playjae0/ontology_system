### 규약

1. **국면 1 (외부 구현)** — 기존 5단계: ①core+공정층+mock 인입 ②질의 4단+이원 채널(Q1~Q5·Q8 mock) ③품질층 config-only+층간 연결(**Rule of Three 관찰** — core 무수정 통과가 §3.5 성공 판정. **⑵-③′로 정밀화: 품질층은 기본 내장이 아니라 신규 층 등록 절차의 첫 검증 대상이다 — 카드 J10**) ④플랫폼 연동 ⑤수정 도구+계기판 최소. **※ 실제 구현 순서는 ⑤(G5 수정 도구) → ④(G6 플랫폼 연동)이며, 계기판은 07-30 판정으로 ⑤에서 G6 4′로 이관됐다 — 귀결: R3의 마감선은 국면 1의 끝이 아니라 G5 착수 전이다(7.5.5 가결정 P-8).** 병목은 코드 생성이 아니라 **사람 검수 시간**. **여기에 파서 공용 코어 6종(reader·preflight·normalizer·tagger·validator·기본 어댑터)+생성 하네스+어댑터 생성 킷이 추가된다**(2026-07-29 결정 + 세션 N ⑴⑻ 확정, 파서_명세 §3·§9) — 창작 표본으로 어댑터 생성 전 과정을 리허설 통과시킨 상태로 사내 반입하는 것까지가 외부 범위다. 신규 단위 전량은 CH6 6.2 규약 4(n1~n10)가 정본.

   **국면 1의 완료 판정은 증분0 §8이 소유한다** — 시나리오 15종 전부 + 기존 판정 전 항목 + `git diff core/`가 빈 것(J3) + `run.py all` 2회 동일 그래프. 이 챕터는 별도 조건을 두지 않는다(7.5 규약 2). 단 증분0가 13회차에 동결되어 있으므로 v1.5 동기화 전까지는 §8 + `CLAUDE.md` delta를 겹쳐 읽는다(7.5 규약 2).

2. **[가결정] 국면 1 착수 앞에 "증분 0"이 삽입된다**: 틀 v2.2·v2.3이 국면 0 마감 이후에 확정되었으므로, 신규 단위의 단위 정의·순서·완료판정을 담은 **구현 증분 문서**를 먼저 만든다. 이것 없이 구현문서 v1.16(구 아키텍처)만으로 착수하면 안 된다(CH6 6.2 경계). **세션 N ⑸ 확정으로 증분 0의 재료가 완비되었다**(단위 10종·순서 원칙 4·완료판정 원칙·mock 시나리오 13종 — CH6 6.2·6.3).
3. **국면 2 (사내)** — ①role 배정 실험(첫 작업, 코딩 아님) ②doc_type 스키마 등록(구축 모드 실사용) ③**파서 반입 + 어댑터 생성 세션 실행·검수** — 구판의 "파서 구현(사내 최대 조각)"은 2026-07-29 결정으로 축소되었다: 파서 공용 코어·생성 하네스·어댑터 생성 킷은 **외부 구현·전달물**이며(파서_명세 §9), 사내에서 코딩하는 것은 없고 어댑터는 사내 LLM이 킷으로 생성한다 ④골격 seed 실명칭+골든셋 실데이터(**기준 구성 120 — CH5 5.5 가결정, 실물 제작하며 조정**) ⑤파일럿 인입 수십 건 → 계기판 첫 측정(**BM-25 대조군 병행 — 세션 N ⑹ 확정**) ⑥측정 기반 P7 결정.
4. **국면 3 · PoC 완료의 정의**: 공정층 plateau 도달 + 품질지식층 연결 동작 + Q1~Q5 골든셋 통과 + 계기판 가동. 이후는 운영 — 지속 인입, 큐 소화, 3층 결정(R5), 3층 진입 시 C 공통 승격.
5. **범위 원칙 (사용자 확정)**: 구현은 **기능 축소 없이 전 기능**을 대상으로 한다. 잘게 가는 것은 빌드 단위이지 범위가 아니다.

2. **챕터 파일이 원천, 덱은 파생이다.** 관리 PPT는 챕터 머리표를 렌더러(관리덱_build_mgmt.js)가 읽어 생성한다 — 덱을 직접 고치지 않는다.
3. **버전은 파일명이 아니라 문서 머리에** 둔다(`version:` 필드 필수 — 세션 1 교훈: 버전 없는 챕터는 낡음이 늦게 발견된다). 파일명 규칙: `00_` 기준 문서 / `CH{n}_` 챕터 / `archive/` 보관.
4. **상태 태그 4종**을 절 단위로 단다: `[확정]` / `[가결정]`(전진용 임시 결정 — DECISIONS 기록) / `[보완필요]`(방향 확정·상세 미서술) / `[미결]`(판정 주체·시점 지정).
5. **명세 v1.19의 분해·클린업은 최후 작업이다.** 챕터가 전부 서술완료·안정된 뒤, 명세를 "챕터 소유 절의 원문 보관소"에서 "챕터로의 참조 목차"로 축소한다. 그 전까지 명세는 골격 챕터의 소유 절에 한해 정본이다.
6. **세션 프로토콜(대장 §6)**: 새 세션은 세 문서(틀·카드·용어)를 먼저 물려받고, 여는 문장에서 원천 대조를 수행한다.

## 7.5 전 트랙 작업 계획 [살아있는 절 — 18회차 신설 · 19회차 검증 반영 · 작업이 끝나거나 늘 때마다 갱신]

### 무엇인가 (구조)

**계획의 단일 원천이다.** 이 절이 생기기 전까지 작업 계획은 일곱 군데로 흩어져 있었고(대장 §5.1·§7 ③, 미러 「다음」, 틀 §5, 여는프롬프트, 이 챕터 7.1, 플랫폼 핸드오프 §3.2) 어느 하나도 전체를 보지 않았다.

그 결과 누적된 것 셋 — **①미배정 잔여**(담당이 없는 작업. 목록은 7.5.4·7.5.5) **②트리거 불일치**(같은 시점을 "G4 통과 / G4 정산 / G4 완료" 셋으로 부르던 유형) **③끊긴 트리거 체인 2건**: `P2 착수 조건이 어느 문서에도 없는데 M4가 P2 산출물에 매달려 있었다` · `국면 1→2 전환 조건이 없었다 — CH7과 증분0가 서로를 참조하지 않았다`.

**7.4와의 구분**: 7.4는 **무엇이 정해졌는가**(결정), 7.5는 **무엇을 언제 누가**(작업)다. 결정이 나면 7.4에, 그 결정이 만든 작업은 7.5에 등재된다. **이 절의 가결정 P-N은 7.4 ④에 참조로 등재한다** — 가결정 원장이 둘이 되지 않게.

**두 좌표계가 있고 서로 대응한다.**

```
국면 좌표 (7.1)     국면 0 마감 ─── 국면 1 외부 구현 ─── 국면 2 사내 이식 ─── 국면 3 운영·확장
                                        │                        │
정지점 좌표 (증분0) G0 · G1+G2 · G3★ · [M2 반입·후속] · G4★ · G5 · G6   ∥   P1 · P2 · P3 · 합류 시나리오
```

**국면 1의 끝은 G6이 아니다** — G6 + P3 + 합류 시나리오(S1·S10·S12·S15)까지다. G/P는 병렬이고 합류가 마지막이다.

### 규약

1. **트랙은 셋이고 그 사이에 허브가 있다.** 코드(Claude Code — 레포에서 실행) · 명세(Cowork 별도 세션 — 설계 판정과 정본 개정) · 플랫폼(사내 플랫폼 반영 설계). **허브는 트랙이 아니라 정산 자리다** — 정지점 정산 판정 · 검사 5·6 · 문서 정합 수리 · 레포 재반입 목록.
2. **국면 1의 완료 판정은 증분0 §8이 소유한다** — 시나리오 15종 전부 + 기존 판정 전 항목 + `git diff core/`가 빈 것(J3) + `run.py all` 2회 동일 그래프. 7.1은 이 판정을 참조하며 별도 조건을 두지 않는다 [가결정 P-5]. **단 증분0가 13회차에 동결되어 있으므로, v1.5 동기화 전까지는 §8 + `CLAUDE.md`의 미반영 delta를 겹쳐 읽는다.**

> **[가결정 P-1 — 개정] P2 트리거 = P1 완료 후.** 초판은 "선행: 세션 1P(파서_명세 개정)"를 달았으나 **철회한다.** 근거: ①대장 §5.6-2(사용자 확정) *"명세 문서 다듬기는 차단물이 아니다"* ②대장 §1 파서_명세 행 *"가결정·확정이므로 **코드는 DECISIONS 기준으로 전진, 문서 개정은 세션 1P**"* — 원천이 이미 정반대로 판정했다. >
> **[가결정 P-2 — 철회] 템플릿 v0.3의 소유는 P2(n8)다.** 초판은 "문안은 명세 트랙, 실물은 코드 트랙"으로 갈랐으나 **철회한다.** 근거: 증분0 §3 P2·n8 「하는 일」① *"생성 프롬프트 템플릿 … **D-29·D-30을 반영해 v0.3으로 개정 후 3차 판정**"* — 이미 n8에 명시 배정돼 있다. 파서_명세 §9는 킷 **구성물 목록·규격**의 정본이지 프롬프트 문안의 정본이 아니다. 또 §5.1 "P트랙과 병행" ↔ §7 ③ "P2와 병행"은 **모순이 아니다**(P2 ⊂ P트랙) — 없는 불일치를 근거로 소유권을 옮긴 것이 초판의 오류였다. **세션 1P는 결과를 파서_명세 §5·§9에 사후 반영한다.**
>
> **[가결정 P-3] "G4 = 마지막 정지점"의 뜻을 한정한다.** G4는 마지막 **승인 게이트**(★)이지 국면 1의 끝이 아니다 — 뒤에 G5·G6·P트랙·합류가 남는다.
>
> **[가결정 P-10] P3 트리거 = P2 완료 후.** 증분0 순서 원칙 ③은 *"n6은 n7 이후"*만 규정해 P2와의 선후를 남겼다. 근거: 증분0 §8의 합류 시나리오 S1·S12·S15가 **n6·n8 공동 판정**이므로 n8이 서지 않으면 P3의 완료판정이 성립하지 않는다. 확정 경로: P트랙 착수 시.

### 경계와 오해

- **이 절은 계획이지 결정이 아니다.** 무엇이 참인지는 틀·카드·챕터가, 무엇이 정해졌는지는 7.4가 갖는다. 여기서 다투어야 할 것은 순서와 담당뿐이다.
- **이 절이 상위 규범을 뒤집을 수 없다.** 초판의 P-1·P-2가 대장 §5.6-2(사용자 확정 진행 원칙)를 뒤집어 코드 트랙을 문서 트랙 뒤에 세웠고, 19회차 검증에서 철회됐다. **계획은 원칙의 하위다.**
- **"미배정"은 안 해도 된다는 뜻이 아니다.** 담당이 정해지지 않았다는 뜻이고, 그 상태가 오래가면 항목이 조용히 사라진다 — 11회차의 `실행검증_1차` 누락이 6일 뒤 "DECISIONS 25건 vs 31건" 상충으로 되돌아온 것이 실례다.
- **국면 좌표와 정지점 좌표는 같은 것을 다르게 자른 것이다.** 국면 1 안에서 G와 P는 병렬이고, 국면 1의 끝은 합류 시나리오다.
- **트리거가 "실수요 확인 시"·"관찰 데이터가 판정"인 항목은 지금 논의 대상이 아니다.** 근거 없이 앞당겨 판정하면 P7(측정 후 결정) 위반이다.

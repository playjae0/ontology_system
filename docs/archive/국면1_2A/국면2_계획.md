# 국면 2 계획 — 실 연결과 사내 이식

> **작성 근거**: 국면 1 종결 시점의 레포 실물 감사 2회(LLM 이음매 감사·산출물/시각화 감사, 2026-08-21). 정적 판독이 아니라 **클론 후 실행 검증**(회귀 423건 재현·CLI 전 명령 실행)까지 포함한 결과다.
> **이 문서의 지위**: 작업 정본. 정제본(명세)은 "무엇을 만드는가"를 정하고, 이 문서는 "지금 무엇이 없고 어떤 순서로 채우는가"를 정한다.

## §0 판정 — 왜 국면 2가 사내 반입의 전제인가

**LLM 이음매가 없다.** 명세(배경 구명세 트리)가 못박은 `core/llm.py`·`core/embeddings.py`는 **전 히스토리 123 커밋에서 한 번도 생성된 적이 없다**. 레포가 "훅 5곳"이라 부른 것은 전부 주석 문자열이고, 자동 점검(`doctor.py`)이 문자열 `"HOOK"`을 세기 때문에 주석이 남아 있는 한 계속 훅이 있다고 보고한다. `USE_MOCK`을 실제로 읽는 비테스트 코드는 3곳뿐이며 그중 하나(`matcher._use_mock`)는 **호출부가 0인 죽은 코드**, 하나(`doctor`)는 화면 출력, 하나(`extract`)만 `NotImplementedError`를 던진다. 즉 **USE_MOCK=0은 시스템 전역 스위치가 아니다** — matcher·struct_map·register·query·ops·tagger는 USE_MOCK=0에서 완전히 동일하게 동작한다.

**다만 "아무것도 못한다"는 과장이다.** LLM 없이 끝까지 도는 경로가 실재한다: 골격 부트스트랩(사내 skeleton.json 교체 시 코드 변경 0) · 실제 xlsx/pptx 파싱(openpyxl·python-pptx 실물) · **정형(table) 인입 전 구간**(`kind=="table"`은 extract를 거치지 않고 그래프까지 완주) · 질의·열람·내보내기(전부 결정적). 반대로 반드시 막히는 것: 비정형 관계 추출(공정층 `extract_patterns`가 빈 배열이라 prose 관계 **영구 0건**, 청크당 최대 1관계, 개체 인식이 골격 seed 스냅샷만 봐서 **실문서 신규 개체 미발견**) · 동의어 병합(`_similarity`가 공백 제거 후 포함관계가 아니면 0.0 → "노칭기"와 "노칭 프레스"가 별개 노드로 누적) · 신규 doc_type 등록(fixture 2종 밖은 `SystemExit`).

**가장 위험한 것은 크래시가 아니라 조용한 오염이다**: `parser/pipeline.py`가 이미지 요약 함수를 넘기지 않아 실제 PPT/엑셀 이미지의 청크 텍스트가 리터럴 `"MOCK 요약: img_001"`이 되고, 그 문자열이 색인되어 **답변 근거로 반환될 수 있다**.

**결론**: 사내 실물 문서로 의미 있는 결과를 보려면 국면 2A(실 연결)가 선행해야 한다. **사내 반입 시점은 2A 완료 이후**로 잡는다.

## §1 국면 2를 둘로 쪼갠다

| | **2A 실 연결** | **2B 사내 이식** |
|---|---|---|
| 목적 | mock 위의 메커니즘을 **실제 모델·실제 열람·실제 그림**에 연결 | 사내 실물 문서·실 골격·보안 절차로 옮김 |
| 전제 | 없음 — **지금 바로 착수 가능** | 2A 완료 + 사내 승인·게이트웨이 실물 |
| 일정 종속 | 우리 통제 | 사내 일정에 묶임 |
| 검증 | mock 문서로 실 연결 회귀 재수립 | 사내 문서 파일럿 → 계기판 첫 측정 |

**왜 쪼개는가**: 섞으면 2A가 2B의 사내 일정에 인질로 잡힌다. 그리고 2B에서 보여줄 것이 있으려면 2A가 먼저 끝나야 한다 — 지금 상태로 반입하면 "정형 엑셀은 되는데 동의어가 안 합쳐지고 prose는 0건"인 물건을 보여주게 된다.

## §2 2A 작업 목록 — 우선순위 순

### ㉠ 오염 차단 (최우선 — 실 연결 전에도 즉시)
- 이미지 요약 미연결 상태에서 **자리표시자 문자열이 청크·그래프에 실리지 않게** 한다. 요약이 없으면 청크를 만들지 않거나 명시 표시로 격리한다. 근거: 정제본 7 §7.6-B 4항.
- `PROMPT_VERSION` 하드코딩이 체크포인트 재현성 기록에 남는 문제 — 템플릿 파일 로더와 연결하거나 기록에서 뺀다.

### ㉡ 게이트웨이 2파일 (모든 것의 전제)
- `core/llm.py`: `chat(messages, *, model=None, json_schema=None) -> dict` + 설정·재시도·JSON 파싱. **LLM 설정 접근의 유일한 수렴점.**
- `core/embeddings.py`: `embed(text) -> vector`.
- 환경변수 3종(게이트웨이 주소·인증·모델명) — 실명칭은 [사내 확인] 슬롯.
- 의존 매니페스트(requirements) 신설 — **현재 레포에 의존 선언 파일 자체가 없다**.

### ㉢ LLM 지점 7종 실호출 배선
착수 순서는 **사내 가치 기여도** 순이다.

| 순 | 지점 | 현 상태 | 필요 작업 |
|---|---|---|---|
| 1 | **개체 동일성 판정**(matcher) | 쌍별 문자열 포함 비교 | `resolve()`의 후보 수집을 분리하고 `_llm_judge(surface, category, candidates)` 신규. **이음매 형태부터 틀렸다** — 명세의 LLM 판정은 mention+후보 집합 일괄인데 코드는 쌍별 비교다. 실문서 중복 노드 누적의 급소 |
| 2 | **비정형 추출** | `NotImplementedError` 가드 | `_llm_candidates()` 신규 + 호출부 분기 + 프롬프트 로더. 공정층 `extract_patterns` 빈 배열도 함께 처리 |
| 3 | **임베딩·질의 링킹 3단** | 지점 자체가 부재 | `core/query.py link()`에 사전 스캔→벡터→LLM 3단 신설. 벡터 저장/검색 신규 |
| 4 | **이미지 요약** | 함수 주입 구멍은 있으나 호출부가 안 넘김 | `pipeline.parse()`부터 배선 |
| 5 | **구축 모드 생성** | fixture 경로 반환만 | `generate_adapter()` 신규 — 템플릿 로드+모델 호출+**파일 실제 생성**. 입력 패키지 조립은 이미 실물이라 재사용 |
| 6 | **구조 지도 패스** | 파일 우선 + 번호 휴리스틱 | `_llm_map()` 신규 + 분기 |
| 7 | 병합 canonical 추천 | 결정적 정렬 | 후순위 — 사람 확정이 정본이라 급하지 않다 |

**유리한 조건**: 소비 쪽 **데이터 계약이 실물이고 423개 테스트로 고정돼 있다**(추출 체크포인트 형태·struct-map row 형태·어댑터+스키마 쌍·fact_templates). 반환 형식을 새로 설계할 필요가 없고 **생산자만 쓰면 된다** — 이것이 국면 1의 실질 자산이다.

### ㉣ 시각화 3형태 (사용자 요구 4)
- 현황: Cypher·CSV·Mermaid 3종은 실물(노드 100·엣지 150·50KB Cypher 실측). **HTML 그래프 뷰어는 없다** — 명세(CH6 §6.4 규약 2)가 요구한 `viz.py` 3형태 중 html이 통째로 미구현이고, 이 요구가 정제본에서도 누락됐던 것을 정제본 7 §7.8에 복원했다.
- 작업: 단일 HTML 파일 뷰어(vis.js/cytoscape 계열 인라인) — GraphStore 경유로 읽고(B6), `layer`·`category`·`status`·`tier`·`polarity` 필드로 필터·색상·LOD. **전체 렌더가 가능한 규모다**(100노드/150엣지, 알람선 200MB 대비 0.09MB).
- 변환 지점 2개: ①`graph.json`의 노드는 배열이 아니라 **id-keyed dict** ②**엣지에 `layer` 필드가 없다** — cross 엣지 23건은 파일 위치로만 층을 안다(합칠 때 주입 필요).
- 기존 결함 동반 수정: `export mermaid quality`가 조용히 빈 다이어그램을 낸다(`layers/quality/config.json`에 `skeleton.relations` 부재 → 0노드, exit 0).

### ㉥ mock 격리 (사용자 요구 2)
**mock은 "걷어낼" 대상이 아니라 "테스트 픽스처로 격리할" 대상이다.** 물리적으로 지우면 `gauges`·`scan`이 죽고 회귀 423건이 ~34건으로 붕괴한다(실측). 원인은 `core/`·`parser/`·`cli/` 본체가 mock 경로를 **USE_MOCK 분기 밖 무조건 상수**로 알고 있다는 것 — mock 경로 참조 중 USE_MOCK 분기 안에 있는 것은 **0건**이다.

- 그냥 지울 것: `mock/review_views/`(4) · `mock/fixtures/log/`(9) · 코드 참조 0인 raw 2종.
- 코드 수정이 따라야 할 것 6개 참조점: `cli/platform.py`(queries.json 무가드 read — 없으면 `gauges` 사망) · `cli/scan.py`(존재하지 않는 디렉터리를 모듈 파일로 로드하는 버그 — 하드 크래시) · `run.py`(parsed glob — 조용한 무동작) · `core/extract.py`(힌트 경로가 **코어 본체**에) · `parser/struct_map.py`(지도 경로 동일) · `tools/gen_parsed_mock.py`(동반 제거).
- 남길 것: `mock/parsed`·`raw`·`queries.json`·`fixtures/{adapters,schemas}`·`extract_hints`·`struct_maps` → **`tests/fixtures/`로 이동**. 없으면 "반입물이 온전한가"를 사내에서 증명할 수단이 사라진다.
- 주의: `extract_hints` 제거는 크래시가 아니라 **결과를 조용히 바꾼다**(실측 대조: 동일 문서에서 `주액기`(Unit)→`주액`(Process), attach 1건→0건). 회귀 기준선을 다시 세워야 하는 자리다.

### ㉦ 실 연결 회귀 재수립
2A의 마감선. mock 회귀 423건은 **결정적 mock 위의 판정**이라 실 연결에서는 그대로 쓸 수 없다. 실호출 경로용 판정 기준을 따로 세운다 — 모델 출력은 비결정적이므로 "동일 산출"이 아니라 **계약 준수·불변식 위반 0·큐 착지 정합**으로 판정한다. 정제본 7 §7.6-B 3항(두 갈래가 같은 반환 계약)이 이것을 가능하게 하는 조건이다.

## §4 국면 1과의 관계 — 상충 여부

사용자 4개 논점 중 **2·3·4는 국면 1과 상충하지 않는다**(전부 국면 2 작업이며 국면 1 판정을 흔들지 않는다). **1은 부분 상충했고, 정제본 개정으로 해소했다**:

- 국면 1 완료판정(시나리오 15종+config-only+클린 2회)은 **메커니즘 검증 기준으로는 참**이고 뒤집지 않는다.
- 그러나 그 판정은 "시나리오가 통과하는가"만 셌고 "명세가 요구한 파일이 있는가"를 세지 않았다. 그래서 `llm.py`·`embeddings.py`·`viz.py` 3파일 부재가 판정을 통과했다.
- 처방: 정제본 7에 **§7.6-B 실 연결 규격**(USE_MOCK=0의 대칭 요구) 신설 + §7.6에 **범위 진술**(완료 = mock 위 메커니즘, 실 연결은 별도 확인) + §7.8에 **시각화 3형태** 복원. 이로써 "정제본만 읽고 재구성하면 또 mock 전용 시스템이 나온다"는 구멍이 닫혔다.

**정제를 지금 한 것은 옳았다.** 근거: ①정제 검증이 아니었으면 못 잡았을 규범 모순 3건·손실 28건을 국면 2 코드가 쌓이기 전에 잡았다 ②오늘 4개 질문에 문서 대조로 답할 수 있었던 것 자체가 정제본 §7.8 산출물 표 덕이다 ③V4가 낸 명세 공백 56건이 국면 2 안건 목록 그 자체다 — 정제 없이 시작했으면 무엇을 정해야 하는지 모른 채 코드를 썼다. 국면 2가 끝나면 정제본은 개정된다. 그것은 실패가 아니라 **개정 규칙이 예정한 정상 경로**이고, 개정을 40문서 더미가 아니라 정돈된 10종 위에서 하게 된 것이 정제의 값이다.

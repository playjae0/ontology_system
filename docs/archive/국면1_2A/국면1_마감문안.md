**실행이 찾은 명세 공백 = [개정]의 새 원천.** 읽기 검증(감사 12회)이 못 본 것을 구현 4회가 찾았다 — B10(anchor 판정 강도)·B14(좌표 없는 노드)·source_hash 전부 *"두 규칙이 각각은 옳은데 함께 서면 틀리는"* 형태였다.

## 3. 배운 것 — 다음 국면이 물려받을 셋

1. **회귀는 필요조건이지 충분조건이 아니다.** 526건 전초록에서 2홉 질의가 끊겨 있었다 — 어서션 없는 자리는 초록이 지켜주지 않는다. 명세를 다시 읽어 대조하는 별도의 눈이 주기적으로 필요하다.
2. **요청문은 명세가 아니다 — 갈리면 명세가 이긴다.** P-B에서 요청문의 `attach_conflict` 지시가 틀렸고 구현자가 명세를 따랐다. 그 판단이 보고에 남아 되짚을 수 있었다.
3. **답이 있어도 못 찾으면 공백과 같다.** P-B 미완 4건 중 3건이 "명세에 있는데 못 찾은 것" — 처방은 명세를 더 쓰는 게 아니라 요청문이 좌표를 주는 것(P-C §2-0) + 입구 문서(구조 설명서).

## §2. 틀 §4B-A11 삽입 문안 (전문)

### A11. 골격의 두 축 — 분해는 구조, 순서는 지식 [M2 판정(사용자) — 2026-08-10]

> 배경: precedes가 구조인지 지식인지 미정인 채 "seed 나열 순서 자동 파생"으로 운영되어, ①극성 형제를 나열하는 순간 거짓 순서(세대 종속 순서를 공장 무관 진실처럼)가 생기고 ②전극 공정의 극성별 병렬 체인과 공정 내 부분 분화(일부 스텝만 극성이 갈림)를 표현할 수 없었다. 제조 정보모델 표준(ISA-95/88·BOP)이 분해 계층과 라우팅을 별도 모델로 가르는 것과 같은 분리를 명문화한다. R9(electrode_type)는 이 분리 위에서 종결된다.

**A11-1. part_of = 구조 [채택]**
> 공정의 분해 계층이며 **공장·제품·세대 무관으로 참인 것만** 담는다. 이것이 주소 체계(좌표 태깅·anchor의 대상)이고 골격의 본질이다. 깊이는 가변이며 기본 3단(main>sub>detail)을 상정하되 고정하지 않는다 — 구 "2단으로 시작" 서술은 이 문안으로 대체.

**A11-2. precedes = 지식(대표 흐름) [채택]**
> 순서는 구조가 아니라 **"대표 흐름"이라는 한 벌의 지식**이다(용도: Q2·Q3 질의). 선언 기준: **회사 표준·현행 기준의 대표 순서 한 벌** — 공장·세대별 미세 상이는 "대표"라는 지위가 명시적으로 흡수한다(그래서 구조가 아니라 지식이다). **선언 방식: seed 자식 배열의 순서가 곧 선언이다**(별도 FLOW 블록 없음, 단일 원천). 구 "나열 자동 파생"과의 차이는 **비참여 옵트아웃의 존재**다: `::` 인스턴스는 자동 비참여, `{"@unordered": <항목>}` 래퍼는 개별 무주장, `"@noflow"`(배열 첫 요소)는 그 부모 아래 전체 무주장 — 따라서 **극성 인스턴스 간 순서와 병렬 스텝의 거짓 순서는 구조적으로 생기지 않는다.** 비참여 항목 사이는 "순서를 주장하지 않음"이다(병렬 단정도 순차 단정도 아님). 문서에서 순서를 추출하지 않는다는 기존 금지(명세 §5.3)는 유지된다 — 출처는 seed 하나뿐.

**A11-3. 부정형 [명문화]**
> **공장별·세대별 실제 라우팅은 골격에 넣지 않는다.** (예: 구세대 설비의 "양극 스텝 전부 후 음극 진행" 순서, 극성 스텝 간 인터리브 방식.) 그것은 공장 무관 골격(T0)의 자격이 없는 지식이다. 표현·저장(신규 층 / context 붙은 순서 엣지 / T3 참조 중 택일)은 R13으로 이연한다. 안전 근거: 골격 노드 id 불변(P4)이 미래 라우팅의 참조 안정성을 보장하고, precedes의 지식 강등이 공존을 보장하며, 라우팅 문서의 원문은 전 청크 보존(N5)으로 이미 소급 가능하다 — 재적재를 강제하는 항목 0.

**A11-4. 극성 표현 3패턴 [채택 — 케이스 ①/② 폐지 · 단극성 문법 확정]**
> 분화의 실제 단위는 공정이 아니라 **스텝**이다 — 한 공정(예: 탭용접) 안에서 일부 스텝만 극성이 갈리고 공유 스텝(이송·검사·마킹 등)은 극성 무관으로 흐른다. 공유 스텝을 극성 가지 안에 복제·격리하는 구조는 금지한다. 표현은 3패턴이며 **어느 패턴을 쓸지는 사람이 공정·스텝마다 정한다**(골격=Tier1):
>
> | 패턴 | 조건 | 표현 |
> |---|---|---|
> | **① 극성 무관** | 극성별로 다른 것이 없다 | 노드 하나 (polarity: none) |
> | **② 주소만 극성** | 스텝·지식은 공통 개념인데 **극성 라인이 실재하고 문서·관행이 극성 공정명을 쓴다** | 개념 노드 + **자식 없는 극성 인스턴스** (예: 노칭 — 전극~노칭은 극성 라인 완전 분리) |
> | **③ 스텝 분화** | **그 스텝이 극성별로 따로 관리된다** | 스텝 개념 노드 + 극성 인스턴스 자식 (`@split`) |
>
> **단극성 특이 공정 = `"@cathode"` 또는 `"@anode"`** — @split의 단극성형이며 **개념 노드 + 인스턴스 1개**를 만든다(명시형 `{"::anode": []}`와 동일). 개념을 생략하지 않는 근거: 반대 극성이 나중에 실재로 판명되면 `@anode` → `@split` 한 글자 수정으로 끝난다 — 기존 노드 무개명·alias 무이동(전달⑥의 결정성 계보). 인스턴스 canonical의 극성 접두도 쌍 유무와 무관하게 균일 유지(같은 근거). **리스트 표기(`["anode"]`)는 금지한다** — 리스트는 자식 배열이므로 "anode"라는 공정 노드가 생겨 마커와 이름이 충돌한다. **Tier1의 단극성 인스턴스는 mirror_asymmetry 큐에 올리지 않는다**(사람 보증 = 짝 없음이 의도. 큐는 Tier2의 문서 편측 갱신을 잡는 장치다).
> 설비만 다른 경우는 어느 패턴도 아니다 — Unit(잎사귀)에서 가른다. **극성 인스턴스 간에는 precedes가 생기지 않는다**(자동 비참여) — 그것이 곧 병렬의 표현이며, 명시적 병렬 주장 장치는 별도로 두지 않는다. "cathode 구간에 속한 스텝"은 노드 소속이 아니라 **파생 집합**(공통 조상 + polarity=cathode)이다 — 트리는 단일 부모이므로 구간 소유와 스텝 개념 소유를 동시에 가질 수 없고, 스텝 개념이 부모를 갖는다(공통 alias의 모호성 방지가 우선).

**A11-5. 순서 파생 규칙 [채택 — 질의 traverse 확장, 결정적 코드]**
> 노드 X의 "다음"을 물으면: ①X 자신에게 precedes 선언이 있으면 그것이 답 ②없으면 부모 P로 올라가 P의 후속 Q를 찾는다 ③Q에 X와 같은 polarity의 인스턴스가 있으면 그 인스턴스, 없으면 Q 자체 ④조상까지 선언이 없으면 "순서 정보 없음"으로 답한다(추측 금지). 귀결: 극성 인스턴스의 순서는 선언 없이 파생되고(pre용접::cathode → pre vision::cathode), **공유 스텝 합류가 자동이다**(laser용접::cathode 다음 → bead press). 파생 답은 어느 해상도에서 나온 답인지 표기한다(fact_template — G4 상세).

**A11-6. 좌표 태깅 닫힌 목록 = 골격 전 노드 [채택 — D5 구조 소멸(스텝 레벨 포함)]**
> 파서에 공급하는 닫힌 목록은 **골격 전 노드**(개념+인스턴스)다. 문서가 상위·개념 해상도로 말하면("탭용접", "pre 용접") 개념 노드를 고른다 — 오류가 아니라 **저해상도 부착**(규칙 B의 철학). **극성 모호 규칙(카드 D5)은 전 레벨에서 구조적으로 소멸한다**: 극성 무관 표면형의 alias는 개념 노드만 소유하고, 극성 수식 표기는 인스턴스의 alias(auto — A11-7)다. "쓰기는 좁게(문서가 말한 해상도), 읽기는 넓게(part_of 하향 포함)"는 유지.

**A11-7. tier와 process_group 파생 [채택 — main/sub/detail]**
> `tier`는 **main(대공정) / sub(공정) / detail(세부공정)**이며 사람이 적지 않는다 — **loader가 seed 중첩 깊이에서 파생한다**(1단=main, 2단=sub, 3단 이하=detail). **극성 인스턴스(마커·@split·@단극성 산출)는 깊이 계수에서 제외하고 자기 개념의 tier를 상속한다.** **process_group = 조상 사슬에서 tier:main인 첫 노드**로 파생한다 — 구 "골격 트리 부모" 규칙(A7-4·C3)은 깊이 가변에서 거짓이 되므로 대체. process_ref = 태깅된 노드 자체. coord_mismatch 대조는 동일하게 동작한다.

**A11-8. R9 종결 — electrode_type은 구조 필드, polarity는 파생 필드 [채택 = 안 C, D-1 확정 승격]**
> `electrode_type`은 **role 배정 대상이 아닌 구조 필드**다 — fields·블록에 넣지 않고, 검수 뷰 6지선다에 올리지 않으며, 소비자는 entity 해소 코드 하나다. 원천 다수(정의서 §5.1 attribute·구현문서 §2.4 role:attribute)는 **문법적 불가능을 근거로 기각**한다: 극성 결합 대상이 한 행의 Unit·Property 둘인데 attach_to_field는 하나만 지정한다.
> **해소 코드는 극성 결합 판정 시 노드(Unit·Property)에 `polarity` 파생 필드를 기록한다.** 닫힌 4값: `cathode` / `anode` / `none`(both·무표기) / `unbound`(극성 표기 있었으나 게이팅 ①②③ 미충족 — 걸침 필드의 [사내 확인] 후 재검토 시 복원 경로). Tier1 seed에서는 극성 마커·@split·@단극성에서 loader가 파생한다 — **polarity·tier는 seed·시스템 전용 어휘이며 LLM·스키마·attribute 핸들러가 쓸 수 없다.**
> **원칙: 코드는 canonical 문자열을 파싱해서 판정하지 않는다.** 판정 근거는 필드다. (process_no 강등·id 무의미화와 같은 계보의 세 번째 결론.) canonical의 `::cathode`는 저장 정보가 아니라 층 내 유일한 이름을 만들기 위한 표기다. mirrors·순서 파생·극성 필터는 전부 polarity 필드 위에서 돈다.
> 분화 축 일반화(identity_axis를 config로 — 안 D)는 이연한다. 트리거: 극성 외 두 번째 분화 축이 실물에서 관찰될 때(Rule of Three).

**A11-9. 부착 정합 — 골격 polarity와 극성 결합의 상호작용 [신설 — 사용자 질문("main용접::anode에 값이 잘 붙는가")이 검출한 미정의 지점]**
> ①**이중 결합 방지**: 부착 대상 골격 노드의 polarity가 none이 아니면 **표면형 극성 결합을 생략한다** — 극성이 이미 주소(스코프 접두)에 있으므로 표면형에 다시 붙이면 이중 표기다(`…::anode::anode 용접 강도` 금지 — F11 이중 접두 방어의 확장). 생성되는 Property·Unit의 polarity 필드는 기록한다(부착 노드에서 상속).
> ②**polarity 대조**: record의 electrode_type과 부착 골격 노드의 polarity가 **둘 다 확정인데 서로 다르면** 조용히 한쪽을 택하지 않고 **coord_mismatch 큐**로 표면화한다(C3의 좌표 대조와 같은 계열의 공짜 검증).
> ③부착 사슬 전체는 기존 메커니즘으로 성립한다: 좌표 태깅(닫힌 목록에서 LLM 선택 — 문자열 일치 아님) → anchor 해소(사전 → 판정 → orphan_anchor 안전망) → Property canonical 스코프(부착 노드 접두 — 극성별 자동 분리) → attribute 저장. 실증은 G3(C11 coord_mismatch 실발생·S14)가 담당한다.

## §4. 골격 seed 작성 규칙 v3.2 (CH4 4.4 편입 + seed 파일 머리 주석)

> 1. **구조는 순서 있는 자식 배열의 중첩으로 쓴다** — 항목은 `"이름"`(잎) / `{"이름": [자식배열]}`(중간) / `{"이름": "@split"|"@cathode"|"@anode"}`(극성 스텝) / `"::cathode"`·`"::anode"`(주소 인스턴스) / `{"@unordered": <항목>}`(순서 비참여 래퍼) / 배열 첫 요소 `"@noflow"`(레벨 전체 무주장). **마커 어휘는 닫힌 7종** — 그 외는 명시적 실패. tier·parent·접두·polarity는 loader 파생 — 수기 접두·이름 문자열 마크업 금지.
> 2. **배열 순서가 곧 대표 흐름 선언이다**(회사 표준·현행 기준 한 벌). 비참여: `::` 인스턴스(자동) / `@unordered` 래퍼(개별 — 병렬 스텝) / `@noflow`(순서 미상의 대량 나열용). 체인은 참여 항목만 건너 잇는다.
> 3. **극성은 3패턴 + 단극성**: 무관=그냥 노드 / 주소만=`::` 인스턴스 / 스텝 분화=`@split` / 단극성=`@cathode`·`@anode`. 리스트 표기(`["anode"]`) 금지. 설비만 다르면 어느 것도 아님(Unit에서).
> 4. **이름과 alias**: 배열에는 짧은 이름만. main/sub 충돌은 명시적 실패. **ALIASES는 skeleton.json 안의 분리 블록**(별도 파일 아님)이며 **지위는 사전이 아니라 원천이다** — 사람 보증 초기 표기만 담고, loader가 dictionary.json(전 층 공유 단일 장부 — B4)에 `provenance: ["seed"]`로 등재한다. 운영 중 표기 축적은 매칭 경로(E5)로 같은 사전에 쌓이며 seed 유래와는 **provenance 태그로 구분**된다(구역 분리 아님 — 조회는 표면형 전체를 한 번에 본다). 키는 짧은 이름 허용, 모호하면 접두 요구(명시적 실패). 극성 수식 표기는 auto alias가 생성하므로 불요. **소비처(anchor 해소·좌표 닫힌 목록·판정 후보·질의 링킹)는 전부 사전만 본다 — seed ALIASES를 읽는 것은 loader뿐이다.**
> 5. **비참여 = 무주장**: 병렬 단정도 순차 단정도 아니다.

> **형식 판정의 경위 [기록]**
> r2~r5는 트리(구조)와 FLOW(순서)를 별도 블록으로 분리했다. **사용자 반박 3건으로 재판정(r6)**: ①무주장 필요 사례의 대부분(극성)은 마커 문법이 이미 순서 밖으로 빼놓았고, 잔여(병렬 스텝)는 옵트아웃으로 충분 ②"JSON 키 순서 무의미" 논거는 dict 형식의 약점 — 배열로 바꾸면 소멸 ③복수 사슬·합류는 실제 seed에서 0회 사용(P7 위반 방어). 추가로 **두 블록의 순서 불일치는 validator가 못 잡는다**(이름만 검증) — 단일 원천만이 이 혼선 클래스를 없앤다. → **배열=흐름 단일 파일 채택.** r7: `~` 접두를 `@unordered` 래퍼로 교체(이름 문자열 마크업 금지). r8: alias 별도 파일 폐지 — **원천(seed 블록)과 장부(dictionary.json)의 2층 구조**로 정리(골격 노드의 seed→그래프 관계와 동형 — 3.9).
> **남는 트레이드오프(의식된 수용)**: 비참여 표시 누락 = 거짓 순서. 구문으로 완전 제거는 불가능하며(형식은 물리적 사실을 모른다 — 구 FLOW 형식도 동일), 완화 3겹: ①래퍼 객체는 배열에서 시각적으로 도드라진다 ②**loader가 로드 시 파생 대표 흐름을 사람이 읽는 형태로 출력한다**(M9 결과 뷰 계보 — 틀린 순서는 나열로 보면 즉시 보인다, n10 완료판정 포함) ③틀려도 seed 1줄+재빌드로 복구(id 불변 — G3), 답변은 "대표 흐름 기준"을 표기해 파급 한정.
> **그래프 의미론은 불변**: precedes = 대표 흐름 지식 · 출처는 seed뿐 · 극성 인스턴스 간 미선언 · 라우팅 배제(R13) — 바뀐 것은 선언의 문법뿐이다.

**loader 파생·검증 규칙 (n10 소유)**

| 항목 | 규칙 |
|---|---|
| tier | 깊이: 1=main, 2=sub, 3+=detail. 인스턴스는 깊이 계수 제외, 개념 tier 상속 |
| parent / part_of | 중첩. 마커·@split·@단극성 인스턴스의 부모 = 그 개념 노드 |
| polarity | 마커(`::cathode`/`::anode`)·`@split`·`@cathode`·`@anode`에서만(닫힌 어휘). 없으면 none |
| precedes | **자식 배열의 참여 항목 순서에서 파생** — 비참여(`::`·`@unordered`·`@noflow`)는 건너뛰고 잇는다. @split류 개념은 참여, 인스턴스는 비참여 |
| canonical | main/sub = 이름 그대로. sub 이하 = 부모 경로 접두 균일. 인스턴스 = `{개념}::{극성}` — 쌍 유무 무관 접두 균일 |

### 11-3. 판정

**규칙 본체는 축 무관이다.** 특수 잔재는 "분화 축의 이름과 값" 하나로 수렴하며, 그것은 ①계약의 한 필드(B1 예외로 명시·격리) ②config·seed의 데이터로만 존재한다. 다른 도메인 이식 시 바뀌는 것은 identity_axis의 선언 내용뿐이고 규칙·코드 구조는 불변 — **확장 조건 충족.** 이 판정 자체를 A11의 서술 원칙으로 삼는다: **이후 A11 계열 규칙의 문안은 "극성"이 아니라 "분화 축"으로 일반형을 쓰고, 극성은 그 첫 사례로 표기한다** (안 D 채택 시 개정 비용을 문안 수준에서 0으로 만드는 조치).

# 정제본 부록 · 용어 대장

> **지위**: 이 체계의 모든 용어의 **단일 정의처**다. 본문 문서는 용어를 재정의하지 않고 사용만 한다. 새 단어는 여기 등록이 먼저다(등록 = 합의 절차).
> 규칙: 정의는 1줄 + 예시 1개 + 원천 1개. 여기의 정의는 "빨리 통하기 위한" 요약이며, **본문 규범과 충돌하면 본문이 이긴다.**
> 원천 표기: 정제본 문서 번호(0~7·부록)로 가리킨다. "(구)" 접두는 정제 전 원천 체계의 좌표다 — 세부 §가 필요하면 원천 보존본에서 찾는다.

## 1. 기본 구조 (그래프와 층)

| 용어 | 뜻 (1줄) | 예시 | 원천 |
|---|---|---|---|
| **정보층 (층)** | 성격이 같은 지식의 묶음 단위. 층마다 카테고리·관계·골격을 따로 정의한다 | 공정정보층, 품질지식층 | (구)명세 |
| **노드** | 그래프의 개체 하나 | "노칭"(공정), "노칭 프레스"(설비) | (구)명세 |
| **엣지** | 노드 사이의 관계 한 줄 | 노칭 프레스 ─part_of→ 노칭 | (구)명세 |
| **카테고리** | 그 층에서 노드가 될 수 있는 종류의 닫힌 목록. 사람이 정의문으로 고정, LLM은 이 중에서 고르기만 | 공정층: Process/Unit/Property | (구)명세 |
| **골격 (skeleton)** | 사람이 직접 심는 고정 뼈대. 자동 생성 금지 영역. seed 형식은 v3.2(순서 배열+마커 — 문서 1) | 공정 트리, FailureEffect 목록 | (구)명세 |
| **Tier1 / Tier2** | Tier1=사람이 파일로 고정하는 구조(골격·유형), Tier2=문서에서 자동 생성되는 인스턴스. 구조적 차이는 "원천의 위치"(파일 vs 그래프) 하나 | 공정 트리는 Tier1, 발견된 설비는 Tier2 | P2, (구)명세 |
| **canonical** | 노드의 대표 이름(층 안에서 유일) | "노칭::cathode 노칭 정밀도" | (구)명세 |
| **alias (표면형)** | 같은 노드를 가리키는 다른 표기. 판정에서 매칭되면 자동 누적 | "notching" → 노칭 | (구)명세 |
| **auto alias** | 사람이 seed에 적지 않아도 시스템이 골격 인스턴스에서 파생해 사전에 싣는 표면형. **극성 수식 표기의 생성 산식은 `"{극성영문} {이름}"`·`"{극성한글} {이름}"` 두 형태다** — 그래서 인스턴스의 극성 수식 표기는 seed ALIASES에 적지 않는다. 산식이 문면으로 없으면 표기 형태가 구현마다 갈려(`"cathode 탭용접"` / `"탭용접 cathode"` / `"탭용접(cathode)"`) 파서 태깅과 에이전트 해소가 서로 다른 표기를 기대한다 — 파서 공유 스냅샷이 "auto alias 포함"을 계약하기 때문이다(문서 2 §2.1 규약 4). 짧은 이름의 자동 등재 조건은 문서 3이 소유한다 | "cathode 탭용접" · "양극 탭용접" | 문서 2·3·4 |
| **동의어 사전** | canonical과 alias를 모아 "표기→노드 후보"를 찾아주는 전 층 공유 장부. 시스템의 영속 지식. **골격 alias의 원천은 seed ALIASES 블록**이며 loader가 provenance=["seed"]로 등재한다(장부는 이 사전 하나 — 운영 축적분과 태그로 구분, 문서 3) | dictionary.json | P4, §8-R2, 문서 1 |
| **attribute (속성값)** | 노드에 붙는 값. 노드를 만들지 않고 필드에 저장. **이름은 property가 아니라 attribute다** — Neo4j 용어는 property이나 이 체계의 카테고리 Property(관리인자)와 이름이 충돌해 attribute를 채택했다. Neo4j 적재·시각화 같은 파생물이나 저장 필드명에서 property로 되돌려 쓰지 않는다 — 되돌리면 카테고리 Property와 필드 개념 property가 같은 단어가 되어 질의 필터·검수 뷰에서 사람이 두 개념을 혼동한다 | 규격 ±0.1mm | (구)정의서 |
| **청크** | 문서에서 잘라낸 원문 조각. 전부 보존하고 관련 노드에 연결(describes) | PPT 슬라이드 1장의 텍스트 | (구)명세 |
| **provenance (출처 이력)** | 이 노드/엣지/값이 어느 문서 어느 행에서 왔는지의 기록. 모든 자동 생성물에 필수. **항목 형식은 source_locator 기반 표기**(doc_id 접두 포함) — 정본 id(chunk_id·record_id) 병기가 필요한 지점은 구현 재량이며 그 선택은 결정 장부에 기록한다. **문서 유래가 아닌 항목은 문서 표기를 쓰지 않는다** — 코드가 규칙으로 만든 것은 `auto:{규칙명}`(예: `auto:mirror_rule`), 골격 seed 유래는 `seed`로 적는다(문서 7 §7.2). 비워 두면 provenance가 0이 된 auto 엣지가 매 빌드 evidence_lost 큐에 적재된다 | ["CP01-C8"] | (구)구현문서, 증분0 §4.1, 문서 7 §7.2 |
| **attrs / aliases (노드 레코드 필드)** *(문서 7 등재)* | 노드 레코드가 값·표면형을 담는 두 필드 — `attrs`는 attr_name별 값 항목 리스트를 담는 컨테이너, `aliases`는 `{surface, provenance}` 항목의 배열. 문자열 배열·스칼라로 줄이지 않는다 — 줄이면 alias별 provenance와 맥락이 다른 두 번째 값이 사라진다 | `attrs: {"spec": [ … ]}` | 문서 7 §7.2 |
| **linked / adapter_version (청크 레코드 필드)** *(문서 7 등재)* | 청크 레코드가 함께 갖는 두 필드 — `linked`=그 청크의 링킹 여부, `adapter_version`=어느 어댑터 판이 만든 청크인가. 없으면 재인입 회수가 무엇을 걷는지가 형태 없이 남는다 | `linked: false` | 문서 7 §7.2 |
| **진실 / 파생물** | 진실=그래프 JSON+청크 저장소. Neo4j·시각화·임베딩 인덱스는 언제든 재생성 가능한 파생물(뷰) | graph.json이 진실 | P5 |
| **GraphStore** *(세션 N+3 등재)* | graph.json 읽기·쓰기의 **유일한 코드 경계**(core/graph.py) — graph.py 밖에서 graph.json을 직접 여는 코드는 금지. 직렬화는 orjson(표준 json 폴백). 저장 방식 전환(R10)이 와도 이 경계 안만 바뀐다 | `GraphStore.load("process")` | 문서 2·4·7, 문서 1 |
| **T0~T3** *(문서 3 등재)* | 정보의 4계층 — T0 골격(파일·사람 보증) / T1 의미(그래프 본체·문서 수 비례) / T2 근거(청크 저장소) / T3 관측(생산 발생 데이터 — 시간 비례·무한이므로 **그래프에 적재하지 않고 참조만**). 현 구축 범위는 T0~T2 | 검사 실측값은 T3, 그 스펙은 T1 | 문서 3, 문서 1 |
| **SeriesRef** *(문서 3 등재 — 개념만, 설계는 미결 R11·R12)* | 그래프 노드에서 외부 T3 데이터(시계열 태그 등)로 가는 참조 핸들 — 설비당 1개라 데이터 포인트 수와 무관. T3을 넣지 않고도 "어느 태그를 볼지"를 그래프가 답하게 하는 장치 | 설비 → PI 태그 "NOTCH03.TEMP" | 문서 3, 미결 R11·R12 |
| **polarity** *(문서 3 등재)* | 노드의 극성 **파생 필드** — 닫힌 4값: cathode / anode / none(극성 표기 자체가 both이거나 무표기) / unbound(cathode·anode 표기는 있었으나 결합 게이팅 3조건 미충족 — [사내 확인] 후 재검토 시 복원 경로). Tier2는 극성 결합 판정 시 해소 코드가, Tier1은 seed 마커에서 loader가 기록. **코드는 canonical을 파싱하지 않고 이 필드로 판정한다**(mirrors·순서 파생·필터). seed·시스템 전용 어휘 — 스키마·attribute 핸들러 불가침 | polarity: "cathode" | 문서 3|
| **tier** *(문서 3 등재)* | 골격 노드의 계층 이름표 — main(대공정)/sub(공정)/detail(세부공정). **loader가 seed 중첩 깊이에서 파생**(사람이 안 적음), 극성 인스턴스는 개념 tier 상속. process_group 파생의 기준(tier:main 조상) | 조립=main, 노칭=sub, 노칭 타발=detail | 문서 3|
| **대표 흐름** *(문서 3 등재)* | precedes의 지위 — 구조가 아니라 "회사 표준 기준 한 벌"의 **지식**. seed 자식 배열의 순서로만 선언되고(비참여 옵트아웃 존재), 공장·세대별 라우팅은 골격에 넣지 않는다(R13) | 노칭→스태킹→탭용접→패키징 | 문서 3, 문서 1 |
| **극성 3패턴** *(문서 3 등재)* | 골격의 극성 표현 닫힌 3형 — ①무관(노드 하나) ②주소만(개념+자식 없는 인스턴스) ③스텝 분화(@split). +단극성(@cathode/@anode = 개념+인스턴스 1). **분화 단위는 공정이 아니라 스텝**이며 선택은 사람(Tier1) | 탭용접 = ②+③+① 혼합 | 문서 3|

## 2. 문서와 인입 (쓰기 경로)

| 용어 | 뜻 (1줄) | 예시 | 원천 |
|---|---|---|---|
| **파서** | 사내 문서(Excel/PPT 등)를 계약된 JSON으로 바꾸는 사내 실행 프로그램(코어·킷은 외부 전달물 — 문서 6). 시스템과는 JSON으로만 만난다 | CP.xlsx → CP01.json | (구)명세 |
| **doc_type** | 문서 양식의 종류. 종류마다 매칭 스키마 1개 | cp, pfmea, ppt_report | (구)명세 |
| **정형 / 비정형** *(세션 1 등재)* | **파일 포맷이 아니라 payload_kind의 구분이다.** 정형=`table`(행=record, role 선언이 추출을 대체하므로 추출 LLM 불요) / 비정형=`prose`(청크, 추출 LLM 필요). **줄글·목차형 엑셀은 비정형으로 취급한다** — 확장자가 아니라 내용의 형태가 정한다 | CP.xlsx=정형 / 목차형 xlsx=비정형 | 문서 0·2, 문서 2 |
| **어댑터 (어댑터 코드)** *(세션 N 정정)* | 한 doc_type의 문서를 정규 조각으로 분해하는 **파서 측 코드 — 선언 1개(ADAPTER)+함수 1개(extract)**. extract는 조각마다 source_locator를 담아 반환하고(별도 locate 없음), 이미지는 placeholder 조각만 낸다(요약 LLM 호출은 코어 소유). 순수 함수(상태·네트워크·LLM 금지). 구축 모드에서 LLM이 생성, 사람이 결과 뷰로 검수. 버전(`adapter_version`)은 봉투에 1회 | adapters/cp.py | 문서 6, 문서 1 |
| **기본 어댑터** *(세션 N 등재)* | 분할이 자명한 계열(PPT=슬라이드 1장이 청크 1개)에 쓰는 **코어 제공 고정 어댑터** — LLM 생성 없이 등록 시 그대로 붙인다. 등록 절차(층 지정·검수·승인)는 생략하지 않는다 | PPT 계열 등록 | 문서 6, 문서 1 |
| **구조 지도 (struct-map)** *(21회차 등재)* | 구조 가변 prose(판본마다 heading pattern이 다른 계열)의 인입마다 산출하는 **헤딩 구조 데이터** — {행/단락 → 헤딩 여부·레벨·제목}. 산출은 코어 소유(어댑터 아님 — 운영은 LLM, USE_MOCK은 `mock/struct_maps/{doc_id}.json` 우선+번호 패턴 휴리스틱 폴백), **타당성 검사는 결정적 코드**(헤딩 0건·레벨 비단조·커버리지 이상 → 평면 폴백+큐), 분할은 결정적 분할기가 지도를 적용. **지도는 파스 산출물과 함께 보존** — 같은 지도→같은 분할→같은 chunk_id(멱등). 어댑터는 여전히 doc_type당 1개 — 매 문서 새로 나오는 것은 지도(데이터)뿐 | TOC01 목차 지도 | 문서 6v0.6 §2·§3, 문서 0~7(D-58) |
| **하강 부착** *(21회차 등재 — 판정필요-6 종결)* | 부착 대상 좌표가 **개념 노드**인데 record의 극성(electrode_type)이 확정이면, **그 개념의 동일 극성 인스턴스가 존재할 때 그리로 하강해 부착**하는 규칙(A11-5 하강과 동형). 인스턴스가 없으면 하강하지 않고 F1 결합 유지 — 임의 인스턴스 생성 금지(골격은 Tier1). 좌표 해상도에 따른 canonical 갈림(동일 지식이 두 노드로 찢어짐)을 봉쇄한다 | 탭용접+cathode → 탭용접::cathode에 부착 | 문서 3, 문서 1, 문서 4 규약 3-⓪ |
| **expects (관찰 상수)** *(세션 N 등재)* | ADAPTER 선언 안의 상수 둘 — **①양식 지문**(헤더 행·열 매핑·분할 신호: preflight가 실물과 대조하는 것)과 **②판단 상수**(PPT 분할 임계 등: 어댑터 extract가 실행 중 쓰는 것). 둘 다 층 config 키가 아니다(정본 문서 6 §6.4-5) — 코드 본문 밖 **데이터**로 분리. 용도 셋: 검수 뷰 표시 · preflight 대조 기준 · 생성 스켈레톤의 빈칸 | header_row: 3 | 문서 6, 문서 1 |
| **preflight** *(세션 N 등재)* | 운영 인입에서 extract 실행 **전에** 문서 실물 지문(헤더)을 지정 어댑터의 expects와 결정적으로 대조하는 검사(코어 소유, LLM 아님). 불일치면 문서 중단+`adapter_mismatch` 큐 — 운영 모드 안의 **양식 표류**를 잡는다. 등록 조회(문서 3)를 대체하지 않는다 | 헤더가 등록 시점과 다름 → 중단 | 문서 6, 문서 1 |

| **adapter_mismatch** *(세션 N 신설)* | preflight에서 문서 실물 지문이 지정 어댑터의 expects와 불일치할 때 올라가는 큐. 사람이 어댑터 개정(구축 모드 재진입) 또는 신규 doc_type 등록을 판단 | 헤더가 등록 시점과 다름 | 문서 6, 문서 1 |
| **coord_mismatch** *(세션 1 신설 · 문서 3 확장)* | `process_group`이 `process_ref`의 골격 조상과 맞지 않을 때, **또는 record의 electrode_type이 부착 골격 노드의 polarity와 불일치할 때**(문서 3 — A11-9) 올라가는 큐. 조용히 한쪽을 택하지 않는다 | 대공정 "조립" + 세부공정 "권취" | 문서 2, 문서 1 |
| **orphan** | 붙일 곳을 못 찾은 것 — 버리지 않고 큐에 보존, 주기적으로 재시도 | 골격에 없는 공정 이름 | (구)명세 |
| **spec_conflict** | 같은 항목에 다른 값이 들어옴 — 덮어쓰지 않고 충돌로 기록 | ±0.2 vs ±0.3 | (구)명세 |
| **재인입 / revision** | 재인입 = 개정 문서가 다시 들어올 때 그 문서 몫(provenance)만 걷어내고 다시 넣는 것. **개정판은 같은 `doc_id`를 유지하고 `revision` 필드로 판을 구분한다** — doc_id가 바뀌면 재인입이 아니라 새 문서가 된다 | CP R1 → R2 교체 | (구)명세, 문서 1 |
| **툼스톤** *(세션 N 정정 — 노드·엣지 공통)* | 지우거나 종결한 것을 삭제하지 않고 남기는 영구 표식 — 노드: `merged_into`(흡수 id의 리다이렉트)·`obsolete`(폐기), 엣지: `deleted_by_user`(사람 삭제 — 재인입이 되살리지 못한다). **표식 없이 지우면 옛 id를 가리키는 참조가 끊기고 사람의 삭제·종결 판정이 재인입에서 조용히 뒤집힌다** — 그래서 지우지 않고 남긴다. 노드 두 표식의 상세는 이 대장 「obsolete / merged_into」 항, 연산 규범은 문서 4 | 삭제된 오류 엣지 · 흡수된 중복 노드 | 문서 4, 문서 1 |
| **mirrors** *(문서 3 정정)* | 극성 대칭을 표시만 하는 엣지(값 공유 없음). 자동 규칙으로 생성 — **판정은 polarity 필드 비교**(같은 부모 또는 부모가 mirror 쌍 + 이름부 동일 + polarity 반대, 하향 연쇄 — 문자열 파싱 폐지). 비대칭은 큐로 노출하되 **Tier1 단극성 인스턴스는 제외**(사람 보증) | 탭용접::cathode ↔ 탭용접::anode | (구)명세, 문서 1 |
| **파급 미리보기** | 병합·개명 등 파급이 1건 넘는 작업 전에 영향 규모(노드·엣지 수)를 먼저 보여주는 규칙 | 공정 개명 → 하위 인자 연쇄 표시 | (구)명세 |

## 5. 원칙·약어

| 용어 | 뜻 (1줄) |
|---|---|
| **P1** | 단계 간 결합은 파일 계약(JSON)으로만 |
| **P2** | 골격·유형(Tier1)은 사람이 고정, 인스턴스(Tier2)는 자동 생성+사후 수정 |
| **P3** | 코어 코드는 최소·안정 — 사람이 전부 읽고 파악 가능해야 |
| **P4** | id 불변, 사전이 영속 지식. 노드 유일성 불변식: 같은 개념은 언제나 한 노드 |
| **P5** | 진실 = 그래프 JSON + 전 청크. 나머지는 재생성 가능한 파생물 |
| **P6** | 질의는 읽기 전용 — 질문 표현을 사전에 누적하지 않음 |
| **P7** | 측정이 복잡도를 정당화한다 — 근거 없는 구조 선반영 금지 |
| **L1~L4** | 변경 등급: L1 필드 변경(스키마 1줄) / L2 새 doc_type(파일 1개) / L3 새 role(함수 1개) / L4 그래프 모델 밖(재검토) |
| **A/B/C** | 범용성 경계: A=전 층 공유 코드(core) / B=층별 값(config) / C=층별 절차 — 원칙적으로 비어 있어야 하며, 남으면 명시적 실패로 드러냄 |
| **Rule of Three** | 추측으로 미리 일반화하지 말고, 표본이 관찰된 만큼만 공통으로 승격 |
| **명시적 실패** | config로 표현 안 되는 경우 조용히 우회하지 않고 시끄럽게 실패해 core 확장을 요구하는 규칙 |
| **여섯 칸** | 층 정의의 6요소: ①메타데이터 스키마 ②골격 ③관계 목록 ④카테고리 정의문·프롬프트 ⑤쓰기 절차 ⑥읽기 절차 |
| **국면 0~3** | 로드맵: 0 명세(종료) → 1 외부 mock 구현(진행 중) → 2 사내 이식 → 3 운영·확장 |
| **USE_MOCK** | LLM·외부 의존 없이 규칙 폴백으로 전체 파이프라인을 돌리는 개발 토글 |
| **PoC 범위** | 공정층 구축 + 품질지식층 구축 + 층간 연결까지. 질의는 Q1~Q5·Q8 |
| **3축** | 이 프로젝트의 상위 프레임: 축1 문서→그래프(쓰기) / 축2 정보층 추가·연결 / 축3 RAG 질의(읽기) |
| **두 모드** *(문서 0)* | 운영 모드 = 등록된 층·doc_type의 문서가 사람 개입 없이 흐르는 것 / 구축 모드 = 처리 방식이 없는 입력(새 doc_type·새 층)에 대해 어댑터 코드·매칭 스키마(+층이면 config)를 먼저 만드는 것. 모드 판별은 등록 여부 조회(결정적) |
| **부트스트랩** *(세션 N 등재)* | 시스템 최초 가동 시의 층 구성 규칙 — **기본 내장 층은 공정정보층 1개**(구현 시 seed·config로 내장, 층 등록 세션 불경유). **품질지식층은 신규 층 등록 절차의 첫 검증 대상**(J3 판정의 실전 시험). 층 등록 기능(R1)은 신규 층 전용 |
| **추출 단계** *(문서 0·2— 독립 단계)* | 비정형 처리에서 청크를 읽고 개체 후보 + 관계 후보(닫힌 목록 선택) + 부착 이름을 출력하는 LLM 단계 — "내용 파악" 담당. 판정·게이트·커밋(연결)은 구축 단계 담당. 산출물 계약은 추출 후보 JSON(문서 4) |
| **근거 축 / 의미 축** *(문서 2·4·7+3 정정)* | 근거 축 = 문서·청크·레코드(개명·동의어 없음 → id를 내용에서 해시로 계산, **계산 주체는 에이전트**) / 의미 축 = Unit·Property·Failure 등(개명·alias 있음 → id 발급 유지 — **발급 방식은 ULID**, 문서 2·4·7). id 규칙이 두 축으로 갈린다 |
| **ULID** *(세션 N+3 등재)* | 의미 축 노드 id의 발급 방식(문서 2·4·7— 구 전역 시퀀스 N####를 대체). 시간순 정렬 가능·충돌 없음·중앙 카운터 파일(id_seq.json) 불요. **id에 의미를 넣지 않는다** — 소속·순서는 그래프가, 가독성은 canonical이 담당(문서 1). 발효는 A0의 N#### 하드코딩 지점 계수 확인 후 |
| **인스턴스 변경 (I축)** *(문서 4)* | 이미 만들어진 노드에 대한 사후 연산 4종 — I1 개명 · I2 병합 · I3 분리 · I4 폐기. 스키마 변경 등급(L1~L4)과 직교한다 |
| **obsolete / merged_into** *(문서 4)* | 노드를 삭제하지 않고 남기는 두 종결 표식. obsolete = 더 이상 유효하지 않음(+replaced_by), merged_into = 다른 노드에 흡수됨(+target). **내용·provenance는 생존자로 이관되므로 정보 손실이 없고, 표식의 용도는 옛 id 참조의 리다이렉트 하나다.** 질의는 둘 다 전이적으로 따라가며 순환은 쓰기·읽기 양쪽에서 막는다 |
| **doc_hash** *(문서 2·4·7)* | 문서 전체 내용의 해시. **에이전트가 인입 진입점에서 계산**해 대조하고, **같은 내용이 다른 doc_id로 들어오는 것**(파일 복사·개명)을 차단한다. 파일명·크기는 판정 기준이 아니라 사람 확인용 참고 표시다 |
| **occ (출현 순번)** *(문서 2·4·7)* | 한 문서 안에서 몇 번째로 나왔는지(0부터). **축마다 정의가 다르다** — 청크는 동일한 (섹션, 내용) 조합의, **레코드는 join된 값 문자열의** 출현 순번이다(레코드에는 section도 text도 없다 — 산식의 정본은 문서 7 §7.2). 청크·레코드 id 해시의 입력에 넣어 **처리 순서에 의존하지 않는 유일성**을 만든다 — 충돌 접미(`#2`)를 쓰면 순서가 바뀔 때 id가 뒤바뀌어 멱등성이 깨진다 |
| **direction_unverifiable** *(문서 2·4·7)* | 동종 카테고리 쌍의 방향성 관계 후보가 비정형 추출에서 나왔을 때, 게이트가 방향을 검증할 수 없어 커밋하지 않고 보존하는 큐. 사람이 방향을 확인하면 커밋된다 |

# 정제본 1 · 금지와 불변 (검사기)

> **지위**: 정제 명세의 **문서 1**이자 전 문서의 검사기다. 여기 있는 조항과 어긋나는 서술을 발견하면 그것이 결함 신호다 — 조항이 이기고, 본문이 진다(본문이 옳다면 이 문서를 판정으로 고친다).
> **구성**: 그룹 A~P = 불변식 카드 승계(조항 원문 보존 — id 불변) + 각 그룹 말미 **확장 조항** = 원천 13종에 흩어져 있던 부정형 규범의 편입(정제 P0: 추출 902 → 카드 중복 제거 → 선별 채택 → 병합 114).
> **부정형 문면 규약**: 확장 조항은 전부 "X하지 않는다" 꼴이다 — `않는다`로 grep하면 금지 전수가 나온다(V3 감사).
> **전수 기준선**: 원시 추출 902건 전량은 `P0_원시추출.json`(작업 자산)에 보존 — 검증 V3의 대조 원본.
> 사용법: 문서를 쓰거나 고칠 때마다 해당 그룹과 대조한다. 같은 규칙이 챕터마다 다르게 서술되는 것(말 달라짐)을 막는 것이 이 문서의 존재 이유다.

## I. LLM 역할

| # | 규칙 | 원천 | 상태 |
|---|---|---|---|
| I1 | 역할 3분할: 사람=구조 확정 / 규칙(코드)=커밋·게이트·순서 / LLM=식별과 초안 제안 | 명세 §7 (재서술) | **[틀 확정]** |
| I2 | 운영 시점의 **에이전트 측** LLM 판정 지점은 두 곳이다: ①추출(비정형 전용 — 내용 파악) ②개체 판정(연결). **파서 측은 별도이며 I6이 소유한다**(이미지 요약·좌표 태깅·분할 규칙의 결정적 실행) — "두 곳"은 에이전트 안에서의 열거다 | 명세 §7-1 + 세션 1 | |
| I3 | **운영 중** 카테고리를 LLM이 발명하는 일은 없다 — 닫힌 목록에서 선택만. **설계 시점**(층 등록)에는 카테고리·정의문 **초안 제안 허용, 확정은 사람** | 명세 §7 (개정 대기) · 틀 §3 | **[틀 확정]** |
| I4 | 구축 파이프라인을 LLM이 조종하는 에이전트로 만들지 않는다 (제어 흐름은 코드 소유) — 실행마다 순서가 달라지면 재현·디버깅·감사(provenance)가 무너지고 P3가 깨진다 | 명세 §7 | |
| I5 | 관계 타입은 LLM이 **발명하지 않는다**. 비정형 추출에서 **선언된 관계 목록 중 선택·출력은 허용**하며, 모든 관계 후보는 (출발 카테고리, 관계, 도착 카테고리) 패턴 대조(**커밋 게이트**)를 통과해야 커밋된다. 방향이 반대인 후보는 뒤집지 않고 큐로. 거부는 사유와 함께 기록. 정형은 불변 — edges 선언이 관계를 정한다 ※ **골격 카테고리 쌍의 골격 관계(공정층 기준 `Process part_of/precedes/mirrors Process`)는 relation_patterns에 선언하지 않는다** — seed는 후보가 아니라 선언(A3 경로 ①)이며, 패턴에 있으면 경로 ②(정형 edges)가 골격을 개정한다(A11-2 위반). **금지의 단위는 관계 이름이 아니라 `(출발 카테고리, 관계, 도착 카테고리)` 삼중이다** — 같은 관계 이름이라도 골격 밖 카테고리 쌍(`Unit part_of Process` · `Unit mirrors Unit` · `Property mirrors Property`)은 패턴에 **있어야 한다**: 앞은 경로 ②(정형 edges)와 attach_to 폴백(category_pair_map `Unit,Process→part_of`)이, 뒤는 경로 ④(자동 규칙 mirrors)가 그 삼중으로 커밋하며 ②·④가 같은 패턴표를 지나기 때문이다. 이름 단위로 읽어 지우면 사람이 확정한 edges 선언과 자동 규칙 산출이 패턴 밖으로 떨어져 게이트가 거부한다(실측). 실측: precedes 패턴 실재 → 제거 + 게이트 실판정 테스트로 잠금(D-52) — **제거 대상은 `Process precedes Process` 그 한 삼중이었다.** — **mirrors는 매칭 스키마 edges에도 선언하지 않는다**: 극성 대칭은 build 저장 직전 자동 규칙(config.mirrors)의 산출이라 스키마 선언 대상이 아니며, 이 병기가 없으면 relation_patterns 한정 금지가 edges 허용으로 읽혀 근거 1쌍짜리 mirrors 엣지가 선언된다(실측). | 틀 §3 (명세 §7-2 개정 대기) · (구) 판정대조_ipqc_1차 §4·§7-5 | **[틀 확정]** |
| I6 | 파서·등록 LLM의 시점별 허용 수준. **설계 시점**(doc_type/층당 1회·검수 있음): 어댑터 코드 + 매칭 스키마(+층이면 config 초안) 생성 허용 — 정형은 head 약 10줄 관찰, 비정형은 문서 구조를 관찰해 **청크 분할 규칙을 코드로 생성**. **운영 시점**(매 문서·무검수): ①이미지 요약(호출 주체는 공용 코어 — C12) ②좌표 태깅(닫힌 목록 선택) ③고정된 분할 규칙의 결정적 실행(구조 안정 계열 — table·분할 자명 prose) ④**구조 지도 패스(구조 가변 prose 한정 — 틀 v2.8 Q2 개정)**: 공용 코어 소유 LLM이 **구조 지도(데이터: 행/단락 → 헤딩 여부·레벨)**를 산출하고, 분할은 결정적 코드가 지도를 적용하며, 지도는 보존된다. 타당성 검사 실패는 평면 폴백(M8)+기존 큐(`hierarchy_unresolved`·`parse_failure` — 신설 없음) — **이 넷이 닫힌 목록이다.** **운영 중 LLM이 청크를 직접 나누지 않는다는 원칙은 불변이다**(④가 내는 것은 지도이지 청크가 아니다 — v5에서 구판의 "청크 분할 보조" 표현을 정정, v16에서 지도 패스와 구분). 비정형의 내용 파악은 파서가 아니라 추출 단계(M7) | 틀 §3·**§4-Q2(v2.8 개정)** | **[틀 확정]** |
| I7 | **운영 중 신규 관계 생성은 없다 — 조건부 예외도 두지 않는다.** 대신 관계 목록을 구축 모드(층 config 생성)에서 충실히 만든다. 게이트 거부가 잦으면 "새 관계가 필요하다"가 아니라 **"관계 목록이 부실하다"는 신호**이며, 대응은 config 개정(구축 모드 재진입)이다 | 틀 §3 | **[틀 확정]** |
| I8 | **동종 카테고리 쌍의 방향성 관계는 방향 출처가 명시된 경로에서만 커밋된다.** 이종 쌍은 카테고리 조합이 방향을 함의하지만(category_pair_map), **동종 쌍은 두 방향이 같은 키로 붕괴**한다. 커밋 가능: ①seed ②edges 선언(정형 — 필드 구분이 방향). **비정형 추출 후보는 방향 출처는 있으나 게이트가 검증할 수 없으므로 커밋하지 않고 `direction_unverifiable` 큐에 후보 보존**(버리지 않음, 사람 확인 시 커밋). **대칭 관계(mirrors 등)는 예외** — 해당 관계 패턴에 `symmetric: true`를 표시한다. **대칭 여부가 사는 자리는 `config.relations`가 아니라 `config.relation_patterns[]`의 각 행이다** — `relations`는 관계 이름의 문자열 배열이라 대칭 여부를 담지 못하고, 게이트가 읽는 것도 패턴 행이다: relations 쪽에 적은 표시는 게이트에 닿지 않아 이 예외가 조용히 죽는다. **게이트를 타지 않는 관계(경로 ① seed 전용 `precedes` 등)는 대칭 표시 대상이 아니다** — 게이트가 판정할 일이 없는 관계에 표시가 없는 것은 결함이 아니다. 조건부 개방: 골든셋 정확도 측정 후 자동 커밋 승격 가능(P7) | 틀 §4B-A3 | **[틀 확정]** |
| I9 | **Failure 병합(고장모드+고장원인)은 유지한다.** 쪼개면 같은 현상이 행 위치에 따라 두 노드가 되어 causes 연쇄가 끊긴다(A5 위반). **원인이냐 모드냐는 노드의 속성이 아니라 엣지에서의 위치다** | 틀 §4B-A3 | **[틀 확정]** |

| N8 | **중복 문서 차단**: 인입 시 문서 내용 해시(`doc_hash`)를 대조해, **같은 해시가 다른 `doc_id`로 이미 있으면 인입을 보류하고 사람에게 확인**을 요청한다(파일명·크기·기존 doc_id를 함께 제시). 파일명·크기는 판정 기준이 아니라 참고 표시일 뿐이다 — 판정은 내용 해시로 한다. 같은 doc_id로 다시 들어오는 것은 중복이 아니라 재인입(정상 경로). **`doc_hash`는 에이전트가 인입 진입점에서 계산한다**(C7) — 청크 해시 계산의 부산물이라 추가 비용이 없다 | 틀 §4B-A6·**A7-2** |
| N9 | **자동 생성된 노드는 기존 노드의 하위 또는 동급으로만 붙는다.** 기존 노드의 **상위에 새 노드가 자동 삽입되는 일은 없다** — 계층 상단의 변경은 골격 개정이며 사람이 파일로 한다. 부착 대상이 바뀌는 경우는 재부착 3분류로, 계층 구조 자체가 바뀌는 경우는 `structural_proposal`로 올라온다. **그래프가 조용히 재편되는 경로는 없다** | 틀 §4B-A5 |

## 사용법 — 이 문서는 검사기다

**본문 문서(0·2~7)를 쓰거나 고칠 때**: 그 문서가 다루는 그룹(A~P)의 조항을 먼저 읽고, 서술이 조항과 일치하는지 확인한다. 조항에 없는 규칙을 새로 서술하게 되면 **먼저 조항으로 올린다** — 본문에만 사는 금지는 다음 사람이 지운다.

**충돌하면 이 문서가 이긴다**(위계: 문서 1 > 본문 0·2~7 > 부록). 조항을 깨는 개정은 **조항의 개정을 먼저 판정한다** — 본문이 조항을 조용히 우회하지 않는다.

**금지 전수 확인**: `않는다`로 grep하면 이 체계의 금지가 전부 나온다. 새 금지를 다른 어미로 쓰지 않는다 — 그러면 감사에서 사라진다.

**그룹 간 교차 대조** — 같은 사안을 두 그룹이 다루는 자리다. 한쪽만 고치면 정제본 안에서 모순이 생긴다(실측된 실패 유형).

| 사안 | 함께 보는 그룹 |
|---|---|
| 어댑터 등록·검수 | C그룹 ↔ M그룹 |
| 층 등록 | J그룹 ↔ M그룹 |
| 추출 단계 | M12 ↔ I2·M6·M7 |
| 저장 경계·공유 자원 | B4(공유 단일) ↔ B6(GraphStore) ↔ H5(직렬 계약) |
| 좌표·구조 필드·극성·이름 | C그룹 ↔ F그룹 ↔ J그룹 ↔ D그룹 |
| payload 구조 필드·6지선다 | C17 ↔ C2 ↔ D그룹 |
| 구조 지도 패스·평면 폴백 | I6 ↔ M6 ↔ C11(어댑터 순수성) ↔ C14·M8 |
| 병합 생존자·파급 미리보기 | L5 ↔ L7 ↔ G6 |

**조항의 개정 이력은 이 문서가 갖지 않는다** — 개정 대장의 몫이다(같은 사실은 한 문서에만 산다).

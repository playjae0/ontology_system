# 정제본 0 · 기반과 원칙

> **지위**: 정제 명세의 첫 문서 — 이 시스템이 무엇이고, 어떤 원칙 위에 서 있으며, 사람·코드·LLM이 각각 무엇을 하는지. 여기가 흔들리면 나머지 전부가 흔들린다.
> **읽는 순서**: 0(이 문서) → 1 금지와 불변 → 2 계약 → 3 구조 → 4 쓰기 → 5 읽기 → 6 파서와 구축 모드 → 7 구현 규격과 검증 → 부록 용어.
> **위계**: 충돌 시 **1 금지와 불변 > 본문 문서들 > 부록**. 같은 사실은 한 문서에만 살고 나머지는 참조한다 — 어긋나면 그 자체가 결함 신호다.

---

## 0.1 한 문장과 3축

**사내 제조 문서를 넣으면 자동으로 지식 그래프까지 만들어지고, 자연어로 물으면 근거와 함께 답하며, 정보층을 계속 추가해도 코드가 늘지 않는 시스템.**

| 축 | 내용 | 정제본 문서 |
|---|---|---|
| 축1 · 쓰기 | 문서 → 그래프 (정형/비정형 상이) | 2 계약 · 4 쓰기 절차 · 6 파서 |
| 축2 · 층 | 새 정보층의 생성과 기존 층과의 연결 | 3 구조 |
| 축3 · 읽기 | RAG 질의 | 5 읽기 절차 |

기본 성격 넷:

1. 사내에서 **지속 운영·확장 가능한** 온톨로지/GraphDB 시스템이다. 공정정보층에서 시작해 층을 추가하고, 층간 연결로 지식을 확장한다.
2. 제조정보 특성상 **관계성이 1급 시민**이다. 주 문서는 Excel(밀도 높은 공정 spec·관리정보)과 PPT(글+이미지 복합), Word/PDF는 보조.
3. **데이터·실물 문서는 사내 밖으로 반출하지 않는다 → 파서는 사내에서 실행한다.** 외부가 완성하는 것은 실물 없이 만들 수 있는 것뿐이다(공용 코어·생성 킷·에이전트·플랫폼). 파서 실행·어댑터 생성 세션·검수 승인은 사내에서만 한다.
4. **모든 결합은 파일 계약(JSON)뿐이다.** 파서↔에이전트↔플랫폼은 코드가 아니라 JSON으로 만난다. 파서 내부 구현은 에이전트 호환성과 무관하다 — 에이전트는 출력 계약(문서 2)만 의존·검증한다.

## 0.2 불변 원칙 P1~P7

전 시스템이 지키는 7원칙. 다른 모든 규칙은 이 7개의 전개이며, **이후 어떤 장치(두 모드·게이트·I축 등)도 원칙의 수정으로 해석하지 않는다** — 전부 원칙의 실행 장치다.

| # | 원칙 |
|---|---|
| P1 | **단계 간 결합은 파일 계약(JSON)으로만.** 한 단계를 고쳐도 다른 단계 코드는 건드리지 않는다. "파일"은 단일 JSON을 뜻하지 않는다 — 요구는 *DB 서버 없이 원천이 복원 가능할 것*이다(샤드 집합·SQLite 파일도 파일) |
| P2 | **골격·유형(Tier1)은 사람이 고정**, 인스턴스(Tier2)는 자동 생성 + 사후 수정 |
| P3 | **코어 코드는 최소·안정, 사람이 전부 읽고 파악 가능.** 의존은 단방향 — 역방향·순환 의존을 만들지 않는다 |
| P4 | **id 불변, 동의어 사전이 영속 지식.** 임베딩은 비저장·재생성 가능한 도구. **노드 유일성 불변식**: 같은 개념(같은 canonical·같은 정체성 축)은 언제나 한 노드 — 재인입·재빌드·동시 실행 등 어떤 경로에서도 중복 생성 금지. 중복 발생은 구현 편의가 아니라 불변식 위반으로 취급한다 |
| P5 | **진실 = 그래프(JSON: 노드·엣지) + 청크 원문(전 청크 보존).** Neo4j·Cypher·시각화·임베딩 인덱스는 재생성 가능한 파생물/뷰. 문서 근거 없는 엣지는 confirmed 불가 |
| P6 | **질의는 읽기 전용** — 질문 표현을 사전에 누적하지 않는다(사용자 입력은 비검증, 사전 오염 방지) |
| P7 | **측정이 복잡도를 정당화한다** — 근거 없는 구조 선반영 금지 |

경계 하나: P4의 "id 불변"은 **의미 축**(발급 id) 이야기다. 근거 축(문서·청크·레코드)은 내용에서 계산하므로 "불변"이 아니라 "결정적"이 정확한 술어다 — 같은 내용이면 언제나 같은 id(문서 4).

경계 둘: P3의 "최소"는 **줄 수가 아니라 사람이 전부 읽고 파악 가능함**이다. 줄 수를 맞추기 위한 압축·생략(에러 처리·로깅·provenance 기록·명시적 변수명의 희생)은 하지 않는다 — 명료함이 짧음보다 우선이다. 근거: "최소"를 "짧게"로 읽으면 로깅·에러 처리·설명적 변수명을 걷어낸 코어가 나오는데, 큐에 착지하지 않는 조용한 실패는 문서 1 G5가 잡아도 로깅·가독성 손실은 어느 조항에도 걸리지 않는다(조항 정본은 문서 1 A20).

## 0.3 두 모드 — 이 시스템의 1급 프레임

```
문서 도착 → doc_type/층 등록 여부 조회 (결정적, LLM 아님)
   ├─ 등록됨   → [운영 모드] 파싱 → (추출) → 구축 → 그래프     ※ 사람 개입 없음
   └─ 미등록   → [구축 모드] 처리 방식을 먼저 만든다 → 검수 → 등록 → 이후 운영 모드
```

**구축 모드의 산출물**

| 산출물 | 소유 | 내용 | 생성 |
|---|---|---|---|
| 어댑터 코드 | 파서(사내) | 정형: 어느 행/열을 어떻게 읽는가 · 비정형은 계열로 갈린다 — **분할 자명 계열**: 분할 신호 상수(분할 규칙) + 이미지 요약 훅 / **구조 가변 계열**: 지도 패스 기능 선언과 힌트까지이고 **어댑터는 분할하지 않는다** — 분할은 코어의 결정적 분할기가 한다(문서 6 §6.3·§6.4-8) | LLM 생성 → 사람 검수 |
| 매칭 스키마 | 에이전트 | 필드 → role + edges 번역표. **동시에 메타데이터 스키마(필드 선언)를 겸한다** | LLM 생성 → 사람 검수 |
| config | 에이전트 | 층 신설 시만 — 카테고리·정의문·관계 목록·골격 선언 | LLM 초안 → 사람 확정 (골격 seed는 사람 입력 — 문서 3) |

비정형 두 계열을 나눠 적는 근거: 누가 분할하는가가 갈리면 어댑터 저자와 코어가 서로 상대가 한다고 보아 어느 쪽도 지도 패스를 태우지 않고, 같은 문서가 구현마다 다른 청크로 잘린다. 계열 선언의 물리 표지는 `expects`의 형태이며 그 규격의 정본은 문서 6 §6.4-8이다.

**검수의 수준**

- **검수는 구축 모드(등록, 양식당 1회)에만 있다. 운영 모드에는 검수가 없다** — 등록이 끝난 타입의 문서는 사람 없이 흐른다. 검수는 flow의 관문이 아니라 등록 때 1회 내는 통행료다.
- 사람이 보는 것은 코드가 아니라 **결과 뷰**다: ①표본 파싱 결과 ②필드→role 배정표 ③어댑터 요약의 **3구획**이며, 규격의 정본은 문서 6 §6.6이다. 층 등록 세션에는 별도의 **층 검수 뷰 5구획**이 있다(문서 3 §3.7 규약 5). 시스템이 이 뷰를 자동으로 만들어 제시한다. 구획의 내용을 여기서 다시 펼치지 않는다 — 이 열거가 소유 절과 어긋나면 그것만 읽은 산출자가 뷰 데이터 JSON(킷 자산 `검수뷰_데이터스키마.json` — 산출자↔렌더러 경계 계약)의 required 필드를 못 채운다.
- **통과 = 승인 1회(클릭 수준, 분 단위).** 문제 있으면 그 자리에서 수정 지시(재생성) 후 재확인 — 재생성 루프는 상한이 없고 매회 지시가 이력으로 남는다.
- **"무수정 = 자동 통과"로는 하지 않는다.** 등록 산출물은 이후 그 타입의 **모든** 문서에 곱해지는 지렛대라서, 명시적 승인 기록 1건이 "운영은 무개입"의 근거가 된다. 무게는 클릭 수준으로, 기록은 명시적으로.

## 0.4 LLM 역할 — 전역 지도

**원리 두 개.** 사람=구조의 확정 / 코드=커밋·게이트·순서 / LLM=식별과 초안 제안. 그리고 **설계는 과감하게(1회+검수), 운영은 보수적으로(무검수+안전망).**

| 단계 | 설계·등록 시점 (구축 모드) | 운영 시점 (운영 모드) |
|---|---|---|
| 파서 | **어댑터 코드 생성** (정형: head ~10줄 관찰 / 비정형 **분할 자명 계열**: 구조 관찰 후 분할 신호 상수 생성 / 비정형 **구조 가변 계열**: 지도 패스 기능 선언과 힌트 생성까지 — 분할 규칙을 만들지 않는다. 분할은 코어의 결정적 분할기 몫이다 — 문서 6 §6.4-8) | 생성된 규칙의 결정적 실행 + 이미지 요약 + 좌표 태깅(닫힌 목록 선택) + 구조 지도 패스(구조 가변 prose 한정 — 문서 6) |
| 등록 | **매칭 스키마 + (층이면) config 초안** — 확정은 사람 | — (조회만) |
| 추출 | 프롬프트·정의문은 사람이 확정 | **내용 파악** — 개체 후보(닫힌 카테고리) + 관계 후보(닫힌 관계 목록) + 부착 이름 |
| 구축 | — | **개체 판정**(같은 개념인가)만. 게이트·엣지 생성·커밋·순서는 전부 코드 |
| 구조 개정 | — | 골격 빈틈 **감지·제안** — 반영은 사람 파일 경유 |
| 질의 | 프롬프트는 사람 | **답변 생성 + 링킹 폴백(1단 사전 스캔 미스 시) 2지점** — 어느 쪽도 그래프를 직접 읽지 않는다. 지점 수를 1로 적지 않는 근거: 문서 7 §7.6-B-2가 LLM 지점마다 mock/실호출 분기를 요구하므로, 폴백이 지도에서 빠지면 그 분기가 서지 않아 USE_MOCK에서 질의 결과가 갈린다(순서의 정본은 문서 5 §5.1-1) |

**발명 금지 3종 (시점 무관)**: ①관계 타입 ②카테고리 ③골격. 운영 중에는 닫힌 목록 선택만, 설계 시점에는 초안 제안까지이며 확정은 사람이다.

**관계에 대한 최종 입장**

- 운영 중 새 관계 생성은 **하지 않는다.** 조건부 신규 출력("정말 필요하면") 같은 예외도 두지 않는다 — 조건 판정이 신뢰되지 않는다.
- 대신 **관계 목록을 구축 모드에서 충실히 만드는 데 힘을 싣는다.** 층 config를 만들 때 LLM이 문서를 충분히 검토해 필요한 관계를 다 뽑고, 사람이 확정한다.
- 운영 중 게이트 거부가 잦다면 그것은 "새 관계가 필요하다"가 아니라 **"관계 목록이 부실하다"는 신호**이며, 대응은 운영 중 생성이 아니라 **config 개정(구축 모드 재진입)**이다.
- 게이트는 유지한다: **경로 ②(edges 선언)·③(추출 후보)·④(자동 규칙)의 관계**는 `(출발 카테고리, 관계, 도착 카테고리)` 패턴 대조를 통과해야 커밋된다 — 경로 ①(seed)만 비경유이며 그것은 후보가 아니라 사람의 선언이라 정상이다. 방향 반대는 자동으로 뒤집지 않고 큐. 거부는 사유와 함께 기록한다(커버리지 신호). **관할 범위와 패턴 금지의 정본은 문서 4 §4.4이며 이 줄은 그 참조다** — 관할 범위가 곧 게이트의 정의라, 여기서 범위를 따로 적으면 두 문서가 서로 다른 게이트를 만든다.

**LLM이 아닌 것 (착각 주의)**: 모드 판별 · 게이트 대조 · 정형의 관계 생성 · mirrors · 재인입 회수 · 2-pass 순서 — 전부 코드의 결정적 연산이다.

**안전망 원칙**: 안전망(지정된 오류 착지점 — 큐·폴백·명시적 실패)이 받지 못하는 위치에 LLM을 두지 않는다.

## 0.5 범위 — PoC와 로드맵

**PoC = 공정층 구축 + 품질지식층 구축 + 층간 연결까지.** 근거: Rule of Three상 2번째 층이 실재해야 공통 경계와 층간 연결의 실물 답이 관찰된다 — PoC는 데모이자 설계 검증 실험을 겸한다.

- 2번째 층 = **품질지식층**(PFMEA류의 정적 지식 체계 — "일어날 수 있는 것"). 실제 발생 사건을 담는 불량이력층("일어난 것" — 사건 스트림·시점 보유)과 성격이 다르다. 불량이력·자재/BOM은 3번째 층 후보(미결 R5).
- PoC 공정층 골격은 **조립 대공정만** 심는다 — 전극/화성은 seed 키 추가로 확장.
- 질의 지원 범위: Q1~Q5·Q8(문서 5). Q6은 훅만, Q7은 범위 밖.

**로드맵 — 4국면**

| 국면 | 내용 | 완료의 정의 |
|---|---|---|
| 0 | 명세 마감 (외부) | 완료 |
| 1 | 외부 구현 — mock 위에서 전 메커니즘 검증 | **정본은 문서 7 §7.6** — 조건을 여기 요약하지 않는다: 요약이 한 조건을 빠뜨리면 이 표만 읽은 사람이 완료로 판정한다 |
| 2 | 사내 이식 — 파서 반입·실데이터·실물 등록·파일럿 인입 → 계기판 첫 측정 | 품질 측정은 여기서 시작한다 — mock 국면의 완료판정은 메커니즘 검증까지다 |
| 3 | 운영·확장 — 3층 도입, 공통 승격 | **PoC 완료 4조건**: plateau + 층간 연결 동작 + 골든셋 통과 + 계기판 가동 |

현재 위치·일정 좌표는 이 문서가 갖지 않는다 — 운영 기록(장부·진행 문서)의 몫이다.

## 0.6 미결 등록부 — 열려 있는 것과 그 트리거

미결은 결함이 아니라 **의도된 이연**이다(P7 — 측정 없는 선반영 금지). 각 항목은 트리거가 오기 전에 풀지 않는다.

| # | 미결 | 트리거 |
|---|---|---|
| R2 | 대량 인스턴스 층의 경유 노드 형태(집계/기간 vs 유형 경유) + **층 구조 일반 규칙의 반증 조건 3건 동시 심사**(문서 3) | 3층 성격 확정 시 |
| R4 | 엑셀 계층 판정의 실측 정확도 | 사내 실물 검증(국면 2) |
| R5 | 3층 후보 선택 (불량이력 vs 자재) | 관찰 데이터(자재 열 빈도·질문 수요). **준비물 — PoC에서 자재 열은 content/meta로 배정하고 등장 빈도를 관찰 항목으로 기록한다**: UNMAPPABLE로 판정하면 매칭 스키마와 어댑터 출력에서 통째로 빠져(문서 1 C19) 원문도 빈도 재료도 남지 않아 이 트리거가 영영 성립하지 않는다 |
| R6 | 벡터 검색의 나머지 결정 — 임베딩 대상·모델·리트리버·융합·랭킹 | 측정 후(P7). 되돌릴 수 없는 것 4건은 이미 고정(문서 4·5) |
| R7 | 동종 쌍 방향의 자동 커밋 승격 | 골든셋 정확도 측정 후 |
| R8 | 문서 노드의 그래프 실체화 여부 | 미정 (현재는 provenance 문자열 참조) |
| R10 | 저장 계층 전환 방향 (샤딩 JSONL vs SQLite) | **알람선 도달 시** — 층별 파일 200MB 또는 build 30초 (계기판 7·8번) |
| R11 | T3 연동 — SeriesRef류 참조 구조 + 외부 사실 확인(시계열 시스템·태그 규칙) | 그래프 구축 완료 후 |
| R12 | 접근 권한 일괄 — 권한 로직·classification 값·집계 범위·조각 단위 등급 | 사내 반입 심사에서 접근 제한 요구 확인 시. 리스크: 섹션 단위 등급 실재 판명 시 해당 doc_type 재인입 |
| R13 | 라우팅 표현 — 공장·세대별 실제 공정 순서의 표현·저장 | 공장별 흐름 질의의 실수요 확인 시 (골격 id 불변·전 청크 보존으로 이연 안전) |
| R17 | prose 재인입 시 section 변동에 의한 chunk_id 이동 | 국면 2 이후 (실물 개정 빈도 관찰 후) |
| — | 층 등록 절차의 실효성 실험(품질층 재등록·정답 대조 — 문서 3) | **국면 2 진입 게이트** |
| — | RPN 인자(발생도·검출도)의 **엣지 속성** 도입 — 정주소가 `causes` 엣지의 속성이라는 판정과 현행 미지원은 문서 3, 질의 승격 축은 문서 5의 질의 이연 목록이 갖는다. 이 등록부가 갖는 것은 트리거다 | 발생도·검출도가 실물에 등장하거나 RPN 질의가 요구될 때(P7) — 트리거가 등재돼 있지 않으면 사내에서 요구가 올라와도 "이연 해제"가 아니라 새 설계 논의로 시작하고, 도입이 L3인지 L4인지 판정할 근거도 없다 |
| — | **Unit 정의문의 포섭 범위 — 검사·계측 장비.** 현행 정의문("공정을 **수행하는** 물리 장비" — 문서 3)이 검사설비·계측기를 포섭하는지가 미정이다. 검사성적서·계측기록 계열 문서를 넣으려면 **Unit 정의문 개정이 선행되어야 한다** — 그때까지는 Unit으로 두되 이 유보를 기록한다. 유보 기록이 없으면 검사설비 열이 UNMAPPABLE로 떨어져 문서 1 C19에 따라 스키마·어댑터 출력에서 통째로 빠지고, 원문도 빈도 재료도 남지 않는다(R5가 자재 열에 대해 경고하는 것과 같은 소실 경로인데, 원인이 정의문 결함임을 가리키는 기록이 정본 어디에도 없게 된다) | **[사내 확인]** — 검사성적서·계측기록 계열 doc_type의 등록 요구가 올라올 때 |

## 0.7 용어

- 모든 용어는 **부록(용어 대장)이 단일 정의처**다. 본문은 용어를 재정의하지 않고 사용만 한다.
- **합의되지 않은 단어를 합의된 것처럼 쓰지 않는다** — 새 단어는 부록 등록이 먼저다(등록 = 합의 절차).
- 부록 정의가 본문 규범과 충돌하면 본문이 이긴다 — 부록의 정의는 "빨리 통하기 위한" 요약이다.

| C13 | **기본 어댑터**: 분할이 자명한 계열(PPT = 슬라이드 1장이 청크 1개)은 코어 제공 고정 기본 어댑터를 등록 시 그대로 붙인다 — LLM 어댑터 생성은 관찰이 실제로 필요한 양식(목차형 엑셀·비표준 Word/PDF)만. **기본 어댑터를 써도 등록 절차(층 지정·검수·승인 1회)는 생략하지 않는다**(M9) | 파서_명세 §5 (세션 N ⑴-B′) |
| C14 | **파싱 실패는 문서 단위 단일이다** — 계약 위반 행(자기완결 불성립)·어댑터 예외·validator 위반이 하나라도 있으면 그 문서는 통째로 미인입 + **`parse_failure` 큐**(사유·해당 행 제시). 수리 경로는 doc_id 재인입(H1) 하나 — 커밋 단위=재인입 단위=문서. **계층 미확정(비정형)은 실패가 아니라 인입되는 성능저하 경로다**(평면 폴백 + 표시·큐 — 틀 Q2·M8 유지). 조각 단위 완화는 실측 후만(P7) | 파서_명세 §5 (세션 N ⑴-C) |
| C15 | **preflight와 투입 분류.** ①preflight(코어, extract 실행 전): 문서 실물 지문(정형: 헤더 행) ↔ `ADAPTER.expects` **결정적 대조**(LLM 아님), 불일치면 문서 중단 + **`adapter_mismatch` 큐** → 사람이 어댑터 개정(구축 모드 재진입) 또는 신규 doc_type 판단. 등록 조회(M2)를 대체하지 않는다 — 운영 모드 안의 양식 표류를 잡는 장치다. ②투입 분류(doc_type 지정): **사람 지정이 기본**(투입함/선택 UI), 미지정 **정형**만 지문 스캔으로 후보 제안 + 사람 1클릭 확정(비정형은 지정 필수 — 지문 변별력 없음). 유일 일치 자동 라우팅은 오배정률 측정 후 승격(P7) | 파서_명세 §5 (세션 N ⑴-C′·C″) |
| C16 | **봉투에 `classification?` 선택 필드** — 문서 등급의 자리(널 허용·자유 문자열). **현 국면에서는 아무도 채우지 않는다** — 권한 로직·값 집합·검증은 전부 R12 이연. 등급은 노드가 아니라 문서의 성질이며 provenance에서 유도된다(노드 등급 부착은 정의 불가 — 한 노드=여러 문서 출처) | 틀 §4B-A10 (쟁점 C) |
| C17 | **구조 필드 판정 3조건 — 셋 전부 만족하면 role 배정 대상이 아니다**: ①계약이 고정한다(doc_type 무관 상존, 스키마가 존재·이름을 못 바꿈) ②소비자가 role 핸들러가 아니라 시스템 코드다 ③값 자체가 그래프 쓰기 6동작을 직접 일으키지 않는다(다른 동작의 조건·입력으로만 쓰임). 확정 구조 필드: 봉투 전체 · 조각 공통 doc_type · context · **electrode_type**(A11-8). **구조 필드는 검수 뷰 6지선다에 올리지 않는다** — UNMAPPABLE(미해결·L3/L4 판정 대기)과 다른 범주(정상·완결)다 | 틀 §4B-A11-8 (M2) |

| I5 | 관계 타입은 LLM이 **발명하지 않는다**. 비정형 추출에서 **선언된 관계 목록 중 선택·출력은 허용**하며, 모든 관계 후보는 (출발 카테고리, 관계, 도착 카테고리) 패턴 대조(**커밋 게이트**)를 통과해야 커밋된다. 방향이 반대인 후보는 뒤집지 않고 큐로. 거부는 사유와 함께 기록. 정형은 불변 — edges 선언이 관계를 정한다 ※ **골격 소유 관계(part_of·precedes·mirrors)는 relation_patterns에 선언하지 않는다** — seed는 후보가 아니라 선언(A3 경로 ①)이며, 패턴에 있으면 경로 ②(정형 edges)가 골격을 개정한다(A11-2 위반). 실측: precedes 패턴 실재 → 제거 + 게이트 실판정 테스트로 잠금(D-52). | 틀 §3 (명세 §7-2 개정 대기) | **[틀 확정]** |

| I7 | **운영 중 신규 관계 생성은 없다 — 조건부 예외도 두지 않는다.** 대신 관계 목록을 구축 모드(층 config 생성)에서 충실히 만든다. 게이트 거부가 잦으면 "새 관계가 필요하다"가 아니라 **"관계 목록이 부실하다"는 신호**이며, 대응은 config 개정(구축 모드 재진입)이다 | 틀 §3 | **[틀 확정]** |
| I8 | **동종 카테고리 쌍의 방향성 관계는 방향 출처가 명시된 경로에서만 커밋된다.** 이종 쌍은 카테고리 조합이 방향을 함의하지만(category_pair_map), **동종 쌍은 두 방향이 같은 키로 붕괴**한다. 커밋 가능: ①seed ②edges 선언(정형 — 필드 구분이 방향). **비정형 추출 후보는 방향 출처는 있으나 게이트가 검증할 수 없으므로 커밋하지 않고 `direction_unverifiable` 큐에 후보 보존**(버리지 않음, 사람 확인 시 커밋). **대칭 관계(mirrors 등)는 예외** — 관계 목록에 대칭 여부를 표시한다. 조건부 개방: 골든셋 정확도 측정 후 자동 커밋 승격 가능(P7) | 틀 §4B-A3 | **[틀 확정]** |
| I9 | **Failure 병합(고장모드+고장원인)은 유지한다.** 쪼개면 같은 현상이 행 위치에 따라 두 노드가 되어 causes 연쇄가 끊긴다(A5 위반). **원인이냐 모드냐는 노드의 속성이 아니라 엣지에서의 위치다** | 틀 §4B-A3 | **[틀 확정]** |

| L6 | **evidence_lost ≠ obsolete.** evidence_lost는 근거 0의 **자동 감지·검토 대기**, obsolete는 사람의 **종결 판정**. 경로: `재인입 → provenance 0 → evidence_lost → 사람이 obsolete 또는 보존`. **근거 소실이 곧 지식 오류는 아니므로 자동 폐기하지 않는다** | 틀 §4B-A2 | **[틀 확정]** |
| L7 | **병합의 id 선택 기준이 하나뿐인 이유는 정확성이 아니라 결정성이다** — 어느 쪽을 죽여도 툼스톤이 리다이렉트하고 내용은 전부 합쳐지므로, 필요한 것은 "처리 순서·병렬과 무관하게 같은 답"이다. 사람이 생존 id를 지정할 수 있다(override). **canonical 선택은 id 선택과 분리**한다 — 두 노드의 canonical+전체 alias를 **출현 빈도·출처 등급과 함께 후보로 제시**, LLM이 1개 추천, **사람이 확정**한다. 빈도를 자동 규칙으로 쓰지 않는 이유는 복사·붙여넣기로 **오타가 반복 등장**할 수 있어서다. 선택 안 된 표기는 전부 alias로 남아 정보 손실이 없다 | 틀 §4B-A2 | **[틀 확정]** |
| L8 | **`merged_into`·`replaced_by` 체인의 순환 방어 2겹**: 쓰기 시점에 도구가 대상이 이미 체인상에 있는지 검사해 **순환이면 거부**하고, 읽기 시점 추적은 **방문 집합 + 최대 깊이 제한**을 두되 한계 초과 시 **결함으로 로그**한다(조용히 멈추지 않는다) | 틀 §4B-A2 | **[틀 확정]** |
| L9 | **재인입은 노드를 제거하지 않는다 — 제거는 별도 기능(I4)이다.** 재인입은 그 문서 몫의 provenance를 회수하고 근거 0인 노드를 `evidence_lost`로 **표시만** 한다. 즉 재인입은 **제거 후보를 찾아주는 것**이고 제거 자체는 도구의 일이다. **시스템이 자동으로 기존 문서를 다시 읽는 경로는 없다** — 재인입은 사람이 그 문서를 다시 넣을 때만 일어난다 | 틀 §4B-A2 | **[틀 확정]** |

| # | 규칙 | 원천 |

- `OK` — 내 생각과 같다
- `다름` — 내 생각과 다르다 → **이 항목이 바꿔야 할 틀이다**
- `?` — 무슨 말인지 모르겠다 → 서술이 부족하다는 신호(챕터에서 보강)

`다름`과 `?`만 모으면 그것이 논의 목록이 된다. 전부 `OK`면 현행 기준으로 챕터를 채우면 된다.

**공백 현황 (v11 기준)**: J7·L5의 공백은 채워졌다. **[틀 확정] 항목들은 방향이 확정되었고 명세 반영(v1.19)만 대기 중이다 — 챕터에서는 이 카드의 문안이 현재의 진실이다.** 카드 v5에서 카드 내부 모순 1건(I6 ↔ M6)이 검사 1로 검출·해소되었으므로, 이후 챕터 검토에서도 **그룹 간 교차 대조**(같은 사안을 두 그룹이 다루는 경우)를 명시적으로 수행한다. v6~v10에서 C11~C15·M10~M12·J10·K8이 신설되었다 — C그룹과 M그룹(M5·M9·M10·M11)이 어댑터 등록·검수를, J그룹(J10)과 M그룹이 층 등록을, M12와 I2·M6·M7이 추출 단계를 함께 다루므로 교차 대조 대상이다. **M9의 "③(층이면) 카테고리 정의문·관계 목록"은 층 등록 세션의 검수 뷰로 이관되었다(M11) — doc_type 등록 화면에는 뜨지 않는다.** v11에서 B6(저장 경계)·N1 개정(ULID)이 추가되었다 — B4(공유 단일)·H5(직렬 계약)·L5(작은 id)와 같은 사안을 다루므로 교차 대조 대상이며, 각 항에 정합 주석을 달아 두었다. **v13(M2)에서 J12·C17이 신설되고 C3·C10·D5·F1·F2·F3이 개정되었다** — C그룹(좌표·구조 필드)·F그룹(극성·이름)·J그룹(골격 두 축)·D그룹(anchor)이 골격·극성을 함께 다루므로 교차 대조 대상이다.

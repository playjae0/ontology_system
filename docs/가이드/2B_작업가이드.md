# 2B 작업 가이드 — 사내에서 치는 명령, 순서대로

> **누가 읽나**: 사내에서 2B를 진행하는 사람. 단계마다 같은 모양이다 — **목적 → 명령 → 화면에서 확인 → 막히면**.
> **여기 없는 것**: 왜 그렇게 도는지(→ `docs/구조도/00_전체_지도.md`) · 무엇이 언제 바뀌었는지(→ `docs/spec/개정대장.md`).
> **명세가 답하지 않으면** 추측으로 메우지 않는다 — §8 형식으로 허브에 가져온다.

## 상황 → 절

| I want to… | Go to |
|---|---|
| 처음 가져와서 세팅한다 | §0 → §1 → §2 |
| 두 번째 층(품질 등)을 세운다 | §3 |
| 새 문서 종류(doc_type)를 등록한다 | §4 |
| 등록된 종류의 문서를 넣는다 | §5 |
| 넣은 결과가 맞는지 본다 | §5.3 |
| 질문해 본다 | §6 |
| 뭔가 이상하다 | §7 |
| 허브에 가져갈 게 있다 | §8 |

모든 명령은 레포 루트에서 친다. `python run.py <명령>`과 `python -m cli.<모듈>`은 같은 것이다.

## §0 반입 — 30분

**목적**: 가져온 것이 온전한지 확인한다.

```bash
pip install -r requirements.txt      # 선택 의존 — 코어는 표준 라이브러리만으로 돈다
python doctor.py                     # 환경 → 회귀 → 상태 → 사내 전환 판정
```

**확인**: `회귀 802/802 PASS` · `[3] LLM 지점 9/9종 … 도달 가능`.

| Symptom | Do |
|---|---|
| 회귀 수가 다르다 | 클론이 main 최신이 아니다 — 태그·커밋을 허브에 보고 |
| `[3]`이 9/9가 아니다 | §1 전에 허브에 보고 — 코드 결함이다 |

## §1 게이트웨이 연결 — 반나절

**목적**: 사내 LLM에 붙인다. **설정은 파일 하나**, 환경변수 export는 쓰지 않는다.

```bash
echo $HOME                            # /config 처럼 이상하면 아래처럼 레포 루트에 둔다
cat > llm.local.json <<'EOF'
{
  "LLM_GATEWAY_URL": "https://사내주소",
  "LLM_API_KEY": "키",
  "CHAT_MODEL": "모델명",
  "USE_MOCK": 0
}
EOF
chmod 600 llm.local.json
python run.py llm-check               # ①설정 파일 → ②도달 → ③인증 → ④응답
```

**확인**: `llm-check`가 **읽은 파일 경로**를 찍고 ④까지 통과. 이후 LLM을 쓰는 명령은 머리에 `모드: 실호출`이 뜬다.

| Setting | Rule |
|---|---|
| 파일 자리 (위가 이긴다) | ①`ONTO_CONFIG=<절대경로>` ②`~/.onto/llm.json` ③레포 루트 `llm.local.json` |
| `USE_MOCK` | `0`이 실호출. 키가 없으면 mock |
| `LLM_CONTEXT_TOKENS` | **적지 않는다** = 무제한. 사내 한도를 확인한 뒤에만 적는다 (틀린 값은 정상 요청을 막는다) |
| `EMBED_MODEL` | 적지 않는다 — 임베딩은 이연 항목 |

| Symptom | Do |
|---|---|
| `설정 파일 없음(환경변수만)` | 자리가 틀렸다 — `$HOME` 확인 후 레포 루트 `llm.local.json` |
| 파일을 고쳤는데 값이 안 바뀐다 | 셸 환경변수가 파일을 덮는다 — `unset LLM_GATEWAY_URL LLM_API_KEY CHAT_MODEL USE_MOCK` |
| `mock 모드입니다 — 계속하려면 --allow-mock` | 게이트웨이가 안 잡혔다. 운영 명령(`register`·`parse run`·`build`·`ingest-*`·`query`)은 mock이면 멈춘다. 일부러 mock으로 볼 때만 `--allow-mock` |
| 게이트웨이가 OpenAI 호환(`/chat/completions`)이 아니다 | `core/llm.py` 한 파일만 고친다 — 허브에 보고 |

## §2 골격 seed — 하루

**목적**: 사내 공정 트리를 좌표계로 세운다. 판단이 핵심이고 명령은 짧다. 작성법은 `골격작성_가이드.md`.

```bash
# 1. 공정 설명 문서 → LLM 초안(골격작성_가이드 §4 프롬프트) → 사람이 검수 → layers/process/skeleton.json 교체
python run.py init --fresh && python run.py bootstrap
python run.py skeleton-confirm process --by <확정자>
```

**확인**: `bootstrap` 화면의 **「파생 대표 흐름 (사람 대조용)」**을 공정 문서와 대조 — 순서·무주장·mirrors 쌍·모호 이름. 문서의 공정 수 = 노드 수인지 한 번 센다(빠진 공정은 뷰가 못 잡는다).

| Symptom | Do |
|---|---|
| 흐름 순서가 문서와 다르다 | seed의 `precedes`·`@unordered` 수정 후 다시 `init --fresh && bootstrap` |
| `(짧은 이름 모호 …)` | 같은 이름이 여러 공정에 있다 — 그대로 둬도 되지만 질의는 접두 키로만 잡는다 |

## §3 층 config — 반나절 · **보통 건너뛴다**

**건너뛰는 조건**: 공정층 하나로 시작한다. `layers/process/`는 내장이고 카테고리(Process·Unit·Property)·관계(part_of·precedes·has_property·mirrors)는 그대로 맞는다 → **§4로**.

**필요한 때**: ①품질층 같은 두 번째 층 ②정의문 예시를 사내 것으로 바꿀 때(급하지 않다). 작성법은 `config작성_가이드.md`, 정의문 초안은 `층정의_프롬프트.md`로 사내 LLM에서 뜬다.

```bash
python run.py init --fresh && python run.py all      # 부팅 확인 — 실패면 어느 키인지 말해 준다
```

## §4 doc_type 등록 — 문서 종류당 반나절

**목적**: 문서 종류 하나에 어댑터·스키마 한 벌을 만든다. **손으로 쓰지 않는다** — LLM이 생성하고 사람은 검수·승인만 한다. 표든 산문이든 같다.

### §4.1 생성

```bash
python -m cli.register generate <doc_type> <층> <표본.xlsx> [표본2 …] [--interview] [--hint "…"]
#                                ^이름      ^process  ^실물 문서 — 등록 뒤 §5에서 다시 넣는다
```

| Option | When | What |
|---|---|---|
| `--interview` | 열 간 상하 구조가 판정을 가른다(다단 헤더·PFMEA) · 힌트로 뭘 적을지 모르겠다 | 생성 **전에** LLM의 이해 요약을 보고 교정. 「진행」을 칠 때까지 계속된다 |
| `--hint "…"` | 표본만으로 안 보이는 것 | 자유 텍스트 — "3~7행 병합은 위 값 채움" |
| `--use-basic` | 표본이 **전부 `.pptx`** | LLM 생성 0회 — 기본 어댑터를 등재. 검수·승인은 그대로 |
| `--resume` | 문답 도중 죽었다 | `generate <doc_type> --resume` — 층·표본 없이 초안만 다시 받는다 |

**확인**: `기계 관문 PASS` 뒤 `review/<doc_type>/view.html` 경로가 찍힌다.

| Symptom | Do |
|---|---|
| 하네스 FAIL이 자동으로 안 풀리고 묻는다 | 문답이다 — 답하면 재생성된다. `더 돌릴까? [y/N]`에서 n이면 §4.2에서 `--instruct` |
| `mock 모드입니다` | §1 |

### §4.2 검수

```bash
python -m cli.register review <doc_type> [--instruct "…"] [--rows N|all]
```

**확인 — `review/<doc_type>/view.html` 3구획**:

| Section | Table | Prose | Approve when |
|---|---|---|---|
| ① 파싱 결과 | 표본을 실제로 파싱한 record 트리 | 청크 트리(제목·구획) | 행·청크 수가 기대와 맞다 |
| ② 무엇이 개체·값이 되나 | 필드→role 배정표 + `excluded`/`undecided` 열 | **추출 결과** — 청크별 개체·관계 후보와 카테고리 집계 | table: 배정이 맞다 · prose: 뽑힌 것이 층 어휘로 말이 된다 |
| ③ 어댑터 요약 | expects · adapter_version | 같음 | 헤더 목록이 원본과 같다 |

**review가 묻는 것 둘** (기본은 끔·묻기, 미리 정하려면 플래그):

| Prompt | Cost | Flag |
|---|---|---|
| `좌표 미스 N건 … LLM 보조를 켤까? [y/N]` | 미스 행마다 1회 | `--llm-coord` / `--no-llm-coord` |
| `추출 리허설 N청크 → LLM N회. 켤까? [Y/n]` (prose) | 청크마다 1회 — **확정 뒤 인입에서 재사용되므로 추가 비용은 아니다** | `--extract` / `--no-extract` |

| Symptom | Do |
|---|---|
| ②가 이상하다 (table) | `review --instruct "헤더는 2행이다. '비고' 열은 optional"` — 손으로 어댑터를 고치지 않는다. 재생성분도 기계 관문을 다시 지난다 |
| ②가 이상하다 (prose) | 고칠 곳은 어댑터가 아니라 **층 정의문**(`layers/<층>/config.json` categories) — §7 |
| 기계 관문 FAIL | 화면의 FAIL 줄이 이유다 — `--instruct`로 재생성. 상한 없음 |
| prose 검수를 켰더니 `data/`에 청크가 생겼다 | 정상 — 추출을 켠 검수는 표본을 그 시점에 인입한다. 확정 뒤 같은 파일 인입은 재인입이다 |

### §4.3 확정

```bash
python -m cli.register confirm <doc_type> --by <승인자>
```

**막는 것**: 기계 관문 FAIL · 표본 파싱 FAIL · `--by` 없음. **막지 않는 것**: UNMAPPABLE 열(표시일 뿐) · `[warning]` · 좌표 미스(인입에서 큐로 간다).

**확인**: 확정 화면이 **다음 명령(§5)을 그대로 낸다**. 등록은 그래프를 만들지 않는다 — 표본도 §5에서 다시 넣는다.

## §5 문서 인입 — 문서마다

### §5.1 보통은 한 줄

```bash
python run.py ingest-file <문서> --dry-run          # 먼저 — 어느 doc_type으로 가나만 본다
python run.py ingest-file <문서> [--doc-type X]     # 1건: parse → extract → build
python run.py ingest-dir  <경로> [--doc-type X]     # 폴더 전부 (하위 폴더 제외)
```

| Rule | |
|---|---|
| doc_id | **파일명**(확장자 제외, 공백→`_`). 경로는 안 들어간다 |
| 같은 파일명 | 같은 문서 = **개정판 재인입** — 이전 몫을 회수하고 새로 쓴다 |
| `--doc-type` 생략 | 헤더 지문으로 찾는다. 유일 일치면 자동, 둘 이상·0건이면 묻는다 |
| `ingest-dir` | 문서 단위 독립 — 한 건 실패해도 나머지는 간다 |

**확인**: `[성공] <파일>  doc_id … record N · chunk M · 그래프 노드 K  [추출 실행|체크포인트 재사용]`.

### §5.2 한 단계씩 보고 싶을 때

| Stage | Table | Prose | Command | Output |
|---|---|---|---|---|
| parse — 형태 | records | chunks | `run.py parse run adapters/<doc_type>.py <문서> [--doc-id X]` | `parsed/<doc_id>.json` |
| extract — 의미 | (없음 — 스키마가 등록 때 정했다) | 청크별 개체·관계 후보 | `python -m cli.extract parsed/<doc_id>.json [--force]` | `extract/<doc_id>.json` |
| build — 그래프 | graph | graph | `run.py build parsed/<doc_id>.json` | `data/` |

`build`는 `extract/<doc_id>.json`이 있으면 재사용한다. 프롬프트·정의문을 고쳐서 다시 뽑고 싶으면 `cli.extract --force`.

### §5.3 인입 뒤 확인 — 5가지

```bash
python run.py show doc <doc_id>          # 이 문서가 만든 것 전부 + 큐 kind별 건수
python run.py show extract <doc_id>      # prose — 청크마다 뭐가 뽑혔나
python run.py show node <이름>           # 값·별칭·근거 청크가 달렸나 (답의 뒷면)
python run.py platform queue [kind]      # 큐 20종
python run.py show log gate              # 관계가 없을 때 — 게이트 거부
```

| Check | Expect | If not |
|---|---|---|
| record·chunk 수 | 기대한 규모 | 0이면 스키마 `fields`나 추출을 의심 — §7 |
| `show extract` (prose) | 층 어휘로 말이 되는 후보 | §7 「엉뚱한 것을 뽑는다」 |
| `show node` | 값·근거 청크가 붙어 있다 | 큐를 본다 |
| 큐 | `orphan_anchor`가 예상 밖으로 많지 않다 | 골격 alias 부족이 가장 흔하다 — §7 |
| 관계 | 그래프에 있다 | `show log gate` 먼저 — config `relation_patterns` 밖이면 저장 안 된다 |

## §7 증상 → 자리

| Symptom | Where | Fix | Effective |
|---|---|---|---|
| 뭐가 공정/설비/관리항목인지 모른다 | 정의문 | `layers/<층>/config.json` categories — `층정의_프롬프트.md`로 초안 | 다음 등록·추출부터 |
| 청크에서 엉뚱한 것을 뽑는다 / 안 뽑는다 | 추출 | 정의문(위) · `prompts/extract.md` → `cli.extract --force` → `show extract` | 재추출부터 |
| 문답 질문이 빗나간다 | 문답 | `prompts/interview.md` | 다음 문답부터 |
| role 배정·출력 형식이 이상하다 | 생성 | `review --instruct` (이 doc_type) · 반복이면 `kit/생성프롬프트_템플릿` (허브) | 다음 생성부터 |
| 뺀 열을 또 묻는다 | 스키마 | 구판 등록분 — `generate <doc_type> --resume`으로 스키마만 다시 | 그 doc_type |
| `adapter_mismatch` (양식 표류) | preflight | 문서 양식이 바뀌었다 — `review --instruct`로 어댑터 재생성 | 그 doc_type |
| 산문 청크가 통째로 나온다 | 구조 지도 | `extract/struct_maps/<doc_id>.json`의 `source`가 `heuristic`이면 §1(게이트웨이). `live`인데 나쁘면 `prompts/struct_map.md` | 다음 인입부터 |
| 좌표를 못 알아본다 (`orphan_anchor` 다량) | 골격 alias | seed `ALIASES` 추가 → `init --fresh && bootstrap` → 재인입 | bootstrap 후 |
| 같은 것이 노드 둘로 섰다 | 개체 판정 | 지금 것은 `run.py ops merge <층> <id> <into-id> --actor …`(흡수된 표기는 alias로 남아 다음부턴 사전 히트) · 반복이면 `prompts/judge.md`·정의문 | 즉시 / 다음 인입부터 |
| 관계가 그래프에 없다 | 게이트 | `show log gate` → config `relation_patterns` (층 개정 절차) | 다음 인입부터 |
| 결측 셀이 많다 | 스키마 | 정상(`missing_field` 큐만 쌓인다). 많으면 `review --instruct "'비고' 열은 optional"` | 그 doc_type |
| 답이 특정 표기를 못 찾는다 | 사전 | 그 표기가 딴 노드로 서 있으면 `ops merge`(위) · 이름이 바뀐 것이면 `ops rename`(옛 이름이 alias로 남는다) · 어디에도 없으면 그 표기를 쓰는 문서를 넣어야 생긴다 | 즉시 |
| B48 이전에 넣은 산문 문서 | 재인입 | 구조 지도가 휴리스틱이다 — 같은 파일명으로 전수 재인입 | — |

자산의 자리: `prompts/`(운영 LLM 지시문) · `layers/<층>/`(config·skeleton) · `schemas/`·`adapters/`(**confirm이 놓는다 — 손으로 고치지 않는다**) · `data/dictionary.json`(사전).

## §8 허브로 가져올 때

| Situation | Format |
|---|---|
| 명세가 답하지 않는다 | BLOCKER — ①근거 원문 ②선택지 2~3 ③귀결 |
| 명세와 실물이 어긋난다 | 어긋난 두 문면 + 실측 화면 |
| 판정이 필요하다 (값 충돌·구조 개정) | 큐 항목 + 판단 재료 |

**명세는 사내에서 고치지 않는다.** 코드 수정은 사내에서 하되 `DECISIONS.md`에 남긴다.

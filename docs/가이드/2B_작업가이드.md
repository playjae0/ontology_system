**공통 규칙** — 모든 명령은 레포 루트에서 친다. 등록 명령은 `python -m cli.register …` 한 형태로 적는다(`python run.py register …`는 같은 함수를 부르는 껍데기다). `[Y/n]`·`[y/N]`은 대소문자를 가리지 않는다 — 대문자 쪽이 Enter의 기본값이다(`[Y/n]`은 안전한 쪽 · `[y/N]`은 돈이 들거나 되돌릴 수 없는 쪽이라 사람이 `y`를 친다). 비대화형(파이프 · 배치)이면 실행 승인이 필요한 명령은 **계획만** 내고 `▶ 다음 줄 — 실행: … --yes`를 준다. 손잡이(사내에서 정할 값)는 `python run.py show knobs` → `$ONTO_HOME/knobs.json`(06 손잡이 대장의 「사내 조정 가능」 열).

## §0 자리 — 상태 폴더 다섯 단

**돌리면 생기는 것은 코드 폴더가 아니라 상태 폴더(`$ONTO_HOME`)에 생긴다** — 사내 기본은 코드 밖(코드 폴더 옆 `onto_state/`)이고, 값이 없을 때만 `<레포>/state/`다. `USE_MOCK=1`(회귀·doctor)은 `<레포>/state_mock/`에만 쓴다. 화면의 경로는 상태 안이면 상태 기준 · 레포 안이면 레포 기준 · 둘 다 아니면 절대 경로다. 다섯 단의 정본은 문서 7 §7.8, 한 장 요약은 `상태_폴더_가이드.md`.

`ingest-file`은 새 그래프 파일을 만들지 않고 **층마다 하나인 `data/<층>/graph.json`에 누적**한다 — 문서마다 생기는 것은 ④뿐이다. **`init --fresh`는 ③④⑤를 지우되 보존 일곱을 남긴다** — ④ `extract/` · `struct_maps/` · `ingest_log/` · `logs/`(명령 로그) · `vectors/`(질의 벡터) · ③ `coord_learned.json` · `alias_book.json`(화면 「남긴 것 · 지운 것 · 크기」) · ②⓪는 어느 쪽이든 남는다. 전부 지우는 클린(회귀 바닥 · 추출·판정을 처음부터)은 `init --fresh --all`이다 — 운영(실호출) 상태 폴더에서는 지울 것과 크기를 보이고 묻는다(터미널 `y/N` · 비대화형은 거부 · `--yes`). `python doctor.py`의 머리 상태 줄(배너 아래)이 지금 어느 폴더를 보는지 말한다: `상태 폴더 <경로> · 모드 <mock|실호출> · 등록 n종 · 층 k · 좌표 층 · 공통 config · 문서 m`.

## §1 연결 — 게이트웨이

| Command | What |
|---|---|
| `python run.py llm-check` | ①설정 파일(읽은 경로 · 무시된 후보) → ②도달 → ③인증 → ④응답 → ⑥임베딩(device · 로드 s · 인코딩 ms) → ⑦그림 입력 |

**설정은 파일 하나 — `$ONTO_HOME/llm.json`**(만드는 법은 부록 A.2). **처음 찾은 파일 하나만** 읽는다(합치지 않는다) — 찾는 순서 ①`ONTO_CONFIG=<절대경로>` ②`~/.onto/llm.json` ③코드 폴더 `llm.local.json` ④`$ONTO_HOME/llm.json`. 앞 자리에 옛 파일이 있으면 그것이 이긴다(`llm-check` ①과 `doctor`가 「무시됨」을 말한다) · 키마다 환경변수가 파일 값을 덮는다(덮은 키 이름이 뜬다 · 값은 안 낸다). **키는 대문자다.**

| Setting | Rule |
|---|---|
| `USE_MOCK` | `0`이 실호출. 키가 없으면 mock · 운영 명령은 mock이면 멈춘다(일부러 볼 때만 `--allow-mock`) |
| `LLM_GATEWAY_URL` · `LLM_API_KEY` · `CHAT_MODEL` | 필수 — OpenAI 호환 `/chat/completions` |
| `LLM_CONTEXT_TOKENS` | **적지 않는다** = 무제한. 사내 한도를 확인한 뒤에만 |
| `CHAT_TEMPERATURE` | **적지 않는다** = 요청에 싣지 않는다(안 받는 모델은 400). 재현성이 필요하면 `0` |
| `EMBED_BACKEND` | `gateway`(기본 · `/embeddings`) · `local`(`EMBED_MODEL`에 모델 폴더 절대경로 · `pip install sentence-transformers` + torch `+cpu`) |
| `EMBED_MODEL` · `EMBED_GATEWAY_URL` | 임베딩 모델(다국어 — bge-m3 등) · 다른 주소일 때만. **없어도 인입은 돈다**(후보 좁히기가 2-gram 겹침으로 · 「임베딩 미설정」 한 줄) |
| `CANDIDATE_NARROW` | `auto`(기본) · `embed`(강제 · 미설정이면 중단) · `overlap` — 한 문서만은 `ingest-file --narrow …` |
| `PROGRESS_EVERY` | 인입 진행 줄 보폭(값 N개마다 · 기본 25) |

**사전 점검** — `ingest-*`·`cli.extract`·`register generate`·`review`는 파싱 **전에** 그 실행이 쓸 것만 왕복한다(`llm-check`와 같은 함수 · 실행당 1회): 설정 · 채팅 · 임베딩 · 그림 · 공통 config · 쓰기. 통과 `사전 점검 — 설정 · 채팅 · 임베딩(local) · 그림(건너뜀) · 공통 config · 쓰기 — 통과 (n초 · 토큰 …)` · 실패 `사전 점검 — **<항목>**에서 멈춘다 (파싱 0 · LLM 추가 0 · 쓰기 0)` + `▶ 다음 줄`.

**화면** — 색은 터미널에서만(파이프·`NO_COLOR`·`--no-color`면 0): 특이점(노랑 new · 빨강 불확실·orphan·실패 · 초록 LLM이 붙인 값) · 구조(청록 — 예고 · 관문 머리 · 표 머리글) · 박자(보라 — `LLM 사용 시작` · 30초 누적) · 보조(흐리게). 출력이 많은 화면은 **이어지는 표**다(머리글 30행마다 · 좁은 칸은 `…` — 전체는 `-v` · 명령 로그 · 체크포인트). 토큰은 늘 `토큰 T(입력 I · 출력 O)`. `-v`는 INFO 로그와 값 줄 전량.

## §3 층 config

공정층 하나로 시작하면 **건너뛴다** — 내장 `layers/process/`의 카테고리(Process·Unit·Property)·관계가 그대로 맞는다. 두 번째 층 · 정의문을 사내 것으로 바꿀 때만: 작성법 `config작성_가이드.md`(사람이 쓰는 11키 · §9 정의문 프롬프트), 새 층을 세우는 순서는 부록 A.4. config를 고치면 `python run.py bootstrap` — 끝의 「등록 스키마 재대조」가 doc_type마다 PASS인가를 본다(FAIL 줄이 고칠 키를 말한다). 층 폴더 이름과 config의 `"layer"`는 같아야 한다(다르면 `bootstrap`·사전 점검이 멈춘다).

| `--interview` | 열 간 상하 구조가 판정을 가른다(다단 헤더·PFMEA) — 생성 **전에** 한 번에 질문 하나 · 「진행」이면 **확정 요약**(생성은 이 요약으로 한다 · `n` 다시 요약 · `수정 3`) |
| `--hint "…"` | 표본만으로 안 보이는 것 — "3~7행 병합은 위 값 채움" |
| `--sheets "2-4:prose 5:ref *:skip"` | 시트 여럿인 산문 엑셀을 비대화형으로 — 인입과 같은 문법 · 같은 기록 · 표본 하나일 때만 |
| (`columns` 값) | 어댑터 `columns`에는 헤더 라벨을 그대로 써도 된다 — 열문자는 관문이 정한다 · 같은 이름이 둘이면 `["Center","G"]` |

xlsx·csv는 **형태 판정**(신호 5 · 투표)이 먼저다 — 산문이면 플래그 없이도 「산문 포맷이다, 고정 어댑터로 갈까? [Y/n]」 · 「사람」이면 `--use-basic`/`--no-basic`으로 정한다. 고정 어댑터 doc_type에는 `--instruct`·`--revise`가 없다(화면의 다음 줄 셋 — 분할 상수 · 스키마 · `--as <새이름> --no-basic`). 산문은 시트(프레임)마다 분할 줄이 뜬다 — 짧음이 많으면 헤딩 신호가 과하고 긺이 많으면 모자란 것. 제목이 고정 규칙으로 안 서는 시트는 등록에서 막지 않고 인입 때 그 시트만 LLM이 규칙을 선언한다(`계층 — 고정 규칙으로 안 선 시트 n장: 인입 때 선언 필요`).

**관문 블록**(`■ 기계 관문 FAIL — <dt>` · `[FAIL] <태그>` · `▶ 다음 줄`)은 `generate`·`confirm`·`review`·`status` 어디서든 같다 — **태그를 읽고 다음 줄을 친다**. 「기계 관문」은 자동 검사이지 사람 검수가 아니다.

**뷰 3구획**(`view.html`): ① 파싱 결과(표 record 트리 · 산문 청크 트리) ② 무엇이 개체·값이 되나(표 — 필드→role 배정표 · 값의 정본은 열 판정 대장 `review/<dt>/columns.json` · role 고르기는 `역할_판정_가이드.md` / 산문 — 분할 분포 · 규칙이 고른 레벨과 사유) ③ 어댑터 요약. `review`가 묻는 것: `좌표 미스 N건 … LLM 보조를 켤까? [y/N]`(`--llm-coord`) · `추출 리허설 N청크 → LLM N회. 켤까? [Y/n]`(`--extract` — **임시 상태 폴더**에서 돈다 · 운영은 읽기만 · 산출은 `work/extract/rehearsal/<dt>/<doc_id>/` · 그 종류로 인입할 때 조건이 같으면 재사용 · 이미 넣은 문서를 표본으로 써도 된다). 확정이 막지 않는 것: UNMAPPABLE 열 · `[warning]` · 좌표 미스(인입에서 큐로).

**동의어는 두 겹이다** — 인입은 표기를 ①**동의어 사전**에서 찾고(LLM 0), 없으면 ②**LLM 판정**이 후보 중에서 고른다. 고르면 그 표기가 사전에 별칭으로 쌓이고(출처 `LLM 매칭`) **별칭 대장**에 이름으로 남는다 — 다음 문서부터는 ①에서 끝나고, 재구축에서도 처음부터 쓰인다. 확인 안 된 auto 노드에는 표기가 같을 때만 붙는다(같은 문서 안에서 방금 만든 auto 노드에는 판정대로). 좌표도 같은 결이다 — 좌표 태깅이 채택한 표기는 좌표 학습 기록에 남아 바로 쓰이고, 사람이 승격·거부한다(§7).

| Rule | |
|---|---|
| doc_id | **파일명**(확장자 제외 · 공백→`_`) — 같은 파일명 = 같은 문서 = 개정판 재인입(이전 몫을 회수하고 다시) · **이름만 같은 다른 문서는 서로 덮는다**(파일명을 가르거나 `parse run … --doc-id X`) · 같은 doc_id가 다른 경로에서 오면 멈춘다(`--revise`) |
| `--doc-type` 생략 | 헤더 지문으로 찾는다(등록부만 — `USE_MOCK=0`이면 내장 cp·pfmea·ipqc는 없다) · 0건은 네 갈래(화면의 「다음」) · 산문은 지문이 없어 `--doc-type` 필수 |
| 형태 판정 | xlsx·csv는 표/산문을 먼저 가른다 — `--doc-type`과 어긋나면 경고만 하고 지정대로 · 「사람」이면 멈춘 것 |
| 좌표 태깅 | 골격 이름·별칭 → 좌표 학습 기록(LLM 0) → 목록 밖 기억(같은 닫힌 목록 판의 null 답 — LLM 0) → 그래도 안 맞는 `process_ref` **표기마다 한 번** LLM(목록 중 고르거나 null) · 넘는 표기는 `orphan_anchor` |
| 좌표 쌍 | 파싱 끝에 판정 전 쌍 표(LLM 0 · 구축 큐 `coord_mismatch`와 같은 수) · 공유 별칭 하위는 행의 상위 아래에서 하나면 그 노드 · 행에 상위가 없으면 문서 좌표를 상위로 대조 |
| 시트 역할 | 산문 엑셀 · 시트 둘 이상이면 파싱 전에 묻는다(`prose` 지식 · `ref` 참조 — 저장만 · `skip` 안 읽는다) · 답은 `registry/sheet_roles/<doc_id>.json` — 같은 문서는 다시 묻지 않는다 · 배치는 「시트 역할 미정」으로 건너뛴다 — 자세히는 `걸어가기_설비문서.md` |
| 그림 · 계층 · 글자 상한 | 그림은 이미지 요약 청크(`그림 요약 — 새 n장 → LLM ≤ n회`) · 산문 시트는 문서 구조(`구조 — 시트 n · 제목 m …` · `work/struct_maps/` — 같은 파일이면 호출 0) · 3,000자 넘는 청크는 행 경계에서 한 번 더(`chunk_max_chars`) |
| 재사용 | 추출 체크포인트 = 문서 해시 · 어댑터 · 지시문 · 층 config 판이 다 같을 때 · 값 판정은 그 문서의 지난 판정 대장에서 재생(같은 자리 · 열 · 표기 · 이름 키 — LLM 0) |

### §5.2 단계별 명령

parse(형태) `python run.py parse run <어댑터.py> <문서> [--doc-id X]` → `work/parsed/<doc_id>.json` · extract(산문의 의미) `python -m cli.extract work/parsed/<doc_id>.json [--force]` → `work/extract/<doc_id>.json` · build(그래프) `python run.py build work/parsed/<doc_id>.json` → `data/`.

**화면 · 로그** — 문서마다 `── 문서 <doc_id> · doc_type · 형태 · 렌즈` 머리줄, 단계 머리 `── [k/n] <단계> — <결과>`와 끝 줄 `└ n.n초 · LLM 호출 k · 토큰 …`(표 7단 · 산문 8단 · 앞에 `[사전 점검]` · 뒤에 `[마무리]` 미러·재시도), 문서 끝 **결과표**(값 → 사전 연결 · LLM 연결 · 새 노드 · 불확실 · 보류 · 층마다 노드·엣지 · 큐 · 동의어 · 부착 · LLM 지점별). 한 줄 한 줄의 뜻은 `인입_이해_가이드.md`. 화면에 나온 줄은 전부 `work/logs/<명령>_<날짜>.log`에도 있다(실행마다 `===== 실행 시작 …` ~ `===== 실행 끝 …` · LLM 호출마다 `LLM 사용량 <지점> · 문서 <doc_id>`).

| Command | What |
|---|---|
| `python run.py rebuild [--yes] [--no-replay]` | 계획(지울 것 · 남길 것 · 다시 넣을 순서 = 처음 인입 순서 · 원본 없음 · 사람 판단 기록의 이름 채움 · 별칭 대장 채움) → `--yes` 실행: 보존 fresh → `bootstrap` → 재인입 → `ops replay` → 끝 보고(판정 재생 · 재판정 사유별 · LLM 호출 · 사람 판단 재생 · 별칭 대장 있음/없음) · 비대화형은 계획만 · `--no-replay`는 판정을 지금처럼 다시 |

## §7 증상표 — 증상 → 원인 → 칠 명령

증상 없이 「무엇을 어디서 바꿀 수 있나」는 `docs/구조도/06_손잡이_대장.md`(칸 순서). 다른 가이드의 증상은 여기 한 표에 모았다. `<dt>`는 doc_type, `<id>`는 doc_id다.

| 증상 | 원인 | 칠 명령 |
|---|---|---|
| 유닛이 경로에서 사라진다(`시트 › 지정사양`) · 유닛 아래 사양이 공정에 붙는다 | 그 시트의 구조에서 유닛 줄이 `주제`이거나 제목이 아니다 | `python run.py ingest-file <문서> --step` → 구조 확인에서 힌트로 사다리 고침(예 「가. 단은 대상 · 그 아래 9)는 사양 묶음」) → `사다리 고침 … 적용 n줄` 확인 → `c` (확정은 재구축이 재생) · 대상의 카테고리(이 층의 노드인가)는 목차 노드화 — 정의문 · 층 힌트는 config작성_가이드 §1-c |
| 화면에 `[약한 구조] 시트 '…' — 대상 0` | 구조가 그 시트에서 대상 줄을 하나도 세우지 않았다(제목이 약한 양식) | 같은 명령 `--step`으로 구조 표를 보고 고친다 · 다 넣은 뒤 `python run.py show summary`의 「약한 구조」 줄이 문서를 모은다 |

**시험을 쓸 때** — 호환은 한 자리에서 잰다(층 어휘 정적 점검 + 네 벌): 기능 시험은 그 기능이 사는 자리의 대표 사례 하나(층 · 형태로 갈리는 자리만 둘 이상) · 어서션은 성질만(화면 글자 · mock 그래프 · 큐 · 사전의 수는 재지 않는다) · 지우는 어서션은 「그 성질은 어디가 잡나」를 보고에 적는다 · 같은 명령을 어서션마다 다시 돌리지 않는다(앞 출력을 쓴다).

**고른 실행은 판정이 아니다** — 개발 중에 「이 변경이 닿는 스위트」를 먼저 보는 문이다. 회차 마감은 마감 한 줄의 doctor(전체)로만 판정한다. 첫 실행에 FAIL이 있으면 고친 뒤 마감 한 줄을 한 번 더 친다.

**명세 패치 양식** — 마감 보고의 「명세가 바뀌어야 할 문장」은 산문이 아니라 이 파일이다(요청문과 같이 다니고 안건 규칙대로 지워진다):

```
### <파일> <절>
지금: <명세에서 그대로 복사 — 그 파일에서 정확히 한 번 나오는 문자열>
바뀔: <그 자리에 들어갈 전체 문장 — 여러 줄이면 다음 열쇠 줄 전까지 · 사이 빈 줄은 새 문단>
까닭: <한 줄 — 회차 · 결정 번호>
```

새 문장 끼우기는 `지금`에 앞 문장, `바뀔`에 앞 문장 + 새 문장(표의 새 행도 같다 — 앞 행 + 새 행). `바뀔`은 지금 규칙만 쓴다 — 취소선 · 바뀐 이력 서술 · `[개정]` 꼬리표 · 표 칸 밖 글 없이 · 출처는 끝 꼬리 `(B<회차>)` 하나. 명세 본문의 모양(취소선 · 1500자 넘는 줄 · 표 칸 밖 글의 수)은 문서 검사 일곱째(`docs/회귀스위트/점검_모양.py`)가 기준값 `docs/회귀스위트/자산/명세_모양.json`과 대조한다 — 늘면 위반 · 줄면 기준을 그 수로 내린다.

**문서 다섯 갈래** — 새 사실은 다섯 중 어디 · 어느 파일 · 어느 절인지 먼저 정한다:

| 갈래 | 질문 | 자리 |
|---|---|---|
| 정본 | 규칙은 무엇인가 | `docs/spec/` — 내용은 허브 · 적용은 명세 패치(구현 세션이 `--check` 뒤 `--apply` — 문서 1 · 재봉인 대상은 허브) |
| 구조도 | 어떻게 돌아가나 | `docs/구조도/` — 명령 없음 |
| 가이드 | 무엇을 치나 | `docs/가이드/` — 지금 동작만 |
| 장부 | 무엇이 정해졌고 무엇이 열려 있나 | 결정 `DECISIONS.md` · 진행 `PROGRESS.md`(최근 3회차) · 막힘 `BLOCKERS.md`(열린 것만) · 정본 개정 `docs/spec/개정대장.md` · 열린 것 `docs/이연대장.md` — **보관 파일 셋** `docs/archive/장부/개정대장_~B99.md`(§A~§CK) · `DECISIONS_~D-150.md`(D-1~D-150) · `이연대장_닫힘.md`(닫힌 항목) · 지난 진행은 `PROGRESS_B<회차>.md` — 남은 장부가 색인 한 줄로 가리키고 발번은 남은 장부의 말번 |
| 안건 | 이번 회차에 무엇을 하나 | `docs/안건/` — 살아 있는 요청문 + 최근 마감 3(그 회차의 명세 패치 포함) |

## 부록 A 처음 설치

### A.1 반입 · 이관 — 한 번

`python -m pip install -r requirements.txt`(openpyxl · python-pptx · PyMuPDF — 문서 읽기용 · 로컬 임베딩이면 sentence-transformers · 코어는 표준 라이브러리) → `python doctor.py --regress`(반입 직후 한 번) → `python tests/test_site.py onsite`. **코드를 새로 옮길 때는 상태를 손대지 않는다** — 코드 폴더를 통째로 교체하고 `ONTO_HOME`이 같은 곳을 가리키면 전부 그대로다. 층이 아직 코드 폴더에 있는 코드에서 넘어올 때 한 번: `python run.py platform migrate --assets --from <그 코드 폴더>`.

상태가 코드 폴더 안에 있던 배치(레포 루트에 `data/`·`review/`·`parsed/`)에서 처음 넘어올 때 — 상태 폴더는 **프로젝트 폴더 안, 코드 폴더 옆**(홈이나 `/data` 같은 공용 자리가 아니다)이고 명령은 새 코드 폴더 안에서 친다:

```bash
cd <새 코드 폴더>
echo "export ONTO_HOME=$(dirname "$(pwd)")/onto_state" >> ~/.bashrc && source ~/.bashrc   # 로그인마다 살아 있게
USE_MOCK=0 python run.py platform migrate --from ../<옛 코드 폴더> --dry-run    # 파일 수가 0이면 경로가 틀린 것
USE_MOCK=0 python run.py platform migrate --from ../<옛 코드 폴더>              # 층 · 등록 · 진실 · 작업 · 골든 · 설정 — 원본은 안 옮긴다
python run.py platform doctypes                                                  # 등록 n종 · 역방향 누락 0
cp -r $ONTO_HOME ${ONTO_HOME}_bak_$(date +%Y%m%d) && mkdir -p $ONTO_HOME/raw    # 원본은 raw/에 끌어다 넣는다
python run.py init --fresh && python run.py bootstrap && python run.py ingest-dir --no-replay   # 이관한 그래프의 중복 노드를 안고 가지 않는다
```

이관 전에 다른 명령을 치면 「이관 먼저 — `platform migrate`」가 근거와 다음 줄을 준다. `USE_MOCK=0`이면 내장 doc_type은 안 보이므로 등록 0이면 목록이 비어 있는 것이 정상이다.

### A.2 게이트웨이 설정 파일

```bash
cat > $ONTO_HOME/llm.json <<'EOF'
{"LLM_GATEWAY_URL": "https://사내주소", "LLM_API_KEY": "키", "CHAT_MODEL": "모델명",
 "EMBED_BACKEND": "gateway", "EMBED_MODEL": "임베딩 모델명 — 없으면 이 키를 뺀다", "CANDIDATE_NARROW": "auto", "USE_MOCK": 0}
EOF
chmod 600 $ONTO_HOME/llm.json && python run.py llm-check
```

코드 폴더 안에 `llm.local.json`을 두지 않는다(두면 그것이 이긴다 — §1 순서). 이관으로 넘어왔으면 옛 `llm.local.json`이 이미 `$ONTO_HOME/llm.json`으로 복사돼 있다 — 그 파일에 키를 더한다. 로컬 임베딩은 `"EMBED_BACKEND": "local", "EMBED_MODEL": "<모델 폴더 절대경로>"`.

### A.3 골격 seed — 처음 쓸 때

공정 설명 문서 → LLM 초안(`골격작성_가이드.md` §4 프롬프트) → 사람이 검수 → `$ONTO_HOME/layers/process/skeleton.json` 교체(코드 폴더의 `layers/`가 아니다) → `python run.py init --fresh && python run.py bootstrap` → 런북 단계 1(문법 · 흐름 대조 · 확정).

### A.4 새 층 — 두 번째 층이 필요할 때

품질층 `layers/quality/`가 실물 예시다: `$ONTO_HOME/layers/<층>/` 폴더(이름 = layer 이름) → `config.json`(`config작성_가이드.md` §0~§6 · 정의문은 §9 프롬프트) → 골격이 있는 층만 `skeleton.json`(닫힌 목록만 두는 층은 config의 `"skeleton": {"type": "flat", "data": [...]}`) → `python run.py bootstrap`(「<층>: 노드 n · 엣지 m」) → 골격 있는 층만 `skeleton-status <층>` → `skeleton-confirm <층> --by <이름>` → `python run.py platform registry`. 그다음 등록(§4)에서 층 이름을 이 층으로 준다 — 관문 G4C·G4D·G4E가 이 층의 config와 대조한다. 품질 문서가 공정 좌표를 쓰면 `cross_layer_traverse`를 선언층에 둔다(config작성_가이드 §4).

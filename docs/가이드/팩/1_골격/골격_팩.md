# 골격 팩 — `layers/<골격 층>/skeleton.json`

> **사람**: 이 폴더의 두 파일(`골격_팩.md` · `skeleton_예시.json`)과 공장의 공정 목록(대공정 · 상위 공정 · 하위 공정 — 순서가 적힌 공정 설명 문서)을 사내 LLM에 함께 넘긴다. 받은 뒤는 맨 끝 「받은 뒤 확인」.

## 1. 할 일

당신은 공장의 공정 목록을 읽고 지식 그래프의 **골격 seed** JSON 하나를 만든다. 출력은 둘이다.

1. `skeleton.json` — JSON 하나(아래 양식).
2. **「확인 필요:」 목록** — JSON 뒤에, 판단이 갈린 자리마다 한 줄(어느 노드 · 왜 갈리는지).

## 2. 골격이 무엇인가

- 골격은 이 시스템의 **좌표계**다. 모든 문서의 공정 이름이 여기서 좌표로 풀리고, 질의가 여기서 출발한다.
- 골격에는 **공정만** 든다. 골격 노드는 사람이 고정한다 — 문서가 골격 노드를 새로 만들지 않는다. 그래서 빠진 공정 · 틀린 순서는 그대로 좌표계 전체의 오류가 된다.
- 공정 골격(좌표계)을 가진 층(골격 층)은 하나다. 사내에서는 **설비층**이 골격 층이다. 다른 층도 제 닫힌 목록을 평면 골격으로 가질 수 있지만(품질층의 영향 분류) 그것은 좌표계가 아니다.

## 3. 사내 모양 — 세 단

| 단(시스템이 깊이로 정한다) | 무엇 | 예(창작) |
|---|---|---|
| 1단 `main` | 대공정 | 조립 |
| 2단 `sub` | 상위 공정 = 설비 단위 | 라미네이션 · 폴딩 · 디개싱 |
| 3단 `detail` | 하위 공정 = unit 단위(설비 안에서 한 동작을 맡는 단) | 히터 unit · 폴딩 unit |

- 상위 공정과 하위 공정은 **둘 다 공정이고 둘 다 설비이기도 하다**(겸 — 공통 config가 선언한다 · 층 config 팩).
- 그 아래 구성 기계 · 부품(히터 블록 · 커팅 나이프)과 파라미터 · 관리 특성(히터 온도)은 **골격에 넣지 않는다** — 문서 인입이 골격 노드에 붙인다.
- 하위 공정의 이름에 「unit」 · 「설비」가 붙어 있어도 공정이면 골격에 넣는다.

## 4. 양식 — 최상위 칸은 넷뿐이다

| 칸 | 뜻 | 규칙 |
|---|---|---|
| `seed_format` | 양식 판 | `3` 고정 |
| `AXIS_LABELS` | 극성 축의 값과 한글 이름 | 키는 사내가 정한 극성 이름(예: `cathode` · `anode`)이고 **이 키가 정본**이다 — 층 config `polarity.values`는 이 키를 그대로 옮긴다 · 극성이 없는 공장이면 뺀다 |
| `TREE` | 공정 트리 | 아래 §5 |
| `ALIASES` | 사람이 보증하는 다른 표기 | 아래 §6 |

이 넷과 `_`로 시작하는 주석 칸 밖의 최상위 키는 쓰지 않는다 — 검사기가 거부한다. `tier` · `polarity` · `parent`는 적지 않는다 — 시스템이 트리에서 만든다.

## 5. TREE — 중첩은 구조, 순서는 흐름

- **중첩**이 소속(`part_of`)이다 — `{"조립": [ … ]}` 안의 공정은 조립의 하위다.
- **배열 순서**가 흐름(`precedes`)이다 — 앞 형제 다음이 뒤 형제다. 순서는 회사 표준의 **대표 흐름 한 벌**이다. 공장 · 세대별 작은 차이는 넣지 않는다.
- 항목은 이름(글) 하나거나, 아래를 가진 공정이면 키 하나짜리 객체 `{"이름": [아래 공정들]}`다.

**마커는 넷뿐이다:**

| 마커 | 뜻 | 쓰는 때 |
|---|---|---|
| `"::<축값>"` (배열 안 글) | 이 공정에 극성 인스턴스가 있다(`라미네이션::cathode`가 자동으로 선다) | 같은 공정이 양극 · 음극으로 따로 돈다 |
| `{"<이름>": "@split"}` | 이 하위 공정도 극성별로 갈린다 | 부모가 `::축값`을 가질 때 그 아래에서 |
| `{"@unordered": "<이름>"}` | 흐름에 넣지 않는다(순서를 주장하지 않는다) | 공급 · 회수처럼 다른 동작과 함께 도는 것 |
| `"@noflow"` (배열 첫 항목) | 이 형제들 전체의 순서를 주장하지 않는다 | 문서에 순서가 없다 |

극성 부모(`::축값`을 가진 공정) 아래의 **보통 자식은 극성 없이 하나로** 선다(양극 · 음극이 함께 쓰는 동작). 축별로 따로 도는 하위만 `@split`을 단다.

순서를 모르는 형제를 나열하면 **거짓 순서**가 박힌다 — 모르면 `@unordered` · `@noflow`를 쓴다.

## 6. ALIASES — 정확히 같은 표기만 잇는다

- 키는 TREE에 있는 이름, 값은 같은 노드를 가리키는 다른 표기 목록이다. **정확 일치로만** 쓰인다 — 「포함」으로 맞추지 않는다.
- **canonical(TREE의 이름)은 한 언어 하나**다. 사내 표준명 하나를 쓰고 다른 언어는 별칭으로 둔다. 「라미네이션(Lamination)」처럼 두 언어를 한 이름에 쓰지 않는다. canonical을 나중에 바꾸면 새 노드가 된다.

| 변형 | 예(창작) | 넣나 |
|---|---|---|
| 다른 언어 | `Lamination` | 넣는다 |
| 약칭 | `LAM` | 넣는다 |
| 설비 접미 | `라미네이션 설비` · `<공정> unit` | 넣는다 — 설비 표기가 그 공정 자신으로 풀리는 길이다 |
| 띄어쓰기 · 붙여쓰기 | `라미네이션설비` · `히터유닛` | 넣는다 — 한글 변형은 자동 대조가 없다 |
| 영문 대소문자만 다름 | `lamination` · `LAMINATION` | **넣지 않는다** — 시스템이 대소문자를 무시하고 맞춘다 |

위 표는 **찾아 넣을 표기의 종류**다 — 공정 목록 · 첨부 문서에 실제로 나온 표기만 넣는다. 나오지 않은 변형(붙여쓰기 · 설비 접미 등)은 지어 넣지 말고 「확인 필요」에 후보로 적는다 — 별칭은 사람의 보증이라 사람이 보고 넣는다.

## 7. 규율 — 어기면 좌표계 전체가 오염된다

1. 공정 목록에 없는 공정을 만들지 않는다. 문서가 말하지 않으면 없는 것이다.
2. 순서가 서술되지 않은 형제는 `@unordered` · `@noflow`로 낸다 — 나열 순서를 흐름으로 지어내지 않는다.
3. 골격에는 공정만 넣는다 — 부품 · 파라미터 · 불량 · 라인 · 호기는 넣지 않는다.
4. 같은 짧은 이름이 두 곳에 있으면(「검사 unit」이 두 설비 아래) 공정 목록의 표기 그대로 두고 「확인 필요」에 적는다.
5. **이름은 첨부한 공정 목록에서만 온다** — `skeleton_예시.json`의 이름은 모양을 보이려고 지은 것이라 출력의 근거가 아니다(첨부에 같은 이름이 있으면 첨부를 근거로 쓴다).
6. 판단이 갈린 자리는 「확인 필요:」에 적는다. 추측으로 채우지 않는다.

## 8. 예시 읽는 법 — `skeleton_예시.json`

- `조립`(1단) 아래 상위 공정 셋(2단) — `라미네이션 → 폴딩 → 디개싱`이 대표 흐름이다.
- `라미네이션`은 극성 인스턴스가 있다(`::cathode` · `::anode`) — 그 아래 `전극 공급 unit`만 극성별로 갈린다(`@split`).
- `폴딩` 아래 `분리막 공급 unit`은 흐름에 넣지 않았다(`@unordered` — 다른 동작과 함께 돈다).
- `디개싱` 아래는 순서가 문서에 없다고 가정해 `@noflow`로 시작했다.
- `ALIASES`는 공정 · unit마다 다른 언어 · 약칭 · 설비 접미 · 붙여쓰기 표기다.

## 받은 뒤 확인 (사람)

```
1. 받은 JSON을 $ONTO_HOME/layers/<골격 층>/skeleton.json으로 저장
   (그 층 config.json의 "skeleton": {"type": "tree-v3.2", "category": "Process", "source": "skeleton.json", …} — 층 config 팩)
2. python run.py bootstrap --dry-run          ← 모르는 키 · JSON 문법 · 마커 위반이면 파일 · 자리 · 다음 줄을 말하고 멈춘다
3. python run.py skeleton-status <골격 층>      ← 「문법 위반 0건」
4. python run.py bootstrap                     ← 「파생 대표 흐름 (seed 선언의 사람 대조용)」을 공정 문서와 대조
     - 흐름이 실제 공정 순서인가 · (무주장: …) 목록이 맞는 자리인가 · mirrors 쌍 수 = 극성 공정 수인가
     - 끝 줄 「골격 'Process'(<층>): 겸 Unit(sub·detail) · 겸 단 별칭 n개」 — 꺼짐 · 반쪽이면 공통 config의 also와 별칭을 본다
5. 빠진 공정은 화면이 못 잡는다 — 공정 목록의 공정 수와 노드 수를 사람이 한 번 센다
6. 맞으면 python run.py skeleton-confirm <골격 층> --by <이름>
```

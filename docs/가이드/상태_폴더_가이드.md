# 상태·폴더 가이드 — 무엇이 어디에 생기고, 지우면 어떻게 되나 (한 장)

> **누가 읽나**: 사내에서 돌리는 사람 · 백업을 맡은 사람 · 코드를 갈아 끼우는 사람. 명령 순서는 `2B_작업가이드`, 정본은 문서 7 §7.1·§7.8. 갈리면 명세가 이긴다.
> **한 줄 요약**: 코드는 레포, 상태는 `ONTO_HOME` 폴더 하나. 그 안이 다섯 단이고 **단이 곧 수명**이다 — 등록은 못 돌아오고, 진실은 비싸게 돌아오고, 작업은 그냥 다시 생긴다.

## 1. 두 뿌리 — 코드와 상태

```
<프로젝트 폴더>/                 예: …/ontology/  — 코드와 상태가 나란히 산다
   ontology23/                  코드 — git이 추적하는 전부. 갈아 끼워도 상태를 건드리지 않는다 (명령은 여기서 친다)
   onto_state/                  상태 = $ONTO_HOME — 코드 폴더의 **부모**에 · 홈이나 /data 같은 공용 자리가 아니다
      llm.json                  설정 (여기 하나만 둔다 — 환경변수 > 코드 폴더 llm.local.json > ~/.onto/llm.json > 여기 순으로 앞이 이기므로 앞 셋은 비워 둔다)
      knobs.json                사내 손잡이 (선택 — 없으면 전부 기본값 = 코드 상수 · 닫힌 목록 · 모르는 키·형 밖은 거부 · `python run.py show knobs`)
      raw/                      ⓪ 원본 — 사람이 넣는 문서 (하위 폴더 자유— 옛 이름 docs/)
      layers/                   ② 등록(층) — 사내 골격 seed·config · common.json(층 공통 config — 집·겸·이름 규칙) · 골격 층 폴더 이름은 자유(Process의 집이 좌표 층) (코드 폴더의 layers/는 mock seed)
      registry/                 ② 등록 — doc_types · adapters · schemas · review · sheet_roles(시트 역할 답) · doc_coords.json(문서 좌표 답) · coord_acks.json(좌표 쌍 확인)
      data/                     ③ 진실
      work/                     ④ 단계 산출·장부 — logs/<명령>_<날짜>.log · register/<dt>/(등록의 디버그 파일) 가 여기 
      export/  golden/          ⑤ 파생 · 골든셋 — 처음 쓸 때 생긴다
   ontology23/state_mock/       USE_MOCK=1(회귀·doctor)의 상태 — ONTO_HOME을 무시하고 여기만 쓴다
```

- `ONTO_HOME`은 환경변수이고 **사람이 정한 평범한 폴더**를 가리킨다 — 숨은 자리가 아니다. 안 정하면 `<코드 폴더>/state/`. `export`는 그 터미널에서만 살므로 **`~/.bashrc`에 한 줄**로 박는다(코드 폴더에서 `echo "export ONTO_HOME=$(dirname "$(pwd)")/onto_state" >> ~/.bashrc`). 지금 실제로 쓰는 폴더는 `python -c "from core import paths; print(paths.home())"` 또는 **`doctor` 첫 줄**: `상태 폴더 <경로> · 모드 <mock|실호출> · 등록 n종 · 층 k · 문서 m`. 「등록 0종 · 문서 0」이 갑자기 나오면 가져온 것이 사라진 게 아니라 다른 루트를 보는 것이다.
- mock 실행은 운영 상태에 한 바이트도 쓰지 않는다 — 회귀가 감시 파일로 잰다. 운영 루트에서 mock 산출을 볼 일은 없다.
- 폴더는 코드가 만든다(`core/paths.py::ensure` 하나). 사람이 손으로 만들 폴더는 없다.
- **레포 정본 자산은 사내에서 고치지 않는다** — `prompts/`(지시문) · `kit/` · 코드 폴더의 `layers/`(mock seed) · `schemas/blocks.json`. 고칠 것이 있으면 허브에 요청해 레포로 반영한다(사용자 확정 2026-09-21 — 최종 확정 뒤에만 손댄다). `doctor`가 레포 판과 대조해 다르면 `[ 주의 ] 레포 정본 자산이 레포 판과 다르다`를 낸다. **사내가 고치는 층 자산은 `onto_state/layers/`**이고 그것만 사람 몫이다.
- `USE_MOCK=0`인데 `ONTO_HOME`이 없으면 모드 줄과 `doctor` 첫 줄에 「(ONTO_HOME 미설정 — 기본 루트 `<코드 폴더>/state`)」가 붙는다 — 거부는 아니지만 새 터미널에서 이 조각이 보이면 `~/.bashrc`를 확인한다.

## 2. 다섯 단 — 지우면 어떻게 되나

| Tier | Folder | What lives here | Made by | If deleted | Backup |
|---|---|---|---|---|---|
| ⓪ 원본 | `raw/` | 원본 문서(엑셀·PPT·PDF …) — 하위 폴더 자유 · 파서가 읽는 포맷 (옛 이름 `docs/` — 문서가 남아 있으면 `ingest-dir`가 `mv` 줄을 준다) | 사람 | **못 돌아온다** — 재구축의 입력 | **한다** |
| ① 자산 | `<레포>/` | 코드 · `prompts/` · `kit/` · `schemas/blocks.json` · 레포 `layers/`(mock 기본 seed) · mock 내장 `tests/fixtures/` | git | git이 돌려준다 | git — 사내에서 고치지 않는다 |
| ② 등록(층) | `layers/` | `<층>/config.json` · `skeleton.json` — 사내 공정 체계 · `skeleton-confirm` 승인 1회 · `common.json`(층 공통 config — `bootstrap`이 층 config에서 맞춘다 · 없으면 바로 만들고 여러 층이 선언한 카테고리의 집만 사람이 채운다) | 사람 + `migrate`/`migrate --assets` | **못 돌아온다** — 레포 seed는 사내 골격이 아니다 · 없으면 「층 자산 먼저」 거부 | **1순위** |
| ② 등록 | `registry/` | `doc_types.json`(등록부) · `adapters/<dt>.py` · `schemas/<dt>.json` · `review/<dt>/`(입력 패키지 · 문답 · 열 판정 대장 · 뷰 · `approval.json`) · `sheet_roles/<doc_id>.json`(시트 많은 엑셀의 시트 역할 — 사람의 답) · `doc_coords.json`(문서 좌표 — `--coord`의 답) · `coord_acks.json`(좌표 쌍 확인 — 「이 어긋남은 봤고 이대로 둔다」 · 쌍 · 행위자 · 시각 · 메모 · 문서) · `ops_log.json`(**사람 판단 기록** — `ops`의 연산마다 행위자 · 시각 · 사유 · 대상의 층·이름(id는 참고) · `ops replay`·재구축이 이름으로 되살린다 · 옛 자리 `data/ops_log.json`은 첫 실행이 옮긴다) | `register generate → confirm` — 사람 승인 1회 · 시트 관문 답 1회 · `--coord` · `ops coord-ack` · `ops`(`--actor` 필수) | **못 돌아온다.** LLM 생성 + 문답 + 검수 + 확정을 처음부터 · 사람 판단은 다시 할 길이 없다 | **1순위** |
| ③ 진실 | `data/` | `<층>/graph.json` · `dictionary.json` · `chunks.json` · `review_queue.json` · `doc_registry.json` · `skeleton_closed_list.json` · `registry.json`(층 등록부) · `coord_learned.json`(좌표 학습 기록) — 8종 | `bootstrap` · `ingest-file` · `ops` | 돌아온다 — **재구축 한 명령**(`python run.py rebuild`): 문서를 처음 인입 순서로 다시 넣고 판정은 ④ 판정 대장에서 재생(LLM 0) · 사람 판단은 ② 기록에서 이름으로 되살린다. 대장이 없거나 이름이 바뀐 값만 **재판정**(보고에 사유별 수) | 2순위 |
| ④ 단계 산출·장부 | `work/` | `parsed/` · `extract/`(체크포인트 + 추출 중 부분 파일 `*.partial.jsonl` — 끝나면 지워진다) · `struct_maps/` · `ingest_log/`(판정 대장 — 판정 재생의 재료) · `rebuild/plan.json`(재구축 계획 — 지우기 전에 남긴 문서 목록 · 끊기면 다음 재구축이 이어 간다) · `register/<dt>/`(등록 디버그 — `last_error.json` 게이트웨이 오류 원문 · `prompt_rendered.md` 조립된 지시문, `ONTO_DUMP_PROMPT=1`일 때) · `gate_rejects.json` · `build_metrics.json` · `defects.log` · `link_miss.log` · `chunk_truncated.log` · `migrate.log` | 인입 각 단계 · `rebuild` | 다음 인입이 다시 만든다 — 단 `extract/`·`struct_maps/`·`ingest_log/`는 **LLM이 든 산출**이라 지우면 추출·지도·판정을 다시 부른다(`init --fresh` 기본이 남기는 것). 체크포인트는 같은 문서를 다시 넣을 때 앞 단계를 건너뛰게 하고, 판정 대장은 판정을 재생하게 한다 | 안 한다 |
| ⑤ 파생 | `export/` | Cypher · CSV · html 뷰어 산출 | `export` | 재생성 | 안 한다 |
| ⑤′ 골든셋 | `golden/` | `queries.json` — 사람이 쓴 질의 · 반출 금지 | `golden init` + 사람 | **못 돌아온다** | 한다 |

**그래서 백업은 `raw/` + `layers/` + `registry/` + `data/` + `golden/` 다섯이다**(설정 `llm.json`·`knobs.json`은 루트의 파일 둘 — 함께 둔다 · 사람 판단 기록 `registry/ops_log.json`은 `registry/`에 든다). `work/`·`export/`는 넣지 않는다 — 넣으면 크기만 커진다(재구축 비용을 아끼려면 `work/extract`·`work/ingest_log`만 따로).

## 3. 명령 → 어디에 쓰나

| Command | Writes to | Note |
|---|---|---|
| `init --fresh` | ③④⑤를 지우되 **LLM이 든 산출 넷**은 남긴다 — ④ `work/extract/`(산문 추출) · `work/struct_maps/`(구조 지도 · 그림 요약) · `work/ingest_log/`(판정 대장) · ③ `data/coord_learned.json`(좌표 학습) · ⓪②(`layers/`·`registry/`)·`golden/`은 남긴다 · 화면 「남긴 것 · 지운 것 · 크기」 한 줄씩 | 재구축의 바닥이다 — 다시 짓는 것은 `rebuild`가 한다(문서 목록을 지우기 전에 남긴다). 남긴 것의 재사용은 각자의 판정 그대로(추출 = 문서 해시 · 어댑터 · 지시문 · 층 config 판) |
| `init --fresh --all` | ③④⑤를 **폴더째 지운다**(클린) · mock 루트에서만 레포 seed를 `layers/`로 다시 복사하고 사람 판단 기록을 비운다 | 회귀 바닥(doctor · 시험)이지 일상 조작이 아니다 — 추출·판정을 처음부터 다시 부른다 |
| `rebuild [--yes] [--no-replay]` | ④ `work/rebuild/plan.json`(지우기 **전에** 문서 목록 · 처음 인입 순서 · 원본 경로 · doc_type · `duplicate_ok` · 그림 뺌) → `init --fresh`(보존) → `bootstrap` → 문서마다 같은 순서로 인입(판정 재생) → `ops replay` → 보고(판정 재생 · 재판정 사유별 · LLM 호출 · 사람 판단 재생 · 대상 없음 · 원본 없음) | **비대화형은 계획만**(지울 것 · 남길 것 · 다시 넣을 순서) — 실행은 `--yes` · 사람 판단 기록은 늘지 않는다 · 원본이 없는 문서는 건너뛰고 목록에 |
| `bootstrap` | ③ `data/registry.json` · `<층>/graph.json`(골격) · `skeleton_closed_list.json` · ② `layers/common.json`(맞출 것이 있을 때만 · 근거는 ④ `work/logs/bootstrap_<날짜>.log`) | 골격 seed(**상태 루트** `layers/`)에서 · 끝에 등록 스키마 재대조(쓰기 0) · `--dry-run`은 계획만(쓰기 0) |
| `register generate` | ② `registry/review/<dt>/` | 초안·문답·대장·뷰 |
| `register confirm` | ② `registry/doc_types.json` · `adapters/` · `schemas/` · `review/<dt>/approval.json` | 승인 1회 |
| `ingest-file` / `ingest-dir` | ② `registry/sheet_roles/<doc_id>.json`(산문 엑셀 · 시트 둘 이상 · 관문의 답) → ④ `work/parsed` · `extract` · `struct_maps` · `ingest_log` → ③ `data/` 넷(그래프·사전·청크·큐) · `doc_registry.json`(원본 경로 — 상태 루트 아래면 상대) | 그래프 파일은 층마다 하나 — 문서마다 생기는 것은 ④뿐 · `ingest-dir` 인자 없으면 ⓪`raw/` 전체 재귀 · 화면 로그 전량은 ④ `work/logs/<명령>_<날짜>.log` |
| `ops confirm/merge/obsolete/alias/rename/transfer/delete-edge` · `ops review` | ③ `data/<층>/graph.json` · `dictionary.json` · `review_queue.json`(사람이 닫은 항목) · ② `registry/ops_log.json`(연산마다 대상의 층·이름) | 사람의 판정 — 재생성되지 않는 것 · 재구축 뒤 `ops replay`가 이름으로 되살린다 |
| `ops confirm all --doc <id>` | 위와 같다(노드마다 confirm 한 번 · 기록도 노드마다) | 그 문서 실행이 만든 auto 노드 전부 — 비대화형은 계획만(`--yes`) · 불확실은 넣지 않는다 |
| `ops replay all [--dry-run]` | ③ 위와 같다(지금 손이 다시 한다) · ② 기록은 **늘지 않는다** | 이미 그 상태면 건너뛴다(두 번 쳐도 같다) · 이름이 지금 그래프에 없으면 「대상 없음」 목록(기록은 지우지 않는다) · `split`은 재생하지 않는다 |
| `ops coord-ack` / `coord-unack` | ② `registry/coord_acks.json` · ③ `review_queue.json`(그 쌍 항목의 종결 `resolution` · 취소는 이 손잡이가 단 것만 걷는다) | 사람의 판정 — 기록은 등록 단이라 `init --fresh`에도 산다(다시 쌓인 큐의 같은 쌍은 확인됨으로 실린다) |
| `export …` | ⑤ `export/` | 되돌려 읽지 않는다 |
| `viewer` | **아무 데도 안 쓴다**(읽기 전용 서버 · 127.0.0.1) | 원본은 `raw/`에서 그대로 내준다 |
| `golden init/score` | `golden/queries.json` · ④ `work/golden_log.json` | 점수는 로그 |
| `platform migrate` | ②(`layers/`·`registry/`)·③④·`golden/`·설정(복사 — ⓪원본은 안 옮긴다, 사람이 `raw/`에 넣는다) · ④ `work/migrate.log` | 옛 배치 → 새 루트 · 한 번 |
| `platform migrate --assets --from <옛 코드 폴더>` | ② `layers/`만 | 층이 아직 코드 폴더에 있는 코드에서 넘어올 때 · 이미 있고 다르면 덮지 않고 멈춘다 |

## 4. 코드를 갈아 끼울 때

**보통은**: 코드 폴더를 통째로 교체한다. `ONTO_HOME`이 같은 곳을 가리키면 끝 — 옮길 것 없음. **층이 아직 코드 폴더에 있는 코드(태그 `B78-3`)에서 넘어올 때 한 번**: `python run.py platform migrate --assets --from <그 코드 폴더>` — 상태 루트에 `layers/`가 생긴다.

**상태가 코드 폴더 안에 있던 배치(레포 루트에 `data/`·`review/`·`parsed/`)에서 처음 넘어올 때** — 한 번만:

```bash
cd <새 코드 폴더>                                                 # 명령은 새 코드 폴더에서
echo "export ONTO_HOME=$(dirname "$(pwd)")/onto_state" >> ~/.bashrc && source ~/.bashrc   # 상태는 그 부모에
USE_MOCK=0 python run.py platform migrate --from ../<옛 코드 폴더> --dry-run   # 무엇이 어디로 가는지만 · 파일 0이면 경로가 틀림
USE_MOCK=0 python run.py platform migrate --from ../<옛 코드 폴더>             # 복사 — 옛 폴더는 남는다 (첫 실행만 USE_MOCK=0 — 설정 파일이 같이 넘어온다)
python run.py platform doctypes                                   # 등록 n종 · ⚠ 0건 · ls $ONTO_HOME 에 layers/ 가 있어야 한다
cp -r $ONTO_HOME ${ONTO_HOME}_bak_$(date +%Y%m%d)                  # 옛 그래프를 이력으로 남기려면 — 지우기 전에
mkdir -p $ONTO_HOME/raw                                           # ⓪원본 자리 — 원본은 탐색기로 끌어다 넣는다 · 하위 폴더 자유
python run.py init --fresh && python run.py bootstrap && python run.py ingest-dir --no-replay   # 다시 짓기 1회 — 인자 없으면 raw/ 전체 · 이관한 판정 대장은 쓰지 않고 지금 코드로 판정(추출은 재사용)
```

`--from`은 **옛 코드 폴더 그 자체**(옛 방식의 `data/` 폴더가 들어 있는 그 폴더)이고 상위 폴더가 아니다. 상대경로는 명령을 친 자리(새 코드 폴더) 기준이다. 백업본도 똑같은 상태 루트라 옛 그래프는 언제든 `ONTO_HOME=<백업 폴더> python run.py show tree`로 열린다.

이관은 **복사**다 — 잘못되면 옛 코드 폴더 + 옛 상태 폴더로 그대로 돌아간다. 이관 전에 다른 명령을 치면 「이관 먼저 — `platform migrate`」로 거부하고 근거와 다음 줄을 준다. 되돌림 좌표(태그): `pre-B78` → `B78-1a` → `B78-1b` → `B78-2a` → `B78-2b` → `B78-2c` → `B78-3`.

# 상태·폴더 가이드 — 무엇이 어디에 생기고, 지우면 어떻게 되나 (한 장)

> **누가 읽나**: 사내에서 돌리는 사람 · 백업을 맡은 사람 · 코드를 갈아 끼우는 사람. 명령 순서는 `2B_작업가이드`, 정본은 문서 7 §7.1·§7.8. 갈리면 명세가 이긴다.
> **한 줄 요약**: 코드는 레포, 상태는 `ONTO_HOME` 폴더 하나. 그 안이 다섯 단이고 **단이 곧 수명**이다 — 등록은 못 돌아오고, 진실은 비싸게 돌아오고, 작업은 그냥 다시 생긴다.

## 1. 두 뿌리 — 코드와 상태

```
<프로젝트 폴더>/                 예: …/ontology/  — 코드와 상태가 나란히 산다
   ontology23/                  코드 — git이 추적하는 전부. 갈아 끼워도 상태를 건드리지 않는다 (명령은 여기서 친다)
   onto_state/                  상태 = $ONTO_HOME — 코드 폴더의 **부모**에 · 홈이나 /data 같은 공용 자리가 아니다
      llm.json                  설정 (여기 하나만 둔다 — 환경변수 > 코드 폴더 llm.local.json > ~/.onto/llm.json > 여기 순으로 앞이 이기므로 앞 셋은 비워 둔다)
      raw/                      ⓪ 원본 — 사람이 넣는 문서 (하위 폴더 자유 · B80 ② — 옛 이름 docs/)
      layers/                   ② 등록(층) — 사내 골격 seed·config · 골격 층 폴더 이름은 자유(B85 — Process 선언 층이 좌표 층) (B79 — 코드 폴더의 layers/는 mock seed)
      registry/                 ② 등록 — doc_types · adapters · schemas · review · sheet_roles(시트 역할 답 · B83)
      data/                     ③ 진실
      work/                     ④ 단계 산출·장부 — logs/<명령>_<날짜>.log 가 여기 (B81)
      export/  golden/          ⑤ 파생 · 골든셋 — 처음 쓸 때 생긴다
   ontology23/state_mock/       USE_MOCK=1(회귀·doctor)의 상태 — ONTO_HOME을 무시하고 여기만 쓴다
```

- `ONTO_HOME`은 환경변수이고 **사람이 정한 평범한 폴더**를 가리킨다 — 숨은 자리가 아니다. 안 정하면 `<코드 폴더>/state/`. `export`는 그 터미널에서만 살므로 **`~/.bashrc`에 한 줄**로 박는다(코드 폴더에서 `echo "export ONTO_HOME=$(dirname "$(pwd)")/onto_state" >> ~/.bashrc`). 지금 실제로 쓰는 폴더는 `python -c "from core import paths; print(paths.home())"` 또는 **`doctor` 첫 줄**: `상태 폴더 <경로> · 모드 <mock|실호출> · 등록 n종 · 층 k · 문서 m`. 「등록 0종 · 문서 0」이 갑자기 나오면 가져온 것이 사라진 게 아니라 다른 루트를 보는 것이다.
- mock 실행은 운영 상태에 한 바이트도 쓰지 않는다 — 회귀가 감시 파일로 잰다. 운영 루트에서 mock 산출을 볼 일은 없다.
- 폴더는 코드가 만든다(`core/paths.py::ensure` 하나). 사람이 손으로 만들 폴더는 없다.
- **레포 정본 자산은 사내에서 고치지 않는다** — `prompts/`(지시문) · `kit/` · 코드 폴더의 `layers/`(mock seed) · `schemas/blocks.json`. 고칠 것이 있으면 허브에 요청해 레포로 반영한다(사용자 확정 2026-09-21 — 최종 확정 뒤에만 손댄다). `doctor`가 레포 판과 대조해 다르면 `[ 주의 ] 레포 정본 자산이 레포 판과 다르다`를 낸다. **사내가 고치는 층 자산은 `onto_state/layers/`**(B79)이고 그것만 사람 몫이다.
- `USE_MOCK=0`인데 `ONTO_HOME`이 없으면 모드 줄과 `doctor` 첫 줄에 「(ONTO_HOME 미설정 — 기본 루트 `<코드 폴더>/state`)」가 붙는다 — 거부는 아니지만 새 터미널에서 이 조각이 보이면 `~/.bashrc`를 확인한다.

## 2. 다섯 단 — 지우면 어떻게 되나

| Tier | Folder | What lives here | Made by | If deleted | Backup |
|---|---|---|---|---|---|
| ⓪ 원본 | `raw/` | 원본 문서(엑셀·PPT·PDF …) — 하위 폴더 자유 · 파서가 읽는 포맷 (옛 이름 `docs/` — 문서가 남아 있으면 `ingest-dir`가 `mv` 줄을 준다) | 사람 | **못 돌아온다** — 재구축의 입력 | **한다** |
| ① 자산 | `<레포>/` | 코드 · `prompts/` · `kit/` · `schemas/blocks.json` · 레포 `layers/`(mock 기본 seed) · mock 내장 `tests/fixtures/` | git | git이 돌려준다 | git — 사내에서 고치지 않는다 |
| ② 등록(층) | `layers/` | `<층>/config.json` · `skeleton.json` — 사내 공정 체계 · `skeleton-confirm` 승인 1회 | 사람 + `migrate`/`migrate --assets` | **못 돌아온다** — 레포 seed는 사내 골격이 아니다 · 없으면 「층 자산 먼저」 거부 | **1순위** |
| ② 등록 | `registry/` | `doc_types.json`(등록부) · `adapters/<dt>.py` · `schemas/<dt>.json` · `review/<dt>/`(입력 패키지 · 문답 · 열 판정 대장 · 뷰 · `approval.json`) · `sheet_roles/<doc_id>.json`(시트 많은 엑셀의 시트 역할 — 사람의 답 · B83) | `register generate → confirm` — 사람 승인 1회 · 시트 관문 답 1회 | **못 돌아온다.** LLM 생성 + 문답 + 검수 + 확정을 처음부터 | **1순위** |
| ③ 진실 | `data/` | `<층>/graph.json` · `dictionary.json` · `chunks.json` · `review_queue.json` · `doc_registry.json` · `ops_log.json` · `skeleton_closed_list.json` · `registry.json`(층 등록부) — 8종 | `bootstrap` · `ingest-file` · `ops` | 돌아오긴 한다 — `bootstrap` + 문서 전량 재인입. 그러나 **재판정**이다: 판정 LLM 비용이 다시 들고, 큐에서 사람이 한 판정(`ops confirm`·merge·alias)은 **돌아오지 않는다** | 2순위 |
| ④ 단계 산출·장부 | `work/` | `parsed/` · `extract/` · `struct_maps/` · `ingest_log/`(판정 대장) · `gate_rejects.json` · `build_metrics.json` · `defects.log` · `link_miss.log` · `chunk_truncated.log` · `migrate.log` | 인입 각 단계 | **아무 일도 없다** — 다음 인입이 다시 만든다. 체크포인트(`parsed/`·`extract/`)는 같은 문서를 다시 넣을 때 앞 단계를 건너뛰게 해 주는 것뿐 | 안 한다 |
| ⑤ 파생 | `export/` | Cypher · CSV · html 뷰어 산출 | `export` | 재생성 | 안 한다 |
| ⑤′ 골든셋 | `golden/` | `queries.json` — 사람이 쓴 질의 · 반출 금지 | `golden init` + 사람 | **못 돌아온다** | 한다 |

**그래서 백업은 `raw/` + `layers/` + `registry/` + `data/` + `golden/` 다섯이다.** `work/`·`export/`는 넣지 않는다 — 넣으면 크기만 커진다.

## 3. 명령 → 어디에 쓰나

| Command | Writes to | Note |
|---|---|---|
| `init --fresh` | ③④⑤를 **폴더째 지운다** · ⓪②(`layers/`·`registry/`)·`golden/`은 남긴다 · mock 루트에서만 레포 seed를 `layers/`로 복사 | 회귀·재구축용이지 일상 조작이 아니다 |
| `bootstrap` | ③ `data/registry.json` · `<층>/graph.json`(골격) · `skeleton_closed_list.json` | 골격 seed(**상태 루트** `layers/`)에서 |
| `register generate` | ② `registry/review/<dt>/` | 초안·문답·대장·뷰 |
| `register confirm` | ② `registry/doc_types.json` · `adapters/` · `schemas/` · `review/<dt>/approval.json` | 승인 1회 |
| `ingest-file` / `ingest-dir` | ② `registry/sheet_roles/<doc_id>.json`(산문 엑셀 · 시트 둘 이상 · 관문의 답 — B83) → ④ `work/parsed` · `extract` · `struct_maps` · `ingest_log` → ③ `data/` 넷(그래프·사전·청크·큐) · `doc_registry.json`(원본 경로 — 상태 루트 아래면 상대) | 그래프 파일은 층마다 하나 — 문서마다 생기는 것은 ④뿐 · `ingest-dir` 인자 없으면 ⓪`raw/` 전체 재귀 · 화면 로그 전량은 ④ `work/logs/<명령>_<날짜>.log` |
| `ops confirm/merge/obsolete/alias` | ③ `data/<층>/graph.json` · `dictionary.json` · `ops_log.json` | 사람의 판정 — 재생성되지 않는 것 |
| `export …` | ⑤ `export/` | 되돌려 읽지 않는다 |
| `viewer` | **아무 데도 안 쓴다**(B82 — 읽기 전용 서버 · 127.0.0.1) | 원본은 `raw/`에서 그대로 내준다 |
| `golden init/score` | `golden/queries.json` · ④ `work/golden_log.json` | 점수는 로그 |
| `platform migrate` | ②(`layers/`·`registry/`)·③④·`golden/`·설정(복사 — ⓪원본은 안 옮긴다, 사람이 `raw/`에 넣는다 · B80 ②) · ④ `work/migrate.log` | 옛 배치 → 새 루트 · 한 번 |
| `platform migrate --assets --from <옛 코드 폴더>` | ② `layers/`만 | B78-3 판에서 B79로 넘어올 때 · 이미 있고 다르면 덮지 않고 멈춘다 |

## 4. 코드를 갈아 끼울 때

**B79 이후 판끼리**: 코드 폴더를 통째로 교체한다. `ONTO_HOME`이 같은 곳을 가리키면 끝 — 옮길 것 없음. **B78-3 판(층이 아직 코드 폴더에 있던 판)에서 처음 B79로 올 때 한 번**: `python run.py platform migrate --assets --from <B78 코드 폴더>` — 상태 루트에 `layers/`가 생긴다.

**B78 이전 배치(레포 루트에 `data/`·`review/`·`parsed/`가 있던 코드)에서 처음 넘어올 때** — 한 번만:

```bash
cd <새 코드 폴더>                                                 # 명령은 새 코드 폴더에서
echo "export ONTO_HOME=$(dirname "$(pwd)")/onto_state" >> ~/.bashrc && source ~/.bashrc   # 상태는 그 부모에
USE_MOCK=0 python run.py platform migrate --from ../<옛 코드 폴더> --dry-run   # 무엇이 어디로 가는지만 · 파일 0이면 경로가 틀림
USE_MOCK=0 python run.py platform migrate --from ../<옛 코드 폴더>             # 복사 — 옛 폴더는 남는다 (첫 실행만 USE_MOCK=0 — 설정 파일이 같이 넘어온다)
python run.py platform doctypes                                   # 등록 n종 · ⚠ 0건 · ls $ONTO_HOME 에 layers/ 가 있어야 한다
cp -r $ONTO_HOME ${ONTO_HOME}_bak_$(date +%Y%m%d)                  # 옛 그래프를 이력으로 남기려면 — 지우기 전에
mkdir -p $ONTO_HOME/raw                                           # ⓪원본 자리 — 원본은 탐색기로 끌어다 넣는다 · 하위 폴더 자유
python run.py init --fresh && python run.py bootstrap && python run.py ingest-dir     # 재구축 1회 — 인자 없으면 docs/ 전체
```

`--from`은 **옛 코드 폴더 그 자체**(옛 방식의 `data/` 폴더가 들어 있는 그 폴더)이고 상위 폴더가 아니다. 상대경로는 명령을 친 자리(새 코드 폴더) 기준이다. 백업본도 똑같은 상태 루트라 옛 그래프는 언제든 `ONTO_HOME=<백업 폴더> python run.py show tree`로 열린다.

이관은 **복사**다 — 잘못되면 옛 코드 폴더 + 옛 상태 폴더로 그대로 돌아간다. 이관 전에 다른 명령을 치면 「이관 먼저 — `platform migrate`」로 거부하고 근거와 다음 줄을 준다. 되돌림 좌표(태그): `pre-B78` → `B78-1a` → `B78-1b` → `B78-2a` → `B78-2b` → `B78-2c` → `B78-3`.

## 5. 증상 → 자리

| Symptom | Where to look |
|---|---|
| 「등록돼 있지 않다」 — 방금 옮겼는데 | ② `registry/doc_types.json`에 키가 없다. `platform doctypes`가 `review/<dt>/approval.json`은 있는데 등록부에 없는 이름을 ⚠로 부른다 |
| 「이관 먼저」 | 옛 배치가 레포 루트에 있고 `ONTO_HOME`이 비어 있다 — §4 |
| 「층 자산 먼저 — 상태 루트에 층이 없다」 | `onto_state/layers/`가 비었다 — `migrate --assets --from <옛 코드 폴더>` 또는 `cp -r <옛 코드 폴더>/layers $ONTO_HOME/` |
| 「넣을 문서가 없다 — `<상태>/raw`가 없다」 | 인자 없는 `ingest-dir`는 ⓪원본 자리를 돈다 — `mkdir -p $ONTO_HOME/raw`에 문서를 넣거나 경로를 준다 |
| 「원본 자리가 `raw/`로 바뀌었다 — 옛 이름에 문서가 있다」 | B79 판에서 `docs/`에 넣은 문서다 — 화면의 `mv` 줄 그대로(B80 ②). 코드가 옮기지 않는 이유: 원본은 사람 물건이다 |
| 화면이 조용한데 무슨 일이 있었는지 보고 싶다 | ④ `work/logs/<명령>_<날짜>.log` — INFO 전량(B81 ②). 화면은 판단이 갈린 값과 요약만 · `-v`면 화면에도 |
| `[ 주의 ] 레포 정본 자산이 레포 판과 다르다` | 코드 폴더의 `prompts/`·`kit/`·`layers/`·`blocks.json` 중 하나가 손댄 상태 — 되돌리고 고칠 것은 허브로 |
| 그래프가 비어 있다 · 문서 0 | 다른 루트를 보고 있다 — `doctor` 첫 줄의 경로 확인 · `ONTO_HOME` 오타 |
| 같은 문서를 넣었는데 앞 단계를 건너뛴다 | ④ 체크포인트 재사용 — `doc_hash`·`adapter_version`이 둘 다 같을 때만이다. 어댑터를 `--revise`했으면 새로 판다 |
| 산문 등록이 `ValueError: … is not in the subpath of …`로 죽는다 | 상태 루트가 코드 밖인데(이 가이드의 기본) B86 이전 코드다 — 화면에 경로를 적는 자리가 레포 기준만 알았다. B86 뒤 코드로 교체(상태는 그대로) · 화면의 경로는 상태 안이면 상태 기준, 레포 안이면 레포 기준, 둘 다 아니면 절대 경로다 |
| 「[대장] '<doc_id>'의 판정 대장이 없다 — …」의 경로 | ④ `work/ingest_log/<doc_id>.json`이다 — B86 이전 문면은 B78 전의 옛 ③단 자리(`data/` 아래)를 적고 거기서 세어 늘 0건이었다 |
| 새 코드 폴더에서 `[상태] … pip install openpyxl` | 상태 폴더 문제가 아니다 — 새 파이썬 환경이라 선택 의존이 없다. `pip install openpyxl python-pptx pymupdf` (B86 ④) |
| 회귀를 돌렸더니 운영 데이터가 바뀌었다(고 의심) | 그럴 수 없다 — mock은 `state_mock/`에만 쓴다. 바뀌었다면 실호출 명령을 친 것 — `ops_log.json`·`doc_registry.json`의 시각으로 확인 |

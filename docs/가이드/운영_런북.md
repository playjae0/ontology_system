# 운영 런북 — 처음부터 끝까지, 한 줄기로

> **누가 읽나**: 사내에서 시스템을 돌리는 사람. 이 문서 하나를 **위에서 아래로** 따라간다. 단계마다 같은 모양이다 — **할 일 → 칠 명령 → 확인할 것(화면 줄) → 막히면**.
> **다른 문서**: 명령의 옵션 전부와 증상표는 [`2B_작업가이드.md`](2B_작업가이드.md)(명령 사전 · §7 증상표) · 화면 한 줄이 무슨 단계인지는 [`인입_이해_가이드.md`](인입_이해_가이드.md) · 무엇이 어디에 쌓이는지는 [`상태_폴더_가이드.md`](상태_폴더_가이드.md) · 시트 많은 설비 문서는 [`걸어가기_설비문서.md`](걸어가기_설비문서.md).

## 0 준비 — 백업 · 반입 · 점검 · 연결

**할 일** — 상태 폴더를 통째로 복사해 둔다(재구축·반입 전에는 늘 — 기본 fresh · 재구축은 산문 추출 · 구조 지도 · 판정 대장 · 좌표 학습 · 별칭 대장 · 명령 로그를 남기지만 그래프 · 사전 · 큐는 지운다 · 그래프 판을 되돌리는 것은 이 백업뿐이다) → 코드 폴더를 새 것으로 바꾼다(상태 폴더는 손대지 않는다) → 점검 → 게이트웨이 연결. 처음 설치(이관 · 설정 파일 만들기 · 선택 의존 설치)는 [2B 부록 A](2B_작업가이드.md#부록-a-처음-설치).

코드를 바꿀 때 같이 볼 것 셋:
- **새 가상환경이면 패키지부터** — `python -m pip install -r requirements.txt`(로컬 임베딩 설정이면 `sentence-transformers`까지 — 없으면 `llm-check` ⑥ 임베딩에서 멈춘다). **PPT · PDF를 넣으려면** 셋이 다 있어야 한다(`requirements.txt` 머리말이 정본): python-pptx · PyMuPDF + 캡처 길 하나(LibreOffice — Impress 포함 · 표준 자리에 깔면 PATH에 없어도 찾는다 · 다른 자리면 셸 설정 파일에 `SOFFICE_PATH=<soffice 경로>` · 또는 PowerPoint에서 PDF로 저장해 원본과 같은 폴더 · 같은 이름으로) + 게이트웨이 그림 입력(`llm-check` ⑦). 확인은 `python doctor.py --env`의 `soffice 있음 — <경로>(PATH | 표준 자리 | 지정)` · `PPT 캡처 — 가능(soffice)` 줄 — 없으면 실호출 PPT · PDF 인입이 파싱 전에 멈추고 빠진 것을 말한다(캡처 없이 진행은 같은 명령에 `--no-capture` · 기록에 남는다).
- **`ONTO_HOME`은 셸 설정(`~/.bashrc` · `~/.zshrc`)이나 가상환경 활성화 스크립트(`<venv>/bin/activate` 끝)에 둔다** — `export`만 치면 그 터미널에서만 산다(새 터미널은 다른 상태 폴더를 본다).
- **설정 파일은 `$ONTO_HOME/llm.json`에 둔다** — 코드 폴더의 `llm.local.json`은 코드 폴더를 바꿀 때 함께 사라진다. `llm-check` ①의 `설정 파일 <경로>`가 읽은 파일이다.
- **판정 · 이름 규칙이 바뀐 판이면 반입 뒤 재구축 한 명령**(`python run.py rebuild` — 기본 fresh · [단계 6](#6-골격-고치고-재구축)) — 노드 칸(부모 경로 · 맨 이름)을 새로 쓰고, 표(CP)와 산문의 같은 개념이 같은 공정 줄기 · 경로 호환이면 한 노드로 선다. 지난 LLM 판정은 재생하고 후보 0으로 끝났던 값만 지금 관문으로 다시 잰다(판정 호출이 늘 수 있다 — 끝의 LLM 끝 표가 센다).

기본 `doctor`는 **점검**이다(환경 · 머리 상태 줄 · 정합 · 설정 파일 · 사내 전환 판정 — 회귀 0 · 몇 초) · 운영 셸(실호출 · `ONTO_HOME`)에서 쳐도 된다 — **운영 상태 폴더는 읽기만 한다**. **회귀는 반입 직후 한 번** `python doctor.py --regress`(사내 Python · 패키지 판 차이를 잡는 자리 — 몇 분) · 클린 · 회귀 · 미설치 모사는 셸과 무관하게 코드 폴더의 mock 루트(`state_mock/`)와 스위트마다의 임시 자리에서 돈다 · 붉은 스위트는 화면의 「붉은 기록 — <자리>」 폴더(안에 `출력.txt`)를 그대로 허브로 가져온다.

**칠 명령**

```bash
cp -r $ONTO_HOME ${ONTO_HOME}_bak_$(date +%Y%m%d)    # 통째 백업 — 시스템에 그래프 판 보관 기능은 없다
python -m pip install -r requirements.txt            # 새 가상환경이면 (로컬 임베딩이면 sentence-transformers 포함)
python doctor.py --regress                           # 반입 직후 한 번 — 회귀(스위트 전부 · 몇 분)
python doctor.py                                     # 평소 — 환경 → 상태 → 사내 전환 판정 (점검만 · 회귀 0 · 몇 초)
python run.py llm-check                              # ①설정 파일 → ②도달 → ③인증 → ④응답 → ⑥임베딩 → ⑦그림 입력
```

**확인할 것**

- `doctor` 머리의 상태 줄(배너 세 줄 아래) — 같은 상태 폴더 · 같은 등록 수인가:
  `상태 폴더 … · 모드 mock · 등록 4종(내장 4) · 층 2(상태 루트) · 좌표 층 process · 공통 config v1 · 문서 0`
  (사내는 운영 상태 폴더 그대로 — 운영 루트 모양 연습 폴더의 실제 줄: `상태 폴더 …/opsdemo · 모드 실호출 · 등록 1종 · 층 2(상태 루트) · 좌표 층 process · 공통 config v1 · 문서 3` · 등록 수 = 사내 등록 종수 · 문서 수 = 지금까지 넣은 수)
- `① 환경`의 설정 두 줄 — 읽은 설정 파일이 상태 폴더의 것이고, 점검이 운영 상태 폴더를 읽기만 한다:
  `[  OK ] LLM 설정 파일` · `설정 파일 …/opsdemo/llm.json`
  `[  OK ] 운영 명령의 모드 — 실호출` · `점검의 하위 실행(클린 · 회귀 · 미설치 모사 · run.py all · 질의)은 이와 무관하게 mock 격리 루트에서 돈다 — 운영 상태 폴더는 읽기만 한다`
- `[  OK ] 정합 — 사라진 노드를 가리키는 것` 아래 `큐 0 · 사전 표기 0 · 끝점 없는 엣지 0`
- `[  OK ] 레포 정본 자산이 레포 판이다`
- 쓰기 두 줄 — `[  OK ] 상태 폴더 쓰기 가능 — <상태 폴더>`(못 쓰면 `[ 필요 ]` — 인입이 돌지 않는다: 상태 폴더 자리 `ONTO_HOME` 또는 그 폴더 권한) · `[  OK ] 코드 폴더 쓰기 가능 — <코드 폴더>`(못 쓰면 `[ 주의 ]` — 인입은 돈다 · 막히는 것은 `--regress --serial`과 파이썬 캐시뿐)
- `② 자체 검증`의 회귀가 PASS (`--quick`이면 `(--quick: 건너뛴다. 반입 직후에는 반드시 한 번 돌려라)`)
- `llm-check` — **실호출에서만**: 읽은 설정 파일 경로가 찍히고 ④(임베딩을 쓰면 ⑥ · 그림 든 문서나 PPT · PDF가 있으면 ⑦ — 캡처 크기 1,600×900 한 장)까지 통과. 설정이 없으면 이렇게 멈춘다(mock 연습 루트의 실제 화면):
  `[ 필요 ] ① 설정` · `설정 파일 없음 (환경변수만)` · `결과: **① 설정**에서 막혔다 — 위 문장이 원인이다`

**막히면** — 설정 파일 자리·키: [2B §1](2B_작업가이드.md#1-연결--게이트웨이) · 「그래프가 비어 있다 · 문서 0」(다른 상태 폴더를 본다) · 「이관 먼저」 · 「층 자산 먼저」 · 선택 의존 없음(`openpyxl`) · 새 가상환경에서 `llm-check` ⑥ 실패: [2B §7](2B_작업가이드.md#7-증상표--증상--원인--칠-명령).

## 1 골격 · 층

**할 일** — 공정 트리(골격 seed)와 층 config가 상태 폴더에 있어야 한다(`$ONTO_HOME/layers/<층>/` — 처음 쓰는 법은 [`골격작성_가이드.md`](골격작성_가이드.md) · [`config작성_가이드.md`](config작성_가이드.md) · 2B 부록 A). 계획을 보고 심은 뒤, 파생 흐름을 공정 문서와 대조해 **사람이 확정**한다.

**칠 명령**

```bash
python run.py bootstrap --dry-run                    # 실제와 같은 검사 · 쓰기 0
python run.py bootstrap
python run.py skeleton-status process                # 문법만 — 위반이 있으면 [FAIL] K## 줄과 seed 줄 번호
python run.py skeleton-confirm process --by <이름>   # 터미널에서 — 흐름을 보고 y
```

**확인할 것**

- `[bootstrap] --dry-run — 쓰기 0 · 바뀔 것 없음 · 멈출 것 0건` — 멈출 것이 0이 아니면 실제 실행도 멈춘다
- 파생 흐름 — 공정 문서와 순서 · 무주장 · 모호 이름을 대조한다:
  `[조립]       노칭 → 스태킹 → 탭용접 → 패키징` · `(짧은 이름 모호 — 사전 미등재, 접두 키로만 조회: ['비전검사'])`
- `[bootstrap] process: 노드 46 · 엣지 83` — 문서의 공정 수 = 노드 수인지 한 번 센다(빠진 공정은 흐름이 못 잡는다)
- `[bootstrap] 등록 스키마 재대조 — doc_type 4종` 아래 doc_type마다 `PASS — 층 process 어휘 안`
- 골격마다 겸 상태 한 줄 — `[bootstrap] 골격 'Process'(process): 겸 없음 — …`(설비층이면 `겸 Unit(…)` · ⚠ `별칭 0`이면 반쪽)
- 별칭 대장이 있으면 층마다 — `[bootstrap] process: 별칭 대장 — 골격 대상 실음 n · 이미 있음 m · 대상 없음 k`(대상 없음 = 그 이름이 골격에 없다 · 대장에는 남는다)
- `■ 골격 판정 — process: 문법 위반 0건 · layers/process/skeleton.json`
- 확정 — `이 흐름이 근거 문서와 맞습니까? [y/N]` → `확정 기록 → layers/process/confirmations.json (1번째 · <이름> · a096d1c48974…)`

**막히면** — `[FAIL] K01`~`K09`: seed의 그 줄을 고치고 `skeleton-status`부터 ([2B §2](2B_작업가이드.md#2-골격)) · 비대화형이면 확정하지 않는다(터미널에서 친다) · 흐름 순서가 문서와 다르다 → 문서를 넣기 전이면 seed를 고쳐 다시 `bootstrap`, 넣은 뒤면 [단계 6](#6-골격-고치고-재구축).

## 2 문서 종류 등록

**할 일** — 문서 종류마다 한 번: **생성 → 기계 관문 → 뷰 확인 → 확정**. 산문(PPT · PDF · Word · 목차형 엑셀)은 고정 어댑터라 LLM 0이고, 표(CP · PFMEA · IPQC …)는 LLM이 어댑터·스키마 초안을 낸다. 관문은 자동 검사다 — 사람은 뷰에서 「판단이 맞나」(role · 열 대응 · 제외)만 본다.

**칠 명령**

```bash
python -m cli.register generate <dt> <층> <표본>                 # 표 — 생성 → 관문 → 뷰
python -m cli.register generate <dt> <층> <표본> --use-basic      # 산문 — 고정 어댑터(LLM 0)
#   시트 여럿인 산문 엑셀은 시트 역할 표가 먼저 뜬다(터미널에서 답한다) · 배치·파이프면 --sheets "2-4:prose 5:ref *:skip"
python -m cli.register status <dt>                               # 관문을 지금 코드로 다시 돌리고 다음 줄을 준다(LLM 0)
python -m cli.register confirm <dt> --by <이름>
```

**확인할 것**(산문 엑셀 `rfq` — 실제 화면)

- `시트 역할 — prose 3 · ref 1 · skip 3 → registry/sheet_roles/RFQ01.json` — 같은 파일을 인입할 때 다시 묻지 않는다
- `기계 관문(하네스): PASS — 41 PASS / 0 FAIL`
- 시트마다 분할 줄 — `분할 — 사양_기계  기준 어댑터 신호: 번호 10 · 레벨 1 (평균 4.3행 · 목표 5~40) · 청크 10 · 행수 1~30 · 짧음 6 · 긺 0 · 구간 밖 — 최근접 레벨`(짧음이 많으면 헤딩 신호가 과하다)
- 좌표 쌍 표(관문 G4I와 같은 판정) — `좌표 쌍 — 어긋남 0쌍(0행) · 상위 이름 골격 밖 0종 · 상위·하위가 둘 다 골격에 맞은 0행`
- `HTML     → registry/review/rfq/view.html` — 연다: ① 파싱 결과 ② 무엇이 개체·값이 되나 ③ 어댑터 요약
- `■ 기계 관문 PASS — rfq` → 확정 `■ ③ 확정 — rfq 등록부 등재 (승인 <이름> @ …)` + `다음 — 인입 …` 두 줄
- 표 doc_type은 관문 줄에 **G4H**(공정 이름 열을 entity로 매핑하면 FAIL — 좌표로) · **G4I**(상위·하위 열이 뒤바뀌면 FAIL · `열을 바꾸면 n/m 맞는다`)가 선다 — **실호출 생성에서 본다**(mock 표본의 표 초안은 아래 FAIL 예시다)

**막히면** — 관문이 FAIL이면 같은 블록이 `generate` · `status` · `confirm` 어디서든 뜬다(mock 표본 `ipqc`의 실제 화면):

```
■ 기계 관문 FAIL — ipqc
```

**이미 넣은 문서를 표본으로 써도 운영은 그대로다** — 검수(`review <dt> --extract`)의 추출 리허설은 **임시 상태 폴더**에서 돈다(그래프 · 문서 대장 · 청크 · 체크포인트 · 렌즈판 · 시트 역할 · 문서 좌표는 읽기만 · 끝나면 그 폴더를 지운다). 화면(실제 줄):

```

```

- **새 종류로 넣는 줄** — 안내 줄의 `python run.py ingest-file <파일> --doc-type <새>`를 친다(시트 역할을 운영 기록과 다르게 골랐으면 그 줄 끝에 `--sheets "…"`가 붙는다).
- **리허설 산출을 쓰는 때** — 그 종류로 그 문서를 인입할 때 · 조건(문서 · 어댑터 · 지시문 · 층 config · 개요)이 같으면: `추출 — 리허설 산출(rfq2 등록 검수)을 운영 자리로 옮겼다` → `추출 — 체크포인트 재사용(LLM 0)`(개요 · 구조 지도도 같다). 조건이 다르면 `리허설 산출(…)을 쓰지 않는다: <이유>` 한 줄 뒤 지금처럼 다시 뽑는다. 아직 넣지 않은 문서도 같다(확정 뒤 첫 인입이 쓴다). 원래 종류로 다시 넣으면 그 자리를 보지 않는다.
- 부분 리허설(`--rows N`) · 실패 · 중단(Ctrl-C)은 리허설 산출을 남기지 않는다(임시 폴더는 지운다).

**이미 등록된 종류는 다시 만들지 않는다** — 코드를 바꾼 뒤에는 `python -m cli.register status <dt>`만 친다(지금 코드로 관문을 다시 돌린다 · LLM 0). 등록(`registry/`)은 재구축 · `init --fresh`(클린 포함)가 지우지 않으므로 `generate`를 다시 치면 이렇게 멈추는 것이 정상이다(실제 화면): `[생성] '<dt>'은 이미 등록돼 있다 (근거 …/registry/doc_types.json). 두 길 중 하나를 고른다:` — 양식이 바뀐 새 판이면 그 화면의 `--revise` 줄 · 스키마 칸만 고치면(재대조 ⚠ 부착 대상) `--schema-only`(운영 어댑터 그대로 — 화면의 다음 줄을 그대로 친다 → 관문 PASS → `confirm`).

## 3 문서 넣기

**할 일** — 처음 몇 부는 한 건씩 `--step`으로 단계마다 보고, 익숙해지면 폴더째. 산문 엑셀은 **문서 좌표**(이 문서가 어느 공정의 것인가)를 준다. **PPT는 덱 구조가 슬라이드마다 제목 · 다루는 공정을 판단한다** — `--coord`는 그 힌트라 없어도 들어가고 폴더째(`ingest-dir`)도 된다 · 추출은 슬라이드마다 한 번(본문 · 표 · 차트 · 노트 · 그림 요약 + 슬라이드 캡처).

**칠 명령**

```bash
python run.py ingest-file <문서> --dry-run                         # 어느 doc_type으로 가나만 — 파싱·인입 0
python run.py ingest-file <문서> --step                            # 단계마다 [계속 c / 멈춤 q] — 계속은 c(ㅊ)만 · q · ㅂ · Ctrl-C는 멈춤(그 문서 되돌림 · 그래프 쓰기 0) · 빈 Enter · 그 밖의 답은 다시 묻는다
python run.py ingest-file <문서> [--doc-type <dt>]                 # 표 — 헤더 지문이 doc_type을 고른다
python run.py ingest-file <산문 문서> --doc-type <dt> --coord <공정>  # 산문 — 문서 좌표(기록이 남아 다음엔 묻지 않는다)
python run.py ingest-file <산문 문서> --doc-type <dt> --coord <공정> --step --split-only   # 구조까지만 — 시트마다 구조 확인 · 추출 0 · 그래프 쓰기 0 · export/split_<doc_id>.md
python run.py ingest-file <PPT> --doc-type <dt> --split-only        # PPT 구조까지만 — 파싱 · 덱 구조 · 그림 요약 → parsed JSON + export/split_<doc_id>.md · 추출 0 · 그래프 쓰기 0
python run.py ingest-dir                                           # $ONTO_HOME/raw/ 전체 — 배치는 묻지 않는다
python run.py show report <doc_id>                                 # 넣은 뒤 — 무엇이 없어서 못 붙었나: 문서 머리 → 원인 묶음 → 목차 나무(-v 전부 · --rows 행 · --trace 값마다)
python run.py show report <doc_id> --md                            # 넣은 뒤 — 화면 표가 잘린 칸까지 전부: export/report_<doc_id>.md
```

**확인할 것**(표 CP01 · 산문 RFQ01 · 표 PFMEA01 — 실제 화면)

- `--dry-run` — `[선택만] CP01.xlsx                doc_id CP01               doc_type cp`(정상 — 다음 줄을 친다)
- 단계 머리 — `── [1/7] 선택 — 지문 스캔 유일 일치 → cp · header_labels 완전 일치 11/11 (누락 0 · 잉여 0)` 아래 `└ 0.0초 · 이 단계 호출 0 · 입력 0 · 출력 0 / 누계 호출 0 · 입력 0 · 출력 0`(단계마다 비용 · 이 실행의 누계)
- 좌표 — `좌표 태깅 — 조각 30 · 정확 일치 30 · 목록 밖 표기 0종(행 0) → LLM 0회 — 정확 일치만`
- 좌표 쌍(판정 전 · LLM 0 · 구축 큐와 같은 수) — `좌표 쌍 — 어긋남 2쌍(2행) · 상위 이름 골격 밖 0종 · 대조 30행` + `상위 '스태킹' ↛ 하위 '노칭' · 1행 · 예 관리계획서!R14` + 다음 줄(상위의 출처마다 한 줄 — `▶ 다음 줄(행의 상위)` = 열 매핑 재등록 · 골격 · 별칭 · 쌍 확인 · `▶ 다음 줄(문서 좌표 상위)` = 문서 좌표를 상위 공정으로 다시 `--coord` · 별칭 · 쌍 확인) → [단계 4](#4-넣은-뒤-정리)에서 처리
- `--step`이 **비용 전에** 멈추는 자리 — `── [3/7] 좌표 — 정확 일치 30 · … · 좌표 쌍 어긋남 2쌍(2행)`(열이 뒤바뀐 문서는 여기서 멈춘다) · 표 `[4/7] 판정 예고` · 산문 `[4/8] 추출 예고`. q면 `멈춤 — 좌표까지의 산출은 남았다(parsed/ · extract/ 체크포인트).` — 그 문서는 그래프 · 사전 · 큐 · 청크에 흔적이 없다(판정 도중 `--step-every`의 q도 같다 · 문서 대장과 체크포인트는 남는다). 다시 치면 체크포인트 재사용(LLM 0)으로 구축만 가고 청크는 그때 다시 선다.
- **묻는 자리의 답**(`--step`의 `[계속 c / 멈춤 q]` 전부 같은 규칙) — 계속은 `c`(한글 자판 `ㅊ`)만 · 멈춤은 `q` · `ㅂ` · `n` · Ctrl-C · 빈 Enter나 모르는 답은 `c(ㅊ)는 계속 · q(ㅂ)는 멈춤 — 다시 친다` 뒤 같은 줄을 다시 묻는다(계속으로 읽지 않는다). 저장 전(표 `[1/7]`~`[4/7]` · 산문 `[1/8]`~`[5/8]`)의 멈춤은 그 문서를 되돌린다 · 저장 뒤 머리(판정 · 부착·엣지 · 큐)의 멈춤은 `멈춤 — 이 문서는 이미 저장됐다(되돌리지 않는다) · 남은 머리는 묻지 않는다` · `[y/N]`은 `y`(`ㅛ`)만 예 · `[Y/n]`은 Enter · `y` 예 · `n`(`ㅜ`) 아니오

시트 확인은 줄 수와 예시 두 줄을 보고 한 번 답하며 그 답이 그 꼴 줄 전부에 걸린다). **`✂ 청크 n — 경로`** = 그 줄에서 청크가 시작한다(경로는 시트부터 그 청크를 연 제목까지 — 추출 맥락 줄이 이 경로를 쓴다 · 본문 줄에서 시작하면 바로 앞 목차 줄 뒤에) · 표지 끝 `청크 안 — 경로 영향 없음` = 청크 안쪽 줄의 판단 필요(답이 경로를 바꾸지 않는다 — 그래도 올린다) · 목차 아래 `청크 n` 한 줄은 수만이고 청크마다 첫 줄 · 끝 줄은 `export/split_<doc_id>.md`에 있다. `LLM —` 한 줄은 그 시트의 답 수 · 규칙 수 · 줄 고침(적용 · 버림 — 이유별 수)이고 버린 고침의 상세는 `export/split_<doc_id>.md` 끝 절 `고침 상세`에만 있다. 토큰 줄은 멈추는 단계마다 — `사다리 —`(문서당 한 번 · 재사용 · 확정이면 호출 0) · `시트 확인 —`(그 시트 · `초안과 다른 줄 x/제목 y` = LLM이 실제로 바꾼 줄 수) · 힌트로 다시 확인할 때마다 `다시 확인 끝 — LLM 사용량 — 이 단계 … / 누계 …` · 끝의 `구조 합계 — … / 누계 …`(누계 = 이 실행이 지금까지 쓴 전부 — 추출 · 판정 전이면 구조 몫이 거의 전부). 구조 호출은 문서당 사다리 1 + 시트당 확인 1이고 **줄 전문은 보내지 않는다**(제목은 앞 40자 + `…총 n자` + 짧은 서식 표시 · 본문은 접는다 · 판단 필요 줄은 앞뒤 두 줄 — 전문은 추출이 청크로 읽는다).
  답은 셋 — `c`(ㅊ) = **이 시트 확정** → 다음 시트(확정 기록 `$ONTO_HOME/registry/structure_confirmed.json` — 사람 판단 · 백업 1순위 · 재구축 · 재인입이 그대로 재생해 LLM 0 · 문서의 사다리도 남는다) · `q`(ㅂ) = 멈춤(구조까지 · 그래프 쓰기 0) · **그 밖의 글 = 힌트 — 문서 규칙**(그 시트를 앞 판단 전체 + 지금까지의 문서 힌트로 다시 확인하고 다시 전부 보인다 · 뒤 시트도 그 힌트로). 힌트는 둘 — **사다리 고침**(「가. 단은 대상」 · 「가.는 1) 위다」 · 「가. 아래 1.로 시작하는 목록은 가.의 묶음」 — LLM이 `규칙 — 서명 '가.' 대상 「…」 → 적용 n줄 / 그 서명 전체 m줄`로 되말하고 그 문서의 맞는 줄 전부(뒤 시트 포함)에 건다 · 같은 고침이 여러 줄이면 규칙 한 줄이다) · **행 고침**(「R36은 제목이 아니다」 — 줄 고침 명령은 없다 · 옛 고침 기록 `structure_fixes.json`은 그대로 재생된다). 역할은 셋 — `대상`(그 아래 글이 그것의 일부 · 특성인 줄) · `묶음`(한 주인 아래 항목을 묶는 소제목) · `주제` — 와 `본문`(제목 아님) · 구조 확인은 층을 모른다 — 대상이 이 층의 노드인가 · 무엇(카테고리)인가는 그래프 단계의 목차 노드화가 층 config `categories` 정의문과 `prompts.structure`로 정한다([config 작성 가이드](config작성_가이드.md) §1-c). md 끝 `고침 상세`의 `버림 — …`은 검사(줄이 시트에 있나 · 부모가 앞의 제목인가 · 이름이 줄 글자 그대로인가 · 붙임이 겹치지 않나 · 규칙의 서명이 문서에 있나)에 어긋나 버린 고침 하나다(나머지는 선다). 방식은 `knobs.json` `structure_mode`(`ladder` 기본 · `rules` = 코드 사다리 · 구조 LLM 0) — 옛 값 `edit` · `llm`이 남아 있으면 명령이 `손잡이 'structure_mode'의 값 "edit"는 폐기한 값이다 — "ladder"로 바꾼다`와 바꿀 줄을 말하며 멈춘다. **방식 비교는 확정 전에**: 방식마다 `--split-only`(`--step` 없이)로 돌리고 `export/split_<doc_id>.md`를 방식 이름을 붙여 복사해 둔 뒤 견준다 → 방식을 정하면 `--split-only --step`으로 시트마다 확정한다(확정은 방식 손잡이보다 이긴다). 목차 규칙이 바뀌기 전의 확정은 재생하지 않고 다시 보인다(파싱 끝 `옛 확정 n시트 — 다시 확인 필요`) · 카테고리가 든 옛 확정 기록은 그대로 재생한다(나무 · 이름 그대로 · 카테고리 칸은 읽지 않는다). **재구축 전후 비교** — 재구축 전에 `work/parsed`를 복사해 두고 뒤에 `python run.py show structure --diff <사본 폴더>`(문서마다 시트 수 · 청크 경계가 바뀐 시트 · 시트 역할이 바뀐 시트 + 합 한 줄). **확정한 시트를 고치려면** `--step`에서 그 시트에 힌트를 친다 — 그 고리에서는 확정을 비켜 두고(`확정 기록을 비켜 둔다 — …`) 기록된 힌트 + 새 힌트로 다시 확인한다 · `c`면 새 나무가 기록을 덮고 `q`면 옛 기록 그대로다. 값 표(`-v`)의 `구조` · `소속(출처)` · `붙은 자리` 칸이 「구조 → 소속 → 붙음」 어디서 틀렸는지를 한 줄에서 보인다.
- **PPT 덱 구조 표**(덱마다 LLM 1회 · 같은 파일이면 LLM 0) — 파싱 끝에 늘 `덱 구조 — 슬라이드 n · 제목 초안과 다름 a · 이어짐 b · 공정 하나 c · 둘 이상 d · 없음 e · 버림 g · LLM 호출 k · 재사용 r` 한 줄(덱 판단은 층 · 골격 · 문서 좌표를 모른다 — 층 config · 골격을 바꿔도 다시 묻지 않는다). `--step`이면 표(번호 · 슬라이드 · 제목 · 초안 = placeholder 제목 · 이어짐 · 다루는 것 · 공정)를 보이고 고친다: `3 공정 노칭,스태킹`(덱에 적힌 표기 그대로 · `없음`) · `3 다루는 것 <말>` · `3 제목 <그 슬라이드 글>` · `4 이어짐 3`(`없음`) · `개요 <한 단락>` — 고침은 `structure_fixes.json`의 `@덱`에 남고 다시 파싱(LLM 0) · 재구축이 그대로 쓴다. 공정 칸은 문서 표기 그대로 · `표기 → 골격`은 좌표 태깅이 골격에 맞힌 것 · `표기(?)`는 안 맞은 것(그래프 단계 `orphan_anchor` 큐) · `—`나 `없음`이면 경로 · 문서 좌표(워드와 같은 길). 여러 공정을 다루는 덱은 문서 좌표를 그 공정들의 상위 공정으로 준다(밖의 공정은 `coord_mismatch`로 보인다). 추출 예고 위의 `캡처 — 있음 n · 없음 m(사유)`는 슬라이드 캡처가 추출에 붙었나다(캡처 길이 없으면 실호출은 사전 점검에서 이미 멈췄다 — 여기의 `없음`은 그 문서의 렌더 실패 · 쪽 수 불일치 · `--no-capture`)
- **PPT 중간 결과 보기**(`--split-only`) — 정본은 `work/parsed/<doc_id>.json`(청크 + 덱 블록 `deck` — 슬라이드마다 제목 초안과 판단 · 이어짐 · 다루는 것 · 공정(문서 표기와 골격 대조) · 개체 없음 · 버림 · 사람 고침 · 근거 조각 · 덱 개요)이고 추출은 그 파일 + 슬라이드 캡처만 본다. `export/split_<doc_id>.md`는 그 JSON에서 찍은 보기다 — 머리(문서 · 덱 개요 · 캡처 쪽) · **슬라이드 표**(번호 · 제목 `초안 → 판단` · 이어짐 · 다루는 것 · 공정 — `표기 → 골격` · `표기(?)` 안 맞음 · `—` = 판정 없음 · `없음` = 공정 없음 · 개체 없음 · 근거 조각 수 · 글자 · `*` = 사람 고침) · 슬라이드마다 `[본문]` · `[표 S#-TB1]` · `[차트 …]` · `[그림 요약 S#-P#]` · `[노트]`와 버림 · 사람 고침. 틀린 판단은 `--step`의 덱 구조 표에서 고친다(다시 파싱 · LLM 0 → JSON · md가 같이 바뀐다)

- **산문의 값**(층 config `value_categories`를 선언한 층 — [config작성 가이드 §1-b](config작성_가이드.md#1-b-유닛-아래의-사양과-그-값--문서-구조--이름은-주인-아래--값은-그-노드의-속성-사내가-바꿀-줄--b119--b120)): 사양 개체가 그 청크에서 그 항목에 걸린 값(원문 글자 그대로)을 함께 내고 그 노드의 속성으로 앉는다(표의 attribute와 같은 함수). 창작 표본(TW 꼴 — 언와인더 · 리와인더 아래 같은 이름 사양 · 값 넷 중 하나는 원문에 없는 값)의 줄: 요약 끝 `| 값 4 = 실림 3 · 버림 1 · 충돌 0` · 맞춤 `값(산문) 4 = 실림 3 + 버림 1 + 충돌 0` · 노드는 `python run.py show node "노칭::언와인더 unit::장력"`의 `── 값 ──` 아래 속성 이름(`설비사양`) · 값(`30N`) · 출처 청크. 버림 = 청크 원문에 그 글자가 없다(지어낸 값 · 계산한 값 — `defects.log`의 `값 버림 — 청크 원문에 없다 '…'`) · 충돌 = 다른 문서가 같은 노드 같은 맥락에 다른 값을 냈다 — 덮어쓰지 않고 큐 `spec_conflict`(있던 값 · 들어온 값 · 출처 — `python run.py platform queue spec_conflict`). 날짜 · 쪽수 · 수량은 값이 아니다 · 선언이 없는 층은 값 0 · 표(CP · PFMEA)의 값은 그대로다
- **빈칸 표시**(`-` · `N/A` · `해당 없음` …)는 개체가 아니다(표 — 창작 표본의 실제 화면): `조각 좌표 30 = 자기 29 + 문서 좌표 1 + … + 없음 0  (빈칸 표시로 비움 1 — 합 밖)` — 좌표 칸이 빈칸 표시면 비워 문서 좌표를 물려받는다 · `값(개체 행) 60 = … + 빈칸 표시 1 + …` — 개체 칸이 빈칸 표시면 노드 0(빈 셀과 같다 · 그 행의 값은 좌표 폴백하지 않는다) · 값 칸(규격 「없음」 등)은 원문 그대로 두고 대장에 표지만 단다. **목록은 `$ONTO_HOME/layers/common.json`의 `null_markers`**(없으면 기본 `-` · `—` · `–` · `N/A` · `n/a` · `해당 없음` · `해당없음` · `없음` · 공백 무시) — 고치면 그 뒤에 넣는 문서부터 따른다(이미 넣은 문서는 다시 넣는다 · `bootstrap`은 이 키를 그대로 둔다)
- **원인 묶음**(인입 끝 위 8줄 · `show report <doc_id>`는 전부) — 수는 **못 붙은 행**이다: 판정 대장에서 좌표 행을 뺀 행 중 보류 · 고아 · 불확실 · 종류는 맞춤표 「보류(행)」의 행 종류(개체 · 속성·내용 · 소속 · 그 밖). 머리 한 줄이 얼마나 못 붙었나(종류마다 못 붙음/전체 — 전체가 0이 아닌 종류는 못 붙음 0이어도 서서 분모 합 = 전체 · 상태는 0이면 뺀다) · 원인 줄이 **못 찾은 것**으로 묶는다 · 원인은 위에서부터(문서 좌표 없음 → 구간 좌표 없음 → 소속 이름 없음 → 관계 끝점 없음 → 그 밖) · 한 행은 가장 위 원인에서 한 번만 센다(원인 줄의 종류별 합 = 머리의 못 붙은 행) · 못 붙은 행이 0인 원인은 원인 줄이 없다 · 행이 아닌 잃은 것은 그 아래 **행 밖**(행의 합 밖 · 처방 한 줄씩 · 못 붙은 행이 0이어도 묶음이 선다 — `원인 묶음 — 못 붙은 행 0 / 전체 N`): `관계 — 끝점 없음 '<이름>' · 못 선 관계 n`(관계 후보의 끝점이 서지 않았다 — 사람 후보 [5/8]) · `공정 표기 — 골격에 없음 '<표기>' · 조각 n`(값은 다른 공정으로 붙었지만 그 표기는 골격 · 별칭에 없다 — `ALIASES` → `bootstrap` → `ops relink`) · 줄마다 아래 `▶` 처방 한 줄(그 종류에 맞는 길 — 고르지 않는다). 창작 표본의 실제 줄(경로는 줄였다):
  ```
    원인 묶음 — 못 붙은 행 5 / 전체 150 — 개체 2/60 · 속성·내용 3/90 · 보류 5
      구간 좌표 없음 — 좌표 표기 '없는공정B149' · 못 붙은 행 5(개체 2 · 속성·내용 3) · 관리계획서!R32
        ▶ 골격 ALIASES["<골격 canonical>"]에 "없는공정B149" → python run.py bootstrap → python run.py ingest-file …/B149_CP.xlsx --doc-type cp
  ```
  산문에서 한 시트만 골격 이름을 가졌으면 다른 시트의 **가장 위 제목**이 한 줄(`구간 좌표 없음 — 기타 사양 · 못 붙은 행 2(개체 2)`) · 문서 전체에 좌표가 하나도 없으면 첫 줄이 `문서 좌표 없음 — 문서 좌표 · 못 붙은 행 n(…) · 가까운 골격 이름(보여만 준다): …` + `▶ … --coord <골격 이름>` · 기다리는 소속 이름은 `소속 이름 없음 — <이름> · 못 붙은 행 n(…)`(고아 큐가 그 이름을 기다리는 행 · `▶ … --step`의 사람 후보 [5/8]) · 개체는 붙고 속성만 못 붙은 원인도 그 종류의 수로 보인다(`그 밖 — 부착 대상이 개체 열이 아니다(스키마 — 다시 등록) · 못 붙은 행 4(속성·내용 4)`).
- **목차 나무**(`show report`) — 제목마다 `좌표 X(출처: 자기 · 문서 좌표 · 무시 · 공유 별칭 건너뜀) · 노드: <카테고리> 노드 / 좌표(골격) / 이 층의 노드 아님 / 보류(사유) · 붙음 a · 못 붙음 b`(고아가 있으면 `못 붙음 b(고아 o)` — 원인 묶음과 같은 행 · 같은 단위) · 문제 있는 가지만 펼치고 다 붙은 가지는 `… 다 붙은 가지 k · 붙음 m`(`-v`면 전부) · 제목 밖 행은 `(목차 밖)` 한 줄 — 펼친 줄 + 접은 줄 + 목차 밖의 못 붙음 합 = 머리의 못 붙은 행 · 표는 그 자리에 **좌표 표기 목록**(`없는공정B149 → 좌표 목록 밖 · 레코드 1 · 붙음 0 · 못 붙음 5`). 한 목차가 좌표를 못 찾으면 그 아래가 함께 못 찾는다 — 가장 위의 그 줄부터 본다 · 행 전부는 `--rows` · 값마다 추적은 `--trace`
- 목록 밖 좌표가 있으면 LLM 전에 진단 표 — `레이저노칭 | 1` + `▶ 다음 줄 — 같은 공정이면 layers/process/skeleton.json의 \`ALIASES\`에 표기를 더하고 python run.py bootstrap (fresh 없이) → 같은 인입` · 결과표 `보류 4(좌표 목록 밖 1 · 좌표 미해소로 스코프 노드 미생성 3)`

## 4 넣은 뒤 정리

**재연결이 지금 하는 일** — 인입 끝 `── [마무리] — 미러 · 재시도 · 연결 보강`이 큐의 미부착 · 미앵커 항목(`orphan_anchor` · `orphan_attach` · `orphan_chunk_link`)과 **좌표 미해소 보류**(좌표 칸이 비어 세우지 못한 행 — `missing_field`)를 **더 붙는 것이 없을 때까지 바퀴로 훑는다**(한 바퀴에 붙은 것이 있으면 한 바퀴 더 — 뒤 청크가 만든 유닛에 앞 청크의 부품이 다음 바퀴에 붙는다 · 상한 5바퀴는 사내 `knobs.json`의 `relink_rounds`). 그래프 수 · 골격 판 · 사전 판 · 좌표 학습(보류 행은 그 문서의 문서 좌표 기록까지)이 그 항목을 지난번에 시도했을 때와 같으면 건너뛴다(같은 입력이면 같은 답 — LLM 0) · 한 항목은 5번까지(넘으면 사람 판정 대기) · 남은 것은 **다음 인입의 마무리가 다시 훑는다**. 보류 행은 추출 체크포인트 · 큐에 든 재료로 다시 선다 — 추출 LLM 0.

**좌표 · 별칭을 고친 뒤** — 재인입 없이 `python run.py ops relink all --actor <이름>`(계획 — 쓰기 0) → `--apply`(인입 끝 마무리와 같은 함수 · 사전 점검을 지난다). 문서 좌표가 없어 멈춘 문서는 `--doc <doc_id> --coord <골격 이름>`을 붙이면 그 기록을 남기고 그 문서의 보류 행을 다시 세운다. **재인입이 필요한 것은** 원본 파일을 고쳤을 때 · 빈칸 표시 목록(`null_markers`)을 고쳤을 때 · 추출 지시문 판이 바뀌었을 때(다시 넣으면 그 문서만 다시 뽑는다)뿐이다.

**할 일** — 순서대로: ① 큐 요약 ② **좌표 어긋남 쌍** ③ 좌표 학습 기록 ④ 불확실 검토 ⑤ 문서 단위 확인 ⑥ 별칭 대장 보기 · 거두기. 쌍 처리는 셋으로 가른다(쌍 묶음 아래 다음 줄이 상위의 출처 — 행의 상위 · 문서 좌표 상위 — 마다 한 줄) — **열이 뒤바뀌었다**(쌍이 문서 전체 · 행의 상위) → 매핑을 고쳐 재등록 · **문서 좌표가 좁다**(문서 좌표 상위 — 여러 공정을 다루는 문서) → `--coord <상위 공정>`으로 다시 · **골격 트리가 틀렸다** → 목록에 적어 두고 [단계 6](#6-골격-고치고-재구축)에서 한 번에 · **그 밖**(다른 이름 · 몇 행 오기) → 별칭(`ALIASES` → `bootstrap`) 또는 쌍 확인.

**칠 명령**

```bash
python run.py platform queue                                    # 큐 20종 요약
python run.py platform queue coord_mismatch                     # 쌍 묶음 · 쌍마다 「이대로 둔다」 줄
python run.py platform queue spec_conflict                      # 값 충돌 — 같은 노드 같은 맥락의 다른 값(덮어쓰지 않는다 · 있던 값 · 들어온 값 · 출처)
python run.py ops coord-ack all "<상위>" "<하위>" --actor <이름> --reason "<메모>"   # 그 쌍을 확인함으로(극성 쌍은 --polarity)
python run.py show learned                                      # 좌표 학습 기록 · 새 공정 후보
python run.py ops review all --actor <이름>                     # 불확실 일괄 검토 — 터미널에서 합침 m · 별개 c · 건너뜀 s
python run.py ops confirm all --doc <doc_id> --actor <이름>     # 그 문서가 만든 auto 노드 확정 — 계획 → --yes
python run.py show aliases [층] [--source <출처>] [--node <이름>]   # 별칭 대장 — seed 것과 대장 것
python run.py ops alias <층> <대상> "<표기>" --actor <이름>      # 표기를 잇는다
python run.py ops alias-reject <층> <대상> "<표기>" --actor <이름>  # 틀린 별칭을 거둔다 — 계획 → --yes
python run.py ops relink all --actor <이름>                      # 재연결 계획 — 대상 · 이번에 볼 것 · 건너뜀(쓰기 0) → --apply
python run.py ops relink all --doc <doc_id> --coord "<골격 이름>" --actor <이름> --apply   # 문서 좌표를 기록하고 그 보류 행을 다시 세운다
```

**확인할 것**(실제 화면)

- 인입 끝의 재연결 줄(산문 RFQ01 — 실제 화면) — `재연결 — 바퀴 1 · 대상 2(orphan_anchor 2) · 붙음 0 · 남음 2(orphan_anchor 2) · 그래프·골격·사전 그대로라 건너뜀 2 · 상한 도달 0 · 시도 1회 2`: 바퀴 = 돈 횟수(붙음 0인 바퀴에서 멈춘다) · 대상 = 재연결 대상의 큐 항목(kind별) · 붙음 = 이번에 붙인 것 · 남음 = 큐에 남은 것(kind별 · 끝은 시도 횟수별) · 건너뜀 = 지난 시도와 판이 같아 돌지 않은 것 · 상한 도달 = 5번을 채운 것 · 바퀴 상한에 닿으면 끝에 `바퀴 상한에서 멈춤(더 붙을 수 있다 — …)`
- 손 명령(문서 좌표 없이 넣은 창작 표본 `B113_전극리와인딩_사양` — 실제 화면):

## 6 골격 고치고 재구축

**할 일** — 고칠 것을 **모아서 한 번에**(단계 4의 골격 트리 오류 쌍 · 새 공정 후보 · 별칭) seed를 고친다. **별칭·노드만 더했으면** `bootstrap`(fresh 없이)으로 끝난다 — 보류분은 다음 인입 마무리에서 붙고, 지금 붙이려면 `python run.py ops relink all --actor <이름> --apply`([단계 4](#4-넣은-뒤-정리) — 재인입 없이 · 문서 좌표가 없던 문서는 `--doc <doc_id> --coord <골격 이름>`). **이름 · 부모가 바뀌면**(그 아래 노드 이름이 바뀐다) 재구축 한 명령이다: 계획을 보고 → 실행 → 끝 보고를 처리한다. 재구축은 지우기 전에 문서 목록 · 사람 판단 기록의 이름 · 별칭 대장을 챙기고, 판정은 대장에서 재생한다(LLM 0) — 이름이 바뀐 노드 아래 키만 다시 판정한다.

- **재구축이 끝나면 문서까지 다시 들어가 있다**(골격만 남는 것이 아니다) — 등록 · 문서를 다시 넣지 않는다. `registry/`(등록 · 문답 기록 · 사람 판단 기록) · `layers/` · `raw/` · 보존 일곱은 남고, 그래프 · 사전 · 큐 · 청크 · 문서 대장은 계획 순서대로 다시 선다.
- **두 길** — 한 번에: `rebuild --yes`. **한 건씩 보며**: 계획(`rebuild` — 순서 목록) → `init --fresh`(`--all`이 아니다 — 보존 일곱을 남긴다) → `bootstrap` → 계획 순서대로 `ingest-file <문서> --step`(판정은 같은 대장에서 재생된다 · 순서를 바꾸면 「대상 없음」 재판정이 는다).
- **재구축 뒤 산문에 `문서 좌표 — 없음 (출처: 없음)`이 뜨면** 그 문서만 `ingest-file <문서> --doc-type <dt> --coord <공정>` — 기록이 남아 다음 재구축부터는 `문서 좌표 — 노칭 (출처: 기록)`처럼 저절로 선다.
- **재구축은 지우기 전에 사전 점검을 돈다**(인입과 같은 판정 — 채팅 · 임베딩 · 그림 · 공통 config · 등록 스키마) — 멈추면 그래프 그대로다. **도중에 끊기면**(문서 실패 · 중단 · 창이 닫힘) 계획 파일이 「진행 중」으로 남아 **같은 명령이 그 계획의 문서 전부로 이어 간다** — 문서 대장에 몇 건이 들어갔든.

**칠 명령**

```bash
cp -r $ONTO_HOME ${ONTO_HOME}_bak_$(date +%Y%m%d)    # 먼저
#   $ONTO_HOME/layers/<층>/skeleton.json 을 고친다 — 옛 이름은 ALIASES에 남기면 문서의 옛 표기가 새 노드로 간다
python run.py skeleton-status <층>                    # 문법 → 확정이 필요하면 skeleton-confirm
python run.py rebuild                                 # 계획 — 지울 것 · 남길 것 · 다시 넣을 순서(비대화형은 계획만)
python run.py rebuild --yes                           # 실행 — 보존 fresh → bootstrap → 처음 인입 순서로 재인입 → 사람 판단 재생 → 끝 보고
python run.py vectors                                 # 질의 벡터 — 글이 같으면 다시 쓰고 바뀐 것만 만든다(LLM 0 · 다른 터미널에서 돌려도 된다)
python run.py show dist embed                         # 임베딩 입력 한도 · 종류별 길이 · 넘은 글 수(끝 줄 「넘어 자른 글」과 같은 수 — 넘는 글은 앞을 지키고 꼬리를 잘라 넣는다)
```

**확인할 것**(seed `ALIASES`에 「레이저노칭」을 더하고 재구축 — 실제 화면)

- 계획 —
  ```
  ■ 재구축 계획 — 문서 3(다시 넣을 것 3 · 원본 없음 0)
    남길 것 — 산문 추출 work/extract · 구조 지도 work/struct_maps · 판정 대장 work/ingest_log · 좌표 학습 data/coord_learned.json · 별칭 대장 data/alias_book.json · 명령 로그 work/logs · ②등록 registry/(…) · layers/ · ⓪원본 raw/ · golden/
    사람 판단 기록 42건 · 이름 채움 0 · 이름 없음 0(재구축하면 돌아오지 않는다)
    별칭 대장 1(이번에 채움 0) · 골격 대상 0 · 거부 1 — 재구축의 bootstrap이 골격 대상 별칭을 스냅샷 전에 싣는다
    다시 넣을 순서(처음 인입 순서):
        1. CP01                 cp         raw/CP01.xlsx
  ```
  — `이름 없음`이 0이 아니면 그 연산은 재구축 뒤 손으로 다시 한다(목록이 뜬다)
- fresh — `[재구축 fresh] 남긴 것 — 산문 추출 1파일 2KB · 판정 대장 3파일 256KB · 별칭 대장 1파일 1KB · 명령 로그 13파일 225KB` — 그 전 명령 로그가 재구축 뒤에도 남는다
- 지우기 전 사전 점검 — `   사전 점검 — 설정 · 채팅(mock) · 임베딩(건너뜀) · 그림(건너뜀) · 공통 config · 쓰기 — 통과 (0.0초 · 이 단계 호출 0 · 입력 0 · 출력 0 / 누계 호출 0 · 입력 0 · 출력 0)` 다음에 `[재구축 fresh]`가 온다(사내는 `채팅`이 실호출 왕복). 연결이 안 되면 지우기 전에 멈춘다(운영 루트 모양 연습 폴더 · 설정 없음의 실제 화면):
  ```
     사전 점검 — **설정**에서 멈춘다 (파싱 0 · LLM 추가 0 · 쓰기 0)
       필요한 키 없음 — LLM_GATEWAY_URL, CHAT_MODEL · 설정 파일 …/opsdemo/llm.json
     ▶ 다음 줄 — 읽힌 설정 파일에 대문자 키로 적는다 — python run.py llm-check ①
  ■ 재구축 멈춤 — 지우기 전에 멈췄다 — 그래프 그대로 (계획 파일 · 상태 폴더 쓰기 0)
    ▶ 다음 줄 — 위 원인을 고친 뒤(연결이면 python run.py llm-check) 같은 명령: python run.py rebuild --yes
  ```
- 끊긴 재구축 뒤의 계획 — 문서 수가 줄지 않고 그 아래 줄이 뜬다: `  지난 재구축이 끝나지 않았다 — 계획 파일에서 이어 간다 · 문서 대장 2건은 그 도중의 것 (work/rebuild/plan.json)`
- 고친 별칭이 듣는다 — PFMEA01의 `좌표 태깅 — 조각 32 · 정확 일치 32 · 목록 밖 표기 0종(행 0)`(고치기 전 31 · 목록 밖 1)
- 끝 보고 —
  ```
  ■ 재구축 끝 — 문서 3(성공 3 · 실패·보류 0 · 원본 없음 0)
    판정 — 재생 93 · 재판정 1(키 없음 1 · 대상 없음 0 · 끔 0)
    LLM 호출 — 추출 0 · 판정 0 · 태깅 0 · 그 밖 0
    사람 판단 재생 — 한 일 40 · 이미 그 상태 2 · 대상 없음 0 · 기록에 이름 없음 0 · 재생 안 함 0 · 거부 0
    별칭 대장 1 · 그래프에 있음 1 · 없음 0
    계획 파일 — 끝 (다음 재구축은 문서 대장에서)
  ```
  — 문서가 하나라도 실패 · 보류 · 원본 없음이면 `계획 파일 — 진행 중 (계획의 문서가 전부 성공하지 않았다 — 고친 뒤 같은 명령이 이 계획에서 이어 간다)`
  재판정 — 「키 없음」은 지난 판정이 없던 값(여기서는 별칭으로 새로 좌표가 선 행) · 「대상 없음」은 이름이 바뀐 노드 아래 키 / 「사람 판단 재생 — 대상 없음 k」 줄마다 연산 · 옛 이름 · 행위자 → 새 이름에 다시 손으로(기록은 남는다) / 「별칭 대장 — 없음 k」 줄마다 표기 → 대상(그 이름이 골격에 없거나 그 문서가 돌아오지 않았다 · 대장에는 남는다)

**막히면** — 재구축이 LLM을 다시 부른다(「판정 n」 · 「태깅 n」 > 0) · 재구축 뒤 사람이 한 것이 없다 · 골격의 부모·이름을 고쳤다(재구축 순서) · 재구축 뒤 `generate`가 「이미 등록돼 있다」 · 계획에 「다시 넣을 문서가 없다」 → [2B §7](2B_작업가이드.md#7-증상표--증상--원인--칠-명령) · 사전 점검에서 멈췄으면 그래프는 그대로다 — 다음 줄대로 고치고 같은 명령 · 도중에 끊겼으면 같은 명령이 계획 파일(`work/rebuild/plan.json` — 「진행 중」)의 문서 전부로 이어 간다.

## 7 허브로 보낼 것

**할 일** — 명세가 답하지 않거나 화면이 이상하면 추측으로 메우지 않고 재료를 모아 허브로 가져온다. **명세 · 레포 정본 자산(`prompts/` · `kit/` · `schemas/blocks.json` · 레포 `layers/`)은 사내에서 고치지 않는다**(`doctor`가 ⚠).

**칠 명령**

```bash
ls $ONTO_HOME/work/logs/                   # <명령>_<날짜>.log — 화면 전부(색 뺌 · 친 답 포함)
python run.py show report <doc_id> --json  # 그 문서의 행별 판정 대장
python run.py show report <doc_id> --md    # 잘리지 않는 보고서 export/report_<doc_id>.md — 요약 · 맞춤 · 카테고리 쌍별 연결 · 추출 청크 · 판정 값(칸 전부)
python doctor.py                           # 머리 상태 줄 · 점검 줄 (운영 셸에서 쳐도 상태 폴더는 읽기만)
```

**확인할 것** — `rebuild_20261014.log`처럼 명령마다 하루 파일이 하나다. **재구축 뒤에도 그 전 명령 로그가 남는다**(기본 fresh도 — 지우는 것은 클린 `init --fresh --all`뿐이다) — 재구축 전 인입 로그도 이 폴더에서 바로 가져온다. 화면을 `| head`로 잘라도 된다 — 화면이 닫히면 명령이 멈추고(종료 코드 141 · 트레이스백 없음) 로그 끝에 「화면이 닫혀 멈췄다 — <명령>」이 남는다.

| 상황 | 가져올 것 |
|---|---|
| 명세가 답하지 않는다 | BLOCKER — ①근거 원문(정제본 어느 절이 무엇까지 말하나) ②선택지 2~3 ③귀결 |
| 명세와 실물이 어긋난다 | 어긋난 두 문면 + 그 실행의 로그 줄 |
| 판정이 필요하다(값 충돌 · 구조 개정) | 큐 항목(`platform queue <kind>`) + 판단 재료 |
| 수(청크 크기 · 적중률 · 호출 수)를 바꾸고 싶다 | `show knobs` · `show dist <무엇>`의 사내 실측 — 바꾸는 자리는 `$ONTO_HOME/knobs.json` |

코드를 사내에서 고쳤으면 `DECISIONS.md`에 남긴다.

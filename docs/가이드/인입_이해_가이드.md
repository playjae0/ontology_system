# 인입 이해 가이드 — 행 하나가 노드·엣지·큐·사전이 되기까지, 화면 한 줄이 무슨 단계인가

> **누가 읽나**: `ingest-file`을 돌리며 화면을 읽는 사람. 「명령을 치는 순서」는 `2B_작업가이드 §5`, 「열의 role을 정하는 법」은 `역할_판정_가이드`, 이 문서는 **그 사이 — 시스템이 안에서 무엇을 하는지**를 사람 순서로 쓴 것이다. 정본은 문서 4(쓰기절차)·문서 2(계약)이고, 실물은 `core/build/loop.py`(행 루프) · `core/build/build.py`(해소·부착) · `core/matcher.py`(후보·판정) · `core/build/retry.py`(재시도)다(파트 폴더 기준 — 옛 `pipeline.py`는 entry·loop·table·prose 넷으로). 아래 문면은 2026-09-16 기준이다.

## 1. 큰 그림 — 문서 하나에 일어나는 일 (순서가 계약이다)

```
ingest-file <문서>
 ├ 선택      doc_type(등록부 · --doc-type 또는 헤더 지문) · 형태 판정(table/prose)          LLM 0
 ├ 파싱      어댑터 extract → 조각(record/청크) · 좌표 태깅(정확 일치 · 미스 표기당 LLM 1) → parsed/<doc_id>.json
 ├ 추출      (산문만) 청크마다 LLM이 개체·관계 후보 → extract/<doc_id>.json        LLM = 청크 수(ref·재사용 제외)
 ├ 구축      조각(행)마다 ⓪→④ (아래 §2)                                                     LLM = 개체 판정
 ├ 커밋      엣지는 (출발 카테고리, 관계, 도착 카테고리) 삼항이 층 config 패턴 안일 때만 저장  LLM 0
 └ finalize  mirrors 자동(극성 쌍) · retry_orphans(큐의 미해결을 다시 시도) · 문서 대장 기록
```

**추출 체크포인트**(산문) — `work/extract/<doc_id>.json`이 생기면 추출 완료다(파일 존재 = 완료). 추출 중에는 청크가 끝날 때마다 **부분 파일** `work/extract/<doc_id>.partial.jsonl`(렌즈면 `<doc_id>@<렌즈>.partial.jsonl`)에 한 줄씩 덧붙이고, 다 끝나면 체크포인트로 올린 뒤 부분 파일을 지운다. 그래서 **도중에 끊겨도 쓴 호출이 사라지지 않는다** — 같은 명령을 다시 치면 `추출 이어서 — 끝난 청크 k · 남은 m`이 뜨고 끝난 청크는 부르지 않는다. 문서 해시·어댑터 판·렌즈가 다르면 부분 파일을 버리고 처음부터(로그 한 줄). 실패 청크는 이어서도 실패로 남는다.

**정본 넷** — `data/<층>/graph.json`(노드·엣지) · `data/dictionary.json`(동의어 사전) · `data/chunks.json`(청크·describes·about) · `data/review_queue.json`(사람 판정 대기). 인입은 이 넷을 쓴다 — 전부 상태 루트 `$ONTO_HOME/data/`(③진실). 나머지 json은 장부·로그이고 `work/`(④)에 산다(§5.4 표) — `parsed/`·`extract/`·`ingest_log/`도 거기다.

## 2. 행 하나의 길 — ⓪ 좌표 → ① role → ② 부착 → ③ 엣지 → ④ 폴백

| Step | What happens | LLM | Ends up in |
|---|---|---|---|
| ⓪ 좌표 | `process_ref`를 골격 닫힌 목록과 **정확 일치·alias**로 해소(anchor — 유사도·LLM 없음). 없으면 `process_group`으로 **저해상도 부착**(개념 노드에 붙는다 · 큐 없음). 둘 다 없으면 `missing_field`. 극성(`electrode_type`)이 있고 그 공정에 극성 인스턴스가 있으면 그리로 **하강**(`탭용접` + cathode → `탭용접::cathode`) | 0 | 해소 실패 → `orphan_anchor` 큐(행은 보류) |
| ① role | 스키마 `fields`의 열마다 role 핸들러. **entity**: 문서 내 buffer → 사전(`exact`, LLM 0 — 키는 부모 아래에서 조립한 스코프 canonical이고 등재도 같은 키) → 후보(**전량이 아니다** — 스코프 카테고리는 같은 부모 아래만 · **같은 부모 아래가 0개면 후보 0 → 그 자리에서 신규, LLM 0** · 그 안에서 유사도 상위 12 — 임베딩 또는 겹침, 임베딩 모델이 없어도 돈다) → 판정(후보의 `status`를 본다 — auto 후보에는 표기가 같을 때만 붙는다) → 매칭/신규/불확실. **attribute·content**는 대상이 정해질 때까지 모아 둔다. **meta**는 값만 장부에. 스키마에 없는 키 → `unknown_field`(그래프에 안 들어간다 — 검색 관점에선 드랍과 같다) | entity 판정만 | 매칭 → 기존 노드에 provenance 추가 + **사전 등재** · 신규 → 노드(status auto) + `auto_node` 큐 + 사전 등재 · 불확실 → 노드(auto) + `uncertain_match` 큐 |
| ② 부착 | attribute를 `attach_to_field`의 노드 필드에 `{value, provenance}`로. content는 청크 저장 + `describes`. 대상 열이 **빈 셀**이면 아무것도 안 한다 · **값은 있는데 미해소**면 보류(`pending_attrs` · `orphan_attach`) | 0 | 노드 `attrs` · chunks.json |
| ③ 엣지 | 스키마 `edges` 선언대로 — 두 끝이 다 해소됐을 때만. 커밋 게이트가 삼항을 층 `relation_patterns`와 대조, 밖이면 거부(`show log gate`) | 0 | graph.json edges · gate_rejects.json |
| ④ 폴백 | 규칙 B — attach 대상이 없거나 미해소인 entity는 **행의 공정 좌표**에 부착(저해상도 · 오류 아님) | 0 | 엣지 |

**「자동 생성: Packaging :: Tab Sealing :: Tab Sealing 강도」** — ①의 신규 갈래. `::`는 canonical 스코프 접두(`canonical_scope.bind_categories` — 관리항목·설비는 공정 아래 이름이 유일하다)이고 「Tab Sealing 강도」가 공정 「Packaging :: Tab Sealing」 아래 만들어졌다는 뜻이다. 연결은 됐고, **사람이 확인한 노드는 아니다**(status auto). `platform queue auto_node`가 항목마다 `ops confirm`(맞다) · `ops merge`(이미 있는 것) · `ops obsolete`(아니다) 세 줄을 준다 — 확정 전까지 그 노드는 다음 판정에서 「표기가 같을 때만」 후보로 붙는다.

**산문(청크)의 좌표는 셋이다** — ① **주 좌표**: 청크의 제목 경로가 가리킨 공정(`process_ref`) — 이름 접두(`노칭::…`)와 극성의 기본. ② **개체별 부모**: 추출이 개체마다 `parent`를 낼 수 있다 — 「3. 스태킹」 절 아래에서 「전 공정(노칭)의 버」를 말하면 `버`의 부모는 `노칭`이고 이름은 `노칭::버`다. 부모는 **후보 안에서만** 고른다(좌표 서브트리 + 청크 본문에 나오는 골격 이름) — 밖이면 버리고 주 좌표를 쓴다(`defects.log`에 「개체 부모 후보 밖」). 이름을 정하기 **전에** 본다. ③ **관련 링크**(`about`): 청크가 「무엇에 관한 글인가」 — 주간 이슈처럼 여러 공정을 두루 말하는 청크가 각 공정에 매달린다(`chunks.json`의 `about` — `describes` 옆 두 번째 매달림). **조회 전용**이다 — 사전·이 문서의 해소 결과로만 찾고 노드를 만들지 않는다(못 찾으면 버리고 「관련 링크 미해소」 기록). 질의의 근거 순위는 describes(직접 > 확장) 다음이 관련 링크(직접 > 확장), 그다음이 ref 청크의 [관련 원문]이다. 옛 추출 체크포인트는 두 필드가 「없음」으로 읽힌다(재추출 강제 없음).

## 4. anode / cathode는 언제 갈라지나

극성은 **표기에 붙이지 않고** `electrode_type` 필드로만 온다(문서 2 §2.4). 갈리는 자리는 셋이다:

| Where | Rule | Example |
|---|---|---|
| 골격 seed | `@split` 마커가 붙은 공정은 개념 노드 + 극성 인스턴스 자식 둘(`@cathode`/`@anode`는 하나). 극성 무관 공정은 노드 하나(`polarity: none`) | `탭용접` → `탭용접`(개념) · `탭용접::cathode` · `탭용접::anode` |
| ⓪ 좌표 하강 | 행의 `electrode_type`이 확정이고 그 공정에 같은 극성 인스턴스가 있으면 **인스턴스로 내려가 부착** — 없으면 개념 노드(저해상도) | `탭용접` + cathode → `탭용접::cathode` |
| ① entity canonical | 스코프 카테고리의 이름은 부모 좌표가 접두되므로 극성이 이름에 실린다 — 후보 검색은 **극성이 다른 노드를 제외**한다 · finalize의 `mirrors`가 같은 이름부·반대 극성 쌍을 자동으로 잇는다 | `탭용접::cathode::용접 강도` ↔ `탭용접::anode::용접 강도` |

극성 열이 문서에 없으면 전부 개념 노드에 붙는다 — 오류가 아니라 저해상도다. 나중에 극성 있는 문서가 오면 인스턴스가 채워진다.

## 5. 큐 20종 — 각각 무엇을 기다리나

| Kind | Made at | Waiting for | You do |
|---|---|---|---|
| `orphan_anchor` | ⓪ | 골격 alias/노드 | seed `ALIASES` → `bootstrap` → 재인입 |
| `auto_node` · `uncertain_match` | ① | 사람 확인 | `ops confirm` / `merge` / `obsolete` — 종결은 항목에 `resolution`을 적는 것이고 계수에서 빠진다(재인입 회수가 보존) |
| `unknown_field` · `missing_field` | ① | 스키마·문서 | 스키마 role 추가 / 문서 값 |
| `orphan_attach` · `orphan_chunk_link` | ② | 대상 노드 해소 | 대개 orphan_anchor가 풀리면 같이 풀린다(retry) |
| `attach_conflict` · `spec_conflict` | ② | 사람 판정 | 어느 값이 맞나 |

| `evidence_lost` · `mirror_asymmetry` · `structural_proposal` | finalize | 사람 | 확인 |

`platform queue`가 kind별 건수, `platform queue <kind>`가 항목이다. **retry**: 인입이 끝날 때마다 미해결 orphan 항목을 다시 시도하되 **그 kind의 후보 집합(층별 노드·엣지 수)이 지난 시도 뒤 바뀐 때만** 돈다 — 그래프가 그대로면 LLM 0. 항목마다 「N회 재시도 · 첫 발생 <doc_id>」가 붙고 5회에서 멈춰 「사람 판정 대기」가 된다.

## 6. 새로 만들까, 누적할까 — 2B §5.5

문서 단위가 기준이다. 새 파일명 → 누적. 같은 파일명(doc_id) → 개정판 재인입(그 문서가 만든 것 회수 후 다시). `init --fresh`는 그래프·사전을 지우고 노드 id가 새로 나서 **판정을 전부 다시 한다** — 골격 구조가 바뀌었을 때만. 자세한 규칙은 `2B_작업가이드 §5.5`.

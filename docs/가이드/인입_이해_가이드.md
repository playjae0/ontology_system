# 인입 이해 가이드 — 행 하나가 노드·엣지·큐·사전이 되기까지, 화면 한 줄이 무슨 단계인가

> **누가 읽나**: `ingest-file`을 돌리며 화면을 읽는 사람. 「명령을 치는 순서」는 `2B_작업가이드 §5`, 「열의 role을 정하는 법」은 `역할_판정_가이드`, 이 문서는 **그 사이 — 시스템이 안에서 무엇을 하는지**를 사람 순서로 쓴 것이다. 정본은 문서 4(쓰기절차)·문서 2(계약)이고, 실물은 `core/pipeline.py`(행 루프) · `core/build.py`(해소·부착) · `core/matcher.py`(후보·판정) · `core/retry.py`(재시도)다. 아래 줄 번호·문면은 2026-09-15 기준 — B72·B73이 화면을 바꾸면 이 문서의 §3·§5가 따라 바뀐다.

## 1. 큰 그림 — 문서 하나에 일어나는 일 (순서가 계약이다)

```
ingest-file <문서>
 ├ 선택      doc_type(등록부 · --doc-type 또는 헤더 지문) · 형태 판정(table/prose)          LLM 0
 ├ 파싱      어댑터 extract → 조각(record/청크) · 좌표 태깅(정확 일치 · 미스 표기당 LLM 1) → parsed/<doc_id>.json
 ├ 구축      조각(행)마다 ⓪→④ (아래 §2)                                                     LLM = 개체 판정
 ├ 커밋      엣지는 (출발 카테고리, 관계, 도착 카테고리) 삼항이 층 config 패턴 안일 때만 저장  LLM 0
 └ finalize  mirrors 자동(극성 쌍) · retry_orphans(큐의 미해결을 다시 시도) · 문서 대장 기록
```

**정본 넷** — `data/<층>/graph.json`(노드·엣지) · `data/dictionary.json`(동의어 사전) · `data/chunks.json`(청크·describes) · `data/review_queue.json`(사람 판정 대기). 인입은 이 넷을 쓴다. 나머지 json은 장부·로그다(§5.4 표).

## 2. 행 하나의 길 — ⓪ 좌표 → ① role → ② 부착 → ③ 엣지 → ④ 폴백

| Step | What happens | LLM | Ends up in |
|---|---|---|---|
| ⓪ 좌표 | `process_ref`를 골격 닫힌 목록과 **정확 일치·alias**로 해소(anchor — 유사도·LLM 없음). 없으면 `process_group`으로 **저해상도 부착**(개념 노드에 붙는다 · 큐 없음). 둘 다 없으면 `missing_field`. 극성(`electrode_type`)이 있고 그 공정에 극성 인스턴스가 있으면 그리로 **하강**(`탭용접` + cathode → `탭용접::cathode`) | 0 | 해소 실패 → `orphan_anchor` 큐(행은 보류) |
| ① role | 스키마 `fields`의 열마다 role 핸들러. **entity**: 문서 내 buffer → 사전(`exact`, LLM 0) → 후보 → 판정 → 매칭/신규/불확실. **attribute·content**는 대상이 정해질 때까지 모아 둔다. **meta**는 값만 장부에. 스키마에 없는 키 → `unknown_field`(그래프에 안 들어간다 — 검색 관점에선 드랍과 같다) | entity 판정만 | 매칭 → 기존 노드에 provenance 추가 + **사전 등재** · 신규 → 노드(status auto) + `auto_node` 큐 + 사전 등재 · 불확실 → 노드(auto) + `uncertain_match` 큐 |
| ② 부착 | attribute를 `attach_to_field`의 노드 필드에 `{value, provenance}`로. content는 청크 저장 + `describes`. 대상 열이 **빈 셀**이면 아무것도 안 한다 · **값은 있는데 미해소**면 보류(`pending_attrs` · `orphan_attach`) | 0 | 노드 `attrs` · chunks.json |
| ③ 엣지 | 스키마 `edges` 선언대로 — 두 끝이 다 해소됐을 때만. 커밋 게이트가 삼항을 층 `relation_patterns`와 대조, 밖이면 거부(`show log gate`) | 0 | graph.json edges · gate_rejects.json |
| ④ 폴백 | 규칙 B — attach 대상이 없거나 미해소인 entity는 **행의 공정 좌표**에 부착(저해상도 · 오류 아님) | 0 | 엣지 |

**「자동 생성: Packaging :: Tab Sealing :: Tab Sealing 강도」** — ①의 신규 갈래. `::`는 canonical 스코프 접두(`canonical_scope.bind_categories` — 관리항목·설비는 공정 아래 이름이 유일하다)이고 「Tab Sealing 강도」가 공정 「Packaging :: Tab Sealing」 아래 만들어졌다는 뜻이다. 연결은 됐고, **사람이 확인한 노드는 아니다**(status auto — B73 ④ `ops confirm`).

## 3. 화면·로그 한 줄이 무슨 단계인가

| Line you see | Module | Step | Meaning · what to do |
|---|---|---|---|
| `선택 근거: … ← adapters/<dt>.py` | ingest | 선택 | 어느 어댑터로 가나. 「선택만」 = `--dry-run`이라 여기서 끝 |
| `형태 판정 — … table 찬성 5` | parser.form | 선택 | 표/산문. `--doc-type`과 어긋나면 경고만 |
| `좌표 태깅 — 조각 N · 정확 일치 a · 목록 밖 표기 k종 → LLM 최대 k회` | parser.tagger | 파싱 | 골격 이름과 안 맞는 **표기 종수**만큼 LLM(B69). 상한 `--coord-llm` |
| `onto.llm  LLM 사용량 ⑨좌표 태깅 — 입력 … 출력 …` | llm | 파싱 | 그 표기 하나의 호출 |
| `onto.store  큐 unknown_field — 스키마에 없는 필드 '…'` | store | ① | 어댑터가 낸 키가 스키마 `fields`에 없다 — 스키마에 role을 넣고(`meta`면 `{"role":"meta"}`) `register status` → 재인입. B72 뒤엔 등록에서 막힌다(G39) |
| `onto.llm  LLM 사용량 ②개체 동일성 판정 — 입력 … 출력 …` | llm | ① | 그 행의 entity 열 하나의 판정. **unknown_field와 무관** — 같은 행의 다음 단계다. 입력이 크면 후보가 많은 것(B73 ①) |
| `큐 판정 …` / `큐 orphan_anchor — …` | store | ⓪ | 골격 밖 좌표. 드랍 아님 — 보류. alias → `bootstrap` → 재인입 |
| `큐 auto_node — 자동 생성: A :: B :: C` | store | ① | 신규 노드. 나중에 `ops confirm/merge/obsolete`(B73 ④) |
| `게이트 거부 …` (`show log gate`) | gate | ③ | 삼항이 층 패턴 밖 — config `relation_patterns` 또는 스키마 edges |
| `mirrors …` | build | finalize | 같은 이름부 + 극성 반대 쌍을 자동 연결 |
| `인입 — record n · chunk m · 그래프 노드 k` | ingest | 끝 | k=0이면 골격 미확정 또는 좌표 전부 목록 밖(§5.3) |

`onto.<모듈>`은 로거 이름(문서 7 §7.8)이다 — `onto.llm`은 LLM 호출 1건에 한 줄, `onto.store`는 저장·큐에 한 줄.

## 4. anode / cathode는 언제 갈라지나

극성은 **표기에 붙이지 않고** `electrode_type` 필드로만 온다(문서 2 §2.4). 갈리는 자리는 셋이다:

| Where | Rule | Example |
|---|---|---|
| 골격 seed | `@split` 마커가 붙은 공정은 개념 노드 + 극성 인스턴스 자식 둘(`@cathode`/`@anode`는 하나). 극성 무관 공정은 노드 하나(`polarity: none`) | `탭용접` → `탭용접`(개념) · `탭용접::cathode` · `탭용접::anode` |
| ⓪ 좌표 하강 | 행의 `electrode_type`이 확정이고 그 공정에 같은 극성 인스턴스가 있으면 **인스턴스로 내려가 부착** — 없으면 개념 노드(저해상도) | `탭용접` + cathode → `탭용접::cathode` |
| ① entity canonical | 스코프 카테고리의 이름은 부모 좌표가 접두되므로 극성이 이름에 실린다 — 후보 검색은 **극성이 다른 노드를 제외**한다(D-40) · finalize의 `mirrors`가 같은 이름부·반대 극성 쌍을 자동으로 잇는다 | `탭용접::cathode::용접 강도` ↔ `탭용접::anode::용접 강도` |

극성 열이 문서에 없으면 전부 개념 노드에 붙는다 — 오류가 아니라 저해상도다. 나중에 극성 있는 문서가 오면 인스턴스가 채워진다.

## 5. 큐 20종 — 각각 무엇을 기다리나

| Kind | Made at | Waiting for | You do |
|---|---|---|---|
| `orphan_anchor` | ⓪ | 골격 alias/노드 | seed `ALIASES` → `bootstrap` → 재인입 |
| `auto_node` · `uncertain_match` | ① | 사람 확인 | `ops confirm` / `merge` / `obsolete`(B73 ④) |
| `unknown_field` · `missing_field` | ① | 스키마·문서 | 스키마 role 추가 / 문서 값 |
| `orphan_attach` · `orphan_chunk_link` | ② | 대상 노드 해소 | 대개 orphan_anchor가 풀리면 같이 풀린다(retry) |
| `attach_conflict` · `spec_conflict` | ② | 사람 판정 | 어느 값이 맞나 |
| `invalid_category` · `coord_mismatch` · `direction_*` | ①③ | 스키마·config | 층 어휘·패턴 |
| `parse_failure` · `adapter_mismatch` · `hierarchy_unresolved` · `duplicate_doc_hold` | 파싱·선택 | 문서·어댑터 | `--revise` / 재인입 / 해제 |
| `evidence_lost` · `mirror_asymmetry` · `structural_proposal` | finalize | 사람 | 확인 |

`platform queue`가 kind별 건수, `platform queue <kind>`가 항목이다. **retry**: 인입이 끝날 때마다 미해결 항목을 다시 시도한다 — 지금은 전량(B73 ②로 조건부).

## 6. 새로 만들까, 누적할까 — 2B §5.5

문서 단위가 기준이다. 새 파일명 → 누적. 같은 파일명(doc_id) → 개정판 재인입(그 문서가 만든 것 회수 후 다시). `init --fresh`는 그래프·사전을 지우고 노드 id가 새로 나서 **판정을 전부 다시 한다** — 골격 구조가 바뀌었을 때만. 자세한 규칙은 `2B_작업가이드 §5.5`.

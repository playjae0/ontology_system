# 정제본 회귀 스위트

> **왜 있는가**: 정제본은 읽기로만 검증돼 왔다. 개정할 때마다 검증 없는 변형이 쌓이면 묶음이 조용히 망가진다. 코드에 회귀 테스트가 있듯 **명세에도 있어야 한다.**
> **규율**: 개정은 아래 셋을 전부 통과해야 확정된다. 사람이 "괜찮아 보인다"고 판단하는 자리를 두지 않는다.
> **시험지는 고정한다** — 매번 새 질문을 만들면 매번 다른 것을 놓친다. 고정해야 회귀가 잡힌다.

## 시험 3종

| # | 시험 | 자산 | 잡는 것 | 통과 기준 | 실행 |
|---|---|---|---|---|---|
| 1 | **조항 대조** | `자산/조항_기준선.json` (1,699건 = 원천 13종 902 + 배경 구명세 3종 797) | 원천 규범이 개정으로 사라졌는가 | 소실 0 | 에이전트 대조 (§실행 1) |
| 2 | **판정 재현** | `자산/V1_문제지.json` (78문항) + `자산/V1_정답행.json` (장부 82건) | 개정이 다른 규칙의 해석을 깨뜨렸는가 | 직전 회차 대비 하락 0 | 에이전트 응시·채점 (§실행 2) |
| 3 | **문면 기계 점검** | `점검_문면.py` | 문면 규격 이탈 | 위반 0 | `python3 점검_문면.py` |

## 시험 3 — 무엇을 보는가 (8규칙, 사람 판단 0)

역참조 블록 보유(문서 0·2~7 — 문서 1은 검사기 자신이라 제외) · 금지 문면 통일(`않는다` 밖으로 새는 금지형 어미) · 마크다운 표 깨짐 · 코드펜스 짝 · 절 번호 중복 · 일정 서술 금지 · 문서 상호참조 범위(0~7·부록) · **원천 체계 안에서 말하는 서술**(정제본이 자신을 카드/챕터라 부르거나 챕터에 지시 — 좌표 표기 "(구)명세"·"21회차 등재"는 허용).

## 실행

### 시험 3 — 즉시
```
python3 회귀스위트/점검_문면.py          # exit 0 = 통과
REFINED_DIR=/다른/경로 python3 …         # 대상 디렉터리 변경
```

### 시험 1 — 조항 대조 (에이전트)
기준선 1,699건을 배치로 나눠 각 조항이 정제본에 살아 있는지 Grep으로 확인시킨다. **개정 직후에만 돌린다** — 전량은 비싸므로(실측 104분), 평시에는 **그 개정이 건드린 문서의 조항만** 부분 대조한다.

### 시험 2 — 판정 재현 (에이전트)
정제본만 읽은 응시자 6기가 78문항을 풀고, 채점자가 `V1_정답행.json`(결정 장부 원문)과 대조한다. **저자는 채점하지 않는다.** 직전 회차 성적: **일치 55 · 부분 16 · 불일치 7**(2026-08-21). 하락하면 그 개정이 무언가를 깨뜨린 것이다.

## 한계 — 정직하게

- 시험 1·2는 **자산에 있는 것만** 잡는다. 새 유형의 누락은 못 잡는다.
- 시험 3은 문면만 본다. 내용이 틀린 것은 못 잡는다.
- 그래서 **세 번째 겹이 필요하다**: 국면마다 독립 실행 감사 1회(클론해서 실제로 돌려 보기). 문서 대조로는 영영 안 나오는 것이 거기서 나온다 — 실측된 사례가 `core/llm.py` 부재다.

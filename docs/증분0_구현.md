# 증분 0 — 구현 증분 문서

> **목적**: 세션 N까지 확정된 전부를 **실행 가능한 구현 단위의 배열**로 번역한다. 구현자는 (구현문서 v1.16) + (이 문서)를 함께 읽되, 겹치면 이 문서를 따른다.
> **단위 정의의 규격**: 모든 단위는 3요소 — **인풋**(무엇을 넣나) · **조절점**(무엇을 조정할 수 있나: config·프롬프트·expects·임계 등 관리 자산) · **아웃풋**(결과를 무엇으로 보나: 산출 파일·큐·계기판·검수 뷰) — 를 명시한다. 사내 반입 시 이 3요소가 곧 점검표다(대장 §5.6-⑤).

## §1 진행 원칙과 결정 위임

상위 규범은 대장 §5.6(6항)이다. 구현 중의 실행 규칙만 여기 못박는다.

1. **BLOCKERS.md** — 카드·계약(§0의 원천)과 충돌하는 지점 = **멈춤**. 기록 후 의존 없는 다음 독립 작업으로 이동(구현문서 §9.4 유지). 추측으로 메우지 않는다. **BLOCKERS 기록·판정 요청 시 3요소를 첨부한다: ①근거 원문(어느 문서 어느 절) ②선택지 2~3개 ③각 선택지의 귀결** — 재료 없는 선택지는 판정이 아니라 추측이 된다(대장 §6.4-1).
2. **DECISIONS.md** — 그 외 세부 = **가결정 + 기록 + 전진**. 기록 형식: `[D-##] 지점 / 가결정 내용 / 근거 / 확정 경로(어느 세션·어느 절)`. **초기값 = 31건 (13회차 정정 — 구 "25건"은 실행검증_1차 미등재 상태의 계수 오기)**: §7의 D-1~D-14 + raw_mock_대장 §6의 D-15~D-21 + 판정대조_ipqc_1차 §8의 D-22~D-25 + **실행검증_1차 §6의 D-26~D-31**. 구현 시작 시 네 문서에서 그대로 옮겨 적는다.
3. **PROGRESS.md** — 단위 완료·테스트 결과·`git diff core/` 상태·소요 기록(구현문서 §9.5 유지). 세션 종료 시 프로젝트로 미러링한다(CH6 6.5의 실측 공백을 반복하지 않기 위한 계약).
4. 테스트는 완료판정의 기계 번역일 뿐이다 — 테스트가 통과해도 판정 문구와 어긋나면 판정이 이긴다(구현문서 §9.3 유지).

## §5 USE_MOCK 확장 정의 (구현문서 §8의 증분)

1. **추출 mock**: mock/extract_hints/{doc_id}.json이 존재하면 그 내용을 후보로 반환(결정적 — 게이트·구축 검증용). 없으면 문형 규칙 폴백: "(A)로 인해 (B)" / "(A)는 (B)를 유발" → (A, causes, B) · "(A)는 (B)로 이어진다" → (A, affects, B) · 카테고리는 config 정의문 예시·사전 매칭. mock 텍스트는 이 규칙이 잡는 통제 문형으로 창작한다(가결정 D-10).
2. **등록 생성 mock**: 어댑터·매칭 스키마 생성 LLM 호출을 fixture 반환으로 대체. **fixture의 정의(D-26, 13회차 편입): "미리 만든 정답"이 아니라 "외부 세션에서 실제 LLM이 산출한 결과물의 스냅샷"이다 — `mock/fixtures/`의 adapter·schema 실물이 그것이며, 사람이 손으로 써서 fixture에 넣으면 그 리허설은 아무것도 검증하지 않는다.** 재생성 지시 시 fixture의 대안본(…_rev1)을 반환해 루프 배선을 검증한다.
3. **이미지 요약 mock**: 고정 문자열 `"MOCK 요약: {image_ref}"` + meta.image_summary=true.

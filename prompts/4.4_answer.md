# 답변 생성 지시문 (LLM 지점 ⑧)

> **이 파일이 정본이다**(문서 7 §7.6-B-5).
> **그래프를 직접 읽지 않는다**(문서 0) — 넘어오는 것은 문장화된 사실과 청크 원문뿐이다.

## 지시문

**답은 짧게 — 기본 5줄 이내.** 링크 결과(링킹 · 경로 · 사실 · 근거 청크)는 화면이 답 옆에 따로 보인다 —
답은 그것을 다시 늘어놓지 않고 **질문에 답한다.**

넘어오는 채널(있는 것만):

- **[그래프 사실]**(`i` 번호) — 시스템이 보증하는 **구조 정보**. 순서·소속·규격이 여기 있다.
- **[노드 근거]**(`i` 번호) — 질문이 가리킨 노드와 그 이웃을 **서술하는** 원문.
- **[문서 검색]**(`i` 번호) — 질문 문장으로 **찾은** 원문(그래프에 닿지 않았어도 온다). 질문과 무관하면 쓰지 않는다.
- **[관련 원문]**(`i` 번호) — 질문의 대상 이름이 **들어 있기만 한** 참조용 원문(목록·표 등).

청크 번호(`i`)는 [노드 근거] · [문서 검색] · [관련 원문]을 **이어서 하나로** 센다.

1. **그래프 사실을 먼저 쓴다.** 구조·순서·규격 질문에서는 **그래프 사실이 이긴다** — 원문의 옛 서술이
   그래프 사실을 덮어쓰지 않게 한다. 채널을 동급으로 섞지 않는다.
2. **근거 번호를 인용한다** — 문장 끝에 `[사실 2]` · `[청크 5]`처럼.
3. **근거 밖은 모른다.** 근거에 없으면 **없다고 밝힌다** — 일반 지식으로 메우지 않는다.
4. **무관한 사실·청크는 버린다**(문서 5 §5.3 Q5 — **필터의 주체는 답변 LLM이다**).

## 출력 형식

```json
{"answer": "…", "used_facts": [0, 2], "used_chunks": [1, 4]}
```

`used_facts`는 **실제로 쓴 [그래프 사실]의 번호**, `used_chunks`는 **실제로 쓴 청크의 번호**다 — 화면이
「무엇을 써서 답했나」를 표시하고(링크 결과와 나란히) 계기판이 필터를 센다.
